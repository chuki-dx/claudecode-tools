What is CLAUDE.md?

Claude Code (an AI coding agent from Anthropic that runs in the terminal) starts every conversation with no memory of the previous one. CLAUDE.md is the instruction file it reads at the start of each session, so you don't have to repeat the same explanations every time. Its contents are plain Markdown (text where you can write headings and bullet lists).

Three lines covering role, tools, and priorities are enough to start. Keep growing the file by adding one line each time you explain the same thing twice. The official docs suggest keeping each file under 200 lines (as of writing), because the longer it gets, the heavier it is to load and the less likely it is to be followed. This tool counts the lines in its output and does not generate combinations that exceed 200 lines.

Where to put it

Where you place it changes its scope. These are the locations I confirmed in the official docs (as of writing: October 2026).

Where to put itScope of effectWhat to write
Organization-wide (Windows: C:\Program Files\ClaudeCode\CLAUDE.md)Everyone who uses that PCRules you want to apply across the whole organization. Placed by an administrator
Personal, shared across all projects (~/.claude/CLAUDE.md)All projects you useYour own preferences and rules shared across every project
For a project (CLAUDE.md in the root of your working folder, or .claude/CLAUDE.md)Everyone who works in that folderAssumptions and procedures to share with your team. The output of this tool is meant to go here.
For yourself, this project only (CLAUDE.local.md at the top level of the working folder)Just mePersonal notes you don't share. Add it to .gitignore

Your personal ~/.claude/CLAUDE.md is loaded no matter which folder you start in. If you test a CLAUDE.md meant for other people on your own PC, your personal instructions will affect the result too, so be careful (there is a real example in the Troubleshooting Cheat Sheet).

Put what you want to prohibit in settings.json

CLAUDE.md is not an enforced setting. It is instructions that Claude reads and tries to follow. Writing "don't read .env" there does not actually block anything. For operations that must be blocked, use the Permissions Generator to create deny rules in settings.json. The division of labor is: CLAUDE.md records the reasoning behind a rule, and permissions do the blocking.

In my testing, when CLAUDE.md said not to read a file, Claude did not attempt to read it. When you test whether deny works, temporarily rename CLAUDE.md first and then try.

FAQ

Should I start with the 3-line version or the template?

If you're using it alone, the 3-line version is enough. If you're distributing it through a department folder, use a template that covers how to use the folder and what to follow.

What if the folder already has files in it?

Type /init inside Claude Code and it looks at the contents of your folder and creates an initial CLAUDE.md. If a CLAUDE.md already exists, it suggests improvements instead of overwriting it. You can also compare it with this tool's output and add assumptions that only you know.

Is the content I enter sent anywhere?

No, it is not sent. This page runs on HTML and JavaScript only, and generation happens inside your browser. To count page views, only the URL of the page you opened is sent to the operator's server (no cookies or external analytics services are used. Details).
