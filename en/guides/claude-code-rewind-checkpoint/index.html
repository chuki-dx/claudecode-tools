How to roll back Claude Code changes: what checkpoints and /rewind can restore

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • According to the official docs, Claude Code automatically tracks changes made by Claude's file editing tools, and you can return to an earlier state with /rewind.
  • You can choose to rewind the code, the conversation, or both. There is also an operation that summarizes the conversation to free up space in the context window.
  • Bash commands, subagents, and changes made outside Claude Code may not be reversible, so this is not a substitute for Git.

What checkpoints can do

According to the official docs, Claude Code (an AI coding agent from Anthropic that runs in the terminal) automatically tracks Claude's file edits as it works. If the work goes in an unexpected direction, you can undo the changes and return to an earlier state.

Each time you send a prompt that starts a turn, Claude Code records the state of the code just before it as a checkpoint. The official docs state the following.

  • A new checkpoint is created for every prompt that starts a turn.
  • File snapshots keep the most recent 100 checkpoints per session.
  • Checkpoints are saved along with the conversation, so you can run /rewind even after resuming a session.
  • By default, session snapshots are deleted by a cleanup process about 30 days after they were last saved. If you try to rewind to a checkpoint whose snapshot is gone, it may fail with No files were restored. To keep them longer, set cleanupPeriodDays.

Source: Checkpointing

How to open /rewind and the actions you can choose

Run /rewind, or press Esc twice while the prompt input is empty, to open the rewind menu. If there is text in the input field, pressing twice only clears the input and does not open the menu. The cleared text is saved in the input history, so you can bring it back with Up after you finish in the menu.

The menu lists the prompts you sent during the session. Select the point you want to work from, then choose one of the following actions.

  • Restore code and conversation: Restores both the code and the conversation to that point.
  • Restore conversation: Returns the conversation to the point of that message while keeping the current code.
  • Restore code: reverts file changes while keeping the conversation.
  • Summarize from here: Compresses the conversation from this point onward into a summary, freeing up space in the context window.
  • Summarize up to here: Compresses the conversation before this point into a summary and keeps the later messages as they are.
  • Never mind: Returns to the message list without changing anything.

The two options for restoring code appear only when there are tracked file changes that can be rolled back to the checkpoint you selected. If no file edits were recorded after that point, the menu shows only Restore conversation, the two summarize options, and Never mind.

After you rewind the conversation or choose Summarize from here, the original prompt of the selected message is restored to the input box, so you can resend or edit it.

Source: Checkpointing

Conversation summary and returning to the state before /clear

If you choose Summarize up to here, you jump to the end of the conversation and the input box is empty. With either kind of summary, a Summarized conversation marker appears at the point where the conversation was compacted.

Summarizing doesn't change any files on disk, and the original messages remain in the session transcript, so Claude can still refer to the details. To specify what the summary should focus on, use the arrow keys to highlight the Summarize option, type your instructions on the row labeled add context (optional), and press Enter. If you select with a number key, it summarizes immediately without instructions.

Summarizing compresses the context within the same session, much like a targeted /compact. If you want to try a different approach while keeping the original session, the official docs point you to /branch or claude --continue --fork-session.

Go back to the conversation before /clear

If you ran /clear earlier in the same Claude Code process, an entry /resume <session-id> (previous session) is added at the top of the rewind menu. Selecting it resumes the conversation from before /clear, and it stays available until you exit Claude Code or resume a different session.

Source: Checkpointing

What can't be undone, and cautions

The official docs list the following limitations. These are points worth understanding before you use it internally.

Changes made by Bash commands

Checkpoints do not track files changed by Bash commands. For example, when Claude Code runs the following commands:

rm file.txt
mv old.txt new.txt
cp source.txt dest.txt

rewind cannot undo these changes. Only direct edits made by Claude's file editing tools are tracked.

Editing subagents

Subagents also edit files with Claude's file editing tools, but those edits are normally not recorded in the session checkpoints. Whether you can roll them back depends on how they were run.

  • When a skill with context: fork runs in the foreground, it edits the working tree during your own turn, so you can undo changes as usual. To run a fork in the foreground, set background: false. In some situations it runs in the foreground regardless of the setting; details are on the skills page.
  • Edits made by other subagents are not reverted; use Git to roll them back. This includes forked skills, which run in the background by default, and background /code-review --fix.

External changes and links

Only files edited within the current session are tracked. Manual changes made outside Claude Code, and edits from other sessions running at the same time, are normally not recorded. The exception is when they change the same files as the current session.

Files that are symbolic links or hard links are not restored. If you choose Restore code or similar, those paths are skipped, a Restored the code, but skipped N files warning appears, and the skipped files keep their current contents. This applies to config files linked by a dotfile manager and files that pnpm places as hard links. To see which paths will be skipped, enable debug logging with /debug before restoring.

Messages sent while work is in progress

A message you typed while Claude was working may show No code restore in the menu, because checkpoints are created for the prompt that starts a turn. To undo those file changes, select the prompt that started the turn and choose Restore code or Restore code and conversation. The whole turn is rolled back, including edits made before you sent the message.

Source: Checkpointing

Decision points for internal use

The official docs say checkpoints are meant for quick, session-level recovery, and that for permanent history and collaboration you should keep using version control such as Git for commits, branches, and long-term history. The docs list the following situations as a good fit.

  • Try a different implementation approach without losing your starting point
  • Quickly undo changes that caused bugs or defects
  • Try feature variations, as long as you can restore a working state
  • Summarize a long debugging conversation from the middle, keeping the initial instructions while freeing up context space

This content is based on the official docs as of writing (October 2026). Retention periods and display names may change, so check the official docs before you distribute this internally.

Source: Checkpointing

FAQ

Can /rewind restore files that Claude Code deleted with Bash rm?

You can't undo them. According to the official docs, checkpoints don't track files changed by Bash commands. They track only direct edits made through Claude's file editing tools.

Source: Checkpointing

Can I still use /rewind after resuming a session?

Yes, you can. Checkpoints are saved along with the conversation. However, by default snapshots are deleted about 30 days after the last save, and if they're gone, the restore can fail with No files were restored. To keep them longer, set cleanupPeriodDays.

Source: Checkpointing

Can I roll back only the conversation to an earlier point while keeping the code as is?

Choosing Restore conversation rolls the conversation back to the selected message while keeping your current code. To roll back only the code, choose Restore code.

Source: Checkpointing
