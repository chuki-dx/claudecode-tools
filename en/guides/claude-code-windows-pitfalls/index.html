10 common problems when using Claude Code on Windows, and how to fix them

Published: October 14, 2026 ・ Chuki DX Lab ・ Verified on a real machine with Windows 11 and Claude Code 2.1.296 (October 2026)

Key takeaways

  • Most Windows problems come down to three things: character encoding (BOM), the PowerShell execution policy, and the folder you launch from.
  • For permission settings, keep two points in mind: allow doesn't take effect until you accept the folder trust prompt, and deny doesn't block reads made through scripts.
  • Before you distribute it company-wide, try the 10 items in this article once on your own PC. It will cut down on questions.

Claude Code (Anthropic's AI coding agent that runs in the terminal) also runs on Windows, but if you follow guides written for macOS or Linux, you can get stuck in unexpected places. This article covers 10 items, limited to things that actually happened in Chuki DX Lab's testing and training preparation or that I confirmed in the official docs, organized as symptom, cause, and fix.

Shell and PowerShell

1. Commands run in PowerShell instead of Bash

Cause: According to the official docs, on a PC without Git for Windows, Claude Code runs shell commands in PowerShell. Once you install Git for Windows, they run in Git Bash.

Fix: If you use Bash-based procedures, install Git for Windows. The official docs also state that even when Git for Windows is present, the PowerShell tool is available by default alongside it for claude.ai and Console accounts. So in your permission settings, write PowerShell rules such as PowerShell(Invoke-WebRequest *) as well as Bash(curl *). Standardizing the requirements of the PCs you distribute internally reduces mismatches in procedures.

2. Japanese text in PowerShell scripts is garbled or causes syntax errors

Cause: Windows PowerShell 5.1 reads UTF-8 scripts without a BOM (a byte order mark, a marker at the start of a file that identifies its encoding) as a different character encoding.

Fix: Re-save the script as UTF-8 with BOM. When you have Claude Code create a script, include "save as UTF-8 with BOM" in your request.

3. You see "running scripts is disabled on this system"

Cause: It is blocked by the PowerShell execution policy.

Fix: Run the script in the form powershell -NoProfile -ExecutionPolicy Bypass -File script-name.ps1. This setting applies only to that single run and does not change the PC's settings.

Character encoding and Excel

4. CSV files it generates show garbled text when opened in Excel

Cause: The CSV was saved as UTF-8 without a BOM. Even if it displayed correctly once, re-saving it in another tool can remove the BOM.

Fix: In your request, say "save as UTF-8 with BOM so it opens in Excel." If writing that every time is a hassle, add one line to the rules section of CLAUDE.md.

5. The first column name of a CSV read in Python doesn't match

Cause: The BOM at the start of the file is read as part of the first column's name. You can't see it by looking at the file.

Fix: Ask it to read the file with encoding="utf-8-sig" specified in the script. It helps to think of cases 4 and 5 as combinations of "write with a BOM" and "skip the BOM when reading."

Permissions

6. A command is in allow, but I still get a confirmation prompt every time

Cause: You have not yet accepted the workspace trust prompt for that folder. According to the official docs, allow rules in the project's .claude/settings.json are not used until you accept, while deny and ask rules take effect regardless of trust. When you run claude -p, you may see a warning that allow rules were ignored.

Fix: Start claude once in that folder in an interactive screen and approve the trust prompt. After you distribute the settings, have each user do this once.

7. A .env file listed in deny can still be read through a script

Cause: A Read deny applies to Claude's read tool and to commands like cat, but not to scripts that open files on their own. This is documented behavior in the official docs. Also, as of writing, the sandbox that blocks access at the OS level is not available on native Windows, and is described as available on WSL 2.

What to do: As a baseline, don't put real API keys or real data in your working folder. If you need a stronger block, consider sandboxing with WSL 2 or managed settings that users cannot override.

Usage and environment

8. "File not found" errors

Cause: You started Claude Code outside the folder you want to work in. Claude Code works from the folder where it was started.

Fix: Use cd to move to the folder you want to work in, then restart. For training sessions, make sure everyone starts from the same folder.

9. Response tendencies differ between your PC and other people's PCs

Cause: Your personal ~/.claude/CLAUDE.md (personal instructions that apply to every project) is loaded as well. This can show up as an extra sentence you never asked for at the end of a reply.

What to do: Before training or rollout, run your checks with an account that has the same conditions as the end users. Move anything you want the team to share into the project's CLAUDE.md.

10. Running the script shows "python not found"

Cause: Python is not installed, or it is not in your PATH (the list of places the shell searches for commands).

Fix: Try running the script with the Windows Python launcher, as in py -3 script_name.py. If that still doesn't work, install Python. Before you distribute it, it's a good idea to check that your users' PCs have Python.

FAQ

Does installation require administrator privileges?

According to the official docs, on Windows you can install from PowerShell or CMD, and you don't need to run it as administrator. However, check separately whether your company requires an application for installing software.

Should I use WSL or native Windows?

If you want to use the sandbox, choose WSL 2. If you mainly work with Excel and PowerShell business files, native Windows combined with Git for Windows is an easy setup to start with. Decide based on the conditions of the PCs you distribute within your company.

I have a symptom that isn't listed here

First, run claude doctor to check for installation or configuration problems. Also see the cheat sheet, where you can look things up by symptom.
