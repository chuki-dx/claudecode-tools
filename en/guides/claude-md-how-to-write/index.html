How to write CLAUDE.md: where to put it and how to keep it short

Published: October 14, 2026 ・ Chuki DX Lab ・ Content is based on the official docs as of writing (October 2026)

Key takeaways

  • CLAUDE.md is the set of instructions Claude Code reads at the start of a session. Three lines covering role, tools, and priorities are enough to start.
  • Where you put a rule determines how far it reaches. Choose among organization, personal, project, and local scopes based on who the rule is for.
  • The official docs suggest keeping each file under 200 lines. Put things you want to forbid in the permission settings, not in CLAUDE.md.

What is CLAUDE.md?

Claude Code (an AI coding agent from Anthropic that runs in the terminal) starts each new session without remembering the previous conversation. CLAUDE.md is the file where you write the instructions it reads first, so you don't have to type the same explanation every time. Its contents are plain Markdown (text that supports headings and bullet lists).

The key point is that CLAUDE.md is not an enforced setting. Claude tries to follow what is written, but it is not a mechanism that blocks operations. If you want to reliably ensure "never read this file" or "never run this command," put it in the permission settings in settings.json.

Where files go and what they affect

In the official docs as of writing, CLAUDE.md can be placed in the following four locations.

TypeWhere to put itScope and what to write
For organizationsWindows: C:\Program Files\ClaudeCode\CLAUDE.mdAll users of that PC. Organization-wide rules set by an administrator
For yourself (all projects)~/.claude/CLAUDE.mdAll the projects you work on. Your personal preferences and common habits
For projectsCLAUDE.md or .claude/CLAUDE.md in the working folderEveryone who works in that folder. Assumptions and procedures meant to be shared by the team
For local useCLAUDE.local.md in the working folderJust for you, just for this project. Add it to .gitignore and don't share it

Even for the same line, where it goes depends on whom the rule is for. If "prioritize code that others can read and fix" is the team's policy, it belongs in the project file; if it's your own writing preference, it belongs in your personal file. With this split, when you hand the project CLAUDE.md to a new member, you won't carry over personal preferences with it.

How it is loaded

According to the official docs, all CLAUDE.md and CLAUDE.local.md files in the folder you launch from and in the folders above it are loaded at startup. When there are several, they are concatenated rather than overwritten, and the ones closer to the launch folder are read later. At the same level, CLAUDE.local.md is appended after CLAUDE.md.

On the other hand, a CLAUDE.md located in a folder below the one where you launched Claude is not read at startup. It is loaded when Claude reads or writes files in that folder. If you wrote something in a subfolder and it seems to have no effect, remember this difference.

The first three lines to write

If you're not sure what to write, start by writing the following three items, one line each.

  1. Your own position (what you're using it for)
  2. Frequently used tools
  3. Order of priority when you can't decide
# 業務環境メモ

- 私は中小企業の情シス担当で、社内の業務改善ツールを作っています
- よく使うのは Microsoft 365、Power Automate、Excel、Python です
- コードは「短さ」より「他の人が読んで直せること」を優先してください

If the folder already has files, run /init inside Claude Code and it creates an initial CLAUDE.md from the folder's contents. The official docs say that if a CLAUDE.md already exists, it suggests improvements instead of overwriting it.

A good time to add to the file is when you notice you've typed the same explanation twice. If you add one line each time, it grows into something that fits your own work.

Tips for keeping it short

The official docs suggest keeping each file to 200 lines or fewer. The longer a file gets, the more it costs to load and the less likely it is to be followed. To keep files short, keep the following writing tips in mind.

  • Be specific: Instead of "format it nicely," write "output dates in yyyy/mm/dd format." One vague line invites extra clarifying lines.
  • Write it so it can be verified: Instead of "test it," write "when finished, check whether the results match a sample Excel file."
  • Avoid contradictions: When instructions conflict, Claude picks one of them. When you add a line, look for an existing line on the same topic and rewrite it if there is one.

When you're about to exceed 200 lines, first look for lines you can cut. Good candidates are things Claude follows without being told, tools or procedures you no longer use, and personal preferences that belong somewhere else.

If it's still too long, the official docs describe two approaches. You can split topics into separate files under .claude/rules/, which lets you load specific files only when Claude works with matching files. You can also write @path inside CLAUDE.md to import another file, but those imports are loaded at launch along with the file, so the amount loaded doesn't shrink.

What not to write

A project's CLAUDE.md is often a file shared through Git or similar. Don't write passwords, API keys, tokens, personal information, customer names, or transaction amounts in it. Manage these in files excluded from sharing, and block anything you don't want Claude Code to read with deny in the permission settings.

FAQ

Responses tend to differ between my PC and other people's PCs

This is probably because your personal ~/.claude/CLAUDE.md is also being loaded. Move anything the team should share into the project-level file, and before you distribute it, test with an account that has the same conditions as your users.

How do I choose between CLAUDE.md and skills?

CLAUDE.md is meant to be read every time, while a skill is a procedure used when that task is requested. Moving the steps and output format of a routine task, such as summarizing meeting minutes, into a skill keeps CLAUDE.md short.

Does running /init in a folder that already has CLAUDE.md overwrite it?

The official docs say that if a CLAUDE.md already exists, it is not overwritten and improvement suggestions are offered instead. You can also use this as a starting point for periodic reviews.
