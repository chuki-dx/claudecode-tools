VS Code Claude Code extension settings: permission modes such as Manual, and using the CLI

Published: November 26, 2026 | Chuki DX Lab | Content is based on sources such as the official docs as of writing (November 2026); sources are listed at the end of each section

Key takeaways

  • Install the extension with the "Install for VS Code" link in the official docs, or by searching for "Claude Code" in the Extensions view. To use claude in a terminal, you need to install the CLI separately.
  • Manual is an alias for default. Choose a permission mode within the "Best for" range given in the source. The mode a new conversation starts in depends on initialPermissionMode and on your Claude Code version.
  • To get a terminal-style screen, use useTerminal. You can carry a conversation from the extension over to the CLI with claude --resume.

Installation methods and prerequisites

According to the official docs, the Claude Code extension (Claude Code is Anthropic's AI coding agent that runs in the terminal) requires VS Code 1.94.0 or later and an Anthropic account. The account can be a paid Claude subscription (Pro, Max, Ultra, Team, Enterprise) or a Claude Console account, and an API key is not required. If you use an external provider such as Amazon Bedrock, check the official docs.

There are two ways to install. Open the "Install for VS Code" link (which points to vscode:extension/anthropic.claude-code), or open the Extensions view with Ctrl+Shift+X (Cmd+Shift+X on Mac), search for "Claude Code", and click Install.

The extension marketplace is third-party software, and the docs note that Anthropic does not recommend, maintain, or audit it. If the extension doesn't appear after installation, try restarting VS Code or running "Developer: Reload Window" from the Command Palette.

Where the extension settings are and the main options

The official docs split settings into two places. The VS Code extension settings (Ctrl+, (Cmd+, on Mac), then Extensions > Claude Code) control how the extension behaves. ~/.claude/settings.json is shared by the extension and the CLI, and you use it for allowed commands, environment variables, hooks, MCP servers, and so on.

The main extension settings are as follows.

  • useTerminal (default false): Launches Claude in terminal mode instead of the graphical panel.
  • initialPermissionMode (unset by default): Controls the approval prompt for new conversations. The values are default, plan, acceptEdits, and bypassPermissions.
  • preferredLocation (default panel): Where Claude opens, either sidebar (right) or panel (new tab).
  • allowDangerouslySkipPermissions (default false): Adds Bypass permissions to the mode selection. The docs say to use it only in sandboxes without internet access.

For initialPermissionMode, only the value in user settings is read; the workspace value is ignored. Before v2.1.225, the default was default and the workspace value was also applied.

Permission modes and where Manual fits

According to the official docs, each mode is a trade-off between convenience and oversight. Manual mode is written as default in settings values. In the extension's initialPermissionMode, too, manual is an alias for default, and you pick Manual in the mode display. In the CLI you can also write claude --permission-mode manual or "defaultMode": "manual".

The "Best for" entries in the source table are below. I don't claim which is best; use them as input for choosing based on your use case and internal rules.

  • default (Manual): sensitive work and unfamiliar code
  • acceptEdits: Iterative work on code you are reviewing
  • plan: Work that involves exploring the codebase before making changes
  • auto: Long tasks, or when you want fewer approval prompts
  • dontAsk: Locked-down CI and scripts
  • bypassPermissions: isolated containers and VMs only

The extension's initialPermissionMode accepts the four values from the previous section. Deny rules apply in all modes, including bypassPermissions, while allow rules have no effect in bypassPermissions.

Which mode a new conversation starts in

If you leave initialPermissionMode unset, the extension decides the starting mode. According to the official docs as of writing (November 2026), when you start in the terminal or the VS Code extension, the built-in default is auto on Claude Code v2.1.283 and later. Before that, it was auto for sessions on Pro, Max, Ultra, and Team plans that fetch the feature flag, and default otherwise.

However, even if auto is selected, the session starts in Manual if auto mode isn't available in that session. It is also default if disableAutoMode is "disable" in any settings file.

In the extension too, from v2.1.283 onward ~/.claude/settings.json can be one of the inputs for the starting mode (before that, only for Pro, Max, Ultra, and Team plans). However, when the extension decides the starting mode, it does not read project settings. For the exact order, see "Switch permission modes" in the official docs.

If you want terminal sessions to always start in Manual, save the following in ~/.claude/settings.json.

{
  "permissions": {
    "defaultMode": "default"
  }
}

In the next session, the status bar shows ⏸ manual mode on.

Differences between the extension and the CLI, and how to use claude in the integrated terminal

According to the official docs, the extension is a graphical panel and the CLI is a terminal command line, and some features are CLI-only. The CLI has all commands and skills, while the extension has a subset (check with /). The ! Bash shortcut and tab completion are CLI-only.

If you want a CLI-style screen, check Use Terminal (useTerminal) under Extensions > Claude Code.

To use claude in the integrated terminal, you need to install the CLI separately. The extension does not add claude to your PATH, and the bundled CLI is a private copy for the chat panel. If claude still can't be found after installing, see the PATH troubleshooting steps in the official docs.

To connect the extension to an integrated terminal, install the extension and then start claude; it connects automatically. Claude Code v2.1.318 and later do not install the extension automatically, so until you install it, /ide reports "No available IDEs detected". In an external terminal, connect to VS Code with /ide.

The extension and the CLI share conversation history. To continue an extension conversation in the CLI, run claude --resume in a terminal and pick it from the selection screen.

FAQ

Is Manual mode separate from default?

manual is not a separate mode; it is an alias for default. According to the official docs, Manual mode is written as default in the settings value, and in the extension's initialPermissionMode, manual selects the Manual mode shown in the mode display.

Source: Choose a permission mode

If I install the extension, can I also use the claude command in a terminal?

No. The extension does not add claude to your PATH, so to use it in a terminal you need to install the CLI separately. If it still can't be found after installing, see the PATH troubleshooting steps in the official docs.

Source: Use Claude Code in VS Code

Can I set initialPermissionMode in workspace settings?

The official docs say VS Code reads initialPermissionMode from user settings and ignores workspace values. Before v2.1.225, workspace values were also applied.
