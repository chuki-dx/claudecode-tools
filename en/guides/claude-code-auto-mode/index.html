Claude Code auto mode settings: what the classifier blocks and how to add permissions

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • The classifier reads CLAUDE.md and the autoMode in personal, organization, and --settings configuration. An autoMode written in the project's .claude/settings.json is not read.
  • If you write environment, allow, soft_deny, or hard_deny without including "$defaults", it replaces the default rules for that entry.
  • To require confirmation before a push or PR, use permissions.ask. For operations that must never run, use permissions.deny.

Where the classifier reads its settings from

In auto mode in Claude Code (Anthropic's AI coding agent that runs in the terminal), a classifier (a mechanism that judges whether an action is safe) checks each action. According to the official docs as of writing (October 2026), the classifier reads the same CLAUDE.md content that Claude itself reads. So rules like "never force push" are best written in CLAUDE.md first.

For rules shared across multiple projects, use the autoMode settings block. It is read from the following three locations.

  • Personal: ~/.claude/settings.json (for infrastructure you personally trust)
  • Organization-wide: managed settings (for infrastructure you trust, distributed to all developers)
  • --settings flag or Agent SDK: for per-invocation overrides

autoMode in the project's .claude/settings.json and .claude/settings.local.json is not read, because that would let a repository inject allow rules. If you have it there, move it to ~/.claude/settings.json.

Entries from each scope are merged. Developers can't remove Managed settings entries, but an allow they add can override the organization's soft_deny. The official docs say this is not a strict policy boundary, so for operations that must always be blocked, use permissions.deny in Managed settings.

Keep the default rules and add to them, or replace them

According to the official docs, the classifier's default rules are replaced by the following three arrays. Each array is written in natural-language sentences.

  • autoMode.hard_deny: an unconditional safety boundary
  • autoMode.soft_deny: destructive operations that the user's intent can override
  • autoMode.allow: Exceptions to soft_deny

Precedence runs hard_deny, soft_deny, allow, and finally explicit user intent overrides the remaining soft_deny rules. A general request like "clean up the repository" does not count as explicit intent. You need to ask for the specific operation, such as "force push this branch."

To keep the default rules and add your own, put the string "$defaults" in the array. The following example keeps the default rules in all four arrays.

{
  "autoMode": {
    "environment": [
      "$defaults",
      "Source control: github.example.com/acme-corp and all repos under it"
    ],
    "allow": [
      "$defaults",
      "Deploying to the staging namespace is allowed: staging is isolated from production and resets nightly",
      "Writing to s3://acme-scratch/ is allowed: ephemeral bucket with a 7-day lifecycle policy"
    ],
    "soft_deny": [
      "$defaults",
      "Never run database migrations outside the migrations CLI, even against dev databases",
      "Never modify files under infra/terraform/prod/: production infrastructure changes go through the review workflow"
    ],
    "hard_deny": [
      "$defaults",
      "Never send repository contents to third-party code-review APIs"
    ]
  }
}

Note: If you set any of environment, allow, soft_deny, or hard_deny without including "$defaults", all the default rules for that entry are discarded. For soft_deny, built-in rules such as force push, curl | bash, and production deploys are removed. Each entry is evaluated independently.

Omit the defaults only when you plan to manage the whole list yourself. In that case, run claude auto-mode defaults to print the built-in rules, copy them into your settings file, and review them. You can also edit them in the Auto mode tab of /permissions, but it appears only in v2.1.246 and later, and only in sessions where auto mode is available.

Put a human check on push and PR

By default, pushing to and creating PRs from any branch of the repository you're working in, including the default branch, is allowed. However, non-default branches whose names indicate a deploy or publishing target, such as production, release, and gh-pages, are excluded, and the classifier also treats them as production deploys. Force pushes and commits containing secrets remain blocked.

If you want a human to confirm an action, use permissions.ask. According to the official docs, ask rules that specify content are evaluated before the classifier, so a confirmation always appears even in auto mode.

{
  "permissions": {
    "ask": [
      "Bash(git push *)",
      "Bash(gh pr create *)"
    ]
  }
}

This rule matches commands that start with git push or gh pr create. A push written with git -C or git -c in between does not match and will not prompt for confirmation. If you want to see the full command, add a PreToolUse hook.

  • Require confirmation: permissions.ask. The classifier cannot auto-approve matching operations.
  • To prevent execution: permissions.deny. It stops the action before the classifier and cannot be overridden.
  • This session only: tell it in conversation, "Don't push until I've reviewed." This can be lost when the context is compacted, so use ask or deny if you need certainty.

What to check and how to fix it when a request is denied

Actions denied by the auto mode classifier are recorded in the Recently denied tab of /permissions, where you can press r to mark one for retry (actions denied because the classifier couldn't reach a decision are not recorded). When calls are collapsed like Ran 3 shell commands, press Ctrl+O to expand them.

When Denied by auto mode classifier comes with a reason such as [Production Deploy], the classifier has judged the action to be risky. Here is how to handle it.

  • Destinations needed throughout the work (package registries, internal domains, repository hosts): add them to autoMode.environment
  • Commands you want to run without review: add an allow rule
  • An action you intended once: state your intent in the next message and have it retry

If the same destination is denied repeatedly, the classifier usually lacks context. Have it draft entries with /auto-mode-setup, then confirm they took effect with claude auto-mode config. If the classifier gives no verdict at all, as in Not run · auto mode's check had no usable answer, see the error section of the official docs.

Source: Configure auto mode

Billing notice for classifier requests

According to the official docs, in environments where server-side checks are enabled, the classifier check is performed free of charge as part of the session's model request. If the check can't reach the server, for example because an LLM gateway or proxy sits in between, a notice appears and Claude Code's own classifier requests count toward token usage. On Pro, Max, and Team plans, no notice appears.

As an administrator, the fix is to make sure the gateway passes requests and responses through unmodified. If you know the gateway can't support this, set the following before launch. A direct Anthropic API connection requires v2.1.281 or later, and because this is a temporary setting, it may be removed later.

export CLAUDE_CODE_AUTO_MODE_SERVER=0

FAQ

If I write autoMode in the project's .claude/settings.json, does it apply to the whole team?

It has no effect. The classifier does not read autoMode in project settings. Put it in ~/.claude/settings.json for yourself, or in managed settings for the whole organization.

Source: Configure auto mode

What happens if I forget to add "$defaults"?

This replaces all of the default rules for that entry. With soft_deny, you lose built-in rules such as force push and production deploys; with hard_deny, you lose the built-in data exfiltration rules.

Source: Configure auto mode

What happens if I press Enter on a billing notice?

For the pending action and the rest of the session, Claude Code's own classifier requests are used and count toward token usage. If the notice named the gateway, it won't appear again on this machine for 24 hours. With Esc or Ctrl+C, the action isn't run and nothing is remembered.
