How to share Claude Code skills across a team, and the order to check when they don't work

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, skills in Claude Code (an AI coding agent from Anthropic that runs in the terminal) can be distributed at three scopes: project, plugin, and managed settings.
  • To start small, you can commit .claude/skills/ to version control. Also check the runtime environment for bundled scripts (Python 3 in the official example) before distributing.
  • If a skill doesn't work, check in this order: keywords in the description, whether it appears when you ask What skills are available?, and whether it runs when invoked directly with /skill-name.

Three scopes for sharing skills across a team

Skills (a mechanism where you write a description and steps in SKILL.md and Claude uses it as needed) can be scoped depending on who you're distributing them to. According to the official docs, there are three options:

  • Project skills: Commit .claude/skills/ to version control.
  • Plugins: create a skills/ directory inside the plugin.
  • Managed: distribute across the whole organization through managed settings.

The specific steps for plugins and managed settings are not covered in this source, so check the official docs. This article is based on the official docs as of writing (October 2026).

Source: Extend Claude with skills

See how to build and test a skill in the official example

The official docs include an example skill called codebase-visualizer that shows a codebase as HTML. The first directory to create is as follows.

mkdir -p ~/.claude/skills/codebase-visualizer/scripts

SKILL.md uses ${CLAUDE_SKILL_DIR} for script paths, so it resolves correctly whether the skill is personal, project, or plugin-based. This is a useful pattern for skills you distribute to a team. The bundled visualize.py requires Python 3, but it uses only built-in libraries, so no extra packages are needed.

To verify, open Claude Code in any project and ask it to "Visualize this codebase." In environments where a browser doesn't open, you can confirm success from the generated file path that is displayed.

Order of checks when a skill isn't invoked

The official docs list these verification steps.

  1. Check that the description contains keywords users would naturally say.
  2. Check that the skill appears in the list when you ask What skills are available?.
  3. Rephrase your request so it is closer to the description.
  4. If the skill is user-invocable, call it directly with /skill-name.
  5. If /skill-name is not recognized either, check whether Claude Code may have rejected the skill name.
  6. If you set paths, check that the files Claude reads, edits, or writes are inside the current working directory. Files in a sibling git worktree don't take effect, even if you added them with /add-dir. Launch Claude Code in that worktree, or move the session with /cd.

If the YAML in the frontmatter (the settings section at the top of the file) is broken, the body is loaded with empty metadata. Even if /skill-name works, Claude cannot match it against description. You can check for parse errors with --debug.

To find a SKILL.md that can't be parsed, use claude plugin validate, for example claude plugin validate .claude/skills. This requires Claude Code v2.1.233 or later. If a skill is invoked too often, make its description more specific, or add disable-model-invocation: true so it runs only when invoked manually.

When it follows at first but stops partway through

If Claude follows an instruction in the first response but stops following it later, the official docs give the following guidance by situation.

  • If you're skipping a rule that must always be followed: move it to a hook (a mechanism that runs on every event). Claude Code runs hooks whether or not it follows a skill.
  • If you skip guidance that requires judgment: Write it so it applies to the whole task, such as "run the tests after every edit" instead of "run the tests." Claude Code adds the skill's content to the conversation when it is invoked and does not reread the file in later turns.
  • If the conversation is compacted: invoke the skill again to restore its full text. After compaction, only the beginning may be retained, so put important instructions near the top of SKILL.md.

Source: Extend Claude with skills

With many skills, descriptions get cut off

According to the official docs, Claude Code loads a list of skill names and descriptions into context. All names are included, but when there are many skills, some descriptions are omitted to fit a character budget, and the keywords needed for matching are lost. The budget is based on 1% of the model's context window. When it overflows, the skills you invoke least often are omitted first.

You can check the estimate with /doctor. To raise the budget, set skillListingBudgetFraction or the environment variable SLASH_COMMAND_TOOL_CHAR_BUDGET. For lower-priority skills, setting skillOverrides to "name-only" lists them without descriptions. Put the main use first in description and when_to_use. The combined text of each entry is capped at 1,536 characters.

FAQ

What are the ways to share skills with a team?

According to the official docs, you can distribute skills by committing .claude/skills/ to version control as project skills, by placing them in a plugin's skills/ directory, or by rolling them out organization-wide through managed settings. For the plugin and managed settings procedures, check the official docs.

Source: Extend Claude with skills

When a skill isn't being used, what should I check first?

Check that the description contains keywords users would naturally say, and see whether the skill appears in the list when you ask What skills are available?. If it still doesn't trigger and it is a user-invocable skill, try calling it directly with /skill-name.

Source: Extend Claude with skills

Why do skill instructions stop working as a conversation gets longer?

According to the official docs, Claude Code adds a skill's content to the conversation when it is invoked and does not re-read the file in later turns. If the conversation is compacted, invoke the skill again to bring back the full text.
