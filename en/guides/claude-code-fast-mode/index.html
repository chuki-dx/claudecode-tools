What Claude Code fast mode is: how pricing works and when to use it

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • Fast mode is a setting that makes Claude Opus responses up to 2.5x faster. Quality is the same, but the price per token is higher. As of writing (October 2026), it is a research preview, and features, pricing, and availability may change.
  • On subscriptions (Pro/Max/Team/Enterprise), it runs on usage credits only and does not count toward the plan's rate limits. For Team and Enterprise, an Owner must enable it first.
  • It suits quick iteration and live debugging, while standard mode is better for long autonomous tasks and CI/CD. If you roll it out company-wide, you can keep costs down with a per-session enablement setting.

What fast mode is and what it can do

According to the official docs, fast mode is a setting in Claude Code (Anthropic's AI coding agent that runs in the terminal) for using Claude Opus at higher speed. It is up to 2.5x faster, in exchange for a higher price per token.

This uses Claude Opus with a different API configuration that prioritizes speed, rather than a different model. Quality and capabilities are the same. It is supported on Opus 5.5, Opus 5, and Opus 4.8, and not on models such as Sonnet or Haiku. Opus 4.7 is not supported, and fast mode turns off if you switch to it.

Because this is a research preview, features, pricing, and availability may change. Mention this when you announce it internally.

Source: Speed up responses with fast mode

How pricing works: unit prices and billing

According to the official docs, fast mode has a higher per-token price than standard Opus. The prices per MTok are as follows.

  • Opus 5.5: $8 input, $40 output
  • Opus 5: $10 input, $50 output
  • Opus 4.8: $10 input, $50 output

The price is flat across the entire 1M-token context window. For a comparison with standard Opus, check the official pricing page.

One thing to note: when you first enable it in a conversation, the fast mode rate for uncached input tokens is charged on the entire context of that conversation. The deeper the conversation, the higher the cost, so enabling it at the start of a session is the cheapest. This cost applies once per conversation and is not repeated if you turn it off and on again.

On a subscription, fast mode is charged directly to usage credits even if your plan still has allowance remaining. In the Claude Console, your organization pays per token, as with other API usage.

Where to check what you've used

The official docs say to run /status first. If you see a Login method line, you're on a Claude subscription; if you see an API key line, you're billed through a Claude Console organization.

  • Pro and Max: the Usage credits section under Settings > Usage on claude.ai shows this month's spending. It includes fast mode usage, but that is not shown separately.
  • Team and Enterprise: paid from your organization's usage credits. You can check your own usage with /usage.
  • Claude Console: On the Usage and Cost pages, choose Speed (Research Preview) in the Group by menu to view them separately. You can select it only if there was fast mode usage during the period.

When to use it: splitting work between fast mode and standard mode

The official docs say it suits interactive work where response wait time matters more than cost.

  • Fast iteration on code changes
  • Live debugging
  • Work with tight deadlines

Standard mode suits long autonomous tasks where speed matters less, batch processing and CI/CD pipelines, and cost-sensitive work.

How it differs from effort level

Lowering the effort level reduces thinking time and speeds up responses, but quality may drop on complex tasks. Fast mode keeps the same quality and lowers latency, at a higher cost. You can also combine the two to get maximum speed on simple tasks.

Steps to enable it and prerequisites

How to switch

In the CLI, run /fast, press Space to toggle it on or off, and press Enter to confirm. You can also write "fastMode": true in your user settings file. While it's on, a small ↯ icon appears next to the prompt.

In the VS Code extension, the Toggle fast mode command is available if the selected model supports it. Turning it off keeps you on Opus, so use /model when you want to go back to a different model.

Prerequisites

  • Only the Anthropic API or a subscription. It can't be used with Amazon Bedrock, Google Cloud's Agent Platform, Microsoft Foundry, or Claude Platform on AWS.
  • On subscriptions, you need to turn on usage credits. Until they are on, /fast reports "Fast mode requires usage credits". On Pro and Max, turn them on in the Usage credits field under Settings > Usage or with /usage-credits. On Team and Enterprise, a member with billing permissions turns them on in Organization settings > Usage.
  • Console requires a paid organization and can't be used on the free Evaluation plan. You also need to configure access provisioning.
  • On Team and Enterprise, this is disabled by default and can't be used until an Owner enables it.

Notes for company-wide rollout

To enable it, go to Claude Code preferences as an admin in Console, or Organization settings > Claude Code as an Owner in Team and Enterprise. To disable it entirely, set CLAUDE_CODE_DISABLE_FAST_MODE=1.

By default, a setting you turn on in an interactive session persists across sessions. To keep costs down in organizations that run many sessions at once, set fastModePerSessionOptIn to true in the settings file. Each session then starts with it off, and you enable it explicitly with /fast.

{
  "fastModePerSessionOptIn": true
}

Owners on Team and Enterprise can distribute this across the whole organization through server-managed settings. When you set this key in managed settings, /fast on is rejected outside interactive terminal sessions.

There are also limits and network caveats. Fast mode has its own rate limits separate from standard Opus, and the supported Opus models share one pool. When you hit the limit, it automatically falls back to standard speed and pricing, then becomes active again after a cooldown. In environments that block direct access to api.anthropic.com through an LLM gateway, the availability check can fail and you get standard speed. See the official docs for workarounds.

FAQ

Is fast mode included in my Pro or Max usage allowance?

No, it isn't included. According to the official docs, on subscriptions (Pro/Max/Team/Enterprise), this feature in Claude Code runs on usage credits only and does not count toward the plan's rate limits. Even if you have allowance left on your plan, charges come directly from usage credits.

Source: Speed up responses with fast mode

Is it safe to turn on fast mode in the middle of a conversation?

You can use it, but when you first enable it, the fast mode rate for uncached input tokens is charged on the entire context of that conversation. The deeper the conversation, the higher the cost, so enabling it at the start of a session is the cheapest.

Source: Speed up responses with fast mode

What causes "Fast mode has been disabled by your organization" when I run /fast?

The official docs list these cases: fast mode isn't enabled for your organization; fastMode: false is set in managed settings; or /fast on was run outside an interactive terminal while fastModePerSessionOptIn: true is set in managed settings. Check with your admin.
