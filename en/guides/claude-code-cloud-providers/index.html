How do you adopt Claude Code in a company? Choosing a delivery route such as Bedrock or Google Cloud

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • Claude for Teams or Enterprise is recommended for most organizations and requires no infrastructure setup. Going through a cloud provider is an option when you have reasons to stay with AWS, GCP, or Azure.
  • Through a cloud provider, features that require a Claude subscription, such as cloud sessions, are unavailable, and so are server-managed settings.
  • Before you distribute it, decide on model pinning, whether you need a proxy or gateway, and route restrictions with allowedProviders.

Teams / Enterprise is recommended first

Claude Code (an AI coding agent from Anthropic that runs in the terminal) can be deployed directly through Anthropic or through a cloud provider. According to the official docs, Claude for Teams or Claude for Enterprise is the easiest option for most organizations: one subscription covers both Claude Code and Claude on the web, billing is centralized, and no infrastructure setup is needed.

Teams is self-service, includes SSO, billing management, and server-managed settings, and is aimed at small teams. Enterprise adds domain capture, role-based permissions, and a compliance API, and is aimed at larger organizations. The Anthropic Console is described as being for individual developers. The source gives no prices, so check the official pricing page for current amounts.

Source: Enterprise deployment overview

Differences between Bedrock, Google Cloud, and Foundry

From the comparison table for cases with infrastructure requirements, I pull out the points that bear on the decision.

  • Amazon Bedrock: For AWS-native setups. You pay usage-based pricing through AWS, authenticate with an API key or AWS credentials, and manage access with IAM policies and CloudTrail.
  • Google Cloud: for GCP-native environments. The official docs call it "Google Cloud's Agent Platform (formerly Vertex AI)." Billing is pay-as-you-go through GCP, authentication uses GCP credentials, and management is handled through IAM roles and Cloud Audit Logs.
  • Microsoft Foundry: for Azure-native setups. Pay-as-you-go billing through Azure, authentication with an API key or Microsoft Entra ID, and management through RBAC policies and Azure Monitor.

Prompt caching is enabled by default on every route. Claude on the web is included only for Teams/Enterprise. For Bedrock and Google Vertex AI, run claude and choose 3rd-party platform on the login screen to launch an interactive setup wizard.

Watch for features that aren't available through cloud providers

This is the crux of the adoption decision. According to the feature list in the official docs, features that require signing in with a claude.ai account, such as cloud sessions, the mobile app, Routines, Remote Control, and the Chrome extension, are not available through third-party providers. Claude Code Desktop is a partial exception; check the official docs for the conditions.

  • Bedrock: Web search, fast mode, Advisor, Channels, the analytics dashboard, and server-managed settings are not available.
  • Google Cloud: fast mode, Advisor, Channels, the analytics dashboard, and server-managed settings are not available. Web search is available with Opus 4, Sonnet 4, Haiku 4.5, and later models.
  • Foundry: fast mode, Advisor, Channels, GitLab CI/CD, the analytics dashboard, and server-managed settings are not available.

The CLI, the VS Code and JetBrains extensions, subagents, hooks, skills, CLAUDE.md, and MCP servers work on every path. As alternatives, the docs point to /loop instead of /schedule, and to GitHub Actions or GitLab CI/CD instead of cloud sessions (which CI you can use differs by path). Zero Data Retention depends on your contract with each cloud provider.

Proxies and LLM gateways

According to the official docs, most organizations can use the cloud directly without extra configuration. If you have network or management requirements, you use the following two. They are separate settings and can be used together.

  • Corporate proxy: For when your policy requires all outbound traffic to go through a proxy. Set it with HTTPS_PROXY or HTTP_PROXY.
  • LLM gateway: A service that handles authentication and routing between Claude Code and the cloud. It suits cases where you need visibility into usage across teams and centralized control of rate limits, budgets, and authentication. You configure it with one of ANTHROPIC_BASE_URL, ANTHROPIC_BEDROCK_BASE_URL, ANTHROPIC_AWS_BASE_URL, ANTHROPIC_VERTEX_BASE_URL, or ANTHROPIC_FOUNDRY_BASE_URL.

You can check the provider or proxy in use with /status. Note that through a gateway or a custom ANTHROPIC_BASE_URL, customer-managed encryption keys (CMEK) are not applied to that session's operational telemetry. To turn off telemetry for all developers, distribute DISABLE_TELEMETRY in managed settings. Also, if ANTHROPIC_BASE_URL points to a host other than Anthropic's API itself, Remote Control and server-managed settings are turned off.

Operational points to decide before rollout

Narrow down what to decide before distribution.

Pinning the model

When deploying through Bedrock, Google Cloud, Foundry, or similar, the docs recommend pinning model versions with ANTHROPIC_DEFAULT_FABLE_MODEL, ANTHROPIC_DEFAULT_OPUS_MODEL, ANTHROPIC_DEFAULT_SONNET_MODEL, and ANTHROPIC_DEFAULT_HAIKU_MODEL. If you don't pin them, the defaults are the ones built into Claude Code, which may lag behind the latest release or may not be enabled on your account.

Restricting routes

With allowedProviders in managed settings, you can restrict which routes managed machines can use. For example, ["bedrock"] allows only Amazon Bedrock. Claude Code v2.1.285 or later is required.

How to Roll It Out

  • If you have your own development environment, provide a one-click way to install it
  • Start with questions about the codebase or small fixes, and have Claude make a plan so you can review its proposal
  • A central team configures MCP and includes .mcp.json in the codebase

Based on the official docs as of writing (October 2026). Conditions may change, so check the latest information before adopting.

FAQ

Can I use MCP and the VS Code extension through Bedrock or Google Cloud?

According to the official docs, the CLI, the VS Code and JetBrains extensions, subagents, hooks, skills, CLAUDE.md, plugins, and MCP servers work with all providers. However, claude.ai connectors are loaded only when the authentication method has an active claude.ai subscription.

Source: Feature availability

Can I use web search with Bedrock?

According to the list in the official docs, web search is not available on Amazon Bedrock. As an alternative, the docs point to the WebFetch tool with a specified URL. On Google Cloud it is available with Opus 4, Sonnet 4, and Haiku 4.5 or later models, and it is also available on Microsoft Foundry.

Source: Feature availability

How can an admin restrict which access paths can be used?

According to the official docs, you use allowedProviders in managed settings. For example, ["bedrock"] allows only Amazon Bedrock. Claude Code v2.1.285 or later is required. You may also need to pin endpoint variables, so check the official docs for details.
