How to install Claude Code on Windows: native vs. WSL, and checks after installation

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, on Windows you can run it either natively (PowerShell or CMD) or in WSL. As a rule of thumb, use WSL 2 if you need sandboxed execution, and native for projects on the Windows side.
  • Commands differ by environment. PowerShell and CMD use different commands, and WSL runs Linux commands in a WSL terminal.
  • When it finishes, run claude --version in a new terminal, and run claude doctor to diagnose problems if needed.

Decide first: native Windows or WSL

This article organizes the steps for installing Claude Code (an AI coding agent from Anthropic that runs in the terminal) on Windows, based on what the official docs describe. It reflects the content as of writing (October 2026) and is not the result of my own testing, so check the official docs for the latest information.

According to the official docs, supported operating systems are Windows 10 1809+ or Windows Server 2019+. You also need 4 GB+ RAM, an x64 or ARM64 processor, and an internet connection. You must also be in a country supported by Anthropic.

The official docs say to choose based on where your project lives and which features you need.

  • Native Windows: no prerequisites (Git for Windows is optional). Sandboxing is not supported. Suited to native Windows projects and tools.
  • WSL 2: Requires WSL 2 to be enabled. Sandbox supported. Intended for Linux toolchains and sandboxed execution.
  • WSL 1: Requires WSL 1 to be enabled. The sandbox is not supported. This is an option when WSL 2 isn't available.

Source: Advanced setup

Steps to install on native Windows

The official docs recommend the native installation. Run it in PowerShell or CMD; you do not need to run as administrator. The only difference is the command you run: if the prompt is PS C:\ it is PowerShell, and if it is C:\ without PS it is CMD. In PowerShell, run the following.

irm https://claude.ai/install.ps1 | iex

In CMD, run the following.

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

No progress is shown during installation. When it finishes, open a new terminal and verify. The native version updates automatically in the background.

If you mix up the commands, the docs say you get the following error.

  • The token '&&' is not a valid statement separator: You are running a CMD command in PowerShell.
  • 'irm' is not recognized as an internal or external command: You are running the PowerShell command in CMD.

For other errors (such as 403), check the official installation troubleshooting for how to handle them.

Git for Windows is optional

Git for Windows is optional and provides Git Bash, which the Bash tool and Monitor tool use. If you don't install it, Claude Code uses PowerShell as its shell tool. If Git Bash still isn't found after you install it, specify the path in env in settings.json.

{
  "env": {
    "CLAUDE_CODE_GIT_BASH_PATH": "C:\\Program Files\\Git\\bin\\bash.exe"
  }
}

Installing with WinGet

You can also install it with WinGet, but it does not auto-update. You need to run winget upgrade Anthropic.ClaudeCode periodically.

winget install Anthropic.ClaudeCode

Source: Advanced setup

Steps to install in WSL

Open your WSL distribution and run the Linux install command. Both the installation and launching claude happen inside the WSL terminal, not from PowerShell or CMD. Git for Windows is not needed in WSL.

curl -fsSL https://claude.ai/install.sh | bash

If you need the sandbox, use WSL 2. If WSL 2 isn't available, you can choose WSL 1, but the sandbox won't work.

Source: Advanced setup

Verifying after installation

Open a new terminal and run the following.

claude --version

If it works, a version number is displayed, such as 2.1.211 (Claude Code). If you see that claude is not found or not recognized, the install location is not on your PATH. See the official troubleshooting page for how to fix PATH.

For more detail, use the following command. It doesn't start a session; it shows the installation status, settings file validation errors, and warnings with suggested fixes, all read-only.

claude doctor

If everything looks fine, open a terminal in the project you want to work on and run the following to start an interactive session.

claude

Source: Advanced setup

Using WSL with the desktop app

According to the official docs, the Code tab of the Windows desktop app can run sessions inside a WSL 2 distribution. The requirements are as follows.

  • Windows 10 or 11 and WSL 2 (WSL 1 is not supported)
  • At least one distribution (for example, Ubuntu)
  • git is already installed in the distribution

This suits cases where the repository is in the distribution's file system. Accessing it from Windows goes through a network file system, which is slow and breaks file watching.

Features listed as not yet available include the integrated terminal, connectors and plugins, session branching, the file browser pane, and file suggestions when typing @. On organization-managed devices, WSL sessions may be unavailable, depending on the administrator's settings.

Source: Claude Code Desktop in WSL

FAQ

Do I need Git for Windows if I install in WSL?

According to the official docs, Git for Windows is not required for a WSL setup. It is recommended when you want to use the Bash tool on native Windows. Even without it, Claude Code uses PowerShell as its shell tool.

Source: Advanced setup

How do I check whether the installation succeeded?

Open a new terminal and run claude --version. According to the official docs, if a version number is displayed, the install is fine. For a more detailed diagnosis, use claude doctor, which shows the installation status and settings file errors in read-only mode.

Source: Advanced setup

Can I use WSL in the desktop app's Code tab too?

According to the official docs, you can run sessions inside a WSL 2 distribution. WSL 1 is not supported, and git is required inside the distribution. Some features, such as the integrated terminal, are not available yet.

Source: Claude Code Desktop in WSL
