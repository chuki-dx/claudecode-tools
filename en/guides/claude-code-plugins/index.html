How to install Claude Code plugins, and what to watch for when choosing a marketplace

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • For Claude Code (Anthropic's AI coding agent that runs in the terminal), the standard way to add a plugin is to run /plugin in a session and pick one from the Discover tab.
  • Marketplaces are divided by name into official, community, and third-party, but at every level an installed plugin can run code with the user's permissions. You need to check before installing.
  • Enabled plugins affect every session. Before you roll them out company-wide, check the scope and Context cost, and decide on a policy of disabling plugins you don't use.

What plugins can do

According to the official docs, a plugin is a directory containing skills, agents, hooks, MCP servers, and more, which Claude Code installs and loads as a single bundled unit. Most are installed from a marketplace. A marketplace is a catalog that lists plugins and where to get them, not a store.

A skill is instructions written in SKILL.md, a hook is a command that runs at key points in Claude Code's behavior such as after an edit, and an MCP server is a server for tools that Claude Code connects to.

These all work on their own without a plugin. The official docs say to use a plugin when you want to bundle several of them together, or when you want to install a setup someone else built with a single command and receive updates from a marketplace.

Source: Plugins overview

How to install it in the terminal

The example in the official docs is commit-commands from the official Anthropic marketplace, which adds commands for committing, pushing, and creating pull requests. The official marketplace is added automatically the first time you start an interactive terminal session (unless it is blocked by a managed policy).

Start claude and run the following command. Inside the session, it doesn't install right away. Instead, the /plugin panel opens on that plugin's details, where you can review it and choose a scope.

/plugin install commit-commands@claude-plugins-official
  1. In the detail view, check the commands, agents, skills, hooks, and MCP and LSP servers the plugin adds. Because plugins can run hooks and MCP servers, read through them before you install.
  2. Choose a scope (explained in the next section).
  3. The last sentence of the post-install summary tells you whether the plugin is usable in the current session. If it says Plugin is now active., no reload is needed. If it says Run /reload-plugins to apply., Claude Code runs the reload, but if the reload would invalidate the prompt cache, it shows a warning and leaves the plugin pending.
  4. Type / and check whether /commit-commands:commit appears. You can also see the list with claude plugin list.

To browse and install, run /plugin without a plugin name to open the Discover tab. The desktop app and VS Code each have their own separate steps. Cloud sessions have no plugin browser and don't load plugins installed on your local machine. See the official docs for details.

From scripts, run claude plugin install in the shell. The default is user scope, and the plugin is loaded at the next startup or when you run /reload-plugins.

Source: Install and manage plugins

How to choose a scope

The scope you choose at install time determines who it is enabled for.

  • User scope: for yourself, and active in all projects on this machine. The setting is stored in ~/.claude/settings.json.
  • Project scope: applies to everyone who works in that repository. The settings go in .claude/settings.json, which you commit. However, committing does not install anything on each person's machine, so each person needs to run the install once with the project scope specified.
  • Local scope: for you only, and active only in that repository. The settings go in .claude/settings.local.json.

When the same plugin is configured in multiple scopes, local overrides project, and project overrides user. Also, some plugins are disabled initially by the author's settings; in that case, enable them from the Installed tab or elsewhere.

Source: Install and manage plugins

Things to watch when choosing a marketplace

The official docs divide marketplaces into three tiers by name. Claude Code recognizes the official and community names only for marketplaces based on repositories under github.com/anthropics/.

  • Official: claude-plugins-official and others. This also includes claude-code-plugins, which is for demos.
  • Community: Anthropic community names such as claude-community.
  • Third-party: Everything else. Plugins published by your coworkers or your own company also fall here.

At any stage, an installed plugin can run code with your user permissions. Before installing one, read Plugin security and trust in the official docs to see how to check it.

To install from a source other than the official one, first add it with /plugin marketplace add. You can specify a GitHub repository, a git repository, a local directory or file, or an https:// URL to a marketplace.json. Community and demo marketplaces are not added automatically. According to the official docs as of writing (October 2026), --marketplace, which adds and installs in one step, is available from Claude Code v2.1.275 or later inside a session, and from v2.1.292 or later from the shell.

Auto-update is enabled by default for the official marketplaces and similar ones (except knowledge-work-plugins and first-party-plugins). It is disabled by default for community, third-party, and local development marketplaces. Organizations can use managed settings to allow or block marketplaces and to force-install plugins.

Source: Plugins overview

Impact after installation and how to manage it

According to the official docs, enabled plugins are always included, even in sessions that don't use them. The names and descriptions of callable skills and similar items enter the context every turn, count toward token usage, and reduce the room left in the context window. MCP servers run per session, and hooks run on their events.

  • Before you install: open a plugin in the Marketplaces tab of /plugin. Plugins from the official marketplace show an estimated Context cost.
  • After installing: plugins you could probably turn off are listed under Not used recently on the Installed tab.
  • To stop it: you can disable it without uninstalling, using /plugin or claude plugin disable in the shell.

Removing a marketplace also uninstalls every plugin you installed from it. Before you do, check the plugin names in the Marketplaces tab.

Source: Plugins overview

FAQ

Can I install only skills without using plugins?

Yes. According to the official docs, skills, subagents, hooks, and MCP servers all work on their own without a plugin. For example, a skill saved in ~/.claude/skills/ is available in every project on that machine.

Source: Plugins overview

What if the part after the @ in an install command from an acquaintance is not claude-plugins-official?

The official docs say to add the marketplace first. Run /plugin marketplace add followed by the source, then install the plugin. Plugins published by coworkers or your own company count as third-party, so you need to review them before installing.

Source: Install and manage plugins

How do I temporarily disable plugins I don't use?

You can disable a plugin without uninstalling it. Use /plugin, or run claude plugin disable in your shell. In the Installed tab, Not used recently helps you find plugins you aren't using.

Source: Plugins overview
