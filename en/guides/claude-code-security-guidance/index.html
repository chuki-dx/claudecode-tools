What the Claude Code security guidance plugin is: what it checks when you edit

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • The security-guidance plugin for Claude Code (Anthropic's AI coding agent that runs in the terminal) reviews code Claude writes at edit time, at the end of a turn, and at commit time, and has it fixed within the same session.
  • None of the layers stops writes or commits, and some things can slip through. The official docs say to use it as one layer of defense in depth.
  • Before adopting it, check the Python and git repository requirements, and note that reviews at the end of a turn and at commit time incur additional model usage.

What it does: Claude reviews the code it wrote

According to the official docs as of writing (October 2026), this plugin has Claude review its own code changes for vulnerabilities and fix any issues it finds in the same session. It catches things like injection and insecure deserialization before they reach a pull request.

After installation it runs automatically, and there is no command to invoke. Its role differs from Code Review, which runs on PRs: the plugin reduces what reaches the PR, while Code Review catches what does arrive. It checks three places.

  • On every file edit: pattern matching for dangerous calls. It doesn't call the model, so it adds no cost.
  • End of each turn: All changes from that turn are run through a background model review.
  • When Claude commits or pushes: a deeper agentic review (one that investigates on its own as it goes) that reads the surrounding code as well.

Getting started: prerequisites and installation

The official docs list these prerequisites: Python 3.7 or later on your PATH, and a working directory that is a git repository. Outside a git repository, end-of-turn and commit-time reviews are skipped without notice, and only edit-time pattern matching runs.

Agentic commit review requires Python 3.10 or later. If you use a third-party provider such as Amazon Bedrock, every model-based review requires 3.10 or later. On first launch, it creates a virtual environment under ~/.claude/security/ and installs the Claude Agent SDK, so you need pip and a network connection.

In a Claude Code session in the terminal, install it from the official Anthropic marketplace.

/plugin install security-guidance@claude-plugins-official

You are asked for a scope. If you choose user scope, the plugin is loaded in every new local session you start on this machine. Cloud sessions do not load plugins from user settings or from the repository's .claude/settings.json, so check the official docs for how they are handled.

To use this across a team, add the following to the project settings you check in to the repository. Admins can also enable it organization-wide through enabledPlugins in managed settings.

{
  "enabledPlugins": {
    "security-guidance@claude-plugins-official": true
  }
}

What each check does and its limits

Examples of what matches on edit include dynamic code execution such as eval( or os.system, pickle, dangerouslySetInnerHTML, .innerHTML =, and edits under .github/workflows/. A warning appears only once per file per session for the same pattern.

The end-of-turn review sends that turn's git diff to a separate, security-focused Claude. It targets issues that string matching can't catch, such as authorization bypasses and server-side request forgery. It covers up to 30 files per turn and runs at most 3 times in a row.

Commit review runs only when Claude runs git commit or git push with the Bash tool. Commits you run in your own shell, including the ! shell escape inside a session, are not reviewed. The limit is 20 per rolling hour.

Adding your own rules, and their limits

There are two extension points, and both are additive only. You cannot remove the built-in checks through these files.

  • For model-based review: write your threat model and review points in plain prose in .claude/claude-security-guidance.md.
  • For edit-time patterns: write regex or substring rules in .claude/security-patterns.yaml. The same format in .claude/security-patterns.yml and .claude/security-patterns.json is also read.

Guidance is direction for the reviewer and is not enforced. Writing that a certain type of vulnerability should be ignored will not suppress findings. If you need enforcement, combine it with a hook that blocks edits or with CI.

The YAML format requires PyYAML to be importable, and the plugin doesn't install it for you. If it's missing, the file is ignored, so security-patterns.json works regardless of your Python environment. You can have up to 50 custom rules.

The files go in three places: ~/.claude/claude-security-guidance.md for the user, a project-level file, and .claude/claude-security-guidance.local.md for personal use. All files that exist are concatenated, and the guidance is limited to 8 KB in total.

Cost, how to stop it, and limits

Reviews at turn end and at commit time use additional model capacity, and count toward your usage like regular requests. A commit review may use multiple model turns for a single commit. The default is a Claude Opus model, which you can change with SECURITY_REVIEW_MODEL and SG_AGENTIC_MODEL. The plugin is available on all plans. Check the official pricing page for amounts and usage limits.

Each layer can be disabled with environment variables.

  • ENABLE_PATTERN_RULES=0: Turns off pattern matching at edit time.
  • ENABLE_STOP_REVIEW=0: turns off the end-of-turn review.
  • ENABLE_COMMIT_REVIEW=0: Turns off review at commit time.
  • ENABLE_CODE_SECURITY_REVIEW=0: Turns off all reviews that use a model.
  • SECURITY_GUIDANCE_DISABLE=1: turns the whole thing off without uninstalling.

None of the layers blocks writes or commits, and the review model can miss things. The official docs say to treat this as one layer of defense in depth, not a complete safeguard, so you still need your existing CI, such as static analysis and dependency scanners.

FAQ

If I install the plugin, are commits I make from my own shell also reviewed?

No. According to the official docs, commit-time review covers only the git commit and git push commands that Claude runs through the Bash tool. Commits you run in your own shell are not reviewed, including those run with the ! shell escape inside a session.

Source: Catch security issues as Claude writes code

What should I check when reviews don't appear?

According to the official docs, start with the diagnostic log at ~/.claude/security/log.txt. Reasons given for a silent skip include: not being in a git repository; a session with neither Anthropic authentication nor a third-party provider (in that case only pattern matching on edit runs); and having a YAML pattern file without PyYAML installed.

Source: Catch security issues as Claude writes code

Can a plugin stop dangerous code from being written?

It can't stop them. According to the official docs, no layer blocks writes or commits, and findings are passed to Claude as instructions. If you want to block and enforce, combine it with a hook that blocks edits or a CI check.
