When Shift+Enter doesn't insert a newline in Claude Code: settings, tmux, notifications, and pasting

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • For a newline, Ctrl+J, or typing \ and then pressing Enter, works in any terminal without setup. Shift+Enter support varies by terminal, and in VS Code and similar you run /terminal-setup once.
  • Inside tmux, Shift+Enter submits by default, and notifications don't reach the outer terminal. Add three lines to ~/.tmux.conf to fix this.
  • Desktop notifications appear by default only in Ghostty, Kitty, and iTerm2. For large pastes, the docs suggest writing the content to a file.

How to enter a line break: support for Ctrl+J and Shift+Enter

According to the official docs, Claude Code (Anthropic's AI coding agent that runs in the terminal) works in any terminal without extra setup. The terminal configuration page is meant for looking up a symptom when a specific behavior isn't what you expect. Based on the content as of writing (October 2026), I summarize only the points you need when explaining this inside your company.

Enter sends the message. To insert a line break, press Ctrl+J, or type \ and then press Enter. These two work in any terminal without setup. Shift+Enter also works in many terminals, but support varies by terminal, as shown below.

  • Works without configuration: Ghostty, Kitty, iTerm2, WezTerm, Warp, Apple Terminal, Windows Terminal
  • Works without setup (with conditions): other terminals that support the kitty keyboard protocol (such as foot and Alacritty 0.16 or later). Requires Claude Code v2.1.269 or later
  • Run /terminal-setup once: VS Code, Cursor, Devin Desktop, Alacritty before 0.16, Zed
  • Not supported: gnome-terminal and JetBrains IDEs such as PyCharm and Android Studio. Use Ctrl+J, or \ followed by Enter.

Cautions when using /terminal-setup

/terminal-setup writes a Shift+Enter keybinding to your terminal's configuration file. Existing bindings are preserved, and if you see a message saying it's already configured, nothing was changed. Run it directly in the host terminal, not inside tmux or screen.

In VS Code, Cursor, and Devin Desktop, it also sets terminal.integrated.gpuAcceleration to "off" (to prevent garbled text in the integrated terminal) and sets terminal.integrated.mouseWheelScrollSensitivity. To undo this, set it back to "auto" and reload the editor window. In Zed, it updates keymap.json. When you roll this out company-wide, it helps to tell people up front that their editor settings will be rewritten.

To swap the roles of Enter and Shift+Enter, for example, assign chat:newline and chat:submit in the keybindings configuration file.

Settings for using it inside tmux

According to the official docs, when you run Claude Code inside tmux, Shift+Enter submits instead of inserting a newline by default, and desktop notifications and progress bars don't reach the outer terminal. Even if the outer terminal supports Shift+Enter, you need configuration inside tmux. Add the following line to ~/.tmux.conf, then apply it to the running server with tmux source-file ~/.tmux.conf.

set -g allow-passthrough on
set -s extended-keys on
set -as terminal-features 'xterm*:extkeys'

The allow-passthrough line passes notifications and progress updates through to the outer terminal. The extended-keys line lets tmux distinguish Shift+Enter from a plain Enter.

Get notified when work is done

When Claude finishes its work or stops to ask for permission, a notification event fires if you seem to be away from your seat. Setting up a bell or desktop notification lets you do other work during long tasks.

By default, desktop notifications are sent only in Ghostty, Kitty, and iTerm2. In other terminals, set preferredNotifChannel to "terminal_bell" to ring the terminal bell.

{
  "preferredNotifChannel": "terminal_bell"
}

Desktop notifications reach your local machine even over SSH. Ghostty and Kitty forward them to the OS notification center with no extra setup. In iTerm2, check "Notification Center Alerts" under Settings → Profiles → Terminal, then enable "Send escape sequence-generated alerts" under "Filter Alerts". If notifications don't appear, check that the OS allows notifications for your terminal app, and if you're inside tmux, apply the settings from the previous section.

On terminals that don't receive desktop notifications, such as Warp or the VS Code integrated terminal, you can also use a Notification hook to play a sound or run a command, in addition to the setting above. The hook runs alongside the built-in notification. See the official hooks guide for concrete examples.

Behavior when pasting large content

According to the official docs, pasting more than 800 characters or more than 3 lines collapses the content into a placeholder like [Pasted text #1 +120 lines]. The input box stays easy to use, and the full text is still sent when you submit.

For large inputs such as whole files or long logs, the docs recommend writing them to a file and having Claude read it instead of pasting. In the VS Code integrated terminal, very large pastes can lose characters, so use a file there.

Claude is told that a placeholder's contents are pasted text, not something the user typed. Because pasted text can contain instructions the user didn't write, Claude is told to follow them only if the typed message asks it to. However, in sessions that don't fetch feature flags, this marker is not applied.

The pasted content is saved in ~/.claude/paste-cache/. If you recall it from history and resend it, the full text is sent again. Caches older than cleanupPeriodDays are deleted, so the content may no longer be there. Check the official docs for how that case is handled.

When Backspace deletes whole words on Windows

On Windows, Claude Code reads Backspace arriving as ^H as Ctrl+Backspace (delete the previous word), except when TERM_PROGRAM is mintty or TERM is cygwin. On macOS and Linux, it reads it as a normal Backspace.

If each press of Backspace deletes a whole word, your terminal is sending ^H for a regular Backspace. Set CLAUDE_CODE_BS_AS_CTRL_BACKSPACE=0 and Backspace and Ctrl+H will each delete one character. Conversely, on macOS or Linux, if only one character is deleted because your terminal sends ^H for Ctrl+Backspace, set this variable to 1.

FAQ

Shift+Enter sends the message in the VS Code terminal. What should I do?

According to the official docs, run /terminal-setup once in VS Code. Run it directly in the host terminal, not inside tmux or screen. If you'd rather not configure anything, you can also insert a newline with Ctrl+J, or by typing \ and then pressing Enter.

Source: Configure your terminal for Claude Code

Inside tmux, notifications don't arrive and Shift+Enter doesn't work.

The official docs describe adding three lines to ~/.tmux.conf: set -g allow-passthrough on, set -s extended-keys on, and set -as terminal-features 'xterm*:extkeys'. Then apply them with tmux source-file ~/.tmux.conf. Even if the outer terminal supports these features, you still need this configuration inside tmux.

Source: Configure your terminal for Claude Code

On Windows, pressing Backspace deletes a whole word at a time.

Your terminal may be sending ^H for the regular Backspace key. The official docs explain that setting CLAUDE_CODE_BS_AS_CTRL_BACKSPACE=0 makes Backspace and Ctrl+H delete one character at a time.
