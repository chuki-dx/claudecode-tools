Getting Started with the Claude Code Desktop App, and Management Settings for Team and Enterprise

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • Claude Code (Anthropic's AI coding agent that runs in the terminal) can be used without a terminal from the Code tab of the desktop app. You need a Pro, Max, Team, or Enterprise plan.
  • Start by choosing a small project with Local, and set how much approval is required with the permission mode.
  • On Team and Enterprise, you can control the desktop app's behavior through the admin console, managed settings, MDM, and similar tools.

What you can do in the desktop app

According to the official docs, the desktop app lets you use Claude Code through a graphical interface. You can ask Claude to work on code in a folder on your computer and review the changes without a terminal. As of writing (October 2026), the official docs state that it requires a Pro, Max, Team, or Enterprise subscription. Check the official pricing page for amounts.

The app has three tabs.

  • Chat: General conversation with no file access.
  • Cowork: An agent that runs autonomously in the background while you work on other things.
  • Code: Interactive coding assistance with direct access to your local files. Depending on the permission mode, you approve each proposed change, or review changes after they are made.

Chat and Cowork are covered in Claude's Help Center, so this article focuses on the Code tab.

Source: Get started with the desktop app

Installation and sign-in

According to the official docs, the steps are as follows.

  1. On macOS and Windows, you run the downloaded installer. Linux is described as beta, and apt or .deb is documented for Ubuntu and Debian.
  2. Launch the app and sign in with your Anthropic account.
  3. Click the Code tab at the top center.

The macOS build supports both Intel and Apple Silicon. The Windows build targets x64, and Windows ARM64 has a separate installer. Because the app includes Claude Code, you reportedly don't need Node.js or a CLI install to use the Code tab.

If the Code tab prompts you to upgrade, you need a paid plan. If it prompts you to sign in online, restart the app after you finish. For 403 errors, see the authentication troubleshooting in the official docs.

Source: Get started with the desktop app

Your first session and permission modes

  1. Choose Local, then pick your project folder with Select folder. The official docs recommend starting with a small project you know well.
  2. Choose a model from the dropdown next to the send button. You can change it later.
  3. Type what you want to do. For example, Find a TODO comment and fix it.
  4. Review the changes and approve them.

Besides Local, you can choose Cloud, which keeps running after you close the app; SSH, which connects to a remote machine; and WSL, which runs inside WSL 2 on Windows. With SSH, a running task may stop if your Claude account sign-in expires.

Differences between permission modes

  • Auto: A classifier reviews actions in the background and blocks risky ones without asking you.
  • Manual: Asks for confirmation before editing files or running commands.
  • Accept edits: Automatically accepts file edits.
  • Plan: proposes how to proceed without editing any files.

In Manual, a diff view with Accept/Reject buttons appears, and files are not changed until you approve. In Auto and Accept edits, a display like +12 -1 appears after the change, and you can review it in the diff view.

Organization settings: admin console and managed settings

According to the official docs, organizations on a Team or Enterprise plan can manage desktop app behavior through the admin console, managed settings files, and device management policies.

Admin console

  • Desktop: Whether people in your organization can use Claude Code in the desktop app
  • Cloud sessions: Enable or disable cloud sessions
  • Remote Control: enable or disable Remote Control

In Enterprise organizations with HIPAA enabled, the Desktop toggle is off by default, and an Owner can turn it on. However, applying the HIPAA configuration turns it off again, so an Owner has to turn it on once more. Cloud sessions and Remote Control are also off by default, and after the HIPAA configuration is applied, even an Owner cannot turn them on.

Managed settings

Managed settings take precedence over project settings and user settings. You can write them in a settings file or deliver them remotely from the admin console. The main keys are as follows.

  • permissions.disableBypassPermissionsMode: set to "disable" to prevent use of Bypass permissions mode.
  • disableAutoMode: Set to "disable" to remove Auto mode from the available options.
  • disableDesktopLocalSessions: Setting it to true disables on-device Code sessions while leaving SSH to other hosts and cloud sessions available. It is read only from managed settings and requires Claude Desktop v1.37937.0 or later.
  • sshHostAllowlist: limits SSH session destinations to hosts whose hostnames match.

The first two also work in user settings and project settings, but if you put them in managed settings, users cannot override them. How far the settings reach depends on the session type, so check the official docs for details.

Distribution, network, and data handling

According to the official docs, device management uses MDM on macOS, Group Policy on Windows, and policy files on Linux. You can enable or disable Claude Code features, control automatic updates on macOS and Windows, and set a custom deployment URL.

  • macOS: the com.anthropic.claudefordesktop preference domain (Jamf, Kandji, etc.)
  • Windows: SOFTWARE\Policies\Claude in the registry
  • Linux: root-owned /etc/claude-desktop/managed-settings.json (the app rejects this file if anyone other than root can write to it)

Distribution is via MDM and .dmg on macOS, and an MSIX package on Windows.

Your firewall must allow traffic to the following hosts. Traffic uses HTTPS on port 443 unless you set a custom port for OTLP, an LLM gateway, or an MCP server.

anthropic.com
*.anthropic.com
claude.ai
*.claude.ai
claude.com
*.claude.com
claude.app
*.claude.app
*.claudeusercontent.com
*.claudemcpcontent.com

For how to reduce wildcards, IP allowlists, and proxy handling, check the official docs. As for data, local sessions process code locally, while in cloud sessions the conversation and code context are sent to Anthropic's API.

FAQ

Do I need to install Node.js or the CLI separately?

According to the official docs, the desktop app includes Claude Code, so you don't need Node.js or the CLI installed to use the Code tab. If you want to use claude in a terminal, install the CLI separately.

Source: Get started with the desktop app

What if we don't want people to use the desktop Code app at work?

On Team and Enterprise, the Desktop setting in the admin console controls whether people in your organization can use Claude Code in the desktop app. To block only on-device sessions, set disableDesktopLocalSessions to true in the managed settings.

Source: Desktop application

What should I do if the Code tab asks me to upgrade or sign in?

According to the official docs, if you are prompted to upgrade, you need a paid plan. If you are prompted to sign in online, complete the sign-in and restart the app. For 403 errors, see the authentication troubleshooting in the official docs.

Source: Get started with the desktop app
