Claude Code context and /compact: what stays and what is lost in a long conversation

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • The context window of Claude Code (Anthropic's AI coding agent that runs in the terminal) holds your instructions, the files it has read, Claude's responses, and even content that isn't shown in the terminal.
  • According to the official docs, sessions don't end when you approach the limit because they are compacted automatically. /compact is a command that replaces the conversation with a structured summary.
  • What happens after compaction depends on how the content was loaded. Pay attention to where you put instructions you want to keep (CLAUDE.md, whether paths: is set, the top of a skill).

What's in the context window

According to the official docs, the context window (the area that holds what Claude knows during a session) contains your instructions, the files Claude has read, Claude's own responses, and content that is not displayed in the terminal.

What gets loaded before you type anything is CLAUDE.md, auto memory, MCP tool names, and skill descriptions. In some cases AGENTS.md is loaded instead of CLAUDE.md.

As you work, context grows every time a file is read. Rules that have paths: are loaded automatically along with the files they match.

The timeline in the official docs says file reads account for most of the usage, and explains that specifying targets concretely in your prompt reduces the number of files read. The token counts are illustrative examples; actual values vary with the size of CLAUDE.md, MCP servers, and file length.

The docs advise keeping CLAUDE.md under 200 lines and moving reference material into skills or path-scoped rules, so it is loaded only when needed.

Source: Explore the context window

What happens with /compact and auto-compaction

Running /compact replaces the conversation with a structured summary. According to the timeline description, the terminal shows only a "Conversation compacted" message, and the summarization work itself is not displayed in the terminal.

The same document says the summary keeps your requests and intent, key technical concepts, files examined or changed and important code snippets, errors and fixes, pending tasks, and current work. Full tool output and intermediate reasoning are not kept, so Claude does not retain the exact contents.

As the context approaches its limit, it is compacted automatically, so a full context does not end the session. Auto-compact works the same way as /compact. The point at which compaction runs depends on the model and settings, so check Default auto-compact thresholds in the official docs.

As of v2.1.198, a summarization request inherits the session's extended thinking setting. If it is enabled in the session, the summary is made with it enabled; if disabled, it stays disabled. The only effect is on how the summary is produced.

What remains and what doesn't after compaction

Summarizing the table in the official docs, this is how each item is handled after compaction.

  • System prompt and output style: both still apply.
  • The project-root CLAUDE.md and rules without a scope: these are re-injected from disk.
  • Auto memory and plans Claude wrote in plan mode: these are re-injected from disk.
  • Git status snapshot: if one existed at session start, it is re-read from the repository to get the latest state.
  • Rules with paths: frontmatter and CLAUDE.md files in subdirectories: reloaded when they become needed.
  • Files Claude has read or edited: up to the 5 most recently updated are reloaded.
  • Body of invoked skills: re-injected up to 5,000 tokens per skill and 25,000 tokens in total, with the oldest dropped first.
  • Context previously added by a hook: it is summarized along with the rest of the conversation.
  • A SessionStart hook with the compact source matcher runs, and its output is added to the context after compaction.
  • Background commands and background subagents: They keep running.

Files over 5,000 tokens become path references without their contents, and show as Referenced file instead of Read. The skill description list is not re-injected after compaction; only skills you actually invoked remain.

Rules with paths: and nested CLAUDE.md files enter the message history when loaded, so they get summarized along with everything else during compaction. To keep a rule after compaction, the docs advise removing the paths: frontmatter or moving the rule into the project root CLAUDE.md. Large skills are truncated and the beginning is kept, so put important instructions near the top of SKILL.md.

Source: Explore the context window

What you can do before the context fills up

The official docs say you can do the following before automatic compaction runs.

  • Run it with instructions, like /compact focus on the auth bug fix. Used before a long new task, it keeps the content you chose in the summary instead of relying on auto-compaction's guesses.
  • Pick a message with /rewind, then choose Summarize from here or Summarize up to here. This lets you summarize only part of the conversation.
  • Specify a token count, as in /autocompact 500k, to change roughly when auto-compaction runs. Check the official docs for the accepted values.
  • Use /clear when you move to unrelated work. Old conversation pushes out the files you need next and consumes tokens with every message.
  • Hand large investigations off to a subagent. The file contents go into the subagent's context, and only a summary of the results comes back.

If you need a larger window, some models support a 1 million token context window. For supported models and availability by plan, see Extended context in the official docs. Compaction works the same way with the larger limit.

Source: Explore the context window

In-session commands and how to check

The session management page in the official docs lists the following three commands for managing context without leaving the session.

  • /clear: Starts over with an empty context. The previous session is saved and can be resumed with /resume.
  • /compact [instructions]: replaces the history with a summary. You can also specify what to focus on.
  • /context: Shows what is currently consuming context.

According to the context window page, /context shows a breakdown by category along with optimization suggestions, and it also shows which CLAUDE.md and auto memory files were loaded. You can open and edit them with /memory. This is based on the official docs as of writing (October 2026), and behavior and versions may change.

Source: Manage sessions

FAQ

Does the session stop when the context is full?

According to the official docs, the context is compacted automatically as it nears the limit, so a full context doesn't end the session. Auto-compaction works the same way as /compact, and the point at which it runs depends on the model and settings.

Source: Explore the context window

Are CLAUDE.md instructions lost when the conversation is compacted?

The CLAUDE.md in the project root is re-injected from disk. Rules with paths: frontmatter and CLAUDE.md files in subdirectories, on the other hand, are summarized during compaction and reloaded when they are needed again. To keep a rule after compaction, remove paths: or move the rule into the project-root CLAUDE.md.

Source: Explore the context window

Can I specify what to keep when compacting?

You can run /compact with instructions. For example, with /compact focus on the auth bug fix, the summary keeps the content you chose instead of what auto-compaction guesses is important.
