Automating Excel Reports with Claude Code: 3 Steps to Replace Manual Work with a Script

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • Start by replacing just one task: collecting Excel files of the same format every month and totaling them. An article from Chuki DX Lab notes that trying to replace everything at once tends to get bogged down in handling exceptions, and people give up.
  • Give Claude Code (Anthropic's AI coding agent that runs in the terminal) three things before having it write a script: the shape of the input file, the shape of the output, and what to do when something goes wrong.
  • For the first month or two, compare the results against your manual work. At the end, leave the batch file for running it and a procedure document, and hand them to the person in charge. A person verifies whether the code is correct.

Why Excel aggregation work doesn't go away, and how to think about what replaces it

The Chuki DX Lab article uses the following example: consolidating the Excel line-item files that arrive from each department at the start of each month. You open the files one by one, paste each line-item sheet into a master workbook, refresh the pivot table, and compile totals by department and by item for reporting. The volume each time is not large, but it happens every month without fail. The article notes that if a file with a different column order gets mixed in, just finding why the totals don't match takes a lot of time.

The article summarizes the existing options as follows.

  • Macros (VBA, a way to automate actions in Excel) can only be written by a limited number of people, and when the person who built one changes roles, nobody can fix it.
  • I find that Power Query (the data retrieval and transformation feature built into Excel) is strong at routine merges, but it is hard to build a process that detects problems in each file and reports them.
  • Recording screen operations with RPA (Robotic Process Automation) tends to break when the screen or column positions change, and it does not guarantee that the calculations themselves are correct.

With Claude Code, by contrast, if you can describe in words what the process does, it can write a readable script for you. The article says the big difference from macros is that the result stays as code, so the next person in charge can have Claude Code read it and fix it.

Step 1: Pick one task to replace and write down its input and output

The guide lists the following three conditions for choosing your first task.

  • Occurs every month (or every week)
  • The input files have a mostly fixed shape (same sheet names and column names)
  • You can check whether the results are correct by comparing them with the results from your previous manual work

Once you've chosen a task, write its input and output in a memo. The article uses a fictional example: collecting per-department office supply purchase records and totaling them by department and by item. The memo reads as follows.

  • Input: .xlsx files in the input/ folder (one file per department)
  • Sheet: "Details"
  • Columns: date / department / item / quantity / unit price
  • Output: 集計結果.xlsx (sheets: "By department" and "By item")

The article also includes make_sample.py, a script that creates fictional sample data in input/ so you can try things yourself. It gives you material to check the flow before touching real data.

Step 2: Describe the input, output, and error behavior, then ask Claude Code

The key to the request is to always state three things: the input format, the output format, and the behavior on errors. The article warns that if you don't specify the behavior on errors, you tend to get code that silently skips files with missing columns. The prompt used in the article is as follows.

input/ フォルダにある .xlsx をすべて読み込んで集計する Python スクリプト aggregate.py を作ってください。

入力:
- 各ファイルのシート「明細」。1行目が見出しで、列は 日付 / 部署 / 品目 / 数量 / 単価
- 列の並び順はファイルによって違うことがあるので、見出しの名前で列を探す
- Excel が作る一時ファイル(~$ で始まるもの)は対象外

出力:
- 集計結果.xlsx に、シート「部署別」(部署, 金額)と「品目別」(品目, 数量, 金額)を作る
- 金額 = 数量 × 単価。金額列は桁区切りの書式にする

異常時:
- シートや列が無いファイル、数量・単価が数値でない行があるファイルは、集計に含めずにスキップする
- スキップしたファイルと理由を最後に画面へ出し、終了コードを 0 以外にする

制約:
- Python 3.10 以上と openpyxl だけで動くこと
- 入力フォルダと出力ファイルはコマンドライン引数で変えられること(省略時は上の既定値)

This request tells Claude to find columns by header name even when the column order differs between files, to skip the temporary files Excel creates, and to print the skipped files and the reasons on screen at the end and exit with a non-zero exit code.

The article's author tidied up the code generated from this prompt and saved it as aggregate.py. It runs on just Python and openpyxl (a library for working with Excel files from Python), and you run it as follows.

pip install openpyxl
python make_sample.py
python aggregate.py

Verification matters here. For the first month or two, compare the results side by side with your manual work, and stop doing it by hand only after the totals match. The article says that even when Claude Code wrote the code, only your own checking guarantees it is correct.

Step 3: Make it run with a double-click and hand it to the person in charge

If only you can run the script, you have just moved the dependency on one person somewhere else. The article shows how to put the following batch file in the same folder as aggregate.py so the person in charge can run it by double-clicking.

@echo off
rem 集計.bat  aggregate.py と同じフォルダに置いてダブルクリックで実行する
cd /d %~dp0
py aggregate.py
pause

The article explains that py is the Python launcher installed by the python.org installer. Also, put the following into a single-page procedure document (README). The article says you can even have Claude Code draft that document by asking it to "write it for the person in charge, without technical jargon."

  • What to do each month (put files in input/ and double-click 集計.bat)
  • What to do when it shows "Skipped" (which department to check what with)
  • How to fix it when columns or items increase (open this folder in Claude Code and ask)

Common pitfalls and precautions when trying it internally

The pitfalls the article lists are as follows, in the order of symptom, cause, and fix.

  • Can't save because of PermissionError: this happens because 集計結果.xlsx was still open in Excel when you ran the script. Close the file and run it again.
  • All amounts are empty: The unit prices are entered as formulas, and the file has never been saved in Excel. Open the original file in Excel and save it again (openpyxl does not calculate formulas).
  • If you see a "columns missing" error: the cause is inconsistent header spelling (for example "unit price" written with a stray space, or "unit price (yen)"). Either standardize the input format, or ask Claude Code to change the code so it accepts alternate header names.
  • py not found: the Python launcher is not installed. Either change py to python, or reinstall Python from python.org.

FAQ

What is the difference between automating with VBA macros and building scripts with Claude Code?

The Chuki DX Lab article names one major difference: because the result stays as code, the next person in charge can have Claude Code read and fix it. Macros can be written by only a limited number of people, and the article explains that when the person who built one moves to another department, no one can fix it. However, it also notes that the only thing guaranteeing the correctness of the results is your own checking.

Source: Escape internal Excel hell with Claude Code in 3 steps: replacing manual aggregation with a script (Japanese)

I ran the aggregation and all the amounts came out empty. What is the cause?

According to the article, the cause is that unit prices are entered as formulas and the file has never been saved in Excel. You can fix it by opening the original file in Excel and saving it again, because openpyxl does not calculate formulas.

Source: Escape internal Excel hell with Claude Code in 3 steps: replacing manual aggregation with a script (Japanese)

How long should I keep running the manual tally in parallel?

The article says that for the first one to two months, you should compare results side by side with the manual work and stop doing it by hand only after confirming the totals match. It doesn't specify detailed criteria for what counts as a match, so decide that yourself.
