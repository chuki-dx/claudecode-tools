Letting Claude Code work outside the working folder: --add-dir and additionalDirectories

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • By default, Claude Code (Anthropic's AI coding agent that runs in the terminal) accesses files in the folder where you started it. There are three ways to let it work with folders outside: --add-dir at startup, /add-dir during a session, and additionalDirectories in the settings file.
  • Added folders are handled under the same permission rules as the original working directory. Reads work without confirmation (except for network path confirmations), and edits follow the current permission mode.
  • Adding a directory extends file access, not where settings are loaded from. A folder you add with permissions.additionalDirectories in a settings file gets file access only.

Three ways to let Claude Code work outside the working folder

According to the official docs as of writing (October 2026), Claude Code can access files in the directory where you launched it by default. That directory is the session's primary working directory, and it stays the primary working directory until you move with /cd.

There are three ways to widen this access scope.

  • At startup: use the --add-dir <path> CLI argument
  • During a session: use the /add-dir command
  • Persistent setting: Add it to additionalDirectories in a settings file

The settings that get loaded depend on how you add it. I explain the details in a later section.

Source: Configure permissions

Added folders get the same permissions as the original folder

The official docs explain that files in additional directories follow the same permission rules as the original working directory. Reads work without confirmation, except for network path checks. File edit permissions follow the current permission mode.

To block reads outside the working directory, set permissions.blockReadsOutsideWorkingDirectories. File tools will then deny those paths in every permission mode. In auto mode, the first time Claude reads outside the working directory, Claude Code offers to enable this setting.

Read operations in added folders no longer prompt for confirmation, so decide which folders to give access to with that in mind.

Source: Configure permissions

Paths you can't add, and notes for macOS

According to the official docs, most network paths, including UNC shares, can't be added as working directories, because checking the path may connect to the specified host. On Windows, the docs advise mapping the share to a drive letter and passing that drive with --add-dir at startup.

In macOS background sessions, when Claude reads or writes protected folders such as ~/Desktop, ~/Documents, and ~/Downloads, the session host requests access separately from the terminal. If reads there fail with Operation not permitted, see the background sessions section of the official docs.

Source: Configure permissions

Settings that are and are not loaded from additional directories

The official docs explain that adding a directory widens what Claude can read and write, but that directory does not become a configuration root. Most settings under .claude/ are not discovered, and only a few are loaded as exceptions.

Note the conditions. The exception applies only to directories you add with the --add-dir flag or the /add-dir command. Directories listed in permissions.additionalDirectories get file access only, and the settings below are not loaded from them.

The following are loaded from directories added with --add-dir.

  • Skills in .claude/skills/: Loaded (with live reload)
  • Command files in .claude/commands/: These are loaded (no live reload). If an added directory and the project have a command with the same name, the project's command runs.
  • Subagents in .claude/agents/: Loaded (no live reload)
  • .claude/settings.json and .claude/settings.local.json: only the enabledPlugins and extraKnownMarketplaces keys
  • CLAUDE.md, .claude/rules/, CLAUDE.local.md: Only when you set CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1

To share settings across multiple projects, the official docs list user-level settings, distribution through plugins, and launching from the directory that contains the settings.

Source: Configure permissions

Use /cd to move instead of add

If you want to change the main working directory itself rather than add a folder, use /cd. According to the official docs, the conversation carries over and the new directory's CLAUDE.md is loaded. The first time you work in a directory, you are asked whether to trust it.

When you move, the new directory's project settings (including permission rules and hooks) apply immediately. Additional directories switch to those from the new directory's settings, but ones you added with --add-dir or /add-dir are kept. For an untrusted directory, the confirmation screen lists the permission rules, additional directories, and other items that its settings would enable. If you decline, the session stays where it is.

Before v2.1.246, after moving with /cd, the new directory's settings, hooks, MCP servers, and skills didn't apply until you resumed the session. Check which version your company uses. You can restrict or disable where users can move with the Cd permission rule.

Source: Configure permissions

FAQ

What is the difference between --add-dir and permissions.additionalDirectories?

Both give access to files in another folder, but they load settings differently. According to the official docs, directories added with --add-dir or /add-dir have their skills, commands, subagents, and so on loaded. Directories listed in permissions.additionalDirectories in a settings file get file access only.

Source: Configure permissions

Can I add a company network share to the working directories?

According to the official docs, most network paths, including UNC shares, cannot be added. On Windows, the docs advise mapping the share to a drive letter and passing that drive with --add-dir at startup. For other environments, check the official docs.

Source: Configure permissions

Is the CLAUDE.md in an added folder loaded?

According to the official docs, CLAUDE.md and similar files in directories added with --add-dir or /add-dir are loaded only if you set CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1. CLAUDE.local.md additionally requires the local settings source, which is enabled by default.

Source: Configure permissions
