What Claude Code agent teams are: when to use them, how to start, and limitations

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • Agent teams are a feature of Claude Code (Anthropic's AI coding agent that runs in the terminal) in which multiple sessions split up roles, work in parallel, and send messages to each other. According to the official docs, it is experimental and disabled by default.
  • It suits research and review, splitting up features, and debugging where competing hypotheses are tested. It is a poor fit for sequential work or editing the same file, and it uses considerably more tokens than a single session.
  • To enable it, you just set the environment variable to 1, and you make requests in natural language. The official recommendation is to start with about 3-5 people and try research and review tasks that don't involve writing code.

What kinds of tasks it suits

According to the official docs, agent teams are most effective for work where exploring in parallel adds real value. The four best-suited cases are:

  • Research and review: multiple teammates investigate different aspects of a problem at the same time, share their findings, and check each other's work
  • New modules or features: each one has its own part, so they don't step on each other's work
  • Debugging with competing hypotheses: try different hypotheses in parallel to converge on an answer faster
  • Coordination across layers: separate teammates handle changes that span the frontend, backend, and tests

On the other hand, coordination takes more effort and uses significantly more tokens than a single session. For sequential work, edits to the same file, or work with many dependencies, a single session or a subagent (a worker that returns results to the main agent) is said to be more effective.

Differences from subagents

According to the official docs, both can parallelize work, but they behave differently. Subagents return their results to the main agent. In teams, teammates pick up work from a shared task list and communicate directly with each other.

  • Context: each has its own context window
  • Best uses: subagents suit focused tasks where only the result matters; teams suit complex work that needs discussion and collaboration.
  • Token cost: subagents are lower because their results are summarized before being returned; teams are higher because each teammate is a separate Claude instance

The distinction is: use a subagent if you want a worker that reports back quickly, and use a team if you need to share findings, challenge each other, or coordinate autonomously.

Source: Orchestrate teams of Claude Code sessions

Enabling it and creating your first team

According to the official docs, agent teams are disabled by default. Setting the environment variable CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS to 1 enables them, and you can set it either in the shell environment or in settings.json.

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

There are two caveats. When this is enabled, subagents that Claude names are launched as teammates, so a team can appear even if you didn't ask for one. Also, launching teammates requires an interactive session. In non-interactive mode with the -p flag (including Agent SDK sessions), they don't launch and run as regular subagents instead.

To use it, describe the task and the team composition in natural language. The official example is described as a good fit because the three roles can explore without waiting for one another.

I'm designing a CLI tool that helps developers track TODO comments across
their codebase. Spawn three teammates to explore this from different angles:
one on UX, one on technical architecture, one playing devil's advocate.

In a session that has the Task tool, Claude creates a shared task list, starts a teammate for each perspective, and summarizes their findings when they finish. Sometimes it uses subagents instead of a team, and the agent panel lists both, so you can't tell from the panel alone whether you have a team. In that case, ask again and explicitly request an agent team. Select a teammate with the up and down arrow keys, then press Enter to open its transcript and send it a message directly.

Operating tips

  • Pass context: Teammates automatically load CLAUDE.md, MCP servers, and skills, but they do not inherit the lead's conversation history. Put task-specific information in the request you give them when they start
  • Number of people: There is no strict limit, but tokens grow in proportion to headcount and coordination effort increases too. In most cases, start with 3-5 people
  • Task granularity: if tasks are too small, the coordination overhead outweighs the benefit; if they are too large, agents can run for a long time without checking in and waste effort. Units with a clear deliverable, such as a function, a test file, or a review, work well.
  • File conflicts: if two people edit the same file, one overwrites the other. Assign files to each person separately
  • Start with research and review: Starting with tasks that don't involve writing code, such as reviewing PRs or researching libraries, lets you see the benefits without the coordination difficulty of parallel implementation
  • Watch: if you leave it running too long, the risk of wasted work goes up. Check progress and correct course as needed.

If the lead starts implementing on its own instead of waiting, tell it the following sentence.

Wait for your teammates to complete their tasks before proceeding

Limits and troubleshooting

As of writing (October 2026), the official docs describe agent teams as an experimental feature with the following limitations.

  • /resume and /rewind do not restore in-process teammates. After resuming, tell the lead to start new teammates.
  • Task status can lag, and if a completion isn't recorded, dependent tasks get stuck. Check whether the work is actually done, then update the status manually or ask the lead to nudge it.
  • Each session can have only one team. You cannot nest teams or promote a teammate to lead.
  • Split panes require tmux or iTerm2. The default in-process mode works in any terminal, but split panes are not supported in the VS Code integrated terminal, Windows Terminal, or Ghostty

Operationally, teammates' permission requests bubble up to the lead and get cumbersome, so pre-approving common operations in your permission settings before launch reduces interruptions. When a teammate stops on an error, select it in the panel to check its output, then give additional instructions or start a replacement teammate. If the lead decides it is finished before all tasks are complete, tell it to continue.

If you want to avoid teams being created unintentionally, set it to 0 as follows.

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "0"
  }
}

You don't need a new session; saving re-applies it to the running session. However, if it is set to 1 in project settings, local settings, or similar, that value takes precedence, and if your organization's managed settings enable it, you need to ask an administrator to change the value.

FAQ

How do I choose between agent teams and subagents?

According to the official docs, use subagents for focused tasks where only the result matters, and agent teams for complex work where teammates need to share findings, challenge each other, and coordinate on their own. Teams consume more tokens.

Source: Orchestrate teams of Claude Code sessions

A teammate starts up even though I didn't ask for one. What should I do?

While it's enabled, subagents that Claude gives names to start as teammates. Setting CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS to 0 returns to starting them as subagents. Also check that it isn't set to 1 in another settings source.

Source: Orchestrate teams of Claude Code sessions

What happens to teammates when I resume a session?

According to the official docs, /resume and /rewind do not restore in-process teammates. The lead may try to message teammates that no longer exist, so in that case tell it to start new teammates.
