How to Set Up the Claude Code Status Line and What to Check When It Doesn't Appear

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • You set up the status line in Claude Code (the AI coding agent from Anthropic that runs in the terminal) either by creating it with the /statusline command or by writing statusLine in a settings file.
  • The official docs say the status line displays a script's standard output, runs locally, and does not consume API tokens.
  • If it doesn't appear, check in this order: execute permission, standard output, workspace trust, and managed settings. This article is based on the official docs as of writing (October 2026).

What you can do with the status line

According to the official docs, Claude Code passes session data as JSON to the script's standard input and displays whatever the script writes to standard output as-is. It runs locally and does not consume API tokens. It is temporarily hidden while the help menu or a permission prompt is shown.

Output can span multiple lines and can be colored with ANSI escape codes (control codes that change text color and so on). Colors require terminal support. You can also create clickable links with OSC 8 escape sequences, but this requires a terminal that supports hyperlinks, such as iTerm2, Kitty, or WezTerm.

The terminal size cannot be read with tput cols; it is read from the COLUMNS and LINES environment variables.

Source: Customize your status line

Method 1: Create it with the /statusline command

There are two main ways to set it up. The first is to describe in natural language what you want displayed. Claude Code generates a script in ~/.claude/ and updates the settings automatically. Here is an example from the official docs.

/statusline show model name and context percentage with a progress bar

Approve the file edit permission prompts when they appear. Before you roll out a generated script company-wide, review its contents.

Source: Customize your status line

Setup method 2: Add statusLine to settings.json

To set it up manually, add a statusLine field to your user settings (~/.claude/settings.json) or your project settings. Set type to "command", and set command to a script path or an inline shell command.

{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 2
  }
}

Because command runs in a shell, you can also write an inline command that uses jq to parse the JSON input and display the model name and context percentage, as in the official example. The optional fields are as follows.

  • padding: Adds horizontal padding to the content, measured in characters. The default is 0. It adjusts the relative indent, not the distance from the edge of the terminal.
  • refreshInterval: Re-runs the command every N seconds, in addition to event-based updates. The minimum value is 1. It is meant for time-dependent displays such as a clock; if unset, the command runs only on events.
  • hideVimModeIndicator: Hides the built-in -- INSERT -- indicator. If your script displays vim.mode, set this to true to avoid showing it twice.

To disable it, ask for it to be removed, for example with /statusline delete, or delete the statusLine field from settings.json.

Update timing and operating tips

The script runs once at session start, and after that it runs again when a new assistant message arrives, when /compact finishes, when the permission mode or Vim mode changes, when you change command, when the refreshInterval timer elapses, and so on. Updates are batched at 300ms, and if the next update occurs while the script is running, the running script is canceled. If you edit the script, the change takes effect on the next update trigger.

The tips are to keep output short and to cache slow operations. The script runs frequently, so commands like git status can cause lag. For the context percentage, the docs say using used_percentage is the simplest and most accurate way. The official docs also include an example of mock input for testing.

The docs mention community projects such as ccstatusline and starship-claude that provide themed configurations. If you use one, review the contents of each project first.

What to check when it doesn't appear

The troubleshooting section of the official docs includes the following checks.

  • Make the script executable with chmod +x ~/.claude/statusline.sh
  • Check whether the output goes to standard output rather than standard error
  • Run the script by hand and check the output
  • If you have Git Bash installed on Windows, use forward slashes in the command path
  • After settings precedence is applied, if disableAllHooks is true in anything other than managed settings, only the statusLine from managed settings runs, and if there is none, it is disabled
  • If your organization uses allowManagedHooksOnly in managed settings, your custom status line disappears without any warning. Ask your admin whether this applies to you
  • Use claude --debug to check the script's standard error on every run and the exit code of the first run in the session

The status line stays blank until you accept the workspace trust dialog. statusLine runs a shell command, so the same trust rules apply as for hooks in settings files. Restart Claude Code and accept the trust dialog to enable it. It is also shown only after the script exits with code 0; a non-zero exit or empty output leaves it blank.

When values or displays look wrong

  • -- or empty values: These can be null before the first API response. Write a fallback such as // 0 in your script.
  • Context percentages differ: /context adds an estimate for messages since the latest response, so it can read higher until the next response.
  • Display is garbled: Complex escape sequences can get garbled when they overlap with other UI updates, and this is more likely with multiple lines. Try simplifying to plain text.
  • Links aren't clickable: Terminal.app doesn't support them. SSH and tmux may strip OSC sequences.
  • Coexisting with notifications: outside fullscreen mode, notifications appear on the same line, so the status line may be cut off in a narrow terminal.

FAQ

Does using a status line consume API tokens?

According to the official docs, the status line runs locally and does not consume API tokens.

Source: Customize your status line

How do I remove a status line I've set?

Ask /statusline to delete or clear it, or remove the statusLine field from settings.json by hand. /statusline delete is given as an example of how to ask.

Source: Customize your status line

How do I keep refreshing time-varying displays, such as a clock?

Set refreshInterval. The command re-runs every N seconds, and the minimum value is 1. If it is not set, the command runs only on events.

Source: Customize your status line
