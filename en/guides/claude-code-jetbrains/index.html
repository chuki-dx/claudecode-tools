Using Claude Code in JetBrains IDEs: installation, settings, and caveats

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • The plugin doesn't bundle the CLI, so install both the claude command and the plugin.
  • Start claude in the IDE's integrated terminal, or run /ide in an external terminal, to use the integration features.
  • acceptEdits mode can increase risk through IDE configuration files, so consider running edits in Manual mode.

What it can do: supported IDEs and main features

According to the official docs, Claude Code (Anthropic's AI coding agent that runs in the terminal) integrates with JetBrains IDEs through a dedicated plugin. Supported IDEs include IntelliJ IDEA, PyCharm, Android Studio, WebStorm, PhpStorm, and GoLand.

The main features are as follows.

  • Quick launch: open it from the editor with Cmd+Esc (Mac) or Ctrl+Esc (Windows/Linux).
  • Diff display: opens changes in the IDE's diff viewer instead of the terminal.
  • Sharing your selection: the selected range and open tabs are shared automatically.
  • File references: press Cmd+Option+K (Mac) or Alt+Ctrl+K (Linux/Windows) to insert a reference such as @src/auth.ts#L1-99.
  • Sharing diagnostics: Claude reads IDE lint and syntax errors through the getDiagnostics tool. Claude Code does not request diagnostics on its own after an edit.

Source: JetBrains IDEs

Setup steps: install both the CLI and the plugin

According to the official docs, the plugin connects by running the claude command in the IDE's integrated terminal, and the CLI is not bundled with it. Set it up in two steps.

  1. Install the CLI by following the official quickstart. If claude is not on your PATH, the plugin shows "Cannot launch Claude Code".
  2. Install the Claude Code plugin from the JetBrains Marketplace and restart your IDE.

If you installed it somewhere your IDE can't find claude, specify the full path in the plugin's Claude command setting.

It works with a paid Claude subscription (Pro, Max, Team, Enterprise) or a Claude Console account, and no API key is needed. You are prompted to log in the first time you run claude. Check the official pricing page for current prices and plan terms.

Source: JetBrains IDEs

Usage and settings: connection, diff display, and plugin settings

Launching and connecting

If you run claude in the IDE's integrated terminal, all integration features are enabled. From an external terminal, start claude and then run /ide.

claude
/ide

On success, you see a message like Connected to IntelliJ IDEA.. To have Claude work on the same files as the IDE, launch it from the same directory as the IDE's project root.

Switching the diff display

In claude, open /config and set Diff tool to auto to show diffs in your IDE, or to terminal to keep them in the terminal. This option appears only while connected to an IDE, so launch Claude Code from the JetBrains terminal or run /ide first.

Plugin settings

Configure this under Settings → Tools → Claude Code [Beta]. In the official docs as of writing (October 2026), this plugin's name carries a [Beta] label. In Claude command, you can specify a launch command such as claude or /usr/local/bin/claude. If the ESC key can't interrupt operations, either uncheck "Move focus to the editor with Escape" under Settings → Tools → Terminal, or remove the "Switch focus to Editor" shortcut.

Source: JetBrains IDEs

Remote development and WSL caveats

For remote development (JetBrains Remote Development), the official docs warn that you must install the plugin on the remote host from Settings → Plugin (Host), not on your local client.

On WSL, set the Claude command to wsl -d Ubuntu -- bash -lic "claude" (replace Ubuntu with the name of the distribution you use).

If you see "No available IDEs detected" on WSL2, the cause is most often that WSL2's NAT networking or Windows Firewall is blocking the connection. WSL1 is not affected. The recommended fix is to allow WSL2 traffic in the firewall without changing the network mode. First, run the following in your WSL shell.

hostname -I

The subnet is the first two segments followed by .0.0/16 (for example, 172.21.123.45 gives 172.21.0.0/16). In PowerShell run as administrator, run the following with your IP range, then restart your IDE and Claude Code.

New-NetFirewallRule -DisplayName "Allow WSL2 Internal Traffic" -Direction Inbound -Protocol TCP -Action Allow -RemoteAddress 172.21.0.0/16 -LocalAddress 172.21.0.0/16

As an alternative, on Windows 11 22H2 or later you can switch to mirrored mode. Add the following to .wslconfig in your Windows user directory, then run wsl --shutdown in PowerShell. On Windows 10, use the firewall rule above.

[wsl2]
networkingMode=mirrored

Security notes: acceptEdits, selections, and the network

According to the official docs, when you use the acceptEdits permission mode in a JetBrains IDE, Claude Code may be able to modify configuration files that the IDE can run automatically. This raises the risk of acceptEdits mode and could let it bypass the permission prompts for Bash execution. The docs list the following mitigations.

  • Make edits in Manual mode. acceptEdits and auto mode approve edits inside the working directory without confirmation, except for protected paths.
  • Use it only with prompts you trust.
  • Know which files Claude Code can change.

While connected to an IDE, the CLI includes your current selection and the paths of open files in the context with every prompt. You can exclude sensitive files such as .env with a Read deny rule for that path.

The plugin runs a local MCP server named ide, which does not appear in /mcp. If your organization uses a PreToolUse hook to allowlist MCP tools, you need to be aware of it. The only tool visible to the model is the read-only mcp__ide__getDiagnostics.

If you disable Accept connections from all network interfaces under Settings → Tools → Claude Code [Beta] → Networking (Advanced), the server listens only on 127.0.0.1. If enabled, it is reachable from the local network, and because it uses unencrypted ws://, session traffic and the authentication token travel in plaintext. Enable it only if you can't connect over loopback; on WSL2, the docs recommend mirrored mode first.

Source: JetBrains IDEs

FAQ

Can I use Claude Code just by installing the plugin?

No, you can't. According to the official docs, the plugin does not bundle the CLI. It connects when you run the claude command in the IDE's integrated terminal. Install both the CLI and the plugin.

Source: JetBrains IDEs

Can I connect from a terminal outside the IDE?

Yes. According to the official docs, you can start claude in an external terminal and run /ide to connect. If you see "No available IDEs detected," check that the plugin is enabled and that you fully restarted the IDE; on WSL, see the firewall section.

Source: JetBrains IDEs

Can I keep sensitive files such as .env from being shared with Claude?

According to the official docs, adding a Read deny rule for that file's path keeps both the selected text and the open-file notification from reaching Claude.

Source: JetBrains IDEs
