Choosing Between CLAUDE.md, Skills, Hooks, MCP, and Subagents in Claude Code

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • Put conventions and build commands you want followed every time in CLAUDE.md, and put reference material and procedures you only need occasionally in skills.
  • Use hooks for things that must run every time and for guardrails that must not be broken. MCP is for connecting to external services, and subagents are for work where you want to isolate large amounts of reading.
  • You don't need to configure everything from the start. When the same mistake or manual work keeps recurring, add the relevant feature one at a time.

A one-line summary of each feature's role

This article organizes when to use each Claude Code (the AI coding agent from Anthropic that runs in the terminal) extension feature, based on the official docs. It reflects the content as of writing (October 2026) and is not the result of my own testing on a real machine.

According to the official docs, the built-in tools can handle most coding work. Extensions are a layer for adjusting what Claude knows, connecting to external services, and automating work.

  • CLAUDE.md: persistent background information that Claude sees every session.
  • Skills: Markdown files containing reusable knowledge or procedures. You can invoke them with a command like /deploy, and Claude can also load them automatically when they're relevant.
  • MCP: connections to external services and tools.
  • Subagents: workers that run in an independent context and return only a summary.
  • hooks: a mechanism that runs scripts or other actions when a lifecycle event is reached.
  • Plugins: a unit for bundling and distributing skills, hooks, subagents, and MCP servers together.

Source: Extend Claude Code

CLAUDE.md vs. skills: every time, or only when needed

Both can store instructions, but they are loaded differently. According to the official docs, CLAUDE.md is loaded automatically every session, while skills are loaded when needed. Only a skill can be invoked like /deploy to run a procedure; CLAUDE.md can't do that.

  • What goes in CLAUDE.md: things Claude should always know, such as coding conventions, build commands, project structure, and "don't do X" rules.
  • What goes in a skill: reference material you only need occasionally, such as API documentation and style guides, and procedures you invoke to run, such as deploy, review, and release.

As a rule of thumb, keep CLAUDE.md under 200 lines. As it grows, move reference material into skills or split it into files under .claude/rules/. If you add paths frontmatter to a rule, it loads only when Claude works with matching files, which saves context.

Source: Extend Claude Code

Put rules that must be enforced in hooks

According to the official docs, a hook fires every time its event occurs, so the trigger is guaranteed. A skill, on the other hand, runs when Claude interprets its instructions, so results can vary.

  • When hooks fit: things that should behave the same way every time without needing Claude's judgment, such as linting after edits, blocking dangerous commands, logging, and notifications.
  • When skills fit: things where you want Claude to decide how to apply them, and content that is knowledge rather than a script. Examples are a /release checklist or a debugging runbook.

Guardrails deserve attention. Writing "don't edit .env" in CLAUDE.md or a skill is a request, not a guarantee. Blocking edits with a PreToolUse hook makes it enforced. The official docs' approach is that rules that must be followed every time should be hooks, not prompt instructions.

Source: Extend Claude Code

MCP and subagents: connect them or keep them separate

MCP connects to external services

MCP is a protocol for connecting to external services. According to the official docs, it gives Claude dedicated tools for external systems, with connection and authentication handled on the server side. Examples include querying a database, posting to Slack, and operating a browser. Skills supply the knowledge for using those tools well. One combination described is connecting to a database via MCP and writing the schema and query patterns in a skill.

Subagents isolate work

Use it when you want to isolate context, or when the context window is filling up. Even if you have it research by reading many files, only a summary returns to the main conversation. A skill's content is added to the main window, but a subagent uses its own separate window.

You can also combine them. You can preload skills into a subagent with the skills: field, or set context: fork on a skill to run it in an isolated environment. See the official docs for details.

Source: Extend Claude Code

Add rules when problems come up: what triggers an addition

According to the official docs, you don't need to configure everything at the start; each feature has a rough trigger for when to adopt it.

  • Claude got the same convention or command wrong twice: write it in CLAUDE.md
  • You type the same prompt every time to start work: Save it as a skill that users can invoke
  • You're about to paste the same procedure into chat for the third time: package it as a skill
  • You keep copying data from a browser tab that Claude can't see: connect that system as an MCP server
  • Output from side tasks fills the conversation and you won't refer to it later: delegate to a subagent
  • When you want something to always run without asking each time: write a hook
  • When a second repository needs the same setup: bundle it into a plugin

Turn repeated mistakes and review comments into CLAUDE.md fixes instead of making one-off corrections in chat. To distribute within your company, bundle them into a plugin so you can roll it out through a marketplace. Plugin skills are namespaced, so multiple plugins can coexist.

Source: Extend Claude Code

Context consumption and how overlaps are handled

The official docs explain that the more features you add, the more context they consume, and adding too many creates noise, which can cause skills to fail to trigger correctly or cause Claude to lose track of conventions.

  • CLAUDE.md: The whole file is loaded at session start and consumed on every request.
  • Skills: the description is loaded on every request, and the full text is loaded when used. Adding disable-model-invocation: true to a skill with side effects makes it run only when you invoke it by name, and it also saves context.
  • MCP: tool names are loaded, and schemas are deferred until needed. You can check connection status with /mcp and token consumption with /context all.
  • hooks: They consume nothing unless they return output.
  • Subagents: They are separated from the main session.

If skill descriptions are vague or overlap, the wrong skill may be loaded or a useful one may be missed. To make Claude use a particular skill, invoke it by name. When the same feature exists at multiple levels, CLAUDE.md is additive across all levels, skills, subagents, and MCP servers use one definition if the names match, and all hooks fire. Check the official docs for the details of precedence.

Source: Extend Claude Code

FAQ

Can writing "don't touch" in CLAUDE.md prevent file edits?

There is no guarantee it will be prevented. According to the official docs, instructions in CLAUDE.md or skills are requests, not guarantees. For rules that must be followed every time, create a hook that blocks edits using a PreToolUse hook.

Source: Extend Claude Code

What should I do when CLAUDE.md gets long?

The official docs suggest keeping it under 200 lines. Move reference material into skills, or split it into files under .claude/rules/. With the paths frontmatter, a rule can also be loaded only when Claude works with matching files.

Source: Extend Claude Code

Do I have to choose between MCP and skills?

They serve different roles and are used together. According to the official docs, MCP provides connections to external services and their tools, while skills provide the knowledge and procedures for using those tools well.

Source: Extend Claude Code
