What to do in the first week after installing Claude Code (for part-time corporate IT)

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • In your first week with Claude Code, the goal is not results but building a fixed routine of 30 minutes a day and a 3-line CLAUDE.md.
  • Split the 30 minutes a day into 10 minutes in the morning, 5 at midday, and 15 at night. In the morning, add one line to CLAUDE.md; at midday, ask for a small task; at night, organize for the next day and try just one automation.
  • Pay attention to what you enter. Put only information your company rules allow into CLAUDE.md and the files you hand over, and never write passwords or customer names. Use permission settings to block operations that must be reliably stopped.

Don't expect results in the first week: what to learn first

A Chuki DX Lab article describes a pattern common among part-time corporate IT staff: they install Claude Code, try it for a few days, and stall without working it into their jobs. It says the cause lies less in "not having time" than in the order in which you build it in and how you decide how much time to spend per session.

The article recommends not aiming for results in the first week. Instead, build just two habits: a "fixed 30-minute daily routine" and a "3-line CLAUDE.md." You do the same thing at the same time every day, so you don't spend time deciding what to do.

This article summarizes what the articles above describe; it is not the result of my own testing at my company. Treat it as the content as of writing (October 2026), try it on a small scale before rolling it out company-wide, and check the official docs for installation steps and pricing.

Source: Chapter 2: Your First Week — a 30-Minute Daily Routine and a 3-Line CLAUDE.md (Japanese)

Split the 30 minutes a day across morning, noon, and evening

The format the article suggests is to split 30 minutes a day into three parts.

  • Morning (first 10 minutes of the workday): add one line to CLAUDE.md (note any assumptions you learned from yesterday's work)
  • Midday (end of lunch break), 5 minutes: hand a small afternoon task to Claude Code
  • Evening (before end of day), 15 minutes: plan tomorrow's work and try automating just one thing

The article explains that the key is not to use it all at once when you have free time, but to build it up little by little between tasks.

Morning 10 minutes: add one line to CLAUDE.md

In the morning, I do the following three things.

  1. Recall one assumption from yesterday's work that you wish Claude had known from the start
  2. Add one line to CLAUDE.md
  3. Start Claude Code in that state and ask one question about today's work

For example, if you talked about a business system the day before and Claude mixed up the type of screen, write one line about the screens and settings your company actually uses. The docs say that as you keep doing this, you will need to explain less each time.

How to ask: the 5-minute daytime request and the 15-minute evening request

Midday, 5 minutes: hand off a small task

Assume you will check the results in the afternoon, and keep instructions to a minimum. The article's example is a request to organize last month's help desk inquiry records.

午後の会議までに、先月のヘルプデスクの問い合わせを以下の観点で整理してください。

- @docs/helpdesk_log.csv を読む
- 質問内容を10カテゴリに分類
- 各カテゴリで最も多い質問を抜粋
- 「マニュアル化すべき度」を高/中/低で評価
- 結果は reports/helpdesk_faq.md に保存

If you write a file path after @, you can point Claude at that file and have it read it. Use only files that fall within the "range of information you may enter into AI" you decided in Chapter 1 of the article. If a record contains personal or customer names, remove those columns before handing it over.

Evening, 15 minutes: organize for the next day and set up one automation

I split the 15 minutes at night into two parts. The first 7 minutes are for pasting in the next day's task list and asking Claude to classify it.

明日の作業一覧:(以下に箇条書きで貼り付け)

これを以下の観点で分類してください:

1. 私が手を動かす必要があるもの
2. Claude Code に任せられるもの(具体的にどう指示すべきかも)
3. 優先度が低くて翌週以降に回せるもの

In the last 8 minutes, I try automating just one task from that day that was mechanical. Limiting it to 8 minutes is the key. If it doesn't work, I assume I'll retry the next day, so I just give it a first try.

Start CLAUDE.md with three lines

Each time you start a conversation, Claude Code begins without remembering the previous one. CLAUDE.md is the set of instructions it reads at the start of a session so you don't have to explain the same things every time. Its contents are Markdown (text that can include headings and bullet lists).

Where you put the file changes its scope. For the first week, a project-level file placed directly under your working folder is enough. The guide covers when to use personal versus team-shared files in Chapter 5.

To start, write the following three items, one line each.

  1. Your own position (what you're using it for)
  2. Tools you'll use often
  3. Order of priority when you can't decide

As examples for corporate IT, the article lists the following.

# 業務環境メモ

- 私は中小企業の情シス担当で、社内の業務改善ツールを作っています
- よく使うのは Microsoft 365、Power Automate、Excel、Python です
- コードは「短さ」より「他の人が読んで直せること」を優先してください

If the folder already has files, type /init inside Claude Code and it will look at the folder's contents and create an initial CLAUDE.md. The docs also recommend adding to the generated file any internal assumptions that only you know.

When to add one more line

The article explains that the official docs recommend adding to CLAUDE.md in cases like the following.

  • When Claude makes the same mistake twice
  • When you notice you're typing the same explanation into chat again
  • When new team members will likely need the same explanation

Source: Chapter 2: Your First Week — a 30-Minute Daily Routine and a 3-Line CLAUDE.md (Japanese)

Cautions: what not to write, and the limits of CLAUDE.md

CLAUDE.md is often a shared file. Avoid writing passwords, API keys, tokens, personal information, customer names, or transaction amounts in it.

Also, CLAUDE.md is not an enforced setting; it is instructions that Claude reads and tries to follow. Operations you must reliably block should be blocked with the permission settings covered in chapter 4 of the article. How to write permission settings isn't in the source, so check the official docs.

Put only information permitted by your internal rules in the files you hand over and in CLAUDE.md.

A one-week plan, handling information, and how to measure results

Here is how to run the week.

  • Day 1: Create a working folder and write a 3-line CLAUDE.md (Day 1 of another guide also includes installing Claude Code)
  • Day 2: Try the 10-minute morning routine. Add one line to CLAUDE.md
  • Day 3: Try the 5-minute midday slot (with a small task)
  • Day 4: Try the 15-minute evening routine
  • Day 5: Review a week's worth of CLAUDE.md and clean up duplicates and contradictions
  • Days 6–7: Rest (a reset so you can keep going)

In the first week, don't aim for results. Your only goal is to build the routine. On days when you can't spare 30 minutes, keep going with just 10 minutes in the morning. If you miss a day, it's fine to pick up again the next day.

On handling business information, the article's author does not enter confidential data itself, but does include business processes, operating rules, and the tool setup in use. When unsure, the first step is to ask the head of corporate IT how far business information may be shared with AI.

The article also says that on individual plans (Pro/Max) you can turn off the use of conversations for model improvement in Claude's privacy settings, and that business plans (Team/Enterprise) are not used for training by default. Check the official page for the latest specifications.

As for the effect, the author writes that their own working time dropped by about 20 hours a month, by feel. This is only the author's impression, not a guarantee that you will get the same result.

FAQ

Is it okay if I don't see results in the first week?

The article says that in the first week you should aim only to build the routine, not to get results. On days you can't spare 30 minutes, keep going with just 10 minutes in the morning, and if you miss a day, returning the next day is fine.

Source: Chapter 2: Your First Week — a 30-Minute Daily Routine and a 3-Line CLAUDE.md (Japanese)

What should I write in CLAUDE.md first?

Write three lines in total, one line each for your role, the tools you use most, and your priorities when you're unsure how to decide. After that, add a line whenever Claude makes the same mistake twice, or when you notice you're typing the same explanation again.

Source: Chapter 2: Your First Week — a 30-Minute Daily Routine and a 3-Line CLAUDE.md (Japanese)

Is it OK to give business information to Claude Code?

It depends on your company policy. The author's approach is not to enter confidential data itself, and when unsure, they check with the head of corporate IT about what can be shared. For how each plan handles training on your data, check the latest details on the official pages.
