Does having ANTHROPIC_API_KEY set make Claude Code bill through the API? How to check and remove it

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official Help Center, Claude Code gives priority to an API key in an environment variable over a subscription, and if an API key is present, usage is billed pay-as-you-go through the API.
  • You verify this in two ways: run /status inside Claude Code, and print the environment variables in a terminal outside Claude Code.
  • If you use a subscription, leave ANTHROPIC_API_KEY unset. Watch out for leftover entries in your shell config files and for forgetting to restart the terminal after changes.

What happens when an API key is set in an environment variable

Claude Code (Anthropic's AI coding agent that runs in the terminal) can sign in with a claude.ai subscription or use an API key. According to the official Help Center, if an API key is set in an environment variable, Claude Code prefers that API key over the subscription. This is described as intentional behavior, giving you flexibility in choosing the authentication method.

In this case, you are billed at API pay-as-you-go rates to the API account tied to that key. This is true even if you are logged in with a claude.ai subscription or a different Console account. Being logged in does not necessarily mean you are running under your subscription allowance.

As of writing (October 2026), the relevant page in the official Help Center does not list specific amounts or counts. Check the official pricing page for the latest figures.

If you want to use a subscription, the official Help Center says to leave ANTHROPIC_API_KEY unset. This prevents unexpected API charges and lets you use the usage included in your subscription. If you want to use an API key, the recommended approach is to set it temporarily, only when needed.

Source: Manage API key environment variables in Claude Code

Check which one is running now

The official Help Center explains that running /status inside Claude Code shows the authentication method currently in effect. Running it periodically to check is recommended.

To check the environment variable itself, run the following command in a terminal outside Claude Code. First, macOS/Linux.

echo $ANTHROPIC_API_KEY

For Windows CMD, use the following.

echo %ANTHROPIC_API_KEY%

For Windows PowerShell, do the following.

echo $env:ANTHROPIC_API_KEY

Also, if Claude Code finds an API key in an environment variable during initial setup, it asks which authentication method to use. After a successful login, if both sets of credentials are active, a notification is said to warn you about possible unexpected API charges.

Source: Manage API key environment variables in Claude Code

Remove the API key environment variable

This is a way to turn it off temporarily, as described in the official Help Center. On macOS/Linux, do the following.

unset ANTHROPIC_API_KEY

For Windows CMD, use the following.

set ANTHROPIC_API_KEY=

For Windows PowerShell, do the following.

Remove-Item Env:ANTHROPIC_API_KEY

If you set it permanently in a configuration file, you also need to remove it there. The removal commands differ between macOS and Linux, so check the official Help Center. On Windows, delete the variable in the system environment variable settings. After changing environment variables, you need to restart the terminal.

Authentication precedence in the official docs

According to the official docs, when multiple credentials are present, Claude Code picks one in the following order.

  1. Cloud provider credentials (when any of CLAUDE_CODE_USE_BEDROCK, CLAUDE_CODE_USE_VERTEX, or CLAUDE_CODE_USE_FOUNDRY is set)
  2. The ANTHROPIC_AUTH_TOKEN environment variable
  3. ANTHROPIC_API_KEY environment variable
  4. Output of the apiKeyHelper script
  5. The CLAUDE_CODE_OAUTH_TOKEN environment variable
  6. Anthropic profiles and federated credentials
  7. Subscription OAuth credentials via /login (the default for Claude Pro, Max, Team, and Enterprise users)

Subscription login comes last in the order. If environment variables or cloud settings higher up remain, those may be used instead.

Handling ANTHROPIC_API_KEY

According to the official docs, in interactive mode, if ANTHROPIC_API_KEY is set, you are asked once whether to approve or reject the key, and your choice is remembered. To change it later, use the "Use custom API key" toggle in /config. This toggle appears only while ANTHROPIC_API_KEY is set in the environment. In non-interactive mode (-p), the key is always used if it is present.

Even with a subscription, if ANTHROPIC_API_KEY is set and you approve it, the API key is used. If the key belongs to an organization where it has been disabled or has expired, authentication may fail. Run unset ANTHROPIC_API_KEY to return to the subscription, then confirm with /status. If both are set, /status marks the one that isn't being used.

Scope

ANTHROPIC_API_KEY and similar variables apply to the CLI, as well as the VS Code extension, Agent SDK, and GitHub Actions that wrap it. Claude Desktop and cloud sessions don't read these environment variables. Cloud sessions always use your subscription credentials.

Notes for trying it out or rolling it out internally

The official Help Center lists the following three points to avoid.

  • Setting environment variables in a shell profile and then forgetting about them
  • Not restarting the terminal after changing environment variables
  • Assuming you're using your subscription when an API key is set in an environment variable

If you are rolling this out company-wide as corporate IT, include in your instructions a check with /status and a check that no ANTHROPIC_API_KEY is left in the settings files. This makes it easier to notice a mix-up in who is being billed. This is an operational suggestion based on the caveats in the source. For how API key usage is billed, check the official pricing page.

FAQ

If I'm logged in with a subscription, won't I be billed through the API?

Not necessarily. According to the official Help Center, if an API key is set in an environment variable, usage is billed pay-as-you-go to that key's API account, even if you are logged in with a subscription or a different Console account.

Source: Manage API key environment variables in Claude Code

How do I check whether an API key is set?

Run /status inside Claude Code to check which authentication method is active. Check environment variables in a terminal outside Claude Code, using the echo command for your OS. The commands are as shown in the main text.

Source: Manage API key environment variables in Claude Code

How is the API key handled when I use -p in scripts?

According to the official docs, in non-interactive mode (-p), if ANTHROPIC_API_KEY is set, that key is always used. Unlike interactive mode, it does not ask you to approve the key.
