How to Use Claude Code Plan Mode: Review the Plan Before Any Edits

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • According to the official docs, plan mode is a mode in which Claude Code (an AI coding agent from Anthropic that runs in the terminal) reads and investigates files, then presents proposed changes as a plan. Source edits are blocked until you approve the plan (except in interactive terminal sessions where bypass permissions are available).
  • You can enter it with Shift+Tab, /plan at the start of the prompt, or claude --permission-mode plan at launch. Before approving, you can press Ctrl+G to edit the plan directly in a text editor.
  • Planning also adds effort, so the official docs say to use it when the approach is uncertain or the change spans multiple files, and to skip it for small fixes whose diff you can describe in one sentence.

What you can do in plan mode

This article is based on the official docs as of writing (October 2026). Displays and behavior may vary by environment, so check the latest official docs before rolling this out.

According to the official docs, plan mode is for investigating and proposing without making changes. Claude reads files, runs shell commands for research, and writes a plan, but does not edit source files. Edits stay blocked until you approve the plan. The exception is an interactive terminal session where bypass permissions are available.

How shell commands are handled during planning

The official docs state that how shell commands in a plan are handled varies by session, and the first of the following that applies is used.

  1. Interactive terminal sessions where bypass permissions is available: neither the classifier (a separate model that vets actions before they run) nor confirmation prompts apply to planned commands.
  2. When auto mode (a mode that runs without routine permission prompts) is available and the useAutoModeDuringPlan setting is on (the default): a classifier reviews shell commands, except deletions of critical paths, instead of showing a confirmation prompt. Approved commands run, and rejected ones are blocked.
  3. If auto mode is unavailable or useAutoModeDuringPlan is off, you get an approval prompt for anything other than the built-in read-only commands. The same applies when sandbox auto-allow mode is enabled.

Source: Choose a permission mode

How to enter and exit plan mode

According to the official docs, you enter plan mode by pressing Shift+Tab or by putting /plan at the start of a single prompt. You can also start in plan mode from the CLI.

claude --permission-mode plan

While in plan mode, the status bar shows ⏸ plan mode on. To exit without approving, press Shift+Tab again.

The Shift+Tab cycle order is: the first press from auto goes to default, then it continues default → acceptEdits → plan.

Differences by interface

  • VS Code: click the mode indicator at the bottom of the prompt box and select Plan.
  • JetBrains: It runs in the IDE's terminal, so it works the same way as the CLI.
  • Web and mobile: the mode selection for cloud sessions includes Plan.

Source: Choose a permission mode

Reviewing, approving, and editing plans

Once the plan is ready, Claude presents it and asks how to proceed. You can choose from the following three options.

  • Yes, and use auto mode: Approves and starts in auto mode. If auto mode is unavailable, for example because your organization has disabled it, this appears as Yes, auto-accept edits. If you started with bypass permissions enabled, it appears as Yes, and switch to BYPASS PERMISSIONS (no further prompts) for this session.
  • Yes, manually approve edits: Approve and review the edits one by one.
  • No, keep planning: Stays in plan mode, and you tell Claude what you want changed.

When you approve, Claude exits plan mode, switches to the permission mode indicated by the option you chose, and starts editing. To have it plan again, return to plan mode with Shift+Tab, or start your next prompt with /plan.

Press Ctrl+G to open the proposed plan in your default text editor and edit it directly before Claude proceeds. When showClearContextOnPlanAccept is enabled, an option to approve the plan and clear the planning context is added at the top.

When you approve a plan, the session gets a title generated from the plan, unless you have already named the session.

Source: Choose a permission mode

Setting plan mode as the default

To make plan mode the project default in a terminal session, set defaultMode to plan in .claude/settings.json. Follow the example in "Start in a different permission mode" in the official docs for the exact syntax.

Conversations started by the VS Code extension do not read the project settings for the starting permission mode. In that case, set claudeCode.initialPermissionMode to plan in your VS Code user settings.

Notes when you select Plan from the UI

  • VS Code: If you pick Plan from the mode indicator, it applies only to that conversation.
  • Desktop app: If you choose Plan, it applies only to the current session.

For details on the other places where settings can live, check the official docs.

Source: Choose a permission mode

What kinds of changes to use it for: the approach the official docs recommend

The official best practices explain that having Claude write code right away can produce code that solves the wrong problem, so you should separate investigation from execution using plan mode. The flow has four stages.

  1. Explore: Enter plan mode and have Claude read files to answer your questions. It makes no changes.
  2. Plan: Claude creates a detailed implementation plan. You can edit it directly with Ctrl+G.
  3. Implementation: approve the plan or press Shift+Tab to leave plan mode, then have Claude write the code while you check it against the plan.
  4. Commit: Ask Claude to commit with a clear message and create a PR.

However, the official docs note that plan mode also has overhead. For small fixes with a clear scope, such as correcting a typo, adding log output, or renaming a variable, ask directly. A plan helps when you're unsure how to proceed, when changing multiple files, or when working in unfamiliar code. If you can describe the diff in one sentence, skip the plan.

The official common workflows also explain that you should switch to plan mode for changes you want to review before they are applied to disk. If you are corporate IT rolling this out company-wide, communicating the criteria for when to use each mode helps avoid confusion.

FAQ

Does Claude edit source files while in plan mode?

According to the official docs, Claude reads files, runs shell commands for investigation, and writes a plan, but does not edit source. Edits are blocked until you approve the plan. The exception is an interactive terminal session where bypass permissions are available.

Source: Choose a permission mode

How do I exit plan mode without approving the plan?

Press Shift+Tab again. Approving a plan also exits plan mode, but in that case it switches to the permission mode that the option you chose indicates, and Claude starts making edits.

Source: Choose a permission mode

Should I use plan mode even for small fixes?

The official best practices say to ask directly when the scope is clear and the fix is small (fixing a typo, adding a log line, renaming a variable). If you can describe the diff in one sentence, they say to skip the plan.
