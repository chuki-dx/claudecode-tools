How to roll out Claude Code managed settings company-wide

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • Admin settings are a mechanism for delivering a policy in the same format as settings.json to devices through a server, MDM, a file, or the HKCU registry.
  • For machines without MDM, and for Linux, the official docs say the quick way is to place managed-settings.json at the fixed location for each OS.
  • After distribution, verify with /status and claude doctor. Also note that some scopes, such as cloud sessions, are not reached.

What you can do: managed settings and four ways to distribute them

Claude Code (an AI coding agent from Anthropic that runs in the terminal) has managed settings, which let admins distribute policies to devices. According to the official docs, every distribution method uses the same policy keys as settings.json. This article is based only on the official docs as of writing (October 2026). Before you roll anything out, check the latest information in the official docs.

There are four ways to distribute it.

  • Server-managed: Distribute settings through the claude.ai admin console or a Claude apps gateway you run yourself. Settings are fetched at startup and rechecked every hour. This suits cases where you want to make changes in one place without touching each device.
  • MDM or OS-level policy: distribute macOS configuration profiles or Windows HKLM registry values with Jamf, Intune, Group Policy, or similar. It is read at startup and checked for changes every 30 minutes.
  • File: place managed-settings.json in the system directory on each machine. It is read at startup and reloaded when the file changes. This is for machines without MDM, Linux, and custom images.
  • HKCU registry (Windows and WSL): an option when you can't write to HKLM. It is used only when conditions are met, such as no higher-priority admin document existing.

MDM profiles, files, and the claude.ai admin console apply the same policy to everyone they reach. To vary it by group, distribute a separate file or profile to that group. The claude.ai admin console can't target groups yet. A self-hosted Claude apps gateway can distribute per IdP group.

When multiple methods reach the same machine, by default only one is used and the rest are ignored. Check the official docs for the order of precedence.

Steps to distribute with a file

According to the official docs, the quickest way to put a policy on each machine is managed-settings.json. There are three steps.

1. Write the file

Write the keys you want to enforce in the same JSON format as settings.json. The following example denies reading two files and disables bypass mode. It also makes Claude Code ignore permission rules from the user, project, and local files, as well as from --allowedTools.

{
  "permissions": {
    "deny": [
      "Read(./.env)",
      "Read(./secrets/**)"
    ],
    "disableBypassPermissionsMode": "disable"
  },
  "allowManagedPermissionRulesOnly": true
}

2. Place it on each machine

Save it as managed-settings.json in the system directory for each OS. To put it in place, you can use the file distribution mechanism you already have.

  • macOS:/Library/Application Support/ClaudeCode/managed-settings.json
  • Linux and WSL: /etc/claude-code/managed-settings.json
  • Windows:C:\Program Files\ClaudeCode\managed-settings.json

3. Verify that it applied

Start with one machine and run /status inside Claude Code. The Setting sources line should show Enterprise managed settings (file). Once you've confirmed that, roll it out to the remaining machines.

Source: Deploy managed settings

Split files by team

When multiple teams each own part of the policy, instead of editing a shared file, you can put one file per part in managed-settings.d/, in the same directory as managed-settings.json. Claude Code merges managed-settings.json first, then the *.json files in alphanumeric order. You can control the order with numeric prefixes, such as 10-telemetry.json and 20-security.json.

When the same key appears in multiple files, it is handled as follows.

  • Single values: the value in the later file replaces the earlier one.
  • Lists (such as permissions.deny): The two lists are merged, with duplicates removed.
  • Nested blocks (such as env and sandbox): merged key by key, and the keys inside follow the same rule.
  • fallbackModel and modelPicker: the later one replaces the whole value.

Confirming it took effect, and what to do if it doesn't work

The official docs say to run /status in the terminal and read the Setting sources line, and to use claude doctor to see discarded entries. The parentheses after Enterprise managed settings show which source was selected.

  • (remote): server-managed settings from claude.ai or a gateway
  • (plist) or (HKLM): MDM or OS policy
  • (file), (drop-ins), (file + drop-ins): a file, a drop-in directory, or both

If no line appears, no managed source that distributes policy keys was found. Check that the file is in the correct location for your OS and that it contains policy keys, not just control keys. If a different source name appears, a higher-priority source is being used. Skipped sources are listed on the Skipped sources line (requires Claude Code v2.1.242 or later).

If a managed settings file is not valid JSON, Claude Code refuses to start, even if other managed sources are distributing the correct policy. Check the JSON syntax before you roll it out.

Source: Deploy managed settings

Caveats to know before you distribute

  • Cloud sessions: sessions in environments operated by Anthropic don't read the MDM profiles or files on your device. That policy must be delivered through server-managed settings.
  • Cowork: Cowork sessions in Claude Desktop do not fetch server-managed settings from the claude.ai admin console, even if you are signed in with a Team or Enterprise account. When a session runs on the device, that device's MDM and files are read.
  • Sessions left open for a long time: requiredMinimumVersion prevents an old binary from starting, but it does not terminate sessions that are already running.
  • Invalid values: If a managed settings value fails validation, entries that can be fixed are dropped with a warning, and values that can't be fixed are discarded. However, restrictive keys such as allowManagedPermissionRulesOnly are treated as restricting if they can't be read (requires Claude Code v2.1.282 or later).
  • Admin-only keys: some keys, such as strictKnownMarketplaces, are read only from managed sources and have no effect if written in user settings.
  • Old path: The Windows file C:\ProgramData\ClaudeCode\managed-settings.json is no longer read.

FAQ

Where do I put managed-settings.json?

According to the official docs, the path is /Library/Application Support/ClaudeCode/managed-settings.json on macOS, /etc/claude-code/managed-settings.json on Linux and WSL, and C:\Program Files\ClaudeCode\managed-settings.json on Windows.

Source: Deploy managed settings

How do I check whether the policy is taking effect?

In a terminal, run /status inside Claude Code and look at the Setting sources line. For a file, it shows Enterprise managed settings (file). You can check discarded entries with claude doctor.

Source: Deploy managed settings

Can I distribute a different policy to only specific groups in the claude.ai admin console?

According to the official docs, the claude.ai admin console cannot yet target specific groups. To vary settings by group, distribute separate files or profiles, or use a self-hosted Claude apps gateway to deliver settings per IdP group.

Source: Deploy managed settings
