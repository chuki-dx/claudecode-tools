How to reduce Claude Code token usage and how to check it

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • According to the official docs, Claude Code is billed by API token consumption. You can check usage in the Session block of /usage, but the dollar amounts are estimates. Check the Usage page in the Claude Console for official billing.
  • The basic way to save is to keep the context small. The docs suggest using /clear between unrelated tasks, and reviewing the model and the extended-thinking effort level for simple tasks.
  • Sessions left open for a long time, cache misses, scheduled tasks, and subagents all push usage up. The docs recommend taking a baseline with a small pilot before rolling out company-wide.

Check your usage first (/usage and the display next to the spinner)

According to the official docs as of writing (October 2026), Claude Code (an AI coding agent from Anthropic that runs in the terminal) is billed by API token consumption. Costs vary widely depending on which model you choose, the size of your codebase, and usage patterns such as multiple instances or automation.

Across enterprise deployments, the average is about $13 per developer per active day, or $150-250 per month, and the docs state that 90% of users stay under $30 per active day. For your own estimate, the docs recommend measuring with a small pilot before expanding.

The Session block in /usage shows the current session's token usage. The dollar amount is a local estimate calculated from token counts at list prices; check the Usage page in the Claude Console for official billing. For Max and Pro users, usage is included in the subscription, so this cost figure doesn't matter for billing. The total resets when you start a new session with /clear.

In v2.1.251 and later, a Prompt cache (main) row is added, showing the share of input tokens served from the cache and the number of cache misses. It covers only the main conversation, not subagents. The token count next to the spinner while Claude works is a rough estimate of that turn's output and does not match the total in /usage.

Keep the context small

The official docs explain that token costs grow as the context gets larger. Claude Code optimizes automatically with prompt caching and auto-compaction (summarizing the conversation history), but the following habits can reduce costs further.

  • When you move to unrelated work, start fresh with /clear. Old context consumes tokens with every later message. If you'll come back to it, use /rename first and /resume later.
  • You can tell Claude what to keep when summarizing, as in /compact Focus on code samples and API usage.
  • You can also write guidance for summarization in the CLAUDE.md at the project root.
# Compact instructions

When you are using compact, please focus on test output and code changes

CLAUDE.md is loaded at the start of a session. Moving detailed steps for specific tasks, such as PR reviews or database migrations, into skills that load only when invoked keeps the base context small. Keep CLAUDE.md to the key points; under 200 lines is the recommended guideline.

Review your model and extended thinking settings

According to the official docs, Sonnet handles most coding work and costs less than Opus. Save Opus for complex design decisions and multi-step reasoning. You can switch models mid-session with /model and set the default with /config. Switching to Opus also applies to subagents that inherit the session's model. For simple subagent tasks, you can specify model: haiku.

Extended thinking is enabled by default, and thinking tokens are billed as output tokens. Depending on the model, the default budget can reach tens of thousands of tokens per request. For simple tasks, lower the effort level with /effort or /model, or disable thinking with /config. However, Opus 5.5, Sonnet 5.5, Haiku 5.5, and Fable-family models always use extended thinking and can't turn it off.

For models with a fixed thinking budget, you can lower the budget with the MAX_THINKING_TOKENS environment variable (for example, MAX_THINKING_TOKENS=8000). Models with adaptive reasoning ignore any nonzero budget, so use the effort level instead.

MCP, hooks, subagents, and how to write requests

  • MCP: Tool definitions are loaded lazily by default. Until a specific tool is used, only its name and the server's instructions enter the context. Run /context to see what is using space, and /mcp to disable servers you don't use.
  • CLI tools such as gh, aws, gcloud, and sentry-cli are said to be more context-efficient than MCP servers because they don't add to the tool list.
  • hooks: Instead of having Claude read a 10,000-line log, a hook can grep for ERROR and return only the matching lines, cutting context from tens of thousands of tokens to a few hundred. The official docs include an example PreToolUse hook that narrows test output to failures only.
  • Subagents: if you hand off high-output work such as running tests or processing logs, only a summary returns to the main conversation. However, the subagent's own requests also count toward usage.
  • How you phrase requests: Vague requests like "improve this codebase" lead to broad scanning. Being specific about the target means fewer files get read.

For complex tasks, press Shift+Tab to switch to plan mode and review the approach before implementing; this helps you avoid rework. If Claude heads in the wrong direction, stop it with Escape and roll back with /rewind. Note that agent teams are said to use about 7 times as many tokens as a standard session when teammates are in plan mode.

When usage tends to grow, and managing it across an organization

The official docs list the following as causes of rising usage in sessions that stay open for a long time.

  • Long context: the entire conversation is sent with every request, so even a one-line question uses as much as the whole conversation.
  • Cache miss: The first message after a break longer than the cache lifetime reprocesses the entire context. The lifetime is 1 hour on a subscription and 5 minutes once you start using usage credits. With API keys or cloud providers, it is 5 minutes by default.
  • Scheduled tasks send the full context at each interval, even when the session is idle. Subagents and teammates also send their own separate requests.
  • Compact: /compact reads the conversation it summarizes, so with a large context it becomes a large request. /clear, which you use when you want a fresh start, costs nothing.

On Pro, Max, Team, and Enterprise, /usage flags behaviors that account for 10% or more of your recent usage (such as long context or cache misses), with tips for reducing them.

When you manage usage at the organization level, Teams and Enterprise rely mainly on the spend reports and limit settings in the admin console, Console on workspace spend limits, and cloud-provider setups on each cloud's billing console. OpenTelemetry works with any setup. Check the official docs for detailed setup steps.

FAQ

Does the dollar figure in /usage match my bill?

They won't necessarily match. According to the official docs, the dollar amount is an estimate calculated locally from token counts at list prices. For organizations that pay contract rates, an admin can enter the rates in modelPricing in managed settings, and the display will then be based on contract rates (v2.1.242 and later). Even so, it's an estimate, not an invoice, and you confirm the actual billing on the Usage page in the Claude Console.

Source: Manage costs effectively

Can I turn off extended thinking on any model?

No, you can't. Extended thinking is on by default, and for simple tasks you can lower the effort level with /effort or /model, or turn it off in /config. However, according to the official docs, Opus 5.5, Sonnet 5.5, Haiku 5.5, and Fable models always use extended thinking and it can't be turned off.

Source: Manage costs effectively

Why does usage spike on the first message after I step away?

According to the official docs, the first message after a break longer than the cache lifetime is a cache miss, and the entire context is reprocessed. The lifetime is 1 hour on a subscription, 5 minutes once you start using usage credits, and 5 minutes by default with an API key or a cloud provider.
