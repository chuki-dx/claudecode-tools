How to Use Claude Code from Slack: Setup Flow, Permissions, and Limits

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • The Slack integration in this article is the older version that runs under a personal account. It applies to Pro and Max, and only to Slack workspaces not connected to Claude Tag.
  • Setup goes in this order: an admin installs the Claude app, each user connects their account, you prepare GitHub and cloud sessions, and then you invite the app to channels.
  • Sessions run under each user's own account and limits, can't be used in DMs, and are limited to GitHub only and one PR per session.

What it can do and which plans include it

According to the official docs, when you ask @Claude in Slack to do a coding task, it creates a cloud session of Claude Code (Anthropic's AI coding agent that runs in the terminal). It lets you hand off development work without leaving your team's conversation. This article is based only on the official docs as of writing (October 2026).

  • Requesting a bug investigation and fix
  • Implementing small features or refactoring based on team feedback
  • Debugging based on reproduction steps and user reports in the conversation
  • Delegate a task from Slack, keep working on something else, and get notified when it finishes

Conditions for the target

According to the official docs, this version runs each session under an individual Claude account, and only Pro and Max accounts respond to @mentions in a channel. It also applies only to workspaces where no organization is connected to Claude Tag (the mechanism that runs @Claude under an organization's shared identity).

On Team and Enterprise plans, the existing Slack app and the @Claude handle remain, and you set up Claude Tag in the new workspace. The source doesn't cover those steps, so check the official docs.

Source: Claude Code in Slack

Setup flow

The official docs list these prerequisites: Pro or Max, the Slack-side requirements, cloud sessions enabled, a GitHub connection and repository authorization at claude.ai/code, and linking Slack with your Claude account. The steps are as follows.

  1. A Slack workspace admin installs the Claude app from the Slack App Marketplace.
  2. Each user clicks "Connect" on the App Home tab of the Claude app in Slack and completes authentication in the browser.
  3. Sign in to claude.ai/code with the same account, connect GitHub, and authorize at least one repository you want people to use.
  4. Choose a Routing Mode in App Home.
  5. Invite it by typing /invite @Claude in the channel.

Routing Mode has two options. "Code only" sends every @mention to Claude Code. "Code + Chat" looks at the content and routes coding to Claude Code, and writing, analysis, and general questions to Claude Chat. When a request is routed to Chat, you can switch it to Claude Code with "Retry as Code", and you can also choose the reverse in the thread.

Source: Claude Code in Slack

How to use it and the screen controls

With Code + Chat, work judged to be coding becomes a cloud session, and everything else gets a normal chat reply. With Code only, everything goes to Claude Code. You can also explicitly ask for something to be treated as coding work.

Context is gathered from all messages in the thread if you invoke it in a thread, or from recent channel messages if you invoke it directly in a channel. When it finishes, the following buttons appear.

  • View Session: Opens the entire session in your browser, where you can also send follow-up requests.
  • Create PR: Creates a pull request from the session's changes.
  • Retry as Code: re-runs in Claude Code something that was a chat response.
  • Change Repo: Use this when the selected repository is wrong.

The official docs say your intent comes across best when a request includes file names, function names, and error messages, states the repository and the completion criteria (such as whether tests or a PR are needed), and continues as a conversation in a thread. For work that needs file uploads or real-time interaction, and for long, complex work, the docs say it is better to use the web app directly.

Source: Claude Code in Slack

Permissions, access control, and cautions

  • Each user runs their session on their own Claude account, and usage and rate limits count against the limits of their personal plan. Specific numbers aren't given in the source, so check the official docs.
  • Each person can use only the repositories they have connected themselves.
  • Sessions remain in your claude.ai/code history. For Team and Enterprise accounts, sessions created from Slack are automatically visible to the organization.

In a workspace, the admin decides whether to install the app. On Enterprise Grid, organization admins can manage which workspaces can use it. When you remove the app, access for all users in that workspace is revoked immediately.

As for channels, installing the app alone does not add Claude to any channel. It responds only to @mentions in channels it has been invited to, and works in both public and private channels. Admins can limit usage by managing which channels it is invited to and who participates.

There are two caveats. It doesn't work in DMs. Also, Claude may read the context of the conversation where it is invoked and follow instructions in other messages, so the official docs ask you to use it only in Slack conversations you trust.

Source: Claude Code in Slack

Limits, and when notifications or errors appear

  • GitHub repositories only
  • One session can create one pull request
  • Requires access to cloud sessions

When a notification comes back

"This workspace isn't set up for Claude Tag yet" is the notice @Claude returns when your organization is not connected to Claude Tag and the linked account is not Pro or Max. Start with @Claude connect in the notice, then continue to the Claude Tag setup.

The retirement notice begins with The legacy Claude in Slack bot is retired effective October 5, 2026 and no longer responds in channels.. It appears when the workspace is connected to a Claude organization and that organization's Claude Tag settings still have the legacy version selected, and it also shows up for Pro and Max regardless of your own plan. An organization Owner needs to turn on Claude Tag in managed settings; if you aren't an Owner, tell your Owner.

Other errors

  • "Claude Code is not enabled for your account": Sign in once at claude.ai/code and finish the web onboarding, and the next @mention will work. This is required for each user.
  • Session won't start: check the connection in App Home, that cloud sessions are enabled, and that the GitHub repository is connected.
  • Wrong repository or none shown: check "Change Repo", the repository name in your request, the connection at claude.ai/code, and GitHub permissions.

FAQ

Can companies on a Team plan use this integration?

According to the official docs, this version applies only to Pro and Max accounts; on Team and Enterprise plans you set up Claude Tag. See the official docs for the steps.

Source: Claude Code in Slack

Can I use it in DMs?

No. It responds only to @mentions in public or private channels after you invite it with /invite @Claude.

Source: Claude Code in Slack

Whose usage does it count toward?

Each session runs under the user's own account and counts toward that user's plan limits. The source gives no amounts or counts, so check the official pricing page for the latest details.
