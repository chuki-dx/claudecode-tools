Claude Code MCP settings: local, project, and user scopes, and .mcp.json

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • MCP server configuration has three scopes: local, project, and user. If you don't specify one, it defaults to local.
  • Add servers you want to share with your team using --scope project. They are written to .mcp.json in the project root, so you can share them through version control.
  • When servers with the same name exist in multiple scopes, local takes precedence over project, which takes precedence over user. The contents of the entries are not merged.

The three MCP scopes: where a server loads and whether it is shared

This article explains the scopes you use when configuring MCP servers (a mechanism for connecting external tools and services) in Claude Code (an AI coding agent from Anthropic that runs in the terminal). It is based on the official docs as of writing (October 2026).

According to the official docs, the scope determines which projects the server is loaded in and whether the configuration is shared with your team.

  • local: Loaded only in the current project and not shared with the team. It is stored in ~/.claude.json.
  • project: Loaded only in the current project and shared with your team through version control. It is stored in .mcp.json at the project root.
  • user: loaded in all of your own projects and not shared with the team. It is stored in ~/.claude.json.

Administrators can also deploy and provide servers to all users through managed configuration (centralized settings by administrators). Check the official docs for details.

local scope (default): just you, just that project

According to the official docs, local is the default scope. A local server loads only in the project where you added it and stays private to you. It is stored in ~/.claude.json under that project's path, so the same server does not appear in other projects. It is described as suitable for personal development servers, experimental configurations, and servers whose credentials you don't want in version control.

# Add a local-scoped server (default)
claude mcp add --transport http stripe https://mcp.stripe.com

# Explicitly specify local scope
claude mcp add --transport http stripe --scope local https://mcp.stripe.com

This command writes to the entry for the current project in ~/.claude.json. Here is the result of running it in /path/to/your/project.

{
  "projects": {
    "/path/to/your/project": {
      "mcpServers": {
        "stripe": {
          "type": "http",
          "url": "https://mcp.stripe.com"
        }
      }
    }
  }
}

Note that MCP's "local scope" is not the same thing as general local settings. MCP local scope is stored in ~/.claude.json (your home directory), while general local settings use .claude/settings.local.json (in the project directory).

The project scope and .mcp.json: using the same settings across a team

The project scope stores its configuration in .mcp.json at the project root. When you add a server, Claude Code creates or updates this file automatically. If you put .mcp.json under version control, everyone on the team can use the same MCP tools and services.

# Add a project-scoped server
claude mcp add --transport http shared-server --scope project https://example.com/mcp

The resulting .mcp.json has the following format.

{
  "mcpServers": {
    "shared-server": {
      "type": "http",
      "url": "https://example.com/mcp"
    }
  }
}

When approval prompts appear and when they don't

For security, interactive sessions ask for your approval before using project-scope servers from .mcp.json. To redo your approval choices, run claude mcp reset-project-choices.

On the other hand, claude -p runs, Agent SDK sessions, and cloud sessions cannot show a confirmation screen, so they load servers without confirmation. The confirmation is also skipped in sessions started in bypassPermissions mode with skipDangerousModePermissionPrompt set in user settings or managed settings. If there are servers you still don't want loaded, the official docs list the following methods.

  • Add it to disabledMcpjsonServers (this blocks it in all permission modes)
  • Exclude project settings entirely with --setting-sources or the SDK's settingSources
  • Start a session with --strict-mcp-config (only the servers passed with --mcp-config are used)

The user scope and precedence among servers with the same name

Servers in the user scope are stored in ~/.claude.json and are available in all projects on that machine. They are private to your user account and are not shared with others. The docs describe this scope as a good fit for personal utilities and for services you use often across many projects.

# Add a user server
claude mcp add --transport http hubspot --scope user https://mcp.hubspot.com/anthropic

If the same server is defined in more than one place, Claude Code connects to it only once and uses the definition with the highest priority. The entire entry from that definition is used; fields are not merged across scopes. The order of priority is as follows.

  1. Local scope
  2. Project scope
  3. User scope
  4. Servers provided by plugins
  5. claude.ai connectors

Duplicates across the three scopes are detected by name. Plugins and connectors are detected by the endpoint they connect to. Servers that your organization provides through the managedMcpServers managed setting take precedence over all of these (requires Claude Code v2.1.259 or later).

If you define the same name in multiple scopes with different endpoints, claude mcp list and /mcp show a warning. You can delete an unneeded definition with claude mcp remove <name> --scope <scope>.

.mcp.json environment variable expansion, and variables that are read as empty

According to the official docs, .mcp.json supports environment variable expansion. You can share the configuration with your team while letting each person supply machine-specific paths and secrets such as API keys.

  • ${VAR}: Expands to the value of the environment variable VAR.
  • ${VAR:-default}: Uses the value of VAR if it is set, and default otherwise.

You can use expansion in command, args, env, url, and headers. Here is an example.

{
  "mcpServers": {
    "api-server": {
      "type": "http",
      "url": "${API_BASE_URL:-https://api.example.com}/mcp",
      "headers": {
        "Authorization": "Bearer ${API_KEY}"
      }
    }
  }
}

If a referenced variable is unset and has no default, the configuration still loads. However, claude mcp list shows a warning, and the literal ${VAR} string is used as-is.

Note that in a remote server's url and headers, variables that are Claude Code or cloud credentials, such as ANTHROPIC_API_KEY and ANTHROPIC_AUTH_TOKEN, are not expanded and are read as empty. This is true even if the variable is set, and :-default is also ignored. Names outside that set, such as API_KEY, are expanded as written. To pass one of those credentials, copy it into a variable with a name you choose and reference that name.

FAQ

Where is an MCP server saved if I add it without specifying a scope?

According to the official docs, local is the default. It loads only in that project, is private to you, and is stored under the project's path in ~/.claude.json.

Source: Connect Claude Code to tools via MCP

Is it OK to put .mcp.json under version control?

The official docs recommend committing .mcp.json to version control so the whole team can use the same MCP tools. Secrets such as API keys can stay in each person's environment by referencing environment variables with ${VAR}. For servers whose credentials you don't want in version control, the local scope is said to be a good fit.

Source: Connect Claude Code to tools via MCP

If a server with the same name exists in both local and user scope, which one is used?

The higher-priority local definition is used, and Claude Code connects only once. The entire entry from that definition is used; its fields are not merged with the user definition.
