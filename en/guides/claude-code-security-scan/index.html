Steps to check code for vulnerabilities and turn the findings into patches with the Claude Security plugin

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, the Claude Security plugin runs inside a Claude Code session, where multiple agents scan an entire repository or a diff of changes for vulnerabilities, and then turn the findings you select into patches.
  • The prerequisites are one of a paid plan, the Anthropic API, or a third-party provider, plus python3 3.9 or later and Git (needed for change scanning and patch creation).
  • Patches are not applied automatically. The user applies them with git apply and reviews them one at a time in separate pull requests.

What the Claude Security plugin can do

The following is based on the official docs as of writing (October 2026). According to the official docs, the Claude Security plugin runs inside a Claude Code session (Claude Code is an AI coding agent from Anthropic that runs in the terminal). Multiple agents map the configuration, build a threat model, and search for vulnerabilities, and every finding is independently verified before it goes into the report.

Besides a whole repository, you can target a branch, a PR diff, or a single commit. You can turn selected findings into patches, and the user reviews and applies them. It runs in a local session, and scans count toward your usage. The source gives no amounts or counts, so check the official pricing page for current figures.

The official docs say it is meant to be used alongside your existing static analysis and dependency scanning, not to replace them. Claude Security, the managed version that monitors your repositories, is a separate product on the Enterprise plan.

Prerequisites to check before running it

These are the prerequisites for running, as listed in the official docs.

  • A paid plan, the Anthropic API, or a third-party provider (because the scan uses dynamic workflows). On Pro, turn it on in the Dynamic workflows row of /config.
  • Python 3.9 or later available on your PATH as python3. No additional installation is needed.
  • Linux, macOS, or Windows.
  • Git. It is required for change scanning and patch creation, and other version control systems are not supported. A full scan works without version control.

The plugin itself doesn't call a model, so you don't need a separate API key. Exploration, verification, and patch creation run on the session's model, which you change with /model. With third-party providers, the sonnet alias may point to a different version, and if it isn't available you need to pin the model. Check the official docs for the steps.

Installing plugins

In the terminal, run claude and enter the following at the prompt. In the VS Code extension and the desktop app, follow the official "Install a plugin" steps.

/plugin install claude-security@claude-plugins-official

The plugin details open, so choose an installation scope and continue. If it fails, use the message shown to resolve it.

  • Marketplace "claude-plugins-official" not found: run /plugin marketplace add anthropics/claude-plugins-official and try again.
  • Plugin "claude-security" not found in marketplace "claude-plugins-official": the catalog may be out of date, so run /plugin marketplace update claude-plugins-official and try again.

If the result shows Run /reload-plugins to apply., check the official docs for how to enable the plugin without restarting. To remove it, run claude plugin uninstall claude-security.

How scanning works and how to narrow its scope

It adds one command, /claude-security, and from its menu you choose one of three options: full scan, change scan, or patch suggestions. The basic flow is as follows.

  1. Run /claude-security and choose Scan codebase.
  2. Choose either the whole repository or a specific area. If you answer "I don't know", a default that fits the project's size is selected.
  3. It asks you to confirm the run. It can use a lot of time and tokens, and you need to keep Claude Code open until it finishes. Nothing runs until you confirm.
  4. You can follow progress with /workflows, and results are written to a timestamped directory.
  5. Run /claude-security again, choose Suggest patches, and select the finding you want to address.
  6. Apply the patches you want to adopt with git apply, one per pull request.

You can also ask with an argument, such as /claude-security scan my branch. The official docs say auto mode, which doesn't ask for permission at each step, is a good fit.

Inspect only the changes

On a branch with commits that aren't in the base, you can scan only that diff. It covers committed changes only, so commit or stash your work-in-progress edits, or use the full scan that reads the working tree. A change scan requires a git repository. The only step that touches the network is finding the pull request, and it is offered only when the session has permission to run the GitHub CLI and you're signed in to gh.

Large repositories

You pick one area at a time to investigate. The report's coverage section lists what was examined and what was not.

How to read the scan results

Results are written to a timestamped directory inside the repository.

  • CLAUDE-SECURITY-RESULTS.md: the report. It includes finding IDs (such as F1), impact, exploit scenario, severity, confidence, and recommended action.
  • CLAUDE-SECURITY-RESULTS.jsonl: The same findings, one JSON object per line.
  • CLAUDE-SECURITY-RESULTS.sarif: a log in SARIF 2.1.0 format that you can use with tools such as GitHub code scanning. Findings include CWE classifications.
  • Revision stamp JSON: records details such as which commit was scanned, tying the report to the code it covers.

This directory is the only place the scan changes, and it contains its own .gitignore, so it won't be committed even if you run git add by mistake. If you want to keep it in history as an audit trail, delete that .gitignore and commit. Only findings that passed independent verification are listed. Scans are non-deterministic, and results can differ even on the same code, so run them regularly and check the stamp to confirm what was scanned.

Turn review findings into a patch and apply it

Choose Suggest patches, or ask something like "fix finding F3," and then select the corresponding finding. Patches are generated against the committed code; findings whose code has changed are skipped with a note, and a new scan is suggested. Drafting happens in a working copy, so your source doesn't change until you apply the patch.

A separate agent from the one that wrote the patch runs the tests, if any, and reviews the diff. A patch is written only when it can guarantee three things: it addresses the finding, it introduces no new vulnerability, and it changes no other behavior. When it can't guarantee them, it leaves a note explaining why.

Patches are written to the patches/ folder as F<n>.patch, one per finding, with an explanatory note. Apply them as follows.

git apply CLAUDE-SECURITY-<timestamp>/patches/F1.patch

If the code has no tests, the notes say so. Each item goes into its own pull request, and you review and test them individually.

FAQ

Can it scan uncommitted changes too?

The change scan covers committed changes only. For edits in progress, commit them, stash them, or use a full scan that reads the working tree.

Source: Scan your codebase for vulnerabilities

Are there any findings that don't come with a patch?

Yes. If a review by a separate agent cannot guarantee three things (that the finding is addressed, that no new vulnerability is introduced, and that no other behavior changes), a note explaining why is produced instead of a patch. Even when a patch is produced, it is not applied automatically.

Source: Scan your codebase for vulnerabilities

What should I do if a Python warning appears in the menu?

python3 3.9 or later must be on your PATH. If it isn't found, you get a warning that it won't work; if the first python3 is too old, you get a warning showing the version that was found. Install Python 3 or put a newer python3 first, then start a new session.
