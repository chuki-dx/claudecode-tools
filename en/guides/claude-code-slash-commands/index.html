How to use Claude Code slash commands, and the main commands for each stage of your workflow

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • According to the official docs, slash commands are a way to control Claude Code (an AI coding agent from Anthropic that runs in the terminal) from inside a session. Type / to see the commands available to you.
  • It's more practical to learn the list by workflow. For first-time setup, start with /init. While working, use /plan and /compact. Before shipping, use /diff and /code-review. When you're stuck, start with /rewind or /doctor.
  • Not every command is shown to every user. Availability varies by plan, platform, environment, and version, so check the / menu on a real machine and the official docs before you roll it out company-wide.

What slash commands can do and the input rules

The following summarizes the official docs as of writing (October 2026); it is not the result of my own testing on a real machine. According to the official docs, commands are for controlling Claude Code from within a session, and they let you quickly switch models, manage permissions, tidy up context (what the AI refers to in the conversation), run workflows, and more.

Typing / shows the available commands, and typing more characters narrows the list. Keep the following points in mind and you won't get lost.

  • A command is recognized only when it is at the start of the message, and any text after the command name is treated as its arguments.
  • Skills (commands you can write yourself) are an exception. If you chain them like /skill-a /skill-b do XYZ, Claude Code loads the skills listed at the start and passes the trailing text to each skill as an argument. You can chain up to six.
  • Commands you send while Claude is responding run after the current turn ends. However, commands such as /status, /tasks, and /usage run immediately without interrupting the response.
  • In fullscreen mode, dialog-style commands such as /theme and /help also open immediately.

Main commands by workflow (from initial setup to parallel execution)

Use first in a repository

Use /init to create a starting template for CLAUDE.md (a guide file for the project), then refine it with /memory. Use /mcp to set up the MCP servers you need and /permissions to decide approval rules. For subagents (separate agents you delegate side tasks to), ask Claude to create them.

In progress

Before a big change, enter plan mode with /plan. If you add a description, as in /plan fix the auth bug, it enters plan mode and starts that task right away. /model switches models and also saves the choice as the default for new sessions. To switch only the current session, open the picker without arguments and press s. /effort adjusts the level of reasoning. When a conversation gets long, check what is taking up space with /context, then summarize with /compact to free room. Use /btw for side questions you don't want added to the conversation history.

Work in parallel

/tasks lists the background work in the current session. /background detaches the whole session and keeps it running, freeing up your terminal. /batch splits a large change across the entire codebase into independent units and, after you approve the plan, runs each in its own worktree. It requires a git repository or a WorktreeCreate hook that creates worktrees. An example is /batch migrate src/ from JavaScript to TypeScript.

Commands for before shipping and between sessions

The official docs show a pre-ship flow: review changes with /diff, then use /code-review to look for correctness bugs in the current diff. Adding --fix applies the findings, and passing a PR number, as in /code-review high 1234, reviews that pull request. /review is an alias. /code-review ultra runs a multi-agent review in the cloud. The /ultrareview description says Pro and Max include 3 free runs, after which usage credits are required. /security-review checks the current branch's changes for vulnerabilities and requires an origin remote.

Moving between sessions

  • /clear: start new work while keeping the project's memory.
  • /resume: Returns to a previous conversation.
  • /branch: Branches the current conversation so you can try a different direction. You can return to the original conversation with /resume.
  • /fork: Copies the conversation into a new background session.
  • /teleport: Pulls a cloud session into this machine. Requires a claude.ai subscription.
  • /remote-control: lets you continue this local session from another device.

Commands for when you get stuck

/rewind rolls code and conversation back to a checkpoint, or summarizes part of the conversation. /doctor diagnoses problems with installation, settings, and CLAUDE.md, and suggests fixes. Claude applies the fixes after you confirm. /debug diagnoses runtime problems. Debug logging is off by default, so if you run it mid-session, it records only from that point on. /feedback reports a bug with session information attached. A consent screen appears before sending, and you can choose how much history to include.

Points to check before you distribute it internally

  • What you see varies by person. The official docs give examples: /desktop appears only on macOS and x64 Windows when signed in with a Claude subscription, and /upgrade does not appear on Enterprise plans. Commands you can't use don't show up in the menu.
  • Some items have version requirements. For example, /output-style requires v2.1.269 or later.
  • Some commands have been removed. /vim was removed in v2.1.92; use Editor mode in /config instead. /ultraplan has been removed; use plan mode.
  • Watch for typos. If nothing is highlighted and you press Enter, your input is sent as is and you get Unknown command.
  • Some hidden commands don't appear in the menu, such as /heapdump. Type the full name to run them. When reporting a bug, attach only -diagnostics.json. Don't share the .heapsnapshot, because it contains the entire conversation and credentials.

FAQ

Why don't some commands in the list appear on my screen?

According to the official docs, which commands are available depends on the platform, plan, and environment. Unavailable commands are removed from the menu, and if nothing matches, No commands match "/name" is shown.

Source: Commands

Can I add our own commands?

The official docs say to add your own commands as skills. Prompts exposed by MCP servers also appear as commands. See the official docs for detailed steps.

Source: Commands

How do I choose between /clear and /compact?

/clear starts a new conversation with an empty context, and you can go back to the previous one with /resume. If you want to free up space while continuing the same conversation, use /compact, which summarizes it.
