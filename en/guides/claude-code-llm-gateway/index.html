Using Claude Code through an LLM gateway: what it can do and how to roll it out

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • A gateway is a proxy an organization places between Claude Code (Anthropic's AI coding agent that runs in the terminal) and the model provider. It lets you manage authentication, usage logging, budgets, and audit logs in one place.
  • The options are the Claude apps gateway included in the claude binary, and an LLM gateway you already run. The former requires browser sign-in, so it can't authenticate in unattended environments such as CI.
  • When you use gateway credentials, you are billed at API rates on the provider account rather than through a subscription. Model selection and other traffic are configured separately from the gateway.

What a gateway is and what it can do

According to the official docs, a gateway is a proxy (a relay for network traffic) that an organization runs between Claude Code and the model provider. Claude Code sends its API traffic to the gateway, and the gateway forwards it to the provider using credentials the organization holds. Developers don't hold provider credentials; they authenticate to the gateway.

You can consolidate authentication, usage tracking, budgets, and audit logs in one place managed by your organization. There are two types of credentials.

  • Developer credentials: issued per developer by the gateway and used for authentication and for identifying usage
  • Provider credentials: the gateway holds one set for the provider account, shared across all the traffic it forwards

The destination is determined by the gateway configuration. Besides Anthropic's API, you can choose Amazon Bedrock, Google Cloud's Agent Platform, or Microsoft Foundry. With a gateway that exposes a single Anthropic-format endpoint, you can switch providers without touching developers' machines.

Source: Run Claude Code through a gateway

When using the Claude apps gateway provided by Anthropic

The Claude apps gateway is Anthropic's self-hosted gateway, included in the claude binary. Upstream you can specify Amazon Bedrock, Claude Platform on AWS, Google Cloud, Microsoft Foundry, or the Anthropic API. Developers sign in to your company's IdP (identity provider) with /login, and model access and managed settings (settings distributed by administrators) are applied per IdP group. Usage is exported as OTLP-format metrics to your own monitoring platform.

It is built and tested together with each Claude Code release, so you don't need to keep updating forwarding rules the way you would with a separately managed gateway. A few features behave differently in sessions through a gateway, so check the limitations in the official docs.

Note: Sign-in uses browser-based SSO, and there is no service token option. CI has no developer to approve the sign-in, so it can't authenticate this way; configure CI directly against the provider. Also, claude -p and Agent SDK sessions on a machine where a developer is signed in use that machine's gateway session and are subject to its policy.

Source: Run Claude Code through a gateway

If you already run an LLM gateway

As of writing (October 2026), the official docs say you can use a gateway you already run, as long as it exposes a supported API format. However, Anthropic does not recommend, maintain, or audit third-party products, and does not support routing to non-Claude models through any gateway.

What you can manage is credentials, usage (by developer and team), budgets and rate limits, audit logs, and provider switching. Provider switching is available only if the upstream exposes a single Anthropic-format endpoint, regardless of what the upstream is.

The trade-off is that the gateway becomes infrastructure your organization has to operate. Claude Code gains features with each release, and if the gateway doesn't forward them, those features stop working, so the gateway needs to be updated to keep up with the product.

How to proceed with rollout

According to the official docs, the steps are the same in this order for any gateway product.

  1. Deploy the gateway and pass it the provider credentials.
  2. Issue gateway credentials to each developer. Usage is tied to the individual developer, and when someone leaves you only need to revoke that one credential.
  3. Use a managed settings file and your secrets management system to distribute the base URL and credentials to every machine. If you distribute both, developers don't have to configure anything.
  4. Each developer checks in Claude Code that the settings have arrived, so you catch distribution problems early.

To make the gateway the only destination on managed devices, set allowedProviders to ["customEndpoint"] in the same managed settings file, and put the gateway's ANTHROPIC_BASE_URL in the env block. Sessions aimed at a direct connection to Anthropic or at a developer's personal proxy are rejected. Claude Code v2.1.285 or later is required.

Source: Other LLM gateways

What to watch for with billing and settings outside the gateway

Subscriptions and billing

When you connect with gateway credentials, usage is billed at API rates to your organization's provider account, and the developer's claude.ai subscription is not used. If you set ANTHROPIC_AUTH_TOKEN on your own gateway, or sign in to the Claude apps gateway with /login, the subscription login is disabled for that session. The exception is when you set only ANTHROPIC_BASE_URL: traffic goes through the gateway, but the saved claude.ai login stays active, so subscription limits and billing apply. Check the official pricing page for current amounts.

What to configure separately from the gateway

  • Choosing a model: You choose with the /model command or the model environment variables. The gateway only decides the destination. The Claude apps gateway can narrow the choices per group with availableModels, but the developer still picks from within that list.
  • Other traffic: Version checks and downloads go directly to Anthropic. Either allow outbound traffic to the required domains, or stop optional traffic with CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC.
  • Client telemetry: in sessions signed in to the Claude apps gateway, client analytics to Anthropic are disabled. To also stop startup analytics before sign-in, distribute DISABLE_TELEMETRY through client-side managed settings on each device. Other gateways vary by provider, so check the table of defaults in the official docs
  • Corporate HTTP proxy: HTTPS_PROXY sits in front of all traffic, including traffic to the gateway, so set up the proxy separately from the gateway if you need one. With a self-hosted Claude apps gateway, sign-in also checks whether the proxy host is on the private network; if it isn't, add the gateway host to NO_PROXY

FAQ

When going through a gateway, does it use my claude.ai subscription allowance?

If you use gateway credentials, the subscription isn't used and the provider account is billed at API rates. If you set only ANTHROPIC_BASE_URL, your saved claude.ai login stays active, and the subscription's limits and billing apply.

Source: Run Claude Code through a gateway

Can I use it from CI through the Claude apps gateway?

According to the official docs, sign-in uses browser SSO and there is no service token method, so CI with no developer present to approve cannot authenticate. Configure CI directly with the provider.

Source: Run Claude Code through a gateway

Can I route requests to non-Claude models through a gateway?

The official docs state that Anthropic does not support routing to non-Claude models through any gateway.
