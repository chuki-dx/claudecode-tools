How to choose and switch models in Claude Code (/model and settings)

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • Specify the model with an alias such as sonnet, opus, or haiku, or with a model name. In the official docs, sonnet is positioned for everyday coding, opus for complex reasoning, and haiku for simple tasks.
  • To switch models, use /model during a session, --model at startup, or the model field in the settings file for a permanent choice. If you pick a model with Enter in /model, it is saved as the default.
  • Before rolling it out company-wide, confirm that the alias gets updated, that Fable may be billed against usage credits, and that managed settings take precedence.

Models and aliases you can specify in Claude Code

In Claude Code (Anthropic's AI coding agent that runs in the terminal), the model setting accepts a model alias (a short name you can use without remembering version numbers) or a model name. According to the official docs as of writing (October 2026), the model name format differs by provider.

  • Anthropic API: full model names
  • Amazon Bedrock: the ARN of the inference profile
  • Microsoft Foundry: deployment name
  • Google Cloud Agent Platform: version names

Note that ANTHROPIC_BASE_URL changes where requests are sent, not which model answers. To see which models suit which kinds of work, check the blog posts the official docs point to.

Source: Model configuration

How to choose an alias by use case

  • sonnet: the latest Sonnet, for everyday coding
  • opus: the latest Opus, for complex reasoning
  • haiku: A fast, efficient model for simple tasks
  • opusplan: a special mode that uses opus in plan mode and sonnet for execution
  • sonnet[1m], opus[1m]: a 1 million token context window, for long sessions. It has no effect if the model already has a 1M window by default
  • fable: For the hardest, longest-running tasks. best is Fable if you can use it, and otherwise the same model as opus
  • default: A special value that clears the override and returns to the account default. It is not an alias itself

What it resolves to depends on the provider

opus, sonnet, and haiku resolve to the latest versions on the Anthropic API, but may resolve to earlier versions on other providers. For example, on Amazon Bedrock they are Opus 5.5, Sonnet 4.5, and Haiku 4.5, and on Microsoft Foundry they are Opus 4.6, Sonnet 4.5, and Haiku 4.5.

Aliases are updated over time. To pin a model, use the full model name such as claude-opus-5-5, or an environment variable such as ANTHROPIC_DEFAULT_OPUS_MODEL. Newer models also have a Claude Code version requirement. For example, Sonnet 5.5 requires v2.1.284 or later. If your version is older, update it with claude update.

How to switch models with /model, --model, and the settings file

The official docs list the following methods in order of priority.

  1. During a session: switch immediately with /model <alias|name>, or run /model with no argument to open the picker (selection screen)
  2. At startup: claude --model <alias|name>
  3. Environment variable: ANTHROPIC_MODEL=<alias|name>
  4. Set it permanently with the model field in a settings file
  5. Default for new sessions: ANTHROPIC_DEFAULT_MODEL=<alias|name> (Claude Code v2.1.236 or later)
claude --model opus
/model sonnet
{
    "permissions": {
        "allow": ["Bash(npm run lint)"]
    },
    "model": "opus"
}

In the picker, Enter switches and saves the model as your default, and s switches for this session only. Typing /model <name> directly behaves like Enter and saves it as the default. --model and ANTHROPIC_MODEL affect only the session they start, so if you use different models in multiple terminals, start each one with --model.

What to check when it doesn't start with the model you expected

You can check the current model in the status line (if you've configured one) or with /status. The official docs list the following as the main reasons the next new session starts with a different model.

  • The choice applied to this session only (s, --model, /model in non-interactive mode)
  • A higher-priority setting exists (model in the project or managed settings, ANTHROPIC_MODEL in the shell, or an organization default where an admin has enabled overrides)
  • Could not write to ~/.claude/settings.json, so it was not saved
  • You resumed a session (claude --resume or --continue normally keeps the model from that session)

Switching with /model also applies to subagents that inherit the main conversation's model.

Notes when using Fable

According to the official docs, Claude Fable 5.1 and Claude Fable 5 are the most capable models in Claude Code, intended for large tasks that can't be finished in one pass. They are not the default for any account type on any plan or provider, so you must select them explicitly. You can select Fable 5.1 with /model fable or claude --model fable (in Claude apps gateway sessions the alias resolves to Fable 5, so use /model claude-fable-5-1 instead). Requires Claude Code v2.1.257 or later.

Depending on your plan and seat type, Fable usage may be billed to usage credits rather than to the limits included in your plan. In that case, the Fable row in the picker shows "Requires usage credits." In interactive sessions, a consent prompt appears before billing (except for members of organization-billed Enterprise plans), but in non-interactive mode with -p, you are billed without confirmation. If you use it for automated runs, check the official docs first.

When admins set restrictions or defaults

According to the official docs, availableModels in managed settings lets you restrict which models users can choose. On the Anthropic API and Claude Platform on AWS, if a family alias points to a model outside the allowlist, it is replaced by the latest version of that family that the list allows. Any other model outside the allowlist produces an error in /model, and a value given with --model or similar is replaced at startup, so the session starts with the default model.

{
  "availableModels": ["sonnet", "haiku"]
}

With the default prefix matching, using only availableModels can leave Default as a model outside the allowlist. In that case, use enforceAvailableModels together with it (v2.1.175 and later). Also, the model setting is the initial selection, not an enforced one, and users can choose Default with /model.

On the Enterprise plan, admins can set the organization's default model in the admin console and can also disable individual models. Haiku, however, cannot be disabled. The organization default takes precedence over model in user, project, and local settings only when the override is enabled.

FAQ

Is the model I pick with /model used the next time I start Claude Code?

Pressing Enter in the picker or typing /model <name> directly saves it as your default. If you choose with s or launch with --model, it applies to that session only. Higher-priority settings such as project settings, managed settings, or ANTHROPIC_MODEL override your saved choice.

Source: Model configuration

How do I use different models in multiple terminals at the same time?

The official docs advise launching each terminal with its own --model flag rather than switching with /model. --model applies only to the session you launch.

Source: Model configuration

How do I pin the model version?

An alias points to the recommended version and is updated over time. To pin a version, use a full model name such as claude-opus-5-5, or set the corresponding environment variable such as ANTHROPIC_DEFAULT_OPUS_MODEL.
