Scheduled runs in Claude Code: the differences between /loop and desktop scheduled tasks, and when to use each

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, Claude Code (Anthropic's AI coding agent that runs in the terminal) offers three kinds of scheduled runs: cloud, desktop, and /loop. As a rule of thumb, use cloud to run without your machine, desktop when you need local files, and /loop for quick checks during a session.
  • /loop works only while the session is open. A fixed-interval loop does not stop with Esc or Ctrl+C; you ask Claude to cancel it.
  • Desktop scheduled tasks run only while the app is open and the PC is awake. To keep them from stalling on permission prompts, test them with Run now after you create them.

How the three scheduling methods differ

This article is based on the official docs as of writing (October 2026). According to the official docs, there are three ways to schedule recurring or one-time tasks.

  • Cloud: By default it runs in a cloud managed by Anthropic, so your machine doesn't need to be on and no session needs to be open. Local files are not available (it uses a fresh clone), and the minimum interval is one hour.
  • Desktop: runs on your own machine. The machine must be powered on, but no active session is needed. It can use local files. The minimum interval is 1 minute when Claude sets it up, and 1 hour when you use the form.
  • /loop: runs on your own machine and needs both power and an open session. The minimum interval is 1 minute, and permission prompts and MCP servers are inherited from the session.

As a rule of thumb, use cloud for work that must run reliably without your machine, desktop for work that needs local files or tools, and /loop for quick checks during a session.

/loop basics: specifying the interval and prompt

/loop is a bundled skill (a feature that ships with Claude Code) and is the quickest way to repeat the same prompt while keeping a session open. You can omit either the interval or the prompt, and what you specify changes the behavior.

  • /loop 5m check the deploy: specify an interval and a prompt. It runs on a fixed schedule.
  • /loop check the deploy: prompt only. Claude picks the interval on each iteration.
  • /loop: With only an interval, or with nothing specified, the built-in maintenance prompt runs, or loop.md if you have one.

Run at a fixed interval

When you specify an interval, Claude converts it to a cron expression (a format for specifying recurring schedules), registers it, and tells you the interval and the job ID.

/loop 5m check if the deployment finished and tell me what happened

Put the interval at the start, like 30m, or append it at the end, like every 2 hours. The units are s, m, h, and d. Seconds are rounded up to 1 minute, and intervals that don't divide evenly, such as 7m or 90m, are rounded to a nearby value, and Claude tells you which value it chose.

Let Claude choose the interval

If you omit the interval, Claude picks a wait time between 1 minute and 1 hour for each iteration and shows it along with the reason.

/loop check whether CI passed and address any review comments

You can also pass a skill (for example, /loop 20m /review-pr 1234). However, only skills that Claude can invoke on its own are run. Built-in commands such as /model, skills with disable-model-invocation: true, and MCP prompts are not run and are passed along as text.

Changing the default behavior with loop.md, and how to stop it

The default for /loop with no arguments is a maintenance prompt. It proceeds in this order: continuing unfinished work, handling the current branch's PR (review comments, failing CI, merge conflicts), and then cleanup if nothing is pending. Irreversible actions such as pushing or deleting proceed only when they continue work already authorized in the conversation.

To replace the built-in prompt with your own instructions, create a loop.md. .claude/loop.md (per project) takes precedence over ~/.claude/loop.md (per user), and if neither exists, it falls back to the built-in prompt. It is a single default prompt, not a list of multiple tasks, and it is ignored if you give a prompt on the command line.

  • Loops with the interval omitted: you can stop them with Esc while waiting for the next iteration.
  • Fixed-interval loops: Esc and Ctrl+C don't stop them; ask Claude to cancel instead. If you don't cancel, they end after 7 days.

/loop limitation: it depends on the session

The official docs list constraints on session-scoped schedules.

  • It fires only while Claude Code is running and idle. If you close the terminal, it stops.
  • Missed runs are not made up. It runs just once when it returns to the idle state.
  • When you resume with claude --resume, tasks scheduled with CronCreate are restored (except things like expired recurring tasks). A /loop without an interval is not restored, so run it again.

For unattended runs, the docs list cloud scheduled tasks, the GitHub Actions schedule trigger, and desktop scheduled tasks.

How to create desktop scheduled tasks, and what to watch for

According to the official docs, local scheduled tasks require Claude Desktop 1.1.5368 or later. In the Code tab, open New task from Scheduled, and if a menu appears, choose Set up manually.

  1. Enter a name in Name. It is converted to lowercase kebab-case and becomes the folder name on disk, so don't reuse the same name across tasks.
  2. Write what to run in the instructions field.
  3. In the General tab of Advanced settings, turn on Only on this computer. If the switch is unavailable, remove the repository, GitHub event, or API triggers. Having any of these makes it a cloud scheduled task.
  4. Choose a folder under Local folder. Create can't be clicked until you pick one.
  5. Choose a schedule preset under Trigger, pick a permission mode and model, then click Create.

If the top of the dialog shows Only on this computer, turn it on before you enter anything.

While the app is open, Desktop checks the schedule every minute and starts due tasks in a new session. Tasks run only while the app is running and the PC is awake; if the scheduled time passes during sleep, that run is skipped. Keep computer awake under Settings > This computer > System prevents idle sleep, but closing a laptop lid still puts it to sleep.

Permissions are set per task. In Manual mode, if a task needs a tool it doesn't have permission for, the run pauses until you approve it. To avoid pauses, click Run now after creating the task and choose "always allow" at the permission prompt. Later runs then auto-approve the same tool, and you can revoke this on the details page. MCP tools with requiresUserInteraction prompt every time and pause each run.

FAQ

Which scheduled run keeps working even after you close your PC?

According to the official docs, only cloud scheduled tasks don't require your machine to be powered on. Desktop tasks and /loop require the machine to be running.

Source: Run prompts on a schedule

How do I stop a fixed-interval /loop?

Ask Claude to cancel it, for example "cancel the deploy check loop". Esc and Ctrl+C don't stop it. If you don't cancel it, it ends after 7 days.

Source: Run prompts on a schedule

Why do scheduled tasks on the desktop stop partway through?

In Manual mode, if a tool without permission is needed, the run stops until you approve it. Open that run's session from the history and approve it, or choose "always allow" with Run now after creating it.
