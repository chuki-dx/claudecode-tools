Getting started with Claude Code skills (SKILL.md): teach Claude your work procedures

Published: October 14, 2026 ・ Chuki DX Lab ・ Content is based on the official docs as of writing (October 2026)

Key takeaways

  • A skill gives a name to a work procedure and an output format so that Claude Code can invoke it. Place it at .claude/skills/<skill name>/SKILL.md.
  • Whether a skill is used automatically depends mostly on the wording of the description at the top. Include the words your users normally use.
  • Before you distribute it, check its structure with claude plugin validate .claude/skills and try it once with fictional data.

What are skills?

A skill in Claude Code (Anthropic's AI coding agent that runs in the terminal) is a file that holds a playbook: "do this task in these steps and output it in this form." It suits work where you write the same instructions every time, such as summarizing meeting minutes, drafting procedure documents, or drafting replies to inquiries.

The difference from CLAUDE.md (instructions loaded every time Claude Code starts) is when it gets loaded. According to the official docs, in a normal session only the skill's description (description) is loaded, and the body is loaded only when the skill is invoked. So if you split detailed per-task procedures into skills, you can keep CLAUDE.md short while still writing the procedures in detail.

Skills are used in two ways. Claude uses one on its own when your request matches its description, and you can also invoke it directly by typing /skill-name. Note that the earlier "custom commands" (files in .claude/commands/) have been merged into skills, and existing files are said to keep working as they are.

Where to put it

TypeWhere to put itWhat you can use
Project.claude/skills/<skill-name>/SKILL.mdSessions for that folder (repository). Share via Git to give the whole team access
Individual~/.claude/skills/<skill-name>/SKILL.mdAll of your own projects on that PC
Organization.claude/skills/ in the managed settings folderEveryone who uses a PC the organization distributed

When skills with the same name exist in multiple places, precedence goes organization, then personal, then project. For a company-wide rollout, an easy way to start is to put them in the project's .claude/skills/ and share them through Git.

The structure of SKILL.md

SKILL.md has two parts. The section enclosed in --- at the top (the frontmatter) holds the name and description, and below it you write the steps Claude follows in Markdown. Here is an example of the format (I did not test this example itself on a real machine).

---
name: notice-draft
description: 社内向けのお知らせ文の下書きを作る。お知らせ、周知文、社内通知の文面を頼まれたときに使う。
---

# 社内お知らせの下書き

## 進め方
1. 依頼から「誰に・何を・いつまでに」を読み取る
2. 読み取れない項目は推測で埋めず、最後に確認事項として挙げる

## 出力の形
- 件名(30字以内)
- 本文(結論を最初に書く。です・ます調)
- 確認事項(読み取れなかった項目の一覧)

According to the official docs, all frontmatter fields are optional, and only description is recommended. If you omit name, the folder name becomes the invocation name.

How to write the description

description is what Claude uses to decide whether to use the skill. Write both what it does and when to use it, in the words users would actually use when asking. Listing alternative phrasings, like "announcement, notice, internal notification" in the example, makes matching easier.

According to the official docs, when a skill appears in the skill list, description and when_to_use are combined and truncated at 1,536 characters. Put the most important use cases first.

How to write the body

  • Steps: Write the order of work as a numbered list.
  • Output format: If you define headings and items in advance, everyone gets the same format no matter who makes the request.
  • Drawing the line: Write down points where the model is likely to hesitate, such as "don't fill gaps with guesses" and "put undecided items on hold."

The official docs recommend keeping SKILL.md under 500 lines and moving detailed reference material into separate files.

Points to watch

  • allowed-tools: An item that lets a skill use tools without asking for confirmation while it runs. The official docs state that it takes effect regardless of the folder trust check. For skills you distribute within the company, it is safer to leave it out unless you need it.
  • Reserved names: synced and anthropic-skills are reserved in the official docs and can't be used as skill names.
  • When you want manual use only: add disable-model-invocation: true, and Claude will no longer use the skill on its own; it will be used only when you call it with /skill-name.

How to verify before you distribute

  1. In the folder where you placed the skills, run claude plugin validate .claude/skills to check for structural errors.
  2. Ask Claude Code to "list the names of the skills you can use," and check whether the skill appears in the list.
  3. Ask once with fictional data and check that the output matches the expected format. Do not use real data.

In my testing at Chuki DX Lab with Windows 11 and Claude Code 2.1.296 (October 2026), frontmatter with just the two fields name and description passed validate and also appeared in the list.

FAQ

My skill doesn't appear in the list

Check the location of .claude/skills/<name>/SKILL.md and that the first line starts with ---, then run claude plugin validate .claude/skills.

Skills aren't being used automatically

Sometimes the words in description don't match the words used in the request. Add phrasing your users commonly use, or call the skill directly with /skill-name.

Skills placed in a subfolder aren't found

According to the official docs, .claude/skills/ in folders below the one where you launched Claude aren't loaded at startup; they load when Claude works with files in that folder. Put frequently used skills in .claude/skills/ in the folder where you launch Claude.
