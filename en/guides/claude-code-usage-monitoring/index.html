How to see Claude Code usage: when to use analytics and when to use OpenTelemetry

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • According to the official docs, you can track usage of Claude Code (Anthropic's AI coding agent that runs in the terminal) with the per-plan analytics dashboards and OpenTelemetry export.
  • The dashboard is suited to checking the number of users, the number of sessions, and accepted lines. For per-user token counts and cost estimates, use an OpenTelemetry export or the spend report.
  • To roll this out to everyone, put the environment variables in managed settings. A settings file inside a repository cannot decide where OpenTelemetry data is sent.

Choose a dashboard by the numbers you want to see

According to the official docs, Claude Code has an analytics dashboard for teams where you can see developers' usage trends and contribution metrics. The dashboards are separated by plan.

  • Claude for Teams / Enterprise: includes usage metrics, contribution metrics via GitHub integration, a leaderboard, and data export.
  • API (Claude Console): includes usage metrics, spend tracking, and team insights.

If you need per-user token counts or cost estimates, set up OpenTelemetry export or export a spend report from the organization's analytics settings. The spend report lists token usage by user and by model, along with estimated spend in credits used.

This article is based on the official docs as of writing (October 2026). Screen names and conditions may change, so check the official docs before you deploy.

Teams / Enterprise dashboard and contribution metrics settings

Only Admins and Owners can view it. Usage metrics (accepted lines, suggestion acceptance rate, daily active users, and session counts) are available on all Teams / Enterprise accounts.

On the other hand, the contribution metrics that track PRs and lines of code are in public beta and require additional setup to connect a GitHub organization. The Owner role is required for setup, and a GitHub admin installs the GitHub app.

Steps to enable it

  1. A GitHub admin installs the Claude GitHub app on the organization's GitHub account.
  2. A Claude Owner turns on the Claude Code analytics feature on the Claude Code page in the admin settings.
  3. On the same page, turn on the "GitHub analytics" toggle.
  4. Complete the GitHub authentication flow and choose the GitHub organizations to include in the analysis.

Data usually appears within 24 hours of enabling and is updated daily.

When contribution metrics don't appear

  • This applies only to users within a claude.ai organization. It does not include usage of the Claude Console API or third-party integrations.
  • In organizations with Zero Data Retention enabled, contribution metrics aren't available, and only usage metrics are shown.
  • This applies to repositories on github.com. For repositories on GitHub Enterprise Server, only usage metrics are available.

How to read the numbers and notes on attribution rules

The official docs explain that contribution metrics are intentionally conservative and are an estimate that undercounts actual impact. Only lines and PRs where Claude Code's involvement is highly certain are counted.

  • Attribution is determined by matching the added lines in merged PRs against Claude Code session activity.
  • Sessions from 21 days before the PR merge date to 2 days after are included; sessions outside that window are not counted.
  • Code that a developer has substantially rewritten (a difference of more than 20%) is not attributed to Claude Code.
  • Lock files, generated code, build directories, test fixtures, and lines longer than 1,000 characters are treated as auto-generated and excluded.
  • Merged PRs that include lines assisted by Claude Code get the claude-code-assisted label on GitHub.

On the Enterprise plan, you can retrieve per-user reports with the Claude Enterprise Analytics API. The Primary Owner creates a key with the read:analytics scope. It isn't available on the Teams plan.

For the API (Claude Console), viewing the dashboard requires the UsageView permission, which is granted to the Developer, Billing, Admin, Owner, and Primary Owner roles. GitHub-integrated contribution metrics are not available at this time. Spend figures are estimates for analysis, so check the billing page for actual costs.

Basic settings for exporting with OpenTelemetry

According to the official docs, OpenTelemetry is configured with environment variables. The following is the quickstart example; you only need to configure the exporters (transmission methods) you actually use.

# 1. Enable telemetry
export CLAUDE_CODE_ENABLE_TELEMETRY=1

# 2. Choose exporters (both are optional - configure only what you need)
export OTEL_METRICS_EXPORTER=otlp       # Options: otlp, prometheus, console, none
export OTEL_LOGS_EXPORTER=otlp          # Options: otlp, console, none

# 3. Configure OTLP endpoint (for OTLP exporter)
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317

# 4. Set authentication (if required)
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer your-token"

# 5. For debugging: reduce export intervals, and reset them for production use
export OTEL_METRIC_EXPORT_INTERVAL=10000  # 10 seconds (default: 60000ms)
export OTEL_LOGS_EXPORT_INTERVAL=5000     # 5 seconds (default: 5000ms)

# 6. Run Claude Code
claude

The docs say to restore the export interval you shortened for debugging to its original value in production.

To verify: if you export metrics, look at your destination for claude_code.session.count, which is emitted when a session starts. If you only log, send a prompt and look for a claude_code.user_prompt event.

If the data does not arrive, start Claude Code with a debug file specified and check the output log. Failures of the exporter you configured appear as [3P telemetry] errors. Lines starting with [Anthropic telemetry] are separate operational telemetry on Anthropic's side and do not indicate a configuration problem.

Cautions when rolling out admin settings to everyone

Administrators can distribute OpenTelemetry settings to all users through the managed settings file. The configuration example from the official docs is below.

{
  "env": {
    "CLAUDE_CODE_ENABLE_TELEMETRY": "1",
    "OTEL_METRICS_EXPORTER": "otlp",
    "OTEL_LOGS_EXPORTER": "otlp",
    "OTEL_EXPORTER_OTLP_PROTOCOL": "grpc",
    "OTEL_EXPORTER_OTLP_ENDPOINT": "http://collector.example.com:4317",
    "OTEL_EXPORTER_OTLP_HEADERS": "Authorization=Bearer example-token"
  }
}

Keep the following points in mind.

  • Claude Code ignores OpenTelemetry exporter variables in the repository's .claude/settings.json and .claude/settings.local.json. You can't enable telemetry or set its destination from a repository; set it in managed settings, or in each developer's shell or ~/.claude/settings.json.
  • OTEL_* environment variables are not passed to subprocesses that Claude Code launches, such as the Bash tool, hooks, MCP servers, and language servers.
  • If you set OTEL_EXPORTER_OTLP_ENDPOINT in managed settings, signal-specific endpoints set by developers are removed at startup, and a warning appears in the debug log.
  • OTEL_METRICS_EXPORTER and OTEL_LOGS_EXPORTER follow the normal precedence, so developers can disable a signal or switch it to console output. If you want to pin them, also write them in managed settings. This item requires Claude Code v2.1.223 or later.

Note that this removal only changes where data is sent; it does not change what Claude Code collects. The OpenTelemetry form for Cowork, found under Monitoring in Data and privacy settings in the admin console, applies only to Cowork sessions and is not a destination for the terminal CLI or the Code tab.

FAQ

Can I view usage without the GitHub integration?

Usage metrics and adoption data are available on all Claude for Teams / Enterprise accounts. Contribution metrics such as PRs and lines of code require connecting a GitHub organization, and they are not available for organizations with Zero Data Retention enabled.

Source: Track team usage with analytics

How do I check that my OpenTelemetry settings are taking effect?

To export metrics, check claude_code.session.count. For logs only, send a prompt and check for the claude_code.user_prompt event. If nothing arrives, start with a debug file specified and look for [3P telemetry] errors.

Source: Monitoring

Can I distribute OpenTelemetry settings by putting them in a repository's settings file?

You can't roll them out that way. According to the official docs, exporter variables in the repository's .claude/settings.json and .claude/settings.local.json are ignored. Use managed settings, or each developer's shell or ~/.claude/settings.json.
