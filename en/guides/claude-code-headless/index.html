How to Run Claude Code from a Script with claude -p (Headless Mode)

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • Claude Code (an AI coding agent from Anthropic that runs in the terminal) can run non-interactively when you add -p (or --print) to the claude command, so you can call it from scripts.
  • In CI and scripts, adding --bare skips loading the host's hooks and CLAUDE.md, which makes results more consistent across machines. Note that it assumes authentication with an API key or similar rather than a subscription login.
  • For unattended runs, decide in advance which operations are allowed by using --allowedTools or --permission-mode. Be careful not to make the permission scope too broad.

What you can do with claude -p

According to the official docs, adding -p (or --print) to the claude command runs it non-interactively. Not every CLI option can be combined with -p; for example, --bg is rejected with an error. Commonly combined options are --continue to continue a conversation, --allowedTools to auto-approve tools, and --output-format for structured output.

claude -p "What does the auth module do?"

The exit code is 0 on success and nonzero when the run fails, so scripts can branch on the exit status. An invalid flag writes an error to stderr, but failures during a run, such as missing authentication, are written to stdout as the result. Keep both in mind when you build monitoring.

--bare and authentication for CI

With --bare, Claude Code skips auto-discovery of hooks, skills, custom commands, subagents, plugins, MCP servers, auto memory, and CLAUDE.md, so it starts faster. Without it, claude -p loads the working directory and even the settings in ~/.claude, just like an interactive session.

In bare mode, hooks in a colleague's ~/.claude and MCP servers in a project's .mcp.json are not loaded and do not run. The official docs recommend --bare for scripts and SDK calls, and say it is planned to become the default for -p in a future release.

claude --bare -p "Summarize README.md" --allowedTools "Read"

Bare mode does not use a subscription login, so you need to set ANTHROPIC_API_KEY before running it. It also does not read OAuth credentials or the system keychain.

Caution: -p without --bare runs the hooks in the project's .claude/settings.json and connects to the servers in .mcp.json, even in a folder you have never trusted. Neither the workspace trust dialog nor the per-server approval prompt appears. When working with external repositories, check the official docs to see what runs.

Piping input and output formats

Non-interactive mode reads standard input, so you can pipe in a log and write the result to a file.

cat build-error.txt | claude -p 'concisely explain the root cause of this build error' > output.txt

Input passed through a pipe is limited to 10MB. Beyond that, it exits with an error and a non-zero status. For large input, the docs suggest writing it to a file and pointing to the path in the prompt.

--output-format accepts text (the default) for plain text, json for the result plus session ID and metadata, and stream-json for real-time output. With json, the text result goes in the result field, so you can extract it with jq.

# Extract the text result
claude -p "Summarize this project" --output-format json | jq -r '.result'

If you pass a JSON Schema with --output-format json and --json-schema, the structured result goes into the structured_output field. The format keyword is treated as an annotation and is not enforced. Also, json output includes total_cost_usd, but it is a client-side estimate and may differ from your actual bill.

Permission settings for unattended runs

Tools listed in --allowedTools are used without confirmation (though listing Read excludes reads from network paths). However, in runs that start in auto mode, a bare Bash is dropped as an overly broad allow rule, and auto mode evaluates each command.

claude -p "Run the test suite and fix any failures" \
  --allowedTools "Bash,Read,Edit"

If you do not specify a permission mode, Claude Code uses the built-in starting mode, which may be auto. Specify the mode you intend explicitly.

  • auto: With --permission-mode auto, a classifier reviews most actions.
  • dontAsk: denies calls that would normally prompt. It suits locked-down CI. However, operations that need no approval, and operations allowed through --allowedTools or similar, still run.
  • acceptEdits: Writes files without confirmation and automatically approves commands such as mkdir, touch, mv, and cp. Other shell commands and network requests need explicit allow rules.

Use --permission-prompts none for cases like scheduled jobs where no one is available to approve. Actions that would prompt are denied unless a PermissionRequest hook allows them, and the run continues. This flag requires Claude Code v2.1.259 or later; earlier versions produce an unknown-option error.

Continuing a conversation and what to watch for when it stops

--continue continues the most recent conversation. When you work with multiple conversations, note the session ID and pass it to --resume. On the same machine, you can find a session by ID even from a different directory.

session_id=$(claude -p "Start a review" --output-format json | jq -r '.session_id')
claude -p "Continue that review" --resume "$session_id"

If you stop it with SIGTERM, the exit code is 143, and the turn in progress is left unfinished with no result recorded. If you want the turn to finish, send SIGINT before stopping, or call interrupt() in the Agent SDK.

Unless a background command started by the main conversation is running, by default it stops anything still running after 10 consecutive minutes of waiting and discards partial results. You can change the limit with CLAUDE_CODE_PRINT_BG_WAIT_CEILING_MS. Also, the official docs as of writing (October 2026) list the Claude Code version each feature requires. Check your local version before you roll it out company-wide.

FAQ

Can I use subscription login even when I add --bare?

According to the official docs, bare mode does not read OAuth credentials or the system keychain, and it does not use a subscription login. For the Anthropic API, set ANTHROPIC_API_KEY.

Source: Run Claude Code programmatically

Can I pipe in a large log file?

Standard input passed through a pipe is limited to 10MB. If you exceed that, it exits with an error and a non-zero status, so the docs suggest writing the content to a file and pointing to its path in the prompt.

Source: Run Claude Code programmatically

How to keep unattended runs from stopping to wait for permission prompts.

Specify the tools to use with --allowedTools, or choose a permission mode such as dontAsk. If there is no one to approve prompts, you can use --permission-prompts none. This flag requires v2.1.259 or later.
