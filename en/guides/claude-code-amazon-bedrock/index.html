Setting up Claude Code with Amazon Bedrock: sign-in, IAM, and troubleshooting

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, the prerequisites are an AWS account with Amazon Bedrock enabled, access to Claude models, and appropriate IAM permissions.
  • To start with your own credentials, you can launch claude, choose 3rd-party platform and then Amazon Bedrock, and follow the wizard.
  • If you're rolling this out to a team, do the manual setup and pin the model versions first, then cover the caveats around IAM, regions, and proxies.

Prerequisites to check first

Claude Code (an AI coding agent from Anthropic that runs in the terminal) can also be used through Amazon Bedrock (an AWS service). According to the official docs, you need to prepare the following in advance.

  • An AWS account with access to Amazon Bedrock enabled
  • Access to the Claude model you want to use on Amazon Bedrock (e.g., Claude Sonnet 4.6)
  • Installing and configuring the AWS CLI (optional; needed only if you have no other way to get credentials)
  • Appropriate IAM (AWS's permission management system) permissions

If you sign in with your own Bedrock credentials, use the wizard in the next section. For a team rollout, the official docs say to follow the manual setup steps and pin the model versions before rolling out. This article does not cover the manual setup in detail, so check the official docs. Note that, as of writing (October 2026), the only source for this is the official docs.

Source: Claude Code on Amazon Bedrock

Sign in to Bedrock with the wizard

The official docs say that if you have AWS credentials, you can configure it through the login wizard. The AWS-side preparation is done once per account, and the wizard handles the Claude Code side.

  1. In the Amazon Bedrock console, select an Anthropic model in the Model catalog and submit the use case form. Access is granted immediately after you submit. If you use AWS Organizations, check the relevant section of the official docs.
  2. Run claude, then on the login screen choose 3rd-party platform, then Amazon Bedrock. If you are already signed in and see the chat screen, run /setup-bedrock. This command does not appear in the command menu until CLAUDE_CODE_USE_BEDROCK=1 is set, so type the full command.
  3. In the wizard, you choose how to authenticate to AWS: an AWS profile detected from ~/.aws, an Amazon Bedrock API key, an access key and secret, or credentials already in your environment. Then you enter a region, and the wizard checks which Claude models your account can call and lets you pin one.

The results are saved in the env block of your user settings file, so you do not need to export the environment variables yourself. Even after signing in, you can change credentials, the Region, and model pinning with /setup-bedrock. It writes to ~/.claude/settings.json, or to $CLAUDE_CONFIG_DIR/settings.json if you have set CLAUDE_CONFIG_DIR.

Configuring IAM policies

The official docs say to create an IAM policy with the following permissions for Claude Code.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowModelAndInferenceProfileAccess",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream",
        "bedrock:ListInferenceProfiles",
        "bedrock:GetInferenceProfile"
      ],
      "Resource": [
        "arn:aws:bedrock:*:*:inference-profile/*",
        "arn:aws:bedrock:*:*:application-inference-profile/*",
        "arn:aws:bedrock:*:*:foundation-model/*"
      ]
    },
    {
      "Sid": "AllowMarketplaceSubscription",
      "Effect": "Allow",
      "Action": [
        "aws-marketplace:ViewSubscriptions",
        "aws-marketplace:Subscribe"
      ],
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "aws:CalledViaLast": "bedrock.amazonaws.com"
        }
      }
    }
  ]
}
  • To restrict access more tightly, you can limit Resource to the ARN of a specific inference profile.
  • bedrock:GetInferenceProfile is used to identify the underlying model from an application inference profile ARN. If the token lacks this permission, Claude Code retries automatically and still works, but each new model costs one extra round trip. Granting the permission avoids the retry, and this is said to occur most often in setups that use AWS_BEARER_TOKEN_BEDROCK.
  • The docs advise that creating a dedicated AWS account for Claude Code makes cost tracking and access control easier.

Region and model ID prefixes

According to the official docs, with the Invoke API, the built-in default model resolves to a cross-region inference profile ID. The preferred prefix for each resolved region is as follows.

  • us-gov-*(AWS GovCloud):us-gov.
  • us-*:us.
  • eu-*:eu.
  • ap-*:apac.
  • Other regions: global.

You can choose the prefix to try first with ANTHROPIC_BEDROCK_REGION_PREFIX. Valid values are us, eu, apac, jp, au, and global, and v2.1.224 or later is required. Use it, for example, when your account has a global. profile enabled but the region causes a different prefix to be selected.

export ANTHROPIC_BEDROCK_REGION_PREFIX=global
# In a us-* region, the primary model now resolves to
# global.anthropic.claude-opus-5-5 instead of us.anthropic.claude-opus-5-5

Note that this prefix is a preference, not a guarantee. If the profile list can't be retrieved, the prefix is applied without verification, and you get a 400 error if a profile with that prefix isn't enabled for your account. GovCloud always uses us-gov., and if you set an invalid value, it falls back to the prefix determined by the region.

Common pitfalls and troubleshooting

The SSO sign-in tab keeps opening

Remove awsAuthRefresh from your settings file. If a corporate VPN or TLS-inspecting proxy interrupts the browser step of SSO, it is treated as an authentication failure, and if the credentials stay expired, awsAuthRefresh runs again and opens another tab. In environments that block browser-based SSO, run aws sso login manually before starting.

Certificate errors behind a TLS-inspecting proxy

Internal root certificates in the OS trust store or in NODE_EXTRA_CA_CERTS are used without any Bedrock-specific configuration. Before v2.1.261, if you chose Use credentials already in my environment in the wizard and the root certificate existed only in the OS store, fetching the credentials used for the model check failed with unable to get local issuer certificate, or models showed as unreachable (inference requests themselves succeeded). Updating to v2.1.261 or later is recommended.

Region issues

  • Check model availability with aws bedrock list-inference-profiles --region your-region.
  • You can switch to a supported region with export AWS_REGION=us-east-1.
  • If you see "on-demand throughput isn't supported", specify the model by its inference profile ID.
  • Claude Code uses the Invoke API and does not support the Converse API.

Streaming fails through a gateway

Any gateway or proxy in between must forward responses, including Content-Type, unmodified. If it is rewritten, you get an error starting with Bedrock streaming response has content-type. If the headers are dropped and the response is converted to server-sent events, every turn falls back to non-streaming and gets slower, and the docs suggest setting CLAUDE_CODE_DISABLE_BEDROCK_CONTENT_TYPE_DEFAULT=1. The real fix is to make the gateway forward responses unmodified.

Other

The issue where each tool group in /context shows 0 tokens occurs in versions before v2.1.196. Update to fix it. For Mantle endpoint configuration and errors, check the official docs.

FAQ

Do I have to install the AWS CLI?

The official docs describe this as optional. You need it only when there is no other way to obtain credentials.

Source: Claude Code on Amazon Bedrock

You are already signed in, so the wizard screen doesn't appear.

If the chat screen is showing, run /setup-bedrock to open the wizard. It doesn't appear in the command menu until CLAUDE_CODE_USE_BEDROCK=1 is set, so type the full command.

Source: Claude Code on Amazon Bedrock

The browser opens many tabs during AWS SSO. What should I do?

Remove awsAuthRefresh from your settings file. If your network environment blocks the automatic browser SSO, run aws sso login manually before starting Claude Code.
