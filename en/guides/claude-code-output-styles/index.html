What Claude Code output styles are: how to change and create them

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • An output style is an instruction that switches Claude's role, tone, and response format for the whole session. The built-in styles are Default, plus four others: Proactive, Concise, Explanatory, and Learning.
  • You can switch styles with the /output-style command, the /config menu, or the outputStyle setting in a settings file. Values in settings files are case-sensitive.
  • An output style is an instruction for Claude to follow, not a guarantee of behavior. For actions that must always run, a hook is the better fit; for project information, use CLAUDE.md.

What output styles can do

Claude Code (an AI coding agent from Anthropic that runs in the terminal) has output styles. According to the official docs, an output style is a set of instructions that defines Claude's role, tone, and response format for every response in a session, so you don't have to repeat the same request in each prompt.

You can use it to make responses shorter, have Claude explain the reason for each change, or have it start working without asking routine questions. If you build your own, you can also create roles other than software engineer, such as a writing assistant or a data analyst. This article is based on the official docs as of writing (October 2026).

Source: Output styles

The four built-in styles and how to choose

According to the official docs, when no style is selected you get Default, which runs on the standard instructions for software engineering. The other four keep those instructions and add their own.

  • Proactive: For routine decisions, it doesn't ask questions; it makes reasonable assumptions and implements right away. It doesn't switch to plan mode unless you ask. It is instructed to confirm in the conversation before deleting data or changing shared or production systems.
  • Concise: States the result in the first sentence and omits preamble, progress narration, and a closing summary. Simple questions get one to three sentences. Requires v2.1.237 or later.
  • Explanatory: Works as usual and adds the reasons for its choices to the conversation as Insight blocks. It does not write them into files as comments.
  • Learning: In addition to Insight, it has the user write a small part that involves a design decision. Claude places a TODO(human) comment in the file and waits, then continues once you tell it you have finished writing.

A caveat: switching to Proactive does not change the permission mode, and permission prompts still appear as before. Proactive confirmations are instructions to Claude and are separate from permission prompts. Even with Concise, error reports, failed test output, security warnings, and confirmations for destructive operations are shown in full.

How to switch output styles

According to the official docs, you can choose it with a command, a menu, or a settings file. Selections made with the command or menu are saved to .claude/settings.local.json at the local project level.

  • /output-style command: Specify a style, as in /output-style concise. Without an argument, it lists the available styles. It also works in non-interactive mode and the Agent SDK, and requires v2.1.269 or later.
  • In the terminal: run /config and select Output style.
  • VS Code extension: Type / to open the command menu and choose Output styles. Custom styles are also available. Requires v2.1.257 or later.
  • Desktop app: Write outputStyle directly in the settings file.

This is an example of editing the settings file directly.

{
  "outputStyle": "Explanatory"
}

Values are case-sensitive, so a value that doesn't match a name exactly, such as explanatory, falls back to Default. The command itself ignores case. You can set a default for all projects with outputStyle in ~/.claude/settings.json, and a project's settings file takes precedence. If you switch mid-session, the new style is used from the next message.

How to create a custom style

A custom style is a Markdown file containing metadata in frontmatter and instructions for Claude.

  1. Save the file. The location can be user (~/.claude/output-styles), project (.claude/output-styles), or managed policy. If you don't specify name, the file name becomes the style name.
  2. Write the frontmatter and the instructions. The example in the official docs is as follows.
  3. In the terminal, choose your own style from /config. Claude Code reads style files at startup, so if you create or edit one while it's running, you need to restart.
---
name: Diagrams first
description: Lead every explanation with a diagram
keep-coding-instructions: true
---

When explaining code, architecture, or data flow, start with a Mermaid diagram showing the structure, then explain in prose.

## Diagram conventions

Use `flowchart TD` for control flow and `sequenceDiagram` for request paths. Keep diagrams under 15 nodes.

You decide whether to keep the coding instructions with keep-coding-instructions. If you only want to change the tone, set keep-coding-instructions: true. If the use case isn't software engineering, omit it. If multiple project styles share the same name, the one closest to the working directory is used.

frontmatter fields

All fields are optional, and a misspelled field is silently ignored with no error. If the YAML can't be parsed, the file is loaded by its file name and the fields are left unset. You can check the cause with claude --debug.

  • name, description: shown in the /config selection screen.
  • keep-coding-instructions: The default is false.
  • force-for-plugin: This is only for plugin styles. When set to true, it is applied automatically while the plugin is enabled and overrides the user's outputStyle setting.

How it differs from other features, and caveats

According to the official docs, an output style is an instruction that Claude follows, and there is no mechanism to enforce it. Here is how to choose by use case.

  • To tell Claude about project conventions or commands: use CLAUDE.md. It stays loaded in every style.
  • Steps for a specific task only (such as a release checklist): a skill. It loads only when you invoke it or when the task matches.
  • For actions you want to run every time without exception (formatting after edits, blocking commands, and so on): use a hook. Claude Code itself runs it, so it doesn't depend on whether Claude follows an instruction.
  • A helper with its own instructions, model, and tools: a subagent. It runs in a separate context.

You can combine these. Under the hood, style instructions are sent with every request, which increases input tokens, but prompt caching reduces the impact. Explanatory and Learning produce longer responses, and Concise produces shorter ones. A style applies to the main conversation and to forks; responses from other subagents are unchanged.

In the full system prompt, a custom style omits the built-in software engineering instructions, unless keep-coding-instructions is true, in which case they remain. This field has no effect with a short system prompt, so check the official docs for details.

FAQ

With the Concise style, are errors and warnings also omitted?

They are not omitted. According to the official docs, requested explanations and details, error reports, failed test output, security warnings, and confirmations for destructive operations are kept in full. Concise requires v2.1.237 or later.

Source: Output styles

What happens if I write explanatory in lowercase for outputStyle in the settings file?

According to the official docs, values are case-sensitive, so explanatory, which doesn't match the name, falls back to Default. Write Explanatory. The /output-style command ignores case.

Source: Output styles

If I edit a custom style file, does it take effect immediately?

Claude Code in the terminal reads style files at startup, so if you create or edit one while a session is running, you need to restart. After you switch, the new style is used starting with your next message.
