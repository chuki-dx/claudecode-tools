How to investigate Claude Code installation and login errors

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • The official docs include a list that lets you look up fixes by the error message shown on screen. The quickest approach is to match the message you see against that list first.
  • If you can't tell why login is failing, the docs say that signing out with /logout, closing Claude Code, and authenticating again from claude resolves it in many cases.
  • A 403 or an "access not granted" error after login can have a cause outside Claude Code, such as the contract, roles, or a proxy.

Start by finding the fix from the error message

As of writing (October 2026), the official docs (troubleshooting installation and login) organize errors into a list where you look up a fix from the message on screen or the symptom. If you roll out Claude Code (Anthropic's AI coding agent that runs in the terminal) company-wide, this list is the starting point for handling support requests. Examples from the list follow.

  • command not found: claude: Explains how to fix your PATH (the list of folders searched for commands).
  • EACCES: permission denied: the guidance is to fix the permissions on the install directory.
  • unable to get local issuer certificate: this points you to configuring your company's CA certificate.
  • Failed to fetch version: The message tells you to check your network and proxy settings.
  • OAuth error or 403 Forbidden: points you to the login and authentication section.

If your issue isn't in the list, use the diagnostic checks in the official docs to narrow down the cause. Note that App unavailable in region means Claude Code isn't offered in your country, and no setting can fix it.

Typical symptoms during installation

The exact steps differ by symptom, so check the relevant section of the official docs.

  • If you see irm is not recognized or 'bash' is not recognized as the name of a cmdlet on Windows: this points you to use the install command that matches the shell you're using.
  • syntax error near unexpected token '<': Guidance for when the install script returns HTML instead of a shell script.
  • If claude isn't found after the PowerShell installer finishes, or an old version is shown: add the install location to PATH and open a new terminal.

If you can't log in, re-authenticate first

According to the official docs, when login fails and you can't tell why, re-authenticating resolves it in many cases. The steps are as follows.

  1. Sign out by running /logout
  2. Closing Claude Code
  3. Restart with claude and authenticate again

If the browser doesn't open automatically, press c to copy the OAuth URL (the sign-in URL) to the clipboard. Then paste it into your browser. This also works when the URL wraps in a narrow terminal or over SSH and can't be clicked.

OAuth error: Invalid code

OAuth error: Invalid code. Please make sure the full code was copied is caused by an expired login code or by part of it being lost when copying. Press Enter to retry and finish the login as soon as the browser opens. Over remote or SSH sessions, the browser may open on a different machine; in that case, open the URL shown in the terminal in your local browser.

When you are asked to log in again

If you're asked to log in again after a session, your OAuth token may have expired. Re-authenticate with /login. If it happens often, check that your system clock is accurate, because token validation depends on correct timestamps.

403 errors and access permission errors after login

If API Error: 403 Request not allowed appears after login, the official docs suggest checking the following.

  • Claude Pro/Max users: Check in the claude.ai settings screen that your subscription is active.
  • Anthropic Console users: check whether your account has the "Claude Code" or "Developer" role. An administrator assigns it on the Console Members page.
  • Behind a proxy: a corporate proxy can interfere with API requests. For configuration, see the official network configuration page.

The "access has not been granted" error

If the sign-in page shows Authorization failed and Claude Code access has not been granted for this account. Contact your administrator., the user's role in your Claude Enterprise organization is Custom, and none of the custom roles assigned to their groups allow Claude Code. A Custom role gets access only through those custom roles, so nothing you change on the Claude Code side will fix it.

To resolve it, ask your organization's Owner either to assign a custom role that allows Claude Code to the group, or to change the role from Custom to a standard role such as User. After the change, run claude and log in again.

You have a subscription but still get an error: API key override

If you have an active subscription but see API Error: 400 and This organization has been disabled, the official docs explain that the ANTHROPIC_API_KEY environment variable is overriding your subscription. This often happens when an old API key from a previous employer or project is left in your shell profile.

If ANTHROPIC_API_KEY exists and has been approved, Claude Code uses that key instead of your subscription's OAuth credentials. In non-interactive mode with the -p flag, the key is always used if it is present. To use your subscription, unset the environment variable. On macOS/Linux:

unset ANTHROPIC_API_KEY
claude

For Windows PowerShell, do the following.

Remove-Item Env:ANTHROPIC_API_KEY
claude

To fix this permanently, delete the export ANTHROPIC_API_KEY=... line from ~/.zshrc, ~/.bashrc, and ~/.profile. On Windows, check your PowerShell profile ($PROFILE) and your user environment variables. Running /status inside Claude Code shows which authentication method is active.

Logging in on WSL2, SSH, and containers

In WSL2, SSH sessions, and containers, the browser usually opens on a different host, so the redirect never reaches Claude Code's local callback server. After you sign in, the browser shows a login code; paste it at the terminal's Paste code here if prompted prompt. If the browser does not open at all in WSL2, set the BROWSER environment variable to the path of your Windows browser.

export BROWSER="/mnt/c/Program Files/Google/Chrome/Application/chrome.exe"
claude

If pasting the code doesn't work, try a different paste method in your terminal, or use claude auth login, which reads the pasted code from standard input.

FAQ

If login keeps failing, what should I try first?

The official docs describe these steps: fully sign out with /logout, close Claude Code, restart it with claude, and authenticate again. If the browser doesn't open, press c to copy the URL and open it manually.

Source: Troubleshoot installation and login

Can I fix Claude Code access has not been granted for this account in the Claude Code settings?

You can't fix it yourself. The cause is that, in a Claude Enterprise organization, the user's role is Custom and the assigned custom role does not allow Claude Code. Ask your organization's Owner to change the role, then log in again with claude.

Source: Troubleshoot installation and login

Why do I see This organization has been disabled even though I have a subscription?

The official docs explain that the cause is that ANTHROPIC_API_KEY is set, so that key is used instead of your subscription. Unset the environment variable and remove it from your shell profile as well.

Source: Troubleshoot installation and login
