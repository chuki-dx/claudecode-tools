Using Claude Code through Microsoft Foundry (Azure): setup steps and caveats

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, Claude Code (an AI coding agent from Anthropic that runs in the terminal) can be used through a Claude deployment created in Microsoft Foundry on Azure.
  • Configuration is done only with environment variables: you enable it with CLAUDE_CODE_USE_FOUNDRY and specify the resource name. There is no interactive setup.
  • Before distributing to multiple people, pin the model version for each deployment. If you don't, an unavailable model may be selected and requests can fail.

Prerequisites, and what you can do through Foundry

Using Claude Code through Microsoft Foundry lets you connect to the Claude resources and deployments you created on Azure. According to the official docs, you need the following three things before you start.

  • An Azure subscription with access to Microsoft Foundry
  • RBAC permissions that let you create Microsoft Foundry resources and deployments (RBAC is Azure's role-based access control)
  • Install and configure the Azure CLI (optional; needed only if you have no other way to get credentials)

When rolling out to multiple people, the docs note that you should pin the model version before rollout. When you create a deployment, you also choose a hosting option that determines whether inference runs on Azure or Anthropic infrastructure. See the official docs for details on the options.

Source: Claude Code on Microsoft Foundry

Steps 1-2: Create the resource and choose an authentication method

1. Create the resource and deployment

In the Microsoft Foundry portal, create a new resource and note the resource name. Then create deployments for Claude Opus, Claude Sonnet, and Claude Haiku, and note the deployment names you assign. You will use the deployment names in the model environment variables in step 4.

2. Choose an authentication method

According to the official docs, there are three authentication methods.

  • API key: Set the key you copied in the portal as ANTHROPIC_FOUNDRY_API_KEY.
  • Microsoft Entra ID: gets a token through the Azure SDK's default credential chain. The example uses an az login session, so no stored API key is needed.
  • Bearer token: pass an Entra ID access token obtained by another process through ANTHROPIC_FOUNDRY_AUTH_TOKEN.

To set the API key, open the resource in the portal and copy the API Key from Endpoints and keys.

export ANTHROPIC_FOUNDRY_API_KEY=your-azure-api-key

When using Entra ID, leave ANTHROPIC_FOUNDRY_API_KEY and ANTHROPIC_FOUNDRY_AUTH_TOKEN unset, and sign in with the Azure CLI on your local PC.

az login

The bearer token is sent with every request as an Authorization: Bearer header. Use this method when a host app or sign-in script has already obtained the token.

export ANTHROPIC_FOUNDRY_AUTH_TOKEN=your-entra-access-token

ANTHROPIC_FOUNDRY_AUTH_TOKEN takes precedence over ANTHROPIC_FOUNDRY_API_KEY and the default credential chain. Also, because authentication is handled by Azure credentials, the /logout command is not available when using Microsoft Foundry.

Steps 3 to 5: environment variables, pinning the model, and verifying startup

3. Environment variable to enable it

# Enable Microsoft Foundry integration
export CLAUDE_CODE_USE_FOUNDRY=1

# Azure resource name (replace {resource} with your resource name)
export ANTHROPIC_FOUNDRY_RESOURCE={resource}
# Or provide the full base URL:
# export ANTHROPIC_FOUNDRY_BASE_URL=https://{resource}.services.ai.azure.com/anthropic

Set ANTHROPIC_FOUNDRY_RESOURCE to the resource name only (for example, my-resource). If you enter a URL or hostname, Claude Code rejects it when you send a message.

4. Pin the model version

The official docs warn you to pin versions in every deployment. If you don't, aliases such as sonnet and opus resolve to the defaults built into Claude Code for Microsoft Foundry. These defaults may lag behind the latest release, and your account may not have access to them yet. Because there is no model check at startup, requests fail if the model is unavailable. When you create a deployment in Azure, choose a specific model version rather than "auto-update to latest."

Set the model variables to match the deployment names from step 1. If you don't set ANTHROPIC_DEFAULT_OPUS_MODEL, opus resolves to Opus 4.6. The official docs give the following example.

export ANTHROPIC_DEFAULT_OPUS_MODEL='claude-opus-4-8'
export ANTHROPIC_DEFAULT_SONNET_MODEL='claude-sonnet-5'
export ANTHROPIC_DEFAULT_HAIKU_MODEL='claude-haiku-4-5'

Some accounts have no Haiku deployment, so background tasks such as generating session titles use the main model by default. To use Haiku, set ANTHROPIC_DEFAULT_HAIKU_MODEL to an available Haiku deployment.

Prompt caching is enabled automatically. To extend the TTL (how long the cache is kept) from the default 5 minutes to 1 hour, set the following variable. Note that writes with the 1-hour TTL are billed at a higher rate. Check the official pricing page for amounts.

export ENABLE_PROMPT_CACHING_1H=1

5. Launch and verify

claude

Claude Code reads the environment variables and connects to your Azure resource on the first prompt. Microsoft Foundry has no interactive setup wizard, so the environment variables in steps 3 and 4 are the only way to configure it. To verify, run /status inside Claude Code and check that the API provider line shows Microsoft Foundry along with the resource name or base URL.

Source: Claude Code on Microsoft Foundry

Permissions and the 1M-token context

According to the official docs, the default Azure AI User and Cognitive Services User roles include all the permissions needed to call Claude models. If you want to narrow them down, create a custom role with the following content.

{
  "permissions": [
    {
      "dataActions": [
        "Microsoft.CognitiveServices/accounts/providers/*"
      ]
    }
  ]
}

When Claude Code can identify the model a deployment serves, Fable models, Sonnet 5 and later, and Opus 4.7 and later run with a 1M-token context window by default, and [1m] is not needed. Identification is based on the deployment name in the model variable, so either name it with the model ID, such as claude-opus-4-8, or map it with modelOverrides. For names it can't identify, it assumes 200K unless you declare a different window.

For example, writing the following in settings.json tells Claude that the deployment named team-opus-prod is Opus 4.8.

{
  "modelOverrides": {
    "claude-opus-4-8": "team-opus-prod"
  }
}

To limit the window to 200K, set CLAUDE_CODE_DISABLE_1M_CONTEXT=1. For Opus 4.6 and Sonnet 4.6, add [1m] to the deployment name to get 1M. Before v2.1.287, Fable models and Opus 4.7 and later also required this suffix.

Source: Claude Code on Microsoft Foundry

Common pitfalls and pre-distribution checks

The official docs troubleshooting covers these two items.

  • If you see "Failed to get token from azureADTokenProvider: ChainedTokenCredential authentication failed", configure Entra ID in your environment or set ANTHROPIC_FOUNDRY_API_KEY.
  • If connection errors repeat on the first prompt, check that ANTHROPIC_FOUNDRY_RESOURCE is the actual resource name rather than a placeholder. The endpoint URL is built from this value, so a wrong value points to a host that doesn't exist.

If you are in corporate IT rolling this out company-wide, it is safer to decide first whether to pin the model version, whether to have a Haiku deployment, and how to name deployments (this affects 1M detection). This reflects the content as of writing (October 2026), so check the official docs for the latest before rollout.

Source: Claude Code on Microsoft Foundry

FAQ

Is the Azure CLI required?

The official docs describe this as optional. You only need it when there's no other way to obtain credentials.

Source: Claude Code on Microsoft Foundry

Why can't I use /logout?

According to the official docs, when you use Microsoft Foundry, authentication is handled by your Azure credentials, so the /logout command is not available.

Source: Claude Code on Microsoft Foundry

What happens if I don't pin the model version?

An alias may resolve to Claude Code's built-in default, which can be a model your account can't use yet. Because there is no model check at startup, the request fails in that case.
