When Claude Code Stops at a Limit: Auto-Resume After Reset, and When It Doesn't Resume

Published: November 26, 2026 | Chuki DX Lab | Content is based on sources such as the official docs as of writing (November 2026); sources are listed at the end of each section

Key takeaways

  • Claude Code (an AI coding agent from Anthropic that runs in the terminal) automatically resumes work after the reset when you hit a usage limit in an interactive session signed in with a claude.ai subscription. It is on by default and requires v2.1.234 or later.
  • To have it continue automatically, keep the session open while it waits. If it doesn't continue, or if you hit the limit three times in a row, choose the next action with /rate-limit-options.
  • Permission prompts still appear as usual when the work continues. Before you step away, expect that it may stop at a prompt. To stop it, press Esc; to disable it, change the setting with /config.

What it does: continues automatically after the limit resets

According to the official docs, when a task stops partway because you hit your claude.ai usage limit, Claude Code waits in the open session and resumes the task on its own after the reset. It is on by default for interactive sessions signed in with a claude.ai subscription, and requires v2.1.234 or later. This is based on the official docs as of writing (November 2026).

The continuation starts with a prompt that nudges Claude to pick up where it stopped, rather than resending your last message.

Source: Interactive mode

What is displayed while waiting, and how the wait ends

While waiting, the two lines at the bottom of the session show when the limit resets and when the continuation will start.

Usage limit reached · limit resets 3:45pm
Continuing automatically at 3:45pm · Esc to cancel

Either line may have a help link on the first line and a follow-up such as /usage-credits to continue now on the second. The wait ends as follows.

  • At reset: The second line changes to Continuing shortly · Esc to cancel, the conversation shows Usage limit reset · Continuing automatically, and work resumes.
  • After your PC sleeps: If the reset happened during a sleep of more than about 30 minutes, the first line reads Your usage limit has reset and the second reads Press enter to continue, so press Enter. If the sleep was shorter, or ended before the reset, it continues automatically.
  • Resume early: While you wait, if you finish adding credits with /usage-credits, sign in again after /upgrade, or switch models with /model, Claude Code checks whether your usage has been restored and continues right away if it has. Upgrades or purchases you made yourself in the browser are not checked. With settings that run plan mode on a different model, such as opusplan, it waits until the reset.

Source: Interactive mode

Precautions before stepping away, and how to cancel

Permission prompts still appear as usual for the resumed task. If you step away, it may stop at a prompt. Also, if the resumed work hits the limit again, the wait starts over.

Automatic continuing stops after 3 times. After the third, it stops and shows the notice Automatic continue stopped after repeated usage-limit hits, and you choose what to do next with /rate-limit-options. If you send your next prompt or choose to wait in that menu, the count resets.

How to cancel

While it's displayed, press Esc or Ctrl+C at an empty prompt, or choose Don't continue automatically in /rate-limit-options. A line starting with Automatic continue cancelled appears. After canceling, it won't continue until you send a prompt or choose the line starting with Wait here, then continue automatically in /rate-limit-options.

The wait also ends without running the continuation in these cases.

  • When you send a prompt (that prompt is sent instead of waiting)
  • You exit Claude Code (resuming the session does not resume the wait)
  • When the conversation is replaced, such as switching accounts with /login, clearing or rewinding the conversation, or /resume of a different session

Source: Interactive mode

When it doesn't resume automatically, and the setting to turn it off

Claude Code does not start a wait on its own in these cases.

  • Remote Control and agent team teammate sessions (a person at that terminal can still start one manually)
  • When the reset is more than 24 hours away (a weekly limit can be several days out)
  • You hit an Opus or Sonnet limit but are running a model outside that family (because the next turn may not hit the limit)

In these cases, or when automatic continuation is turned off, hitting the limit on your own machine opens the usage limit options menu once per reset window. Choose the line that starts with Wait here, then continue automatically to start waiting. In Remote Control or a teammate's session, run /rate-limit-options yourself.

In some cases the option to wait doesn't appear at all: background sessions and -p runs, API keys, cloud providers, and pay-as-you-go billing (metered per request, so there's no reset to wait for), and LLM gateways without a saved claude.ai login.

Turn it off

In /config, turn off Continue automatically at usage limit, or set autoContinueAtUsageLimit to false in your user settings. /config autoContinueAtUsageLimit=false also works, but you can't undo it with the key=value form, because this setting allows unattended runs. Check the official settings reference for which settings files are loaded.

Source: Interactive mode

Options to keep going without waiting: /model, /usage, /usage-credits

The official docs say the response depends on the type of limit. Session and weekly limits apply to all models, so switching with /model won't lift them. Opus and Sonnet limits apply only to that model family, so you can keep working by switching to a model outside that family with /model. However, each model has its own prompt cache, so the next request reloads the entire conversation.

  • /usage: Shows your plan limits and reset times.
  • /usage-credits: On Pro, Max, and Ultra you can buy additional usage; on Team and Enterprise you ask an admin. For how billing is handled, see the official Help Center, and check the official pricing page for current amounts.
  • Code tab in the Desktop app: The session limit card has an Auto-continue when limits reset checkbox (the weekly limit card does not). It is separate from the CLI setting, so turn each one off individually.

Source: Error reference

FAQ

What if I want to stop the automatic continuation setting?

Turn off Continue automatically at usage limit in /config, or set autoContinueAtUsageLimit to false in your user settings. If you only want to stop while it's waiting, press Esc at an empty prompt to cancel.

Source: Interactive mode

What happens if I hit the limit even after three continuations?

Automatic continuing stops and a notice appears. Choose what to do next with /rate-limit-options. If you send your next prompt or choose to wait in the menu, the count resets.

Source: Interactive mode

Can I decide centrally, for all company devices, whether automatic waiting starts?

The official docs state that setting autoContinueAtUsageLimit in managed settings lets you control, organization-wide, whether Claude Code starts waiting automatically. Check the official docs for details such as precedence.
