Using Claude Code in the browser (cloud): what it can do, GitHub connection, and limits

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, Claude Code (Anthropic's AI coding agent that runs in the terminal) can be used as cloud-based sessions. Each session runs in a cloud environment that defines things like network access.
  • There are two ways to connect to GitHub: the GitHub App and /web-setup. They differ in which repositories they can reach, so choose according to your company's practices.
  • Before rolling it out, check the limitations, such as shared rate limits, the GitHub requirement, and IP allowlists. The content is based on the official docs as of writing (October 2026).

Cloud environments: where sessions run

According to the official docs, all cloud sessions run in a cloud environment. A cloud environment is a saved configuration that controls network access, environment variables, and setup scripts.

  • Initial environment: If you don't have one yet, onboarding either creates a Default environment (with Trusted network access) or prompts you to create one. Which of the two happens depends on your plan, so check the official docs.
  • For how one is chosen when there are several, changes to where it can reach or what it runs at startup, and the tools included without any configuration, check each page of the official docs.

Source: Use Claude Code in the cloud

How to connect GitHub

Cloud sessions need access to a GitHub repository to clone code and push branches. The official docs describe the following two options.

  • GitHub App: You authorize the Claude GitHub App during web onboarding. It can reach all public repositories and any private repositories where you've installed the Claude GitHub App. It is described as intended for teams that want browser onboarding or Auto-fix.
  • The /web-setup method: run /web-setup in the terminal to send your local gh CLI token to your Claude account. Any repository your gh token can access is reachable, whether or not the Claude GitHub App is installed. It suits individual developers who already use gh.

Auto-fix and Projects require the Claude GitHub App to be installed on the repository. (For Projects, it is required on each repository you clone, regardless of how you connect.)

In Anthropic-hosted environments, your GitHub credentials are encrypted on Anthropic's servers and never enter the session's VM. GitHub operations from the VM go through a GitHub proxy, which attaches the credentials on the server side.

Quick setup for Team and Enterprise

Quick setup is an organization setting and is off by default on the Team and Enterprise plans. When you turn it on, /web-setup becomes available (the command is hidden while it is off), browser onboarding skips the GitHub App installation prompt, and a Default environment is created automatically. An Owner turns it on with the Quick setup toggle under Organization settings > Claude Code.

Note: Organizations with Zero Data Retention enabled, or with a HIPAA configuration applied, cannot use cloud session features, including /web-setup. Organizations that use customer-managed encryption keys (CMEK) also cannot start cloud sessions.

Working with sessions: reviewing diffs, commands, and sharing

Sessions are listed in the web version's sidebar, where you can review changes, share with your team, archive finished ones, and delete them permanently.

  • Diff review: Each session shows the number of added and deleted lines, such as +42 -18. Open it to view the diff, comment on lines, and send them to Claude along with your next message. By default it compares against the base branch. The diff is computed from raw git blobs, so the repository's diff drivers and textconv filters are not applied.
  • Permission mode: Choose it from the mode dropdown, both when creating a task and while it is running.
  • Commands: built-in commands that output text are available. Terminal-only ones such as /plugin and /resume can't be used. Some commands take a value as an argument, like /model sonnet.
  • Context: /compact and /context work, but /clear does not. Start a new session from the sidebar.

Sharing visibility depends on your account. Enterprise and Team offer Private and Team; Max and Pro offer Private and Public. Public means anyone signed in to claude.ai can view it, and a session may contain code from private repositories or credentials, so review the contents before sharing.

Deleting permanently removes the session and its data and cannot be undone. If you only want to tidy up, use archive instead.

Source: Use Claude Code in the cloud

Security and isolation

According to the official docs, sessions are isolated from your machine and from other sessions through multiple layers.

  • Each session runs in an isolated VM managed by Anthropic. Sessions you route to your own self-hosted environment run on your own infrastructure, and isolation is the responsibility of your own configuration.
  • In Anthropic-hosted environments, network access is restricted by default, and you can also disable it. However, even with networking disabled, Claude Code can still communicate with the Anthropic API, so data may leave the VM.
  • In Anthropic-hosted environments, git credentials and signing keys stay outside the sandbox, and a proxy acts on your behalf with scoped credentials.

Source: Use Claude Code in the cloud

Limitations to check before adopting

  • Rate limits: Cloud sessions share limits with your other Claude and Claude Code usage on the same account. Running multiple tasks in parallel consumes limits that much faster.
  • Time limits: Commands and SessionStart hooks have default timeouts that you can change. A setup script is cached only if it finishes in roughly 5 minutes.
  • Authentication: You can bring a cloud session into your terminal only if you are authenticated with the same account.
  • Platform: GitHub is required to clone repositories and create PRs. Self-hosted GitHub Enterprise Server is supported on Team and Enterprise plans.
  • IP allowlist: If your organization has an IP allowlist enabled, all Anthropic-hosted cloud sessions fail with an authentication error. The same applies to Code Review and to routines that run in Anthropic-hosted environments.

Source: Use Claude Code in the cloud

FAQ

Can I use it with GitLab or Bitbucket repositories?

GitHub is required for cloning repositories and creating PRs. For GitLab, Bitbucket, and others, setting CCR_FORCE_BUNDLE=1 lets you send the repository to the session as a local bundle, but you cannot push the results back to that remote.

Source: Use Claude Code in the cloud

Why doesn't /web-setup appear?

On Team and Enterprise plans, Quick setup is off by default, and the command is hidden while it's off. An Owner turns it on in the organization settings. It isn't available at all to organizations with Zero Data Retention enabled or a HIPAA configuration.

Source: Use Claude Code in the cloud

Can I use it in an organization that uses an IP allowlist?

When this is enabled, Anthropic-hosted cloud sessions fail with an authentication error. You need to contact Anthropic support to have Anthropic-hosted services excluded from the allowlist. Sessions in self-hosted environments call the API from your own network.

Source: Use Claude Code in the cloud
