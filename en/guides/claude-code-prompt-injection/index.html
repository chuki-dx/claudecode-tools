How Claude Code security works and how to defend against prompt injection

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • Claude Code (an AI coding agent from Anthropic that runs in the terminal) uses permission modes to decide which operations can run without confirmation. In manual mode, it asks for confirmation before edits and command execution.
  • Prepare for prompt injection (a technique that tries to rewrite an AI's instructions with malicious text) by requiring permission prompts and not auto-approving network-related commands, among other measures. Even so, the official docs state that no system can fully prevent it.
  • When rolling this out company-wide, combine confirmation before approval, isolation such as a sandbox, and common rules through managed settings.

Use permission modes to decide what Claude can do

According to the official docs, the session's permission mode determines which actions Claude can take without asking first. As of writing (October 2026), Auto mode is the default starting mode for interactive sessions in the terminal and VS Code. For the starting mode in earlier versions or other surfaces, check the official docs.

  • Auto mode: A separate classifier model reviews actions on the user's behalf and blocks anything it judges unsafe. Explicit ask and deny rules remain in effect, and your organization can also turn auto mode off.
  • Manual mode: Starts read-only and asks for confirmation before file edits, tests, and command execution. You can choose to allow an action just once or to keep allowing it from then on. Built-in read-only commands such as ls, cat, and git status run without confirmation.

The official docs state explicitly that the user is responsible for verifying that code and commands are safe before approving them.

Built-in protections and boundary caveats

  • Sandboxed Bash tool: isolates the file system and network, reducing confirmation prompts while staying safe. Use /sandbox to set the boundaries within which it can work autonomously.
  • Working directory boundary: in manual mode, Claude Code asks for confirmation before file tools read or write outside the folder you launched in and its subfolders.
  • Reducing approval fatigue: You can add safe commands to an allowlist at the user, codebase, or organization level.
  • Accept Edits mode: Automatically approves file edits inside the working directory, plus certain filesystem Bash commands such as mkdir, touch, rm, mv, cp, and sed. Other Bash commands and paths outside that scope still ask for confirmation.

Note that the working directory boundary is a permission prompt boundary. An approved Bash command can write anywhere the user's account can write. To restrict Bash commands at the OS level, enable the sandbox.

What the prompt injection protections include

Prompt injection is a technique that inserts malicious text to override or manipulate an AI assistant's instructions. The official docs list the following protections.

  • Permission system: in manual mode, sensitive operations require explicit approval.
  • Approval of network commands: curl and wget are not auto-approved by default. In manual mode they prompt for confirmation like other Bash commands that aren't read-only, and you can also let them through with an allow rule such as Bash(curl *). If you don't want them to run, add them to permissions.deny. Deny rules match the command exactly as written, so for control that doesn't depend on the command string, use the sandbox's network isolation.
  • Web page summaries: In many fetches, WebFetch processes the page with a separate model call, and Claude receives that answer instead of the raw page.
  • Trust check: When you start an interactive session in a folder you haven't trusted, a workspace trust dialog appears. In -p sessions, neither this dialog nor the .mcp.json approval appears.
  • Command injection detection: In manual mode, Bash commands that can't be fully parsed trigger a confirmation prompt first. This confirmation is not skipped even if you have an allow rule for part of a command, such as Bash(git *).
  • Commands that don't match a rule require approval: In manual mode, commands that don't match any rule require approval by default.

On Windows, the official docs recommend not enabling WebDAV and not allowing access to paths that may include WebDAV subdirectories. When enabled, it can bypass the permission system and cause network requests to remote hosts.

Notes on MCP, cloud execution, and Remote Control

Claude Code can connect to MCP (Model Context Protocol) servers. Project servers can be defined in .mcp.json, but servers from other scopes, claude.ai connectors, and servers added by plugins are configured outside the repository. So looking at .mcp.json alone doesn't show every server that could be loaded. The official docs recommend building your own or using ones from a trusted provider. Anthropic reviews connectors against listing criteria, but it does not audit or manage the security of MCP servers. To restrict them across your organization, use managed MCP settings.

Cloud sessions hosted by Anthropic run in a separate VM per session, and network access is restricted by default. You can also disable it or allow only specific domains. GitHub credentials are stored encrypted on the server side and never enter the VM. Actions are recorded in audit logs. If you route sessions to your own self-hosted environment, isolation, outbound traffic, and git credentials are your responsibility.

With Remote Control, code execution and file access stay local. While connected, however, the session transcript is stored on Anthropic's servers so the conversation can sync across devices. No cloud VM or sandbox is used.

Operations for trying it out and rolling it out within your company

The recommendations for handling untrusted content are as follows.

  1. Review proposed commands before approving them
  2. Don't pipe untrusted content directly into Claude
  3. Review changes to important files
  4. Especially when interacting with external web services, run scripts and tool calls in a virtual machine (VM)
  5. Report suspicious behavior with /feedback
  • For sensitive code, use project-level permission settings, run the entire Claude Code process in a sandbox runtime or a dev container, and review your permissions regularly with /permissions.
  • For teams, you enforce organizational standards with managed settings, share approved permission settings through version control, and monitor usage with OpenTelemetry metrics. You can audit or block settings changes during a session with the ConfigChange hook.

The official docs say these protections greatly reduce risk, but no system is fully immune to every attack, so you should keep following basic security practices.

FAQ

Are curl and wget run automatically?

According to the official docs, curl and wget are not auto-approved by default. In manual mode, you get a confirmation prompt. If you don't want them to run, add them to permissions.deny.

Source: Security

In manual mode, can it still write outside the working folder?

File tools prompt for confirmation. However, the boundary is the approval prompt, so a Bash command you approve can write anywhere the user's account can write. To restrict this at the OS level, enable the sandbox.

Source: Security

Does Anthropic verify the safety of MCP servers?

According to the official docs, Anthropic reviews connectors against its listing criteria but does not audit or manage the security of MCP servers. It recommends building your own or using ones from a trusted provider.
