Are Claude Code Plugins Safe? How to Check Before Installing and Spot the Official Marketplace

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, Claude Code plugins can run arbitrary code with your permissions. Check them before you install.
  • A marketplace's name only tells you who publishes the catalog. It doesn't tell you how individual plugins behave, so check each one before installing, no matter where it comes from.
  • Verification has four stages: where it came from, the detail screen in /plugin, the source, and the component list. If you no longer trust a plugin, remove it with claude plugin uninstall <plugin>.

What a plugin can do on your local machine

This guide summarizes the official docs on plugins for Claude Code (Anthropic's AI coding agent that runs in the terminal). According to the official docs as of writing (October 2026), an installed plugin can run arbitrary code with your permissions. You install plugins from a marketplace (a catalog from which Claude Code fetches plugins).

The official docs list the following as things a plugin can do after it is installed.

  • Hooks: run as shell commands at key points in Claude Code's behavior, such as before and after a tool call.
  • Monitors: background shell commands that Claude Code starts automatically at session start, when plugins are reloaded, and the first time a named skill runs.
  • Mod: Runs JavaScript inside Claude Code with the user's permissions.
  • MCP / LSP servers: connect to the servers declared by enabled plugins. stdio-type MCP servers are launched as processes on the user's machine.
  • bin/ directory: The bin/ of an enabled plugin is added to the Bash tool's PATH, so Claude's Bash commands can run the executables there.
  • Skills, commands, and agents: they enter the context as instructions to Claude.
  • Updates: if auto-update is enabled for the marketplace, files you reviewed may change later.

Installing also enables the plugin, unless the manifest or marketplace entry sets defaultEnabled: false and the user hasn't enabled it themselves.

What permission rules and the sandbox do not cover

According to the official docs, permission rules and the sandbox apply to tool calls that Claude makes, not to code a plugin runs on its own. Processes started by hooks, monitors, MCP servers, LSP servers, and Mods run outside the sandbox. Calls to a plugin's MCP tools and Bash commands that run executables in bin/ are tool calls, so permission rules apply to them.

How to identify the official marketplace

According to the official docs, marketplace names fall into one of three tiers: official, community, or third-party. Claude Code accepts official and community names only when the source is a repository under github.com/anthropics/, so a third party can't pass itself off as Anthropic. Marketplaces published by your colleagues or your own company are third-party.

  • Official: anything on the list of official names, such as claude-plugins-official
  • Community: claude-community, claude-plugins-community, healthcare
  • Third-party: everything else

The list of official names also includes others, such as claude-code-marketplace and anthropic-marketplace. Check the official docs for the full list. Note that the claude-community catalog pins nearly every entry to a commit SHA (an identifier for a specific Git version), and Claude Code refuses to install a different commit.

A caveat: the name tells you who publishes the catalog, not what each plugin inside it does.

Steps to check before installing

  1. Check where it came from: run claude plugin marketplace list in a shell to see the source each marketplace was added from (such as a GitHub repository or a directory).
  2. Read the details screen: run /plugin in a session and select a plugin. The Will install field lists its commands, agents, skills, hooks, and MCP / LSP servers. For plugins where Anthropic doesn't publish configuration data, you'll see what the marketplace entry declares, or a note.
  3. Read the source: open it from Open homepage or View on GitHub on the detail screen. If neither is there, look at the repository you identified in step 1. Will install shows that hooks exist but not what they run, so read hooks/hooks.json (the command each hook runs), .mcp.json (each server's command or URL), and bin/ (every file inside).
  4. List the components: clone the repository and run claude --plugin-dir <plugin directory> plugin details <plugin name>. It reads the files without starting a session and displays Component inventory.

After installing, claude plugin details <plugin name> shows the same list for the installed copy.

Warnings, denials, and how to remove it

According to the official docs, the detail view in /plugin shows the same trust warning for every marketplace. It says to make sure you trust a plugin before you install, update, or use it, and that Anthropic does not control the MCP servers, files, or other items a plugin includes, and cannot verify that they work as intended or won't change.

Claude Code sometimes refuses rather than just warning. If a marketplace uses an official or community name but its source is outside github.com/anthropics/, Claude Code blocks that marketplace and stops loading plugins installed from it. It also refuses to install when an archive source has a pinned sha256 digest that doesn't match the downloaded file.

Remove plugins you can no longer trust

In the shell, run claude plugin uninstall <plugin> with the same --scope you used when installing. Then check what was removed and what remains.

  • Persistent data: By default, it is deleted at the last scope. Check the official docs for options such as --keep-data.
  • Cache: files stay in ~/.claude/plugins/cache/ for 14 days and are then deleted in the background. If you uninstall the last plugin, though, they remain until you install another plugin. To remove them right away, delete ~/.claude/plugins/cache/<marketplace>/<plugin>/ yourself.
  • Marketplace: If you don't trust the owner either, remove the marketplace. All plugins installed from it will be uninstalled.

Managed settings for organization-wide rollout

According to the official docs, administrators can use managed settings to enforce allowlists and blocklists for marketplace sources, force-enable plugins, disable the --plugin-dir and --plugin-url flags and the CLAUDE_CODE_PLUGIN_DIRS variable, and restrict hooks. If your organization sets pluginTrustMessage, that text is appended to the trust warning. To see what each key covers, check the control matrix in the official docs.

FAQ

If a plugin comes from the official marketplace, do I still need to check it?

No. According to the official docs, a marketplace's name only indicates who publishes the catalog. It says nothing about how each plugin inside behaves. I check plugins from any marketplace before installing them.

Source: Plugin security and trust

Is a plugin enabled immediately after installation?

According to the official docs, a plugin is enabled when you install it. The exception is when the manifest or marketplace entry sets defaultEnabled: false and the user hasn't enabled it themselves.

Source: Plugin security and trust

If I uninstall a plugin, are its files removed right away?

They don't disappear right away. According to the official docs, the files stay in ~/.claude/plugins/cache/ for 14 days and are then deleted in the background (if you uninstalled the last plugin, they stay until you install another one). If you want them gone immediately, delete the directory yourself.
