Claude Code Code Review (automated PR review): how it works, how to start, and pricing

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • Code Review is a feature where multiple agents read a GitHub pull request and return the findings that pass verification as inline comments. It does not approve or block, so the merge decision stays with a person.
  • This applies to organizations on a Team or Enterprise plan, and the Claude organization Owner enables it. It is not available to organizations with Zero Data Retention or a HIPAA configuration.
  • Pricing is not a flat fee per item. It is pay-as-you-go, based on token usage. The safe approach is to set a monthly spending limit first, start small, check the average cost, and then expand.

What Code Review can do: how it works and its output

Claude Code (Anthropic's AI coding agent that runs in the terminal) includes Code Review, which automatically reviews GitHub pull requests (review requests made before changes are merged). According to the official docs, multiple agents read the changes and the surrounding code, look for logic errors, vulnerabilities, and similar problems, and check each finding against the code in a verification step before reporting it.

It runs on Anthropic's infrastructure in the following four stages.

  1. Search: multiple agents investigate the diff and surrounding code in parallel
  2. Verification: compare the flagged candidates against the code and remove false positives
  3. Ranking: remove duplicates and sort by importance
  4. Post: post the results to a pull request

Results are left as inline comments on the relevant lines, a summary, and a check run named Claude Code Review (the check result shown on the PR). The check run does not finish as a failure, and when there are no findings its title is Code review found no issues.

By default, it focuses on correctness, such as bugs that would break production, rather than formatting or missing tests. To tune this, use REVIEW.md and CLAUDE.md; the REVIEW.md on the base branch or default branch is the one that is read.

Because this is an AI review, it can miss things. The official docs caution that if it reports no findings, that does not mean there are no errors or that the code is safe.

Availability: plans, code hosts, and excluded organizations

According to the official docs, the requirements are as follows.

  • Plan: Team or Enterprise
  • Code hosts: GitHub (including GitHub Enterprise Server and GitHub Enterprise Cloud with data residency)
  • Not available to organizations with Zero Data Retention enabled or a HIPAA configuration applied, and not covered by Anthropic's Business Associate Agreement (BAA)
  • Not yet available to organizations that use customer-managed encryption keys (CMEK)
  • Even if you use Claude Code through Amazon Bedrock, Google Cloud's Agent Platform, or Microsoft Foundry, you need a Claude organization on one of the plans above

Even if none of these apply, you can run /code-review inside a Claude Code session on any plan. For other methods, check the comparison table in the official docs.

Getting started: setup steps in the admin console

According to the official docs, the following three permissions are required.

  • The Owner role in a Claude organization (all admin console steps)
  • A GitHub organization Owner (needed to install and connect the Claude GitHub App; if you are not an Owner, ask one first)
  • Write access to each repository you add

The steps are as follows.

  1. Turn on Allow code review under Code review in Admin settings > Claude Code
  2. When Connect GitHub appears, click Connect and authorize in GitHub
  3. If the target repository doesn't appear, install it with Install GitHub App and approve the permissions
  4. Select the repository and click Continue, then click Finish on the next screen, Code review is set up
  5. Open a non-draft test PR and check that a Claude Code Review check run appears within a few minutes

A few caveats. The app's permission set is broader than review needs, and it is shared with other features such as GitHub Actions. Repository access inside a review is read-only, and code is neither built nor run. Also, if you close the dialog any way other than Finish, the repository stays added but Allow code review remains off.

How costs work: what determines the amount

In the official docs as of writing (October 2026), Code Review has no flat per-review fee. It is billed through usage credits based on token usage, separate from the usage included in your plan. Billing goes to the organization, not to the developer who opened the PR. Because this article's sources don't give a price, check the official pricing page for the latest amounts.

Cost is determined by the cost per review times the number of reviews. The cost per review varies with the review level, the size of the change, the complexity of the surrounding code, and the number of candidates that need verification. The number of reviews is set by the per-repository Review runs setting.

Review level

Quick is the fastest and cheapest, Standard is the balanced default, and Deep is the most thorough but takes the most time and costs the most. An Owner picks one for the organization, and you can also change it per repository.

Setting the number of times

  • Once after PR creation: runs when a PR is opened, reopened, or marked ready for review
  • After every push: Runs on every push, so the cost is multiplied by the number of pushes
  • Manual (@claude review): no review when a PR is opened or when commits are pushed

Right after you add a repository, it is set to After every push, which produces the most reviews. @claude review runs just once, while @claude review always is also billed for later pushes when the setting is Once after PR creation or Manual. PRs from drafts and forks are not eligible for automatic review.

Estimates and limits: what to do before you expand

The official docs recommend running a small pilot before expanding.

  1. Set a monthly spending limit
  2. Enable it on a handful of representative repositories, with Review runs set to Once after PR creation or Manual (@claude review)
  3. After a few reviews, check the average cost in the Average cost column of the Repositories table
  4. Multiply the average by the number of PRs per month. For After every push, also multiply by the number of pushes per PR.

Set the limit on the Claude Code Review service in the usage admin screen (it applies to the whole organization). If the monthly Code Review limit, the organization-wide monthly limit, or the usage credit balance runs out, or the remainder falls below the estimated cost of one review, the review is skipped and developers see a comment on the PR explaining why.

You can view usage on the Code Review dashboard in analytics, but the cost figures may differ from your invoice. Per-repository figures are estimates at list price, before discounts or credits, so check your Anthropic invoice for exact amounts.

FAQ

Does Code Review approve pull requests or block merges?

According to the official docs, a review neither approves nor blocks, and its check run never ends as failed. The merge decision stays with your team.

Source: Code Review

Can I use it on plans other than Team and Enterprise?

Code Review itself is available on Team and Enterprise, and an Owner enables it. However, /code-review runs inside a Claude Code session on any plan.

Source: Code Review

How much does one review cost?

According to the official docs, there is no flat rate; billing is based on token usage. The source gives no amounts, so check the official pricing page. You can see your own average in the Average cost column of the admin console.

Source: Code Review costs and usage
