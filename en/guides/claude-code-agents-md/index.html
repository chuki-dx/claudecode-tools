Using AGENTS.md with Claude Code: Its Relationship to CLAUDE.md and How It's Loaded

Published: October 24, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, Claude Code can read AGENTS.md directly. By default, it reads it only when there is no CLAUDE.md-type file in the working directory or above it.
  • If CLAUDE.md or CLAUDE.local.md exists, AGENTS.md isn't read by default. To have both read, set Project instructions in /config to claude-md-and-agents-md.
  • Reading it directly requires v2.1.277 or later. In environments that can't read it, write @AGENTS.md in CLAUDE.md to import it.

How AGENTS.md is read by default

According to the official docs, Claude Code (Anthropic's AI coding agent that runs in the terminal) can read AGENTS.md as project instructions. A repository already set up for other coding agents works without adding a CLAUDE.md, an import, or extra settings. This article is based on the official docs as of writing (October 2026).

The default behavior is determined by the combination of files in the repository.

  • If only AGENTS.md exists, and there is no CLAUDE.md or CLAUDE.local.md in the working directory or above it, Claude reads AGENTS.md.
  • If both AGENTS.md and CLAUDE.md (or CLAUDE.local.md) exist, only the CLAUDE.md-family files are read.
  • If CLAUDE.md imports AGENTS.md, Claude reads CLAUDE.md, and AGENTS.md is included through the import.

Reading it directly requires Claude Code v2.1.277 or later.

When files are read, and which files are not

The files checked are CLAUDE.md, .claude/CLAUDE.md, and CLAUDE.local.md in the working directory or above it. If any of them exist, they are read instead of AGENTS.md. ~/.claude/CLAUDE.md, the organization's managed CLAUDE.md, and files in .claude/rules/ are not part of this check and are loaded together with AGENTS.md.

When there is nothing to match, at session start all AGENTS.md and .claude/AGENTS.md files in the working directory and above are read. In an interactive session, a line like no CLAUDE.md found; AGENTS.md loaded: /home/you/repo/AGENTS.md appears, so you can confirm they were read. A subdirectory's AGENTS.md is read when Claude opens a file there with the Read tool and that subdirectory has none of the three CLAUDE.md-type files.

AGENTS.local.md, AGENTS.override.md, and anything under the .agents/ directory are not read.

Caveat: CLAUDE.local.md is also checked. If you add CLAUDE.local.md to hold personal, uncommitted instructions, AGENTS.md is no longer read.

Switch which files are read with /config

Type /config in a session to open the settings panel, and set Project instructions to one of the following.

  • claude-md-or-agents-md: The default. It reads CLAUDE.md, and if neither CLAUDE.md nor CLAUDE.local.md exists, it reads AGENTS.md.
  • claude-md-and-agents-md: reads both. In each directory, CLAUDE.md comes first and AGENTS.md second. An AGENTS.md that has already been loaded is skipped, so nothing is read twice.
  • claude-md: reads only CLAUDE.md.
  • managed-only: At startup, only your organization's managed CLAUDE.md and auto memory are loaded. All AGENTS.md files are excluded.

You can also set it in a settings file. Write it under cc-plugin-agents-md@builtin in pluginConfigs. It is read from ~/.claude/settings.json, a --settings file, and managed settings, and is ignored in project and local settings files. Here is an example that loads both.

{
  "pluginConfigs": {
    "cc-plugin-agents-md@builtin": {
      "options": { "instructionFiles": "claude-md-and-agents-md" }
    }
  }
}

Before v2.1.285, the ID is agents-md@builtin, and cc-plugin-agents-md@builtin is ignored. Use agents-md@builtin in environments where older versions read the same file. The change takes effect from the next message, in all new sessions.

Sessions that can't be read, and how they differ from CLAUDE.md

In the following cases only CLAUDE.md is read, and Project instructions doesn't appear in /config either: versions before v2.1.277; when you've disabled the built-in plugin in /plugin; and, in some cases, the first session after upgrading from v2.1.276 or earlier (it's read from the next session). Also, before v2.1.281, only CLAUDE.md was read in sessions such as Amazon Bedrock or those with telemetry disabled. In that case, update Claude Code.

How AGENTS.md differs when read through settings

  • The InstructionsLoaded hook does not run. It works as usual for an AGENTS.md that CLAUDE.md imports or symlinks.
  • While CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD is set, AGENTS.md is not read in directories added with --add-dir.
  • An @path import from outside the working directory is loaded only if you have already approved external imports for this project, and no confirmation is shown.

Sharing one file with other tools

Even when it isn't read directly, you can place an @AGENTS.md import in the adjacent CLAUDE.md to make AGENTS.md the single file shared by all tools. Use this when the project also has a CLAUDE.md, when you chose claude-md, or in sessions that can't read it directly. Write Claude-specific instructions below the import.

@AGENTS.md

## Claude Code

Use plan mode for changes under `src/billing/`.

If you don't need any Claude-specific content, a symlink is fine too.

ln -s AGENTS.md CLAUDE.md

Before choosing a symlink, check the following.

  • The Edit and Write tools refuse to write through a symlink and direct you to edit the target AGENTS.md instead.
  • If anyone works on Windows or clones the repo there, use an @AGENTS.md import. Creating a symlink requires Administrator privileges or Developer Mode, and unless core.symlinks is enabled, Git creates a one-line CLAUDE.md.

Either way, in the next session run /context and confirm that CLAUDE.md appears under Memory files.

FAQ

I already have a CLAUDE.md that contains @AGENTS.md. Should I delete it?

According to the official docs, you can leave it. Whatever value Project instructions has, AGENTS.md is never read twice. If nothing else is in the file you can delete it, but keep it if some sessions can't read AGENTS.md directly.

Source: How Claude remembers your project

How do I make Claude Code read both CLAUDE.md and AGENTS.md?

In /config, set Project instructions to claude-md-and-agents-md. In a settings file, specify instructionFiles under cc-plugin-agents-md@builtin in pluginConfigs. In each directory, CLAUDE.md is read first and AGENTS.md after it.

Source: How Claude remembers your project

What should you check when AGENTS.md isn't being read?

Check whether CLAUDE.md, .claude/CLAUDE.md, or CLAUDE.local.md exists in the working directory or any parent directory. If one does, AGENTS.md is not read by default. Next, check that Claude Code is v2.1.277 or later and that you haven't disabled the built-in plugin with /plugin. If it can't be read directly, you can use an @AGENTS.md import.
