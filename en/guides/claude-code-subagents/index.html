How to use and create subagents in Claude Code (setup, invocation, and cautions)

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • A subagent processes large outputs you won't need to refer to later, such as search results and logs, in a separate context and returns only a summary to the main conversation.
  • To create one, just place a Markdown file with YAML frontmatter in ~/.claude/agents/ (for all projects) or .claude/agents/ (for that project only). You can also have Claude write it for you.
  • Before adopting subagents, check the tool restrictions, the subagent's own token consumption, and the concurrency limit.

What a subagent is and what it can do

According to the official docs, a subagent is a specialized AI assistant that handles a specific type of task. In Claude Code (Anthropic's AI coding agent that runs in the terminal), you use one when search results, logs, or file contents would fill the conversation without being referenced again. A subagent works in its own context and returns only a summary.

Each subagent runs with its own context window, system prompt, tool access, and independent permissions. You can also restrict its tools, or route work to a fast, low-cost model such as Haiku to keep costs down. When you find yourself calling the same kind of worker with the same instructions again and again, that is a good sign it is time to define a custom subagent.

Note that subagents also send their own requests, and these count toward the same usage limit as the main conversation. Subagents also run within a single session.

Built-in subagents and how to stop them

Claude Code has built-in subagents, which Claude uses automatically when it judges them appropriate. Explore is a read-only agent for searching and analyzing the codebase; Write and Edit are denied. Plan is a read-only agent used for research in plan mode. General-purpose is for multi-step tasks that require both exploring and making changes. Explore and Plan start without CLAUDE.md and the git status snapshot, which keeps research fast and cheap.

To prevent a specific subagent from being used, add it to permissions.deny in a form such as Agent(Explore).

{
  "permissions": {
    "deny": ["Agent(Explore)", "Agent(my-custom-agent)"]
  }
}

If you deny the Agent tool itself, Claude no longer delegates to any subagent.

Steps to create your first one

In the official docs quickstart, you ask Claude to create it. A subagent is a Markdown file with YAML frontmatter, so you can also write it by hand. In Claude Code, tell it which subagent you want to create and where to save it.

Create a personal code-improver subagent in ~/.claude/agents/ that scans
files and suggests improvements for readability, performance, and best
practices. It should explain each issue, show the current code, and
provide an improved version. Make it read-only and have it use Sonnet.

Claude writes a file containing name, description, tools, model, and a system prompt. Open ~/.claude/agents/code-improver.md and check that it matches what you asked for. The result looks like this.

---
name: code-improver
description: Scans files and suggests improvements for readability, performance, and best practices. Use after writing or modifying code.
tools: Read, Grep, Glob
model: sonnet
---

You are a code improvement specialist. For each issue you find, explain
the problem, show the current code, and provide an improved version.

This file is in ~/.claude/agents/, so it is available in every project on that machine. If you want to limit it to one project, move it to that project's .claude/agents/.

To try it, ask Claude to delegate, for example: Use the code-improver agent to suggest improvements in this project.

Settings: location, tools, model, and permissions

The only required fields are name and description. Claude reads description to decide whether to delegate, so state clearly and briefly when the subagent should be used. If the combined descriptions of subagents, excluding built-in ones, exceed 15,000 tokens, a warning appears at startup, so put the details in the system prompt.

Locations and precedence

If subagents share the same name, the one in the higher-priority location is used.

  • Organization managed settings: organization-wide, priority 1 (highest)
  • --agents CLI flag: current session only, priority 2
  • .claude/agents/: current project, priority 3
  • ~/.claude/agents/: all of your own projects, priority 4
  • Plugin agents/ directory: applies wherever the plugin is enabled, priority 5 (lowest)

If you check the project-level file into version control, your team can share and improve it.

Tools, models, and permission modes

tools is an allowlist and disallowedTools is a denylist. If you omit tools, the subagent inherits all available tools. If you specify both, disallowedTools is applied first. model accepts sonnet, opus, haiku, fable, a full model ID, or inherit. For how the model is chosen when omitted, check the official docs.

If you omit permissionMode, the subagent inherits the permission mode of the main conversation. When the main conversation is in bypassPermissions, acceptEdits, or auto mode, the subagent runs in the same mode and the configured value is ignored.

How to invoke it and operational notes

There are three ways to invoke a subagent: name it in natural language; use an @-mention to make Claude use that subagent for a single task; or use the --agent flag or the agent setting to run the entire session as that subagent.

claude --agent code-reviewer

With --agent, the custom subagent's system prompt completely replaces the default Claude Code system prompt, unless the prompt is empty.

A subagent starts with a fresh context and cannot see the conversation history. It starts from a delegation message in which Claude summarizes the work.

Keep the following in mind when operating this. If you run many subagents and they return detailed results, they consume a large share of the main conversation's context, and each subagent also uses its own tokens. The default limit on concurrent subagents is 20, and going over it fails with Concurrent subagent limit reached. To change it, set CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS.

Tasks with many back-and-forth exchanges, tasks that share context across multiple phases, and small fixes suit the main conversation. Tasks with long output, tasks where you want to restrict tools, and tasks where only a summary needs to be returned suit subagents.

This is based on the official docs as of writing (October 2026), and the Claude Code version required differs by feature. Before you roll it out company-wide, check the official docs to confirm it works with the version you use.

FAQ

What if Claude can't find the subagent I created?

The official docs advise restarting Claude Code and trying again. This applies when ~/.claude/agents/ didn't exist before the session started, because a running session doesn't detect a newly created agents directory. A directory added with --add-dir also needs a restart after you add or edit its .claude/agents/.

Source: Create custom subagents

How do I turn off a built-in subagent such as Explore?

Add Agent(Explore) to permissions.deny. In the CLI, you can also specify it with claude --disallowedTools "Agent(Explore)". It works for both built-in and custom subagents.

Source: Create custom subagents

Do subagents remember the contents of the main conversation?

The official docs explain that, except for forks (a special type that inherits the entire conversation), a subagent doesn't see the conversation history or the files Claude has already read. It starts work from a delegation message in which Claude summarizes the task.
