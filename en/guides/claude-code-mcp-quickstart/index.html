How to connect an MCP server to Claude Code (add, check, remove)

Published: October 17, 2026 ・ Chuki DX Lab ・ Content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section

Key takeaways

  • According to the official docs, you register an MCP server with claude mcp add and check its connection status with claude mcp list.
  • The default registration scope is local, which makes the server available only to you in the current project. Use --scope user for all your projects, or --scope project to share it with the team.
  • Connected servers consume context window, so remove the ones you don't use with claude mcp remove.

What MCP is and what you need before you start

MCP (Model Context Protocol) is a mechanism that lets Claude Code (Anthropic's AI coding agent that runs in the terminal) use capabilities beyond its built-in features, such as searching issue trackers, querying databases, and controlling a browser. These tools are provided by MCP servers, which can run on your local machine or as hosted services.

The official docs assume you have already installed and authenticated Claude Code and have a terminal open in your project directory (an empty directory is fine). This article covers the CLI steps in the official docs as of writing (October 2026). For adding it from the desktop app, VS Code, or the web, see the official docs.

Source: Connect to MCP servers

Add a server and verify the connection

The official example is a hosted server that lets you run full-text search over the Claude Code docs with no authentication. Run it in a regular terminal, not inside a claude session.

claude mcp add --transport http claude-code-docs https://code.claude.com/docs/mcp

--transport http indicates a server exposed at a URL. claude-code-docs is a name you choose freely, and you use it in operations such as claude mcp remove. When you run the command, a File modified: line is shown, indicating the configuration file it wrote to.

Next, check the connection status.

claude mcp list

According to the official docs, the main indicators mean the following.

  • ✔ Connected: The server is ready to use.
  • ! Needs authentication: Requires signing in through the browser, or a token passed with --header.
  • ✘ Failed to connect: The server is not responding.
  • ! Connected · tools fetch failed: The connection succeeded, but the tool list could not be retrieved. Run claude mcp get <name> to see the error details.

Source: Connect to MCP servers

Use / Delete

Start a session and make your request, naming the server.

claude
Use the claude-code-docs server to look up what MCP_TIMEOUT does

Normally Claude picks the right tool without you naming the server. If you are asked for permission on the first call, approve it. If the tool call in the output includes the server name, you can confirm the answer came from the MCP server.

You can delete it when you're done.

claude mcp remove claude-code-docs

The tool names and instructions of connected servers are loaded in every session and use up the context window (the amount of information Claude can handle at once). Removing servers you don't use keeps that space free.

Scopes and settings file locations

claude mcp add registers to local by default. The storage location for each scope is as follows.

  • local: The entry for that project in ~/.claude.json. Only you, only this project (default).
  • project: the .mcp.json at the project root. It applies to everyone who clones the repository.
  • user: The top-level mcpServers in ~/.claude.json. Only you, across all projects.

On Windows, ~/.claude.json corresponds to %USERPROFILE%\.claude.json. Run claude mcp get claude-code-docs to see which scope defines the server.

The scope is fixed when you add a server, so to change it, remove it and register it again. For example, remove the local definition and then add it at user scope.

claude mcp remove claude-code-docs --scope local
claude mcp add --scope user --transport http claude-code-docs https://code.claude.com/docs/mcp

To share with your team, add it at project scope and commit .mcp.json to version control.

claude mcp add --scope project --transport http claude-code-docs https://code.claude.com/docs/mcp

When a member starts Claude Code, an approval prompt appears, and the server connects once they approve. This prevents a cloned repository from launching processes without the user's consent. .mcp.json is read at startup, so start a new session after editing it.

Local servers and servers that require sign-in

Local server (stdio)

A stdio server is a program that Claude Code launches as a subprocess on your local machine. The official example is the Playwright MCP server, which runs through npx and therefore requires Node.js 18 or later.

claude mcp add playwright -- npx -y @playwright/mcp@latest

Don't add --transport; the launch command goes after --. Even if you see Added, it has only been saved, so confirm with claude mcp list. On the first run, you may see ✘ Failed to connect while npx is still downloading; wait a moment and run it again, and it becomes ✔ Connected.

Servers that require sign-in

Hosted services such as Sentry, Linear, and Notion are protected with OAuth. The official example is Sentry.

claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

Right after you add a server, it shows ! Needs authentication. This is expected. In a session, open /mcp, select sentry and press Enter, then choose Authenticate and a sign-in screen opens in your browser. For servers that authenticate with a fixed token, pass the token when you add the server with --header "Authorization: Bearer <token>".

What to check when you can't connect

Check the status with /mcp inside a session, or claude mcp list from the shell. The main causes listed in the official docs are as follows.

  • No MCP servers configured: A local server added in a different project is tied to that project. Register it again in the current project or use --scope user. Other causes are looking at the wrong config file path (the correct ones are ~/.claude.json and <project>/.mcp.json) or a mistake in .mcp.json.
  • Failed to connect or Connection error: the server isn't running or the URL isn't responding. For HTTP servers, check reachability with curl; for stdio servers, run the configured command directly and look at the error.
  • Startup timeout: If startup exceeds the default 30 seconds, extend it with the MCP_TIMEOUT environment variable (in milliseconds).
  • Tools don't appear: a required environment variable (such as an API key) may be missing. Pass it with --env KEY=value.
  • Changes to .mcp.json are not applied: restart the session. If you previously declined approval, run claude mcp reset-project-choices.
MCP_TIMEOUT=60000 claude

What error details show can vary by version, so check the official docs for specifics.

FAQ

Why can't I use a server I added in a different project?

According to the official docs, the default local scope is active only in the project where you added the server. To use it in all projects, register it again with --scope user.

Source: Connect to MCP servers

If it shows Added, is the server connected?

In the stdio server example, the docs explain that Added only means the configuration was saved, not that the command is guaranteed to run. Check for ✔ Connected with claude mcp list. On the first run, it may show a failure while npx is still downloading.

Source: Connect to MCP servers

What should I do if it says a server with the same name can't be added?

A server with the same name already exists in the same scope. Delete it with claude mcp remove claude-code-docs, or use a different name. If the same name exists in multiple scopes, you'll see exists in multiple scopes, so use --scope to choose which one to remove.
