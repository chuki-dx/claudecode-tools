Examples of how to use Claude Code: official recipes and basic workflows

Published: October 15, 2026 · Chuki DX Lab · The content is based on the official docs and other sources as of writing (October 2026); sources are listed at the end of each section.

Key takeaways

  • Common workflows in the official docs collects short example prompts for using Claude Code (Anthropic's AI coding agent that runs in the terminal) to understand code, fix bugs, refactor, write tests, create PRs, and maintain documentation.
  • Resuming a conversation, working in parallel with worktrees, checking ahead of time in plan mode, and embedding Claude Code in scripts can also be started with short commands.
  • When you distribute this within your company, reword the prompts to fit your own projects. For uses where it can't ask questions midway, such as scheduled runs, the key is to write the success conditions into the prompt.

How to understand code and fix bugs

This article is based solely on the official docs page "Common workflows" as of writing (October 2026). According to the official docs, this page is a short collection of recipes for everyday development. Each prompt works in any Claude Code interface, and the wording is meant to be adjusted to fit your project.

Understand a new codebase

The official docs describe this flow: go to the project root, start Claude Code with claude, and ask for an overview. Here is an example of a first question.

give me an overview of this codebase

Next, narrow from broad questions to specifics, such as how is authentication handled?. The docs also suggest asking about coding conventions or requesting a glossary of project-specific terms.

Find related code

Be specific about what you're looking for, as in find the files that handle user authentication, and follow the flow with trace the login process from front-end to database. The docs suggest using the terms your project uses. They also explain that installing a code intelligence plugin for your language makes jumping to definitions and finding references more accurate.

Fix a bug

This is a three-step process: share the error, ask for a fix, and have it applied. Start by describing the situation, such as I'm seeing an error when I run npm test. It is recommended to include the command that reproduces the error, the stack trace, the reproduction steps, and whether the error is intermittent or constant.

Refactoring, tests, PRs, and documentation

Refactoring goes in this order: find where the old API is used, ask for improvement suggestions, apply the changes, and verify with tests. Start with find deprecated API usage in our codebase and finish by checking with run tests for the refactored code. The docs advise working in small, testable units and asking Claude to keep backward compatibility if needed.

To add tests, Claude finds uncovered functions, creates a scaffold, adds boundary-condition cases, then runs the tests and fixes failures. According to the official docs, Claude examines existing test files and matches the style and framework in use. This assumes you tell it specifically what you want to verify.

You can create a PR by simply asking create a pr, or you can go step by step starting with a summary of the changes. When Claude creates a PR with gh pr create or glab mr create, or works on an existing PR, the session is linked to that PR, and you can find it later with claude --from-pr 1234 (the number is your own PR number). The official docs advise reviewing the generated PR before submitting it and having Claude list risks and caveats.

For documentation work, you can have Claude Code find gaps with a prompt like find functions without proper JSDoc comments in the auth module, then add the comments. Specify the format you want, such as JSDoc or docstrings.

How to use file references, images, and a notes folder

With @, you can include files or directories in the conversation without waiting for Claude to read them. Examples follow.

Explain the logic in @src/utils/auth.js

According to the official docs, file contents are included if they fit within the Read tool's token limit (25,000 tokens by default), and text files over 256KB are not included. If you specify a directory, only the file listing is included, not the contents. Paths can be relative or full, and when you reference a file, the CLAUDE.md files in that directory and its parent directories are also added to the context.

Data from connected MCP servers can be referenced in the form @server:resource. To stop their contents from being embedded, set CLAUDE_CODE_DISABLE_FILE_MENTIONS=1 in your shell or user settings. This variable requires Claude Code v2.1.299 or later, and it is ignored in project settings and local settings.

Folders for images and notes

You can pass images by dragging and dropping them into the window, pasting with Ctrl+V (Alt+V on Windows and WSL), or specifying an image path. The docs show an example of showing a screenshot of an error screen and asking for the cause.

Also, because Claude Code works in any directory, you can search, edit, and organize folders of markdown notes or documents the same way you would code.

Resuming conversations, parallel work, and plan mode

When work spans multiple sessions, the official docs recommend resuming the conversation. Conversations are stored locally.

claude --continue

This resumes the most recent session in the current directory, and if there is none, it prints No conversation found to continue and exits. To choose from a list, use claude --resume; from inside a running session, use /resume.

Work in parallel with worktrees

If you are building a feature on one terminal while having Claude fix a bug on another, using a worktree keeps the edits from colliding. A worktree is a separate checkout for each branch and is created from an existing commit, so the repository needs at least one commit.

claude --worktree feature-auth

Running the same command with a different name in a second terminal starts an independent parallel session. In a repository with no commits, it fails with Failed to resolve base branch "HEAD": git rev-parse failed.

Review changes before editing with plan mode

If you want to review changes before they are written to disk, use plan mode. Claude reads files and presents a plan, but doesn't edit anything until you approve it.

claude --permission-mode plan

You can also switch with Shift+Tab during a session. While it's active, the status bar shows ⏸ plan mode on.

Subagents, script integration, and scheduled runs

Investigating a large codebase tends to fill up the context with file reads. The official docs describe delegating the investigation to a subagent and receiving only the result. The subagent reads files in its own context window and returns a summary.

use a subagent to investigate how our auth system handles token refresh

In CI, pre-commit hooks, and batch jobs, you can run it non-interactively. Standard input and output work the same way as with typical Unix tools.

git log --oneline -20 | claude -p "summarize these recent commits"

Choose scheduled runs based on where they will run

  • Routines: These run in the cloud and are managed by Anthropic by default. They suit tasks that should run even when your PC is powered off, and can also be triggered by API calls or GitHub events.
  • Desktop scheduled tasks: these run on your own machine through the desktop app. They suit work that directly touches local files, tools, and uncommitted changes.
  • GitHub Actions: Runs in a CI pipeline and suits work tied to repository events, such as creating a PR, or to cron.
  • /loop: runs inside the current CLI session and is meant for lightweight checks while the session is open.

According to the official docs, scheduled tasks run autonomously, so they can't ask questions midway. State the success conditions and how to handle the results explicitly in the prompt.

FAQ

How do I resume Claude Code from where I left off last time?

claude --continue resumes the most recent session in the current directory. To choose from a list, use claude --resume; inside a running session, use /resume.

Source: Common workflows

If I run several tasks at the same time, will the edits conflict?

The official docs show using worktrees, as in claude --worktree feature-auth. If you run the same command from another terminal with a different name, you get an independent parallel session. The repository needs at least one commit.

Source: Common workflows

Can I review the contents before a file is overwritten?

Use plan mode. If you start with claude --permission-mode plan, Claude only presents a plan and does not edit anything until you approve. During a session, you can also switch with Shift+Tab.
