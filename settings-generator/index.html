ルール区分確認状況

settings.json の権限設定でできること

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、作業フォルダの .claude/settings.json に書いた権限ルールに従って、ファイルの読み取りやコマンドの実行を止めたり、実行前に確認を求めたりします。ルールは3種類で、deny は禁止、ask は毎回確認、allow は確認なしで許可です。公式ドキュメントでは deny → ask → allow の順に評価され、どこかで deny されたものはほかで allow しても使えないと説明されています(執筆時点)。

CLAUDE.md(Claude Code が起動時に読む説明書のファイル)に「.env を読まないこと」と書くのは AI へのお願いですが、settings.json のルールは Claude Code 本体が止めます。社内で配るなら、ルールは文章ではなくファイルで配るほうが写し間違いが起きません。

使い方

  1. 上のチェックを選び、「settings.json を保存」を押します。
  2. 業務フォルダの中に .claude フォルダを作り、そこに保存したファイルを置きます。
  3. そのフォルダで claude を起動し、信頼の確認を承認します。/permissions でルールが読み込まれたかを確認できます。

止まらないものがある(既知の限界)

私の検証では、Read(./.env) のルールで Claude の読み取りツールと cat .env は止まりました。一方で、Python スクリプトの中で .env を開く方法では読めてしまいました。公式ドキュメントにも、スクリプトが自分でファイルを開く場合のような間接的な読み書きには効かないと書かれています。Bash(curl *) も、パスで呼ぶ書き方や sh -c で包む書き方は止めないとされています。

deny ルールは「うっかり読む・送る」を防ぐ網として使い、本物の API キーなどは作業フォルダに置かない運用と組み合わせてください。組織で強制したい場合は、利用者が上書きできない管理用設定(managed settings)やサンドボックスが公式ドキュメントで案内されています。

よくある質問

settings.json はどこに置けばよいですか

業務フォルダ(Claude Code を起動するフォルダ)の .claude/settings.json です。Git で共有すれば、同じフォルダを使う全員に同じルールを配れます。個人だけの設定は .claude/settings.local.json、全プロジェクト共通の個人設定は ~/.claude/settings.json です。

deny に入れたのに読めてしまいました

スクリプトの中でファイルを開く場合など、Claude Code がファイルの読み取りと認識できない方法には deny が効きません。上の「既知の限界」をご覧ください。まずは /permissions でルールが読み込まれているかを確認してください。

allow に入れたコマンドで確認が出ます

プロジェクトの allow ルールは、そのフォルダで信頼の確認を承認するまで使われません。対話の画面で一度 claude を起動して承認してください。deny と ask は承認と関係なく効きます。

入力した内容はどこかに送られますか

送られません。このページは HTML と JavaScript だけで動き、生成もブラウザの中で行います。閲覧数を数えるため、開いたページの URL だけを運営者のサーバに送ります(Cookie や外部の解析サービスは使いません。詳しく)。

「個別には未確認」のルールは使わないほうがよいですか

書き方は公式ドキュメントと実機で確認したルールにそろえていますが、そのルール自体で止まるかは試していません。配る前に、ダミーのファイルやコマンドで止まることを手元で確かめてから使うことをおすすめします。
