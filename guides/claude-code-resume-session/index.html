Claude Code で前の会話を再開する方法:--continue・--resume・名前の付け方

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の会話は、プロジェクトごとにローカルへ保存されます。claude --continue で直近、claude --resume で一覧から選んで再開できます。
  • 並行作業が多いなら、claude -n auth-refactor や /rename auth-refactor で名前を付けておくと、claude --resume <name> で直接戻れます。名前を付けなくても、生成された題名なら再開に使えます。
  • 再開しても復元されない起動オプションがあり、bypassPermissions で終わった会話の権限モードも復元されません。社内に配る前に、復元される範囲を確認してください。

前の会話を再開する入口

公式ドキュメントによると、セッションとはプロジェクトのディレクトリに結び付いた保存済みの会話です。作業中に保存され続けるので、終了後や /clear の後でも戻れます。この記事は CLI の話で、デスクトップアプリ、claude.ai/code、VS Code 拡張はそれぞれ別のセッション一覧を持ちます。

  • claude --continue:現在のディレクトリで最も新しいセッションを開き直します
  • claude --resume:セッションピッカー(一覧から選ぶ画面)を開きます
  • claude --resume <name>:名前を付けたセッションを直接再開します
  • claude --resume <transcript-path>:.jsonl の記録ファイルを、フルパスで指定して再開します
  • claude --from-pr <number>:そのプルリクエストに紐づくセッションに絞ったピッカーを開きます
  • /resume:起動中のセッションの中から、別のセッションに切り替えます

執筆時点(2026年10月)の公式ドキュメントに基づく整理で、自分で試した結果ではありません。バージョンで挙動が変わる点もあるため、導入前に最新の公式ドキュメントで確認してください。

名前を付けて再開する

公式ドキュメントでは、複数のタスクを並行するときほど、わかりやすい名前を付けることが勧められています。名前はピッカーで探しやすくなり、名前での再開にも使えます。

  • 起動時:claude -n auth-refactor
  • セッション中:/rename auth-refactor(名前はプロンプトバーにも出ます)
  • ピッカーから:セッションを選んで Ctrl+R
  • プランモードでプランを承認したとき:名前が未設定なら、プランに基づく題名が自動で付きます

名前を付けたら claude --resume <name> か /resume <name> で戻れます。完全一致なら、別のワークツリー(同じリポジトリの別の作業ディレクトリ)にあっても直接再開されます。名前が複数のセッションに当てはまる場合、claude --resume <name> は名前を検索語に入れてピッカーを開き、/resume <name> はエラーになります。その場合は引数なしの /resume でピッカーを開きます。

名前を付けないセッションには、既定の表示名(my-app-3f のような形)と、最初のプロンプトを要約した生成題名が付きます。再開に使えるのは生成題名だけで、既定の表示名を渡してもセッションは見つかりません。

セッションピッカーの使い方と探せる範囲

claude --resume を引数なしで実行するか、セッション中に /resume を実行するとピッカーが開きます。主な操作は次のとおりです。

  • ↑ / ↓ で移動、Enter で再開、Space で内容のプレビュー
  • / などで検索。プルリクエストの URL を貼ると、それを作ったセッションを探せます
  • Ctrl+A はこの端末の全プロジェクト、Ctrl+W はリポジトリの全ワークツリー、Ctrl+B は現在の git ブランチに絞り込み

既定で出るのは、現在のワークツリーのセッションと、/add-dir で現在のディレクトリを追加した別の場所で始めたセッションです。

一覧に出てこないときの注意点があります。最初のプロンプトが /loop だったセッションは、ピッカーにも claude --continue にも出ません。claude -p や Agent SDK で作ったセッションも同様ですが、claude --resume <session-id> にセッション ID を渡せば再開できます。

再開で復元されるものと、渡し直すもの

公式ドキュメントによると、記録から会話を読み込むと、ツール呼び出しと結果を含む会話履歴のほか、次の状態が復元されます。

  • モデル:使っていたモデルで続きます(例外は公式のモデル設定のページを確認してください)
  • エージェント:--agent などで始めたセッションは、そのエージェントとして続きます
  • 権限モード:ターミナルで claude --continue などを -p なしで使うと、終了時の権限モードが復元されます。--permission-mode などで上書きできます
  • 予定タスク:期限切れでないものは復元されますが、バックグラウンドの Bash やモニタータスクは復元されません

復元されないものもあります。--mcp-config、--settings、--plugin-dir、--fallback-model、--add-dir に依存していたセッションは、再開時に渡し直します。/add-dir で途中に追加したディレクトリも復元されません。settings.json などの設定ファイルは起動時に読み直されるので、渡し直しは不要です。

権限モードでは、bypassPermissions で終わったセッションをターミナルで再開しても、そのモードは戻らず、新規セッションと同じモードで始まります。プランモードで終わった場合は、ターミナルの再開でプランモードに戻ります(--fork-session を付けた場合と、deny ルールで ExitPlanMode ツールが外されている場合を除く)。

長く放置した会話の再開

Pro または Max プランで、約1時間を超えて動かしておらず 100,000 トークンを超えるセッションを再開すると、最初のメッセージの前にダイアログが出ます。Resume from summary は /compact を実行して要約を引き継ぎます。以降のコストは下がりますが、要約から漏れた内容は Claude の文脈から消えます。Resume full session as-is は会話をそのまま読み込みます。Don't ask me again を選ぶと、今後の再開でダイアログが出なくなります。

分岐と保存場所での注意

元の会話を残して別の進め方を試すなら、セッション中に /branch を使うか、コマンドラインで次のように --fork-session を組み合わせます。

claude --continue --fork-session

同じセッションを分岐せずに 2 つのターミナルで再開すると、両方のメッセージが 1 つの記録に混ざります。

記録は既定で ~/.claude/projects/<project>/<session-id>.jsonl に保存され、保持期間は30日です。settings.json の cleanupPeriodDays で変更できます。記録の形式は Claude Code の内部仕様でバージョンにより変わるため、直接解析するスクリプトは壊れる可能性があります。人が読む形で残すなら /export を使います。早く消したい場合は claude purge があります。

よくある質問

直近の会話をすぐ再開するには?

claude --continue を使います。現在のディレクトリで最も新しいセッションを開き直します。最初のプロンプトが /loop だったセッションや、claude -p・Agent SDK で作ったセッションは対象外です。まだ動作中のバックグラウンドセッションも開かず、メッセージを出して終了します。

出典: Manage sessions

名前を付けていない会話は再開できますか?

できます。ピッカーで選ぶか、生成された題名を claude --resume や /resume に渡します。既定の表示名(my-app-3f のような形)は再開に使えません。なお、シェルやスクリプトから直接実行した claude -p には題名が付きません。

出典: Manage sessions

別のディレクトリで始めた会話を再開できますか?

claude --resume <session-id> はどのディレクトリからも実行できます。現在のプロジェクトのディレクトリとそのワークツリーを先に探し、次にこの端末の他のプロジェクトを探します。他のプロジェクトでは、記録を持つのが1つだけのときに限って解決されます。一致するものがなければ No conversation found with session ID: <session-id> と表示されます。
