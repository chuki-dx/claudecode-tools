Claude Code の plan モードの使い方:編集の前に計画を確かめる

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、plan モードは Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)に、ファイルを読んで調べさせ、変更案を計画として出させるモードです。計画を承認するまで、ソースの編集はブロックされます(バイパス権限が使える対話型ターミナルセッションは例外です)。
  • 入り方は Shift+Tab、プロンプト先頭の /plan、起動時の claude --permission-mode plan のいずれかです。承認前に Ctrl+G で計画をテキストエディタで直接編集できます。
  • 計画には手間も増えるため、公式ドキュメントでは、方針が不確かなときや複数ファイルに及ぶときに使い、差分を一文で説明できる小さな修正では省くよう説明しています。

plan モードでできること

この記事は、執筆時点(2026年10月)の公式ドキュメントを出典にしています。表示や挙動は環境によって変わる場合があるため、導入前に最新の公式ドキュメントも確認してください。

公式ドキュメントによると、plan モードは、変更を加えずに調べて提案するためのモードです。Claude はファイルを読み、調査のためにシェルコマンドを実行し、計画を書きますが、ソースは編集しません。計画を承認するまで編集はブロックされます。ただし、バイパス権限(bypass permissions)が使える対話型ターミナルセッションは例外です。

計画中のシェルコマンドの扱い

計画中のシェルコマンドの扱いはセッションによって変わり、次のうち最初に当てはまるものが適用されると公式ドキュメントに書かれています。

  1. バイパス権限が使える対話型ターミナルセッション:計画中のコマンドには、分類器(実行前に操作を審査する別モデル)も確認プロンプトも適用されません。
  2. auto モード(定型的な権限確認なしで実行させるモード)が使え、useAutoModeDuringPlan 設定がオン(既定でオン)の場合:クリティカルパスの削除を除くシェルコマンドを、確認プロンプトの代わりに分類器が審査します。承認されたコマンドは実行され、拒否されたものはブロックされます。
  3. auto モードが使えない、または useAutoModeDuringPlan がオフの場合:組み込みの読み取り専用コマンド以外は、承認の確認が出ます。サンドボックスの auto-allow モードが有効な場合も同様です。

plan モードの入り方と抜け方

公式ドキュメントでは、Shift+Tab を押すか、1回のプロンプトの先頭に /plan を付けて plan モードに入ります。CLI から plan モードで始めることもできます。

claude --permission-mode plan

plan モードの間、ステータスバーには ⏸ plan mode on と表示されます。承認せずに抜けるには、もう一度 Shift+Tab を押します。

Shift+Tab の切り替え順は、auto からの最初の1回で default になり、その後 default → acceptEdits → plan と進みます。

利用画面ごとの違い

  • VS Code:プロンプト欄下部のモード表示をクリックして Plan を選びます。
  • JetBrains:IDE のターミナルで動くため、CLI と同じ操作です。
  • Web とモバイル:クラウドセッションのモード選択に Plan があります。

計画の確認・承認と編集

計画ができると Claude が計画を示し、進め方を尋ねます。選べるのは次の3つです。

  • Yes, and use auto mode:承認して auto モードで始めます。組織が無効にしているなど auto モードが使えない場合、表示は Yes, auto-accept edits になります。バイパス権限を有効にして始めた場合は、Yes, and switch to BYPASS PERMISSIONS (no further prompts) for this session と表示されます。
  • Yes, manually approve edits:承認し、編集を1件ずつ確認します。
  • No, keep planning:plan モードにとどまり、変更してほしい点を Claude に伝えます。

承認すると plan モードを抜け、選んだ選択肢が示す権限モードに切り替わって、Claude が編集を始めます。もう一度計画させるときは、Shift+Tab で plan モードに戻すか、次のプロンプトの先頭に /plan を付けます。

Ctrl+G を押すと、提案された計画を既定のテキストエディタで開き、Claude が進む前に直接編集できます。showClearContextOnPlanAccept が有効な場合は、計画を承認して計画時のコンテキストを消去する選択肢が先頭に加わります。

計画を承認すると、すでにセッションに名前を付けていない限り、計画に基づく生成タイトルがセッションに付きます。

plan モードを既定にする設定

ターミナルセッションで、プロジェクトの既定を plan モードにするには、.claude/settings.json の defaultMode を plan に設定します。書き方は、公式ドキュメントの「Start in a different permission mode」にある例に従ってください。

VS Code 拡張が始める会話は、開始時の権限モードについてプロジェクトの設定を読みません。この場合は、VS Code のユーザー設定で claudeCode.initialPermissionMode を plan にします。

画面から Plan を選んだ場合の注意

  • VS Code:モード表示から Plan を選んだ場合、適用されるのはその会話だけです。
  • デスクトップアプリ:Plan を選んだ場合、適用されるのは現在のセッションだけです。

そのほかの設定場所の詳細は、公式ドキュメントで確認してください。

どんな変更で使うか:公式が勧める進め方

公式のベストプラクティスでは、いきなりコードを書かせると、目的とずれた問題を解くコードになることがあるため、plan モードで調査と実行を分けるよう説明しています。流れは次の4段階です。

  1. 探索:plan モードに入り、Claude にファイルを読ませて質問に答えさせます。変更はしません。
  2. 計画:詳細な実装計画を作らせます。Ctrl+G で直接編集できます。
  3. 実装:計画を承認するか Shift+Tab で plan モードを抜け、計画と照らして確認しながらコーディングさせます。
  4. コミット:分かりやすいメッセージでのコミットと PR の作成を依頼します。

ただし公式ドキュメントは、plan モードにはオーバーヘッドもあると述べています。誤字の修正、ログ出力の追加、変数名の変更のように範囲が明確で小さい修正は、直接依頼します。計画が役立つのは、進め方に迷うとき、複数のファイルを変更するとき、不慣れなコードを触るときです。差分を一文で説明できるなら計画は省きます。

公式の一般的なワークフローでも、ディスクに反映される前にレビューしたい変更では plan モードに切り替えると説明されています。情シスの方が社内に展開する場合は、この使い分けの基準をあわせて伝えておくと迷いにくくなります。

よくある質問

plan モードの間、Claude はソースを編集しますか?

公式ドキュメントによると、Claude はファイルを読み、調査のためにシェルコマンドを実行し、計画を書きますが、ソースは編集しません。計画を承認するまで編集はブロックされます。例外は、バイパス権限が使える対話型ターミナルセッションです。

出典: Choose a permission mode

plan モードを、計画を承認せずに抜けるにはどうしますか?

もう一度 Shift+Tab を押します。計画を承認した場合も plan モードを抜けますが、その場合は選んだ選択肢が示す権限モードに切り替わり、Claude が編集を始めます。

小さな修正でも plan モードを使うべきですか?

公式のベストプラクティスでは、範囲が明確で修正が小さい場合(誤字の修正、ログ出力の追加、変数名の変更など)は、直接依頼するよう説明しています。差分を一文で説明できるなら、計画は省くとされています。
