Claude Code の利用状況を把握する方法:アナリティクスと OpenTelemetry の使い分け

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の利用状況は、公式ドキュメントによると、プラン別のアナリティクスダッシュボードと OpenTelemetry の書き出しで把握できます。
  • ダッシュボードは利用者数やセッション数、承認された行数の確認向きです。ユーザーごとのトークン数やコスト見積りは、OpenTelemetry の書き出しか spend レポートで見ます。
  • 全員に配る場合は管理者設定(managed settings)に環境変数を書きます。リポジトリ内の設定ファイルでは OpenTelemetry の送信先を決められません。

見たい数字でダッシュボードを選ぶ

公式ドキュメントによると、Claude Code にはチーム向けのアナリティクスダッシュボードがあり、開発者の利用傾向や貢献指標を確認できます。ダッシュボードはプランごとに分かれています。

  • Claude for Teams / Enterprise:利用指標、GitHub 連携による貢献指標、リーダーボード、データのエクスポートを含みます。
  • API(Claude Console):利用指標、支出の追跡、チームのインサイトを含みます。

ユーザーごとのトークン数やコスト見積りが必要な場合は、OpenTelemetry の書き出しを設定するか、組織のアナリティクス設定から spend レポートを書き出します。spend レポートには、ユーザー別・モデル別のトークン使用量と使用クレジットの推定支出が載ります。

本記事は執筆時点(2026年10月)の公式ドキュメントに基づきます。画面名や条件は変わる可能性があるため、導入前に公式ドキュメントで確認してください。

Teams / Enterprise のダッシュボードと貢献指標の設定

閲覧できるのは Admin と Owner です。利用指標(承認された行数、提案の承認率、日次のアクティブユーザー数とセッション数)は、すべての Teams / Enterprise アカウントで使えます。

一方、PR と行数を扱う貢献指標は公開ベータで、GitHub 組織を接続する追加設定が必要です。設定には Owner ロールが必要で、GitHub アプリのインストールは GitHub 管理者が行います。

有効化の手順

  1. GitHub 管理者が、組織の GitHub アカウントに Claude の GitHub アプリをインストールする。
  2. Claude の Owner が、管理設定の Claude Code のページで Claude Code analytics 機能を有効にする。
  3. 同じページで「GitHub analytics」のトグルを有効にする。
  4. GitHub の認証フローを完了し、分析に含める GitHub 組織を選ぶ。

データは有効化から通常 24 時間以内に表示され、毎日更新されます。

貢献指標が出ない条件

  • 対象は claude.ai 組織内のユーザーだけで、Claude Console API や第三者連携の利用は含まれません。
  • Zero Data Retention が有効な組織では貢献指標は使えず、利用指標のみ表示されます。
  • 対象は github.com 上のリポジトリです。GitHub Enterprise Server のリポジトリは利用指標のみです。

数字の読み方と帰属ルールの注意

公式ドキュメントでは、貢献指標は意図的に控えめで、実際の影響より少なく出る見積りだと説明されています。Claude Code の関与に高い確信がある行と PR だけが数えられます。

  • 帰属の判定は、マージされた PR の追加行と Claude Code のセッション活動を照合して行います。
  • 対象は PR のマージ日の21日前から2日後までのセッションで、枠の外は考慮されません。
  • 開発者が大きく書き換えたコード(20% を超える差)は Claude Code に帰属されません。
  • ロックファイル、生成コード、ビルドディレクトリ、テストのフィクスチャ、1,000文字を超える行は、自動生成とみなされ除外されます。
  • Claude Code 支援の行を含むマージ済み PR には、GitHub 上で claude-code-assisted ラベルが付きます。

Enterprise プランでは、Claude Enterprise Analytics API でユーザー別のレポートを取得できます。Primary Owner が read:analytics スコープのキーを作成します。Teams プランでは使えません。

API(Claude Console)の場合、ダッシュボードの閲覧には UsageView 権限が必要で、Developer、Billing、Admin、Owner、Primary Owner のロールに付与されています。GitHub 連携の貢献指標は現時点で使えません。支出額は分析用の見積りなので、実際の費用は請求ページで確認します。

OpenTelemetry で書き出す設定の基本

公式ドキュメントによると、OpenTelemetry は環境変数で設定します。次はクイックスタートの例で、exporter(送信方式)は必要なものだけ設定すればよいとされています。

# 1. Enable telemetry
export CLAUDE_CODE_ENABLE_TELEMETRY=1

# 2. Choose exporters (both are optional - configure only what you need)
export OTEL_METRICS_EXPORTER=otlp       # Options: otlp, prometheus, console, none
export OTEL_LOGS_EXPORTER=otlp          # Options: otlp, console, none

# 3. Configure OTLP endpoint (for OTLP exporter)
export OTEL_EXPORTER_OTLP_PROTOCOL=grpc
export OTEL_EXPORTER_OTLP_ENDPOINT=http://localhost:4317

# 4. Set authentication (if required)
export OTEL_EXPORTER_OTLP_HEADERS="Authorization=Bearer your-token"

# 5. For debugging: reduce export intervals, and reset them for production use
export OTEL_METRIC_EXPORT_INTERVAL=10000  # 10 seconds (default: 60000ms)
export OTEL_LOGS_EXPORT_INTERVAL=5000     # 5 seconds (default: 5000ms)

# 6. Run Claude Code
claude

デバッグ用に短くした書き出し間隔は、本番では元に戻すよう書かれています。

確認方法は次のとおりです。メトリクスを書き出す設定なら、セッション開始時に出る claude_code.session.count を送信先で探します。ログのみの設定なら、プロンプトを送って claude_code.user_prompt イベントを探します。

届かない場合は、デバッグファイルを指定して Claude Code を起動し、出力されたログを確認します。設定した exporter の失敗は [3P telemetry] のエラーとして出ます。[Anthropic telemetry] で始まる行は Anthropic 側の別の運用テレメトリで、設定の問題を示すものではありません。

管理者設定で全員に配るときの注意

管理者は managed settings ファイルで、全ユーザーの OpenTelemetry 設定を配れます。公式ドキュメントの設定例は次のとおりです。

{
  "env": {
    "CLAUDE_CODE_ENABLE_TELEMETRY": "1",
    "OTEL_METRICS_EXPORTER": "otlp",
    "OTEL_LOGS_EXPORTER": "otlp",
    "OTEL_EXPORTER_OTLP_PROTOCOL": "grpc",
    "OTEL_EXPORTER_OTLP_ENDPOINT": "http://collector.example.com:4317",
    "OTEL_EXPORTER_OTLP_HEADERS": "Authorization=Bearer example-token"
  }
}

注意点は次のとおりです。

  • Claude Code は、リポジトリの .claude/settings.json と .claude/settings.local.json にある OpenTelemetry の exporter 変数を無視します。有効化や送信先の指定はリポジトリからはできず、managed settings か、各開発者のシェルまたは ~/.claude/settings.json で設定します。
  • OTEL_* の環境変数は、Bash ツール、フック、MCP サーバー、言語サーバーなど、Claude Code が起動するサブプロセスには渡されません。
  • managed settings で OTEL_EXPORTER_OTLP_ENDPOINT を設定すると、開発者が設定した信号別のエンドポイントは起動時に削除され、デバッグログに警告が出ます。
  • OTEL_METRICS_EXPORTER や OTEL_LOGS_EXPORTER は通常の優先順位に従い、開発者が信号を無効にしたり、コンソール出力に切り替えたりできます。固定したい場合は managed settings にも書きます。この項目には Claude Code v2.1.223 以降という条件が付いています。

なお、この削除は届け先を変えるもので、Claude Code が何を収集するかは変えません。管理コンソールの Data and privacy settings で Monitoring の下にある Cowork 用の OpenTelemetry フォームは Cowork のセッションにだけ適用され、ターミナルの CLI や Code タブの書き出し先にはなりません。

よくある質問

GitHub 連携なしでも利用状況は見られますか?

利用指標と導入状況のデータは、すべての Claude for Teams / Enterprise アカウントで使えます。PR や行数の貢献指標は GitHub 組織の接続が必要で、Zero Data Retention が有効な組織では使えません。

出典: Track team usage with analytics

OpenTelemetry の設定が効いているか確認するには?

メトリクスの書き出しなら claude_code.session.count を、ログのみならプロンプトを送って claude_code.user_prompt イベントを確認します。届かなければデバッグファイルを指定して起動し、[3P telemetry] のエラーを探します。

出典: Monitoring

リポジトリの設定ファイルに OpenTelemetry の設定を入れて配れますか?

配れません。公式ドキュメントによると、リポジトリの .claude/settings.json と .claude/settings.local.json にある exporter 変数は無視されます。managed settings か、各開発者のシェルまたは ~/.claude/settings.json を使います。
