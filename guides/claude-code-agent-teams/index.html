Claude Code のエージェントチーム(agent teams)とは:使いどころ・始め方・制限

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • エージェントチームは、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の複数のセッションが役割を分けて並行し、互いにメッセージを送り合う機能です。公式ドキュメントによると実験的で、既定では無効です。
  • 向くのは調査・レビュー、機能の分担、仮説を競わせるデバッグなどです。逐次作業や同じファイルの編集には向かず、トークンも単一セッションよりかなり多く使います。
  • 有効化は環境変数を 1 にするだけで、依頼は自然言語で行います。最初は 3-5 人程度で、コードを書かない調査やレビューから試すのが公式の勧めです。

どんな作業に向くか

公式ドキュメントによると、エージェントチームは並行して探索することに実際の価値がある作業で最も効果的です。特に向くのは次の4つです。

  • 調査とレビュー：複数のチームメイトが問題の別の側面を同時に調べ、所見を共有して互いに検証します
  • 新しいモジュールや機能：それぞれが別の部分を持ち、互いの作業を踏みません
  • 競合する仮説でのデバッグ：異なる仮説を並行して試し、より早く答えに収束します
  • 層をまたぐ調整：フロントエンド、バックエンド、テストにまたがる変更を別々のチームメイトが担当します

一方で、調整の手間が増え、単一セッションよりトークンを大幅に多く使います。逐次的な作業、同じファイルの編集、依存関係の多い作業では、単一セッションかサブエージェント(メインのエージェントに結果を返す作業役)のほうが効果的とされています。

サブエージェントとの違い

公式ドキュメントによると、どちらも作業を並列化できますが動き方が違います。サブエージェントは結果をメインのエージェントに返します。チームでは、チームメイトが共有タスクリストで作業を引き受け、互いに直接やり取りします。

  • コンテキスト：どちらも独自のコンテキストウィンドウを持ちます
  • 向く用途：サブエージェントは結果だけが重要な焦点の絞られた作業、チームは議論や協力が要る複雑な作業です
  • トークンコスト：サブエージェントは結果が要約されて戻るため低め、チームは各チームメイトが別々の Claude インスタンスなので高めです

素早く報告する作業役が欲しいならサブエージェント、所見の共有や相互の反論、自律的な調整が要るならチームを使う、という整理です。

有効化と最初のチームの作り方

公式ドキュメントによると、エージェントチームは既定で無効です。環境変数 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS を 1 にすると有効になり、シェルの環境か settings.json のどちらでも設定できます。

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "1"
  }
}

注意点が2つあります。有効にすると、Claude が名前を付けたサブエージェントがチームメイトとして起動するため、頼んでいなくてもチームができることがあります。また、チームメイトの起動には対話セッションが必要で、-p フラグの非対話モード(Agent SDK のセッションを含む)では起動せず、通常のサブエージェントとして動きます。

使うときは、タスクとチームメイトの構成を自然言語で書きます。公式の例は、三つの役割が互いを待たずに探索できるので向いているとされています。

I'm designing a CLI tool that helps developers track TODO comments across
their codebase. Spawn three teammates to explore this from different angles:
one on UX, one on technical architecture, one playing devil's advocate.

Claude は、Task ツールを持つセッションでは共有タスクリストを作り、視点ごとにチームメイトを起動し、終わると所見をまとめます。ときにはチームではなくサブエージェントが使われ、エージェントパネルには両方が並ぶため、パネルだけではチームかどうか判断できません。その場合はエージェントチームを明示して再度頼みます。チームメイトは上下矢印で選び、Enter でその記録を開いて直接メッセージを送れます。

運用のコツ

  • 文脈を渡す：チームメイトは CLAUDE.md、MCP サーバー、スキルを自動で読み込みますが、リードの会話履歴は引き継ぎません。起動時の依頼文にタスク固有の情報を入れます
  • 人数：厳密な上限はありませんが、トークンは人数に比例して増え、調整の手間も増えます。ほとんどの場合は 3-5 人から始めます
  • タスクの粒度：小さすぎると調整の手間が上回り、大きすぎると確認なしで長く動いて無駄になりやすくなります。関数、テストファイル、レビューのような、成果物が明確な単位が適切です
  • ファイルの衝突：2人が同じファイルを編集すると上書きになります。担当ファイルを分けます
  • 最初は調査とレビューから：PR のレビューやライブラリの調査など、コードを書かない作業から始めると、並列実装の調整の難しさなしに効果を確かめられます
  • 見守る：長く放置すると無駄な作業になるリスクが上がります。進捗を確認し、方針を修正します

リードが待たずに自分で実装を始めたときは、次の一文を伝えます。

Wait for your teammates to complete their tasks before proceeding

制限とトラブル時の対処

執筆時点(2026年10月)の公式ドキュメントでは、エージェントチームは実験的な機能で、次の制限があるとされています。

  • /resume と /rewind ではプロセス内のチームメイトが復元されません。再開後は新しいチームメイトを起動するようリードに伝えます
  • タスクの状態が遅れることがあり、完了が記録されないと依存するタスクが止まります。作業が済んでいるか確認し、手動で更新するかリードに促してもらいます
  • 1セッションにつきチームは1つで、入れ子のチームや、チームメイトのリードへの昇格はできません
  • 分割ペインは tmux か iTerm2 が必要です。既定のプロセス内モードはどの端末でも動きますが、VS Code の統合ターミナル、Windows Terminal、Ghostty では分割ペインは未対応です

運用面では、チームメイトの許可要求がリードに上がって煩雑になるため、起動前に権限設定で一般的な操作を事前承認しておくと中断が減ります。チームメイトがエラーで止まったときは、パネルで選んで出力を確認し、追加の指示を出すか代わりのチームメイトを起動します。リードが全タスクの完了前に終わったと判断した場合は、続けるよう伝えます。

意図せずチームが作られるのを避けたい場合は、次のように 0 にします。

{
  "env": {
    "CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS": "0"
  }
}

新しいセッションは不要で、保存すると実行中のセッションに再適用されます。ただし、プロジェクト設定やローカル設定などで 1 にしていればそちらが優先され、組織の管理設定で有効にされている場合は管理者に値の変更を頼む必要があります。

よくある質問

エージェントチームとサブエージェントはどう使い分けますか?

公式ドキュメントによると、結果だけが重要な焦点の絞られた作業にはサブエージェント、チームメイト同士が所見を共有し、反論し、自分たちで調整する必要がある複雑な作業にはエージェントチームです。チームはトークンの消費が高くなります。

出典: Orchestrate teams of Claude Code sessions

頼んでいないのにチームメイトが起動します。どうすればよいですか?

有効な間は、Claude が名前を付けたサブエージェントがチームメイトとして起動します。CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS を 0 にすると、サブエージェントとして起動する状態に戻ります。他の設定元で 1 になっていないかも確認してください。

出典: Orchestrate teams of Claude Code sessions

セッションを再開したらチームメイトはどうなりますか?

公式ドキュメントによると、/resume と /rewind ではプロセス内のチームメイトは復元されません。リードが存在しないチームメイトにメッセージを送ろうとすることがあるため、その場合は新しいチームメイトを起動するよう伝えます。
