Claude Code のスラッシュコマンドの使い方と、作業の流れごとの主なコマンド

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、スラッシュコマンドは Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)をセッションの中から操作する仕組みです。/ を入力すると、自分が使えるコマンドが表示されます。
  • 一覧は作業の流れで覚えるのが現実的です。初回設定は /init、作業中は /plan や /compact、出荷前は /diff や /code-review、困ったときは /rewind や /doctor が入口になります。
  • すべてのコマンドが全員に表示されるわけではありません。プラン、プラットフォーム、環境、バージョンで変わるため、社内で配る前に実機の / メニューと公式ドキュメントで確認してください。

スラッシュコマンドでできることと入力のルール

以下は執筆時点(2026年10月)の公式ドキュメントの内容を整理したもので、私が実機で試した結果ではありません。公式ドキュメントによると、コマンドはセッションの中から Claude Code を操作するためのもので、モデルの切り替え、権限の管理、コンテキスト(AI が会話の中で参照する内容)の整理、ワークフローの実行などを手早く行えます。

/ を入力すると使えるコマンドが表示され、続けて文字を入力すると絞り込めます。次の点を押さえておくと迷いません。

  • コマンドはメッセージの先頭にあるときだけ認識され、コマンド名の後ろの文字列は引数になります。
  • スキル(自作できるコマンド)は例外です。/skill-a /skill-b do XYZ のように続けると、先頭に並べたスキルを読み込み、後ろの文章を各スキルに引数として渡します。連結できるのは6つまでです。
  • Claude の応答中に送ったコマンドは、現在のターンの終了後に実行されます。ただし /status、/tasks、/usage などは応答を止めずに即時に実行されます。
  • フルスクリーン表示では、/theme や /help などのダイアログ系コマンドも即時に開きます。

作業の流れごとの主なコマンド(初回設定から並列実行まで)

リポジトリで最初に使う

/init で CLAUDE.md(プロジェクト向けの案内ファイル)のひな形を作り、/memory で整えます。/mcp で必要な MCP サーバーを設定し、/permissions で承認ルールを決めます。サブエージェント(補助作業を任せる別のエージェント)は、Claude に作成を頼みます。

作業中

大きな変更の前は /plan で計画モードに入ります。/plan fix the auth bug のように説明を付けると、計画モードに入ってすぐその作業を始めます。/model はモデルの切り替えで、新しいセッションの既定としても保存されます。現在のセッションだけ切り替えたい場合は、引数なしで開いた選択画面で s を押します。/effort は推論の度合いの調整です。会話が長くなったら /context で何が占めているかを確認し、/compact で要約して空きを作ります。/btw は、会話履歴に加えたくない横道の質問に使います。

並列で進める

/tasks は現在のセッションのバックグラウンド作業を一覧します。/background はセッション全体を切り離して動かし続け、端末を空けます。/batch はコードベース全体にわたる大きな変更を独立した単位に分け、計画の承認後に、それぞれ別のワークツリーで実行します。git リポジトリか、ワークツリーを作る WorktreeCreate フックが必要です。例は /batch migrate src/ from JavaScript to TypeScript です。

出荷前とセッション間で使うコマンド

公式ドキュメントでは、出荷前は /diff で変更を確認し、/code-review で現在の差分の正しさに関するバグを調べる流れが示されています。--fix を付けると指摘を適用でき、/code-review high 1234 のように PR 番号を渡すとプルリクエストをレビューします。/review は別名です。/code-review ultra はクラウドで複数エージェントによるレビューを行います。/ultrareview の説明には、Pro と Max で無料実行が3回含まれ、その後は利用クレジットが必要とあります。/security-review は現在のブランチの変更を脆弱性の観点で調べ、origin リモートが必要です。

セッション間の移動

  • /clear: プロジェクトのメモリを保ったまま、新しい作業を始めます。
  • /resume: 以前の会話に戻ります。
  • /branch: 現在の会話を分岐させ、別の方向を試せます。元の会話は /resume で戻れます。
  • /fork: 会話を新しいバックグラウンドセッションにコピーします。
  • /teleport: クラウドのセッションをこの端末に取り込みます。claude.ai のサブスクリプションが必要です。
  • /remote-control: このローカルセッションを別の端末から続けられます。

困ったときのコマンド

/rewind は、コードと会話をチェックポイントまで戻すか、会話の一部を要約します。/doctor はインストールや設定、CLAUDE.md の問題を診断し、修正案を示します。修正は確認後に Claude が適用します。/debug は実行時の問題を診断します。デバッグログは既定でオフのため、セッションの途中で実行すると、その時点からの記録になります。/feedback は、セッションの情報を付けてバグを報告します。送信前に同意画面があり、含める履歴の量を選べます。

社内で配る前に確認したい注意点

  • 表示は人によって変わります。公式ドキュメントでは、/desktop は Claude サブスクリプションでサインインした macOS と x64 Windows でのみ表示され、/upgrade は Enterprise プランでは表示されないと例示されています。使えないコマンドはメニューに出ません。
  • バージョン条件があるものがあります。たとえば /output-style は v2.1.269 以降が必要です。
  • 廃止されたものがあります。/vim は v2.1.92 で削除され、/config の Editor mode を使います。/ultraplan は削除済みで、計画モードを使います。
  • 打ち間違いに注意してください。何もハイライトされず、Enter を押すと入力のまま送信されて Unknown command になります。
  • /heapdump のように、メニューに出ない隠しコマンドがあります。全名を入力すると実行されます。不具合を報告するときは -diagnostics.json だけを添付してください。.heapsnapshot は会話の全体と認証情報を含むため、共有しないでください。

よくある質問

一覧にあるコマンドが自分の画面に出ないのはなぜですか?

公式ドキュメントによると、利用できるコマンドはプラットフォーム、プラン、環境によって変わります。利用できないコマンドはメニューから外れ、一致するものがないと No commands match "/name" と表示されます。

出典: Commands

自社用のコマンドを追加できますか?

公式ドキュメントでは、自分のコマンドはスキルで追加すると案内されています。また、MCP サーバーが公開するプロンプトもコマンドとして表示されます。手順の詳細は公式ドキュメントで確認してください。

出典: Commands

/clear と /compact はどう使い分けますか?

/clear は空のコンテキストで新しい会話を始め、前の会話は /resume で戻れます。同じ会話を続けながら空きを作りたいときは、会話を要約する /compact を使います。
