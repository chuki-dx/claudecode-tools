Claude Code デスクトップアプリの始め方と、Team・Enterprise での管理設定

公開: 2026年10月17日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、デスクトップアプリの Code タブからターミナルなしで使えます。利用には Pro、Max、Team、Enterprise のいずれかの契約が必要です。
  • 最初は Local で小さなプロジェクトを選び、権限モードで承認の度合いを決めます。
  • Team・Enterprise では、管理コンソール、管理設定、MDM などでデスクトップアプリの挙動を制御できます。

デスクトップアプリでできること

公式ドキュメントによると、デスクトップアプリはグラフィカルな画面で Claude Code を使えるようにするもので、パソコン上のフォルダにあるコードの作業を Claude に頼み、変更をターミナルなしで確認できます。執筆時点(2026年10月)の公式ドキュメントでは、利用に Pro、Max、Team、Enterprise のいずれかのサブスクリプションが必要とされています。金額は公式の料金ページで確認してください。

アプリには三つのタブがあります。

  • Chat: ファイルにアクセスしない一般的な会話です。
  • Cowork: 他の作業をしている間も、自律的にバックグラウンドで動くエージェントです。
  • Code: ローカルファイルに直接アクセスする対話型のコーディング支援です。権限モードにより、変更の提案ごとに承認するか、変更後に確認します。

Chat と Cowork は Claude のヘルプセンターで扱われているため、この記事は Code タブに絞ります。

インストールとサインイン

公式ドキュメントによると、手順は次のとおりです。

  1. macOS と Windows は、ダウンロードしたインストーラーを実行します。Linux は beta とされ、Ubuntu・Debian 向けに apt または .deb が案内されています。
  2. アプリを起動し、Anthropic アカウントでサインインします。
  3. 上部中央の Code タブをクリックします。

macOS 版は Intel と Apple Silicon の両方に対応した build、Windows 版は x64 向けで、Windows ARM64 には別のインストーラーがあります。アプリに Claude Code が含まれているため、Code タブの利用に Node.js や CLI のインストールは不要とされています。

Code タブでアップグレードを促されたら、有料プランの契約が必要です。オンラインでのサインインを促されたら、完了後にアプリを再起動します。403 エラーは公式ドキュメントの認証トラブルシューティングを参照してください。

最初のセッションと権限モード

  1. Local を選び、Select folder からプロジェクトのフォルダを選びます。公式ドキュメントは、よく知っている小さなプロジェクトから始めることを勧めています。
  2. 送信ボタン横のドロップダウンでモデルを選びます。後から変更できます。
  3. やりたいことを入力します。例は Find a TODO comment and fix it です。
  4. 変更内容を確認し、承認します。

環境は Local のほか、アプリを閉じても続く Cloud、リモートマシンに接続する SSH、Windows の WSL 2 内で動かす WSL も選べます。SSH では、Claude アカウントのサインインが切れると実行中のタスクが止まる場合があります。

権限モードの違い

  • Auto: 分類器がバックグラウンドで操作を審査し、危険なものは確認せずにブロックします。
  • Manual: ファイル編集やコマンド実行の前に確認します。
  • Accept edits: ファイル編集を自動で受け入れます。
  • Plan: ファイルを編集せず、進め方だけを提案します。

Manual では差分表示と Accept/Reject ボタンが出て、承認するまでファイルは変更されません。Auto と Accept edits では、変更後に +12 -1 のような表示が出て、差分表示で確認できます。

組織向け設定:管理コンソールと管理設定

公式ドキュメントによると、Team または Enterprise プランの組織は、管理コンソール、管理設定ファイル、デバイス管理ポリシーでデスクトップアプリの挙動を管理できます。

管理コンソール

  • Desktop: 組織の利用者がデスクトップアプリで Claude Code を使えるか
  • Cloud sessions: クラウドセッションの有効・無効
  • Remote Control: Remote Control の有効・無効

HIPAA を有効にした Enterprise 組織では、Desktop のトグルは既定でオフで、Owner がオンにできます。ただし HIPAA 構成を適用するとオフに戻るため、Owner が改めてオンにする必要があります。Cloud sessions と Remote Control も既定でオフで、HIPAA 構成の適用後は Owner でもオンにできません。

管理設定

管理設定はプロジェクト設定・ユーザー設定より優先され、設定ファイルに書くか、管理コンソールからリモートで配信します。主なキーは次のとおりです。

  • permissions.disableBypassPermissionsMode: "disable" で Bypass permissions mode を使えなくします。
  • disableAutoMode: "disable" で Auto モードを選択肢から外します。
  • disableDesktopLocalSessions: true でデバイス上の Code セッションを止め、他ホストへの SSH とクラウドは残します。管理設定からのみ読まれ、Claude Desktop v1.37937.0 以降が必要です。
  • sshHostAllowlist: SSH セッションの接続先を、ホスト名が一致するものに限ります。

最初の二つはユーザー設定・プロジェクト設定でも動きますが、管理設定に置くと利用者が上書きできません。設定が届く範囲はセッションの種類で異なるため、詳細は公式ドキュメントで確認してください。

配布・ネットワーク・データの扱い

公式ドキュメントによると、デバイス管理では macOS は MDM、Windows はグループポリシー、Linux はポリシーファイルを使います。Claude Code 機能の有効・無効、macOS と Windows の自動更新の制御、カスタムデプロイ URL の設定などができます。

  • macOS: com.anthropic.claudefordesktop の設定ドメイン(Jamf や Kandji など)
  • Windows: レジストリの SOFTWARE\Policies\Claude
  • Linux: root 所有の /etc/claude-desktop/managed-settings.json(root 以外が書き込めると、アプリはこのファイルを受け付けません)

配布は、macOS は MDM と .dmg、Windows は MSIX パッケージです。

ファイアウォールでは、次のホストへの通信が必要とされています。通信は、OTLP・LLM ゲートウェイ・MCP サーバーにカスタムポートを設定しない限り、ポート 443 の HTTPS です。

ワイルドカードを減らす方法や IP 許可リスト、プロキシの扱いは、公式ドキュメントで確認してください。データについては、ローカルセッションではコードをローカルで処理し、クラウドセッションでは会話とコードの文脈が Anthropic の API に送られます。

よくある質問

Node.js や CLI は別に入れる必要がありますか?

公式ドキュメントによると、デスクトップアプリに Claude Code が含まれるため、Code タブの利用に Node.js や CLI のインストールは不要です。ターミナルで claude を使いたい場合は、CLI を別にインストールします。

出典: Get started with the desktop app

社内でデスクトップ版の Code を使わせたくない場合は?

Team・Enterprise では、管理コンソールの Desktop で、組織の利用者がデスクトップアプリで Claude Code を使えるかを制御できます。デバイス上のセッションだけを止めるなら、管理設定で disableDesktopLocalSessions を true にします。

出典: Desktop application

Code タブでアップグレードやサインインを求められたらどうしますか?

公式ドキュメントによると、アップグレードを促される場合は有料プランの契約が必要です。オンラインでのサインインを促される場合は、サインインを完了してアプリを再起動します。403 エラーは公式ドキュメントの認証トラブルシューティングを参照してください。
