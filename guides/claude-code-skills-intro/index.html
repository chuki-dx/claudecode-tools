Claude Code のスキル(SKILL.md)入門:業務手順を Claude に覚えさせる

公開: 2026年10月14日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントにもとづきます

結論

  • スキルは、作業の手順と出力の形に名前を付けて、Claude Code が呼び出せるようにしたものです。.claude/skills/<スキル名>/SKILL.md に置きます。
  • 自動で使われるかどうかは、先頭に書く description の言葉でほぼ決まります。利用者がふだん使う言葉を入れます。
  • 配る前に claude plugin validate .claude/skills で形を確かめ、架空のデータで一度試します。

スキルとは

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のスキルは、「この作業はこの手順で、この形で出す」という手順書をファイルにしたものです。議事録の要約、手順書の下書き、問い合わせ回答の下書きのように、毎回同じ指示を書いている業務ほど向いています。

CLAUDE.md(起動時に毎回読ませる説明書き)との違いは、読み込まれるタイミングです。公式ドキュメントによると、通常のセッションではスキルの説明(description)だけが読み込まれ、本文はそのスキルが呼び出されたときに初めて読み込まれます。そのため、作業ごとの細かい手順をスキルに分けると、CLAUDE.md を短く保ちながら、手順を詳しく書けます。

スキルの使われ方は2通りあります。依頼の内容が description に合えば Claude が自分で使い、利用者が /スキル名 と入力して直接呼び出すこともできます。なお、以前の「カスタムコマンド」(.claude/commands/ のファイル)はスキルに統合され、既存のファイルもそのまま動くとされています。

置き場所

種類置き場所使える範囲
プロジェクト.claude/skills/<スキル名>/SKILL.mdそのフォルダ(リポジトリ)のセッション。Git で共有すればチーム全員
個人~/.claude/skills/<スキル名>/SKILL.mdその PC の自分のすべてのプロジェクト
組織管理用設定のフォルダの .claude/skills/組織が配った PC の利用者全員

同じ名前のスキルが複数の場所にある場合は、組織、個人、プロジェクトの順に優先されます。社内で配るなら、まずプロジェクトの .claude/skills/ に置いて Git で共有する形が始めやすいです。

SKILL.md の形

SKILL.md は2つの部分でできています。先頭の --- で囲んだ部分(frontmatter)に名前と説明を書き、その下に Claude が従う手順を Markdown で書きます。形の例を示します(この例そのものは実機で試したものではありません)。

---
name: notice-draft
description: 社内向けのお知らせ文の下書きを作る。お知らせ、周知文、社内通知の文面を頼まれたときに使う。
---

# 社内お知らせの下書き

## 進め方
1. 依頼から「誰に・何を・いつまでに」を読み取る
2. 読み取れない項目は推測で埋めず、最後に確認事項として挙げる

## 出力の形
- 件名(30字以内)
- 本文(結論を最初に書く。です・ます調)
- 確認事項(読み取れなかった項目の一覧)

公式ドキュメントでは、frontmatter の項目はすべて省略でき、description だけは書くことが推奨されています。name を省くとフォルダ名が呼び出し名になります。

description の書き方

description は、Claude がそのスキルを使うかどうかを判断する材料です。「何をするか」と「いつ使うか」を、利用者が実際に頼むときの言葉で書きます。例の「お知らせ、周知文、社内通知」のように、言い換えを並べておくと合いやすくなります。

公式ドキュメントでは、スキルの一覧に載るときに description と when_to_use を合わせて1,536文字で切られるとされています。大事な使い道を先頭に書きます。

本文の書き方

  • 進め方: 作業の順番を番号付きで書きます。
  • 出力の形: 見出しや項目を決めておくと、誰が頼んでも同じ形でそろいます。
  • 線引き: 推測で埋めない、決まっていないことは保留に入れる、のように迷いやすい点を書きます。

公式ドキュメントでは、SKILL.md は500行以内に収め、詳しい参考資料は別のファイルに分けることが勧められています。

気をつけたい点

  • allowed-tools: スキルの実行中に確認なしでツールを使わせる項目です。公式ドキュメントでは、フォルダの信頼の確認と関係なく効くとされています。社内で配るスキルでは、必要がない限り書かないほうが安全です。
  • 予約されている名前: synced と anthropic-skills は公式ドキュメントで予約されており、スキルの名前に使えません。
  • 手動でだけ使いたいとき: disable-model-invocation: true を書くと、Claude が自分で使うことはなくなり、/スキル名 で呼んだときだけ使われます。

配る前の確かめ方

  1. スキルを置いたフォルダで claude plugin validate .claude/skills を実行し、形の誤りがないかを確かめます。
  2. Claude Code に「使えるスキルの名前を一覧にして」と頼み、一覧に出るかを見ます。
  3. 架空のデータで一度頼み、出力の形どおりになるかを確かめます。実データは使いません。

中小DXラボで Windows 11 と Claude Code 2.1.296 を使って試した範囲では(2026年10月)、name と description の2項目だけの frontmatter で、validate が通り、一覧にも表示されました。

よくある質問

スキルが一覧に出ません

.claude/skills/<名前>/SKILL.md の位置と、先頭行が --- で始まっているかを確かめ、claude plugin validate .claude/skills を実行してください。

スキルが自動で使われません

description の言葉と、頼み方の言葉が合っていないことがあります。利用者がふだん使う言い方を足すか、/スキル名 で直接呼んでください。

サブフォルダに置いたスキルが見つかりません

公式ドキュメントでは、起動したフォルダより下の階層の .claude/skills/ は起動時には読み込まれず、Claude がそのフォルダのファイルを扱ったときに読み込まれるとされています。よく使うスキルは、起動するフォルダの .claude/skills/ に置きます。

SKILL.md のひな形を作る

Claude Code スキル(SKILL.md)雛形生成 で、スキル名・説明・いつ使うか・手順・出力の形を入れると、置き場所つきで SKILL.md のひな形を出力できます。スキル名の書き方と frontmatter の形も確かめます。
