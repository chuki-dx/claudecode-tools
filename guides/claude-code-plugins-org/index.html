Claude Code のプラグインを組織で管理する:配布・必須化・インストール制限の設定

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のプラグインは、管理設定に extraKnownMarketplaces と enabledPlugins を一緒に書くと、全端末へ配布して有効化できます。
  • インストール元は strictKnownMarketplaces(許可リスト)と blockedMarketplaces(拒否リスト)で絞れます。ローカルや URL からの読み込みを止めるには disableSideloadFlags を併用します。
  • ユーザー別・グループ別の出し分けや /plugin の非表示にはキーがありません。執筆時点(2026年10月)の公式ドキュメントに基づくため、導入前に最新の記述をご確認ください。

何ができるか:配布・必須化・制限の全体像

公式ドキュメントによると、マーケットプレイスとは、Claude Code が git リポジトリ、URL、ローカルパスから取得するプラグインのカタログです。端末に登録すると、そこからプラグインをインストールできます。

多数の端末に配るには、管理設定(組織内の全端末が読むポリシーファイル、またはサーバーから配信されるポリシー)に2つのキーを同時に設定します。extraKnownMarketplaces が各端末にマーケットプレイスを登録し、enabledPlugins がそこからインストール・有効化するプラグインを指名します。

出典: Manage Claude Code plugins for your organization

管理設定をどう端末に届けるか

管理設定の届け方は次の3つです。

  • サーバー管理設定:Organization settings > Claude Code > Managed settings にプラグインのキーを JSON で設定します。Claude の組織の Owner ロールが必要です。
  • MDM ポリシー:macOS では設定キーをトップレベルに持つ plist を配ります。Windows ではレジストリ値に JSON 文書全体を文字列で保存します。
  • 管理設定ファイル:プラットフォームのシステムパスに managed-settings.json を置きます。隣の managed-settings.d/ ディレクトリにファイルを足すこともできます。

公式ドキュメントでは、claude.ai の Claude for Teams または Enterprise の組織があり、全デバイスが MDM 配下ではない場合はサーバー管理設定を、そうでなければ MDM かファイルを使うとしています。

複数の経路を使うときの注意

既定では、1台で適用されるのは3つのうち1つだけです。サーバー管理設定、MDM、ファイルの順に確認し、ポリシーのキーを配信した最初のものを使います。サーバー管理設定が無関係なキーを1つでも配信すると、その端末では MDM やファイル側のプラグインキーが無視されます(全ソースから読むキーを除く)。全ソースを適用するには managedSourcesBehavior を "merge" にします。

出典: Manage Claude Code plugins for your organization

プラグインを必須にする設定

マーケットプレイスは extraKnownMarketplaces に、その marketplace.json にある name をキーとして追加します。プラグインは enabledPlugins に plugin-name@marketplace-name の形で追加します。次は組織のマーケットプレイスを登録し、2つのプラグインを強制的に有効にする例です。

{
  "extraKnownMarketplaces": {
    "your-marketplace": {
      "source": { "source": "github", "repo": "your-org/your-marketplace" },
      "autoUpdate": true
    }
  },
  "enabledPlugins": {
    "code-formatter@your-marketplace": true,
    "deploy-helper@your-marketplace": true
  }
}

設定が届くと、ユーザーの次のセッション開始時にマーケットプレイスの登録とプラグインのインストールが行われ、/plugin に表示されます。管理設定はほかのどのスコープより優先されるため、ユーザーが自分のスコープで無効にしても読み込みは止まりません。全スコープでブロックして一覧からも隠すには、管理側の enabledPlugins で false にします。

注意点です。マーケットプレイスがプライベートな git リポジトリなら、各ユーザーに読み取り権限が必要で、クローンは各自の端末の git が保存済みの認証情報で、確認なしに実行します。-p や CI の実行ではインストールがバックグラウンドで進むため、最初のターンにプラグインが無いことがあります。CLAUDE_CODE_SYNC_PLUGIN_INSTALL=1 を設定すると、最初の問い合わせの前にインストールを待たせられます。

1つのリポジトリに限るなら、そのリポジトリの .claude/settings.json に同じキーを書けます。ただし extraKnownMarketplaces は信頼済みのフォルダーでだけ適用され、未信頼のフォルダーではメッセージなしで無視されます。

インストール元を制限する

許可リストと拒否リストは、プラグインの取得元であるマーケットプレイスのソースに対して照合します。マーケットプレイス内の個々のプラグインは対象ではありません。ダウンロード前(追加・インストール・更新・自動更新など)に加え、セッション開始時にもインストール済みのプラグインへ再適用され、合わなければ読み込まれません。

  • 空の許可リスト [] は、公式マーケットプレイスを含むすべてのソースを締め出します。
  • 拒否リストは許可リストより先に確認され、両方に載るソースはブロックされます。
  • 許可リストの github や git は、repo や url、ref、path が一致する必要があります。末尾のスラッシュや .git の有無も別の値として扱われます。複数の URL でクローンできるなら hostPattern が勧められています。
  • { "source": "github", "repo": "your-org/*" } のように、オーナー配下の全リポジトリをまとめて許可できます(Claude Code v2.1.223 以降)。

許可リストを設定して { "source": "skills-dir" } を入れないと、.claude-plugin/plugin.json を持つフォルダーとして ~/.claude/skills/ などに置かれたプラグインが読み込まれなくなります。

公式と自社だけを許可する一般的な構成は次のとおりです。両方の登録、2つのプラグインの強制有効化、--plugin-dir の拒否も含みます。

{
  "strictKnownMarketplaces": [
    { "source": "github", "repo": "anthropics/claude-plugins-official" },
    { "source": "github", "repo": "your-org/*" },
    { "source": "skills-dir" }
  ],
  "extraKnownMarketplaces": {
    "claude-plugins-official": {
      "source": { "source": "github", "repo": "anthropics/claude-plugins-official" }
    },
    "your-marketplace": {
      "source": { "source": "github", "repo": "your-org/your-marketplace" }
    }
  },
  "enabledPlugins": {
    "code-formatter@your-marketplace": true,
    "deploy-helper@your-marketplace": true
  },
  "disableSideloadFlags": true
}

この設定の端末では、許可外のソースの追加は is blocked by enterprise policy を含むメッセージで失敗します。許可リストは何も登録しないため、extraKnownMarketplaces での明示的な登録も必要です。

管理設定でできないことと確認方法

公式ドキュメントは、セキュリティレビューでよく出る要望のうち、現在の設定スキーマに専用のキーが無いものを挙げています。

  • ユーザー別・グループ別の適用:すべてのプラグインキーは、設定を受け取る全ユーザーに適用されます。サーバー管理設定は組織に1つの構成です。グループ別にはエンドポイント管理設定かゲートウェイポリシーを使います。
  • 許可したマーケットプレイス内の特定プラグインの禁止:管理側の enabledPlugins で false にします。
  • /plugin の非表示:無効にするキーはありません。近い構成は、自社のマーケットプレイスだけの許可リスト、配布するプラグインの enabledPlugins、disableSideloadFlags の組み合わせです。
  • --plugin-dir の制御:許可リストは対象外で、disableSideloadFlags が拒否します。
  • claude.ai のプラグイン切り替え:Organization settings > Plugins & skills は、ここで説明したキーを設定しません。そこでの設定は同期プラグインとして CLI に届き、別の制御があります。

配布後の確認

1台なら Claude Code を起動して /plugin を実行し、マーケットプレイスとプラグインが並ぶか見ます。CI では claude -p に --output-format stream-json --verbose を付け、init イベントの plugins を確認します。

よくある質問

ユーザーが自分でプラグインを無効にできますか?

管理設定の enabledPlugins で有効にしたプラグインは、ユーザーが自分のスコープで無効にしても読み込まれます。管理設定がほかのどのスコープより優先されるためです。全スコープで止めたい場合は、管理側で false にします。

出典: Manage Claude Code plugins for your organization

許可リストを設定すれば --plugin-dir も止められますか?

止められません。公式ドキュメントでは、許可リストは --plugin-dir を対象にせず、disableSideloadFlags が拒否するとしています。このキーは --plugin-url なども起動時に拒否します。

出典: Manage Claude Code plugins for your organization

特定の部署だけにプラグインを配れますか?

専用のキーはありません。プラグインのキーは設定を受け取る全ユーザーに適用され、サーバー管理設定は組織に1つの構成です。グループ別にはエンドポイント管理設定かゲートウェイポリシーが挙げられていますので、詳細は公式ドキュメントで確認してください。
