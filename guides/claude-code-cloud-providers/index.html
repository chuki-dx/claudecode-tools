Claude Code を企業導入するには?Bedrock・Google Cloud など提供経路の選び方

公開: 2026年10月17日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 多くの組織には Claude for Teams または Enterprise が推奨され、インフラ構築は不要です。クラウド経由は AWS・GCP・Azure に寄せたい事情があるときの選択肢です。
  • クラウド経由ではクラウドセッションなど Claude サブスクリプション必須の機能が使えず、サーバー管理設定も使えません。
  • 配る前に、モデルの固定、プロキシやゲートウェイの要否、allowedProviders による経路制限を決めます。

まず Teams / Enterprise が推奨される

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、Anthropic 直接かクラウド事業者経由で導入できます。公式ドキュメントによると、多くの組織には Claude for Teams または Claude for Enterprise が最も使いやすいとされ、1つのサブスクリプションで Claude Code と Web 版の Claude が使え、請求も一元化され、インフラ構築も不要です。

Teams はセルフサービスで、SSO、請求管理、サーバー管理設定を含み、小規模チーム向けです。Enterprise はドメインキャプチャ、ロールベースの権限、コンプライアンス API を加えた、大きな組織向けです。Anthropic Console は個人開発者向けとされています。金額は出典にないため、最新の金額は公式の料金ページで確認してください。

Bedrock・Google Cloud・Foundry の違い

インフラ要件がある場合の比較表から、判断に関わる点を抜き出します。

  • Amazon Bedrock:AWS ネイティブ向け。AWS 経由の従量課金で、認証は API キーまたは AWS 認証情報、管理面は IAM ポリシーと CloudTrail です。
  • Google Cloud:GCP ネイティブ向け。公式では「Google Cloud's Agent Platform(旧 Vertex AI)」と表記されます。GCP 経由の従量課金で、認証は GCP 認証情報、管理面は IAM ロールと Cloud Audit Logs です。
  • Microsoft Foundry:Azure ネイティブ向け。Azure 経由の従量課金で、認証は API キーまたは Microsoft Entra ID、管理面は RBAC ポリシーと Azure Monitor です。

プロンプトキャッシュはどの経路でも既定で有効です。Web 版の Claude が含まれるのは Teams/Enterprise だけです。Bedrock と Google Vertex AI では、claude を実行してログイン画面で 3rd-party platform を選ぶと、対話式のセットアップウィザードを起動できます。

クラウド経由で使えない機能に注意する

導入判断の肝がここです。公式ドキュメントの機能一覧によると、クラウドセッション、モバイル版、Routines、Remote Control、Chrome 拡張など、claude.ai アカウントでのサインインが必要な機能は、サードパーティ経由では使えません。Claude Code Desktop は部分的な例外で、条件は公式ドキュメントで確認してください。

  • Bedrock:Web 検索、fast mode、Advisor、Channels、分析ダッシュボード、サーバー管理設定が使えません。
  • Google Cloud:fast mode、Advisor、Channels、分析ダッシュボード、サーバー管理設定が使えません。Web 検索は Opus 4、Sonnet 4、Haiku 4.5 以降のモデルで使えます。
  • Foundry:fast mode、Advisor、Channels、GitLab CI/CD、分析ダッシュボード、サーバー管理設定が使えません。

CLI、VS Code と JetBrains の拡張、サブエージェント、フック、スキル、CLAUDE.md、MCP サーバーは全経路で使えます。代替として、/schedule の代わりに /loop、クラウドセッションの代わりに GitHub Actions や GitLab CI/CD が案内されています(使える CI は経路ごとに異なります)。Zero Data Retention(ゼロデータ保持)は各クラウドとの契約次第です。

プロキシと LLM ゲートウェイ

公式ドキュメントでは、多くの組織は追加設定なしでクラウドを直接使えるとしています。ネットワークや管理の要件がある場合に、次の2つを使います。別の設定で、併用できます。

  • 企業プロキシ:外向き通信を必ずプロキシに通す方針がある場合向けで、HTTPS_PROXY または HTTP_PROXY で設定します。
  • LLM ゲートウェイ:Claude Code とクラウドの間で認証とルーティングを担うサービスです。チーム横断の利用状況の把握、レート制限や予算、認証の一元管理が必要な場合向けで、ANTHROPIC_BASE_URL、ANTHROPIC_BEDROCK_BASE_URL、ANTHROPIC_AWS_BASE_URL、ANTHROPIC_VERTEX_BASE_URL、ANTHROPIC_FOUNDRY_BASE_URL のいずれかで設定します。

使用中のプロバイダやプロキシは /status で確認できます。注意点として、ゲートウェイや独自の ANTHROPIC_BASE_URL 経由では、顧客管理の暗号鍵(CMEK)がそのセッションの運用テレメトリに適用されません。全開発者でテレメトリを止めるには、管理設定で DISABLE_TELEMETRY を配布します。また ANTHROPIC_BASE_URL が Anthropic の API 本体以外のホストを指すと、Remote Control とサーバー管理設定はオフになります。

配る前に決めておく運用ポイント

配布前に決める点を絞ります。

モデルの固定

Bedrock、Google Cloud、Foundry などで導入する場合、ANTHROPIC_DEFAULT_FABLE_MODEL、ANTHROPIC_DEFAULT_OPUS_MODEL、ANTHROPIC_DEFAULT_SONNET_MODEL、ANTHROPIC_DEFAULT_HAIKU_MODEL でモデルバージョンを固定するよう勧められています。固定しないと、既定は Claude Code 内蔵のものになり、最新リリースより遅れたり、アカウントで未有効だったりすることがあります。

経路の制限

管理設定の allowedProviders で、管理下のマシンが使える経路を制限できます。例えば ["bedrock"] は Amazon Bedrock だけを許可します。Claude Code v2.1.285 以降が必要です。

展開の進め方

  • 独自の開発環境なら、ワンクリックで入れられる手段を用意する
  • 最初はコードベースへの質問や小さな修正から始め、計画を立てさせて提案を確認する
  • MCP は中央のチームが設定し、.mcp.json をコードベースに含める

執筆時点(2026年10月)の公式ドキュメントに基づきます。条件は変わり得るため、導入前に最新を確認してください。

よくある質問

Bedrock や Google Cloud 経由でも MCP や VS Code 拡張は使えますか?

公式ドキュメントによると、CLI、VS Code と JetBrains の拡張、サブエージェント、フック、スキル、CLAUDE.md、プラグイン、MCP サーバーは全プロバイダで使えます。ただし claude.ai のコネクタは、claude.ai のサブスクリプションが有効な認証方法のときだけ読み込まれます。

出典: Feature availability

Bedrock では Web 検索を使えますか?

公式ドキュメントの一覧では、Amazon Bedrock の Web 検索は使えません。代替として、URL を指定した WebFetch ツールが案内されています。Google Cloud では Opus 4、Sonnet 4、Haiku 4.5 以降のモデルで、Microsoft Foundry では使えます。

出典: Feature availability

管理者が使える経路を制限するには?

公式ドキュメントによると、管理設定の allowedProviders を使います。例えば ["bedrock"] は Amazon Bedrock だけを許可します。Claude Code v2.1.285 以降が必要です。エンドポイント変数の固定が必要になる場合があるため、詳細は公式ドキュメントで確認してください。
