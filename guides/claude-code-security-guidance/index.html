Claude Code のセキュリティガイダンス・プラグインとは:編集時に何を確かめるか

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)用の security-guidance プラグインは、Claude が書いたコードを編集時・ターン終了時・コミット時に確認し、同じセッションで直させます。
  • どの層も書き込みやコミットを止めず、見逃しもありえます。公式ドキュメントは、多層防御の1層として使うよう書いています。
  • 導入前に、Python と git リポジトリの条件、ターン終了時とコミット時のレビューで追加のモデル利用が発生する点を確認してください。

何ができるか:書いたコードを Claude 自身がレビューする

執筆時点(2026年10月)の公式ドキュメントによると、このプラグインは Claude が自分のコード変更を脆弱性の観点でレビューし、見つかった問題を同じセッションで直す仕組みです。インジェクションや安全でないデシリアライズなどを、プルリクエストに届く前に拾います。

インストール後は自動で動き、呼び出すコマンドはありません。PR 時に動く Code Review とは役割が違い、プラグインは PR に届くものを減らし、Code Review は届いたものを拾います。チェックは次の3か所です。

  • ファイル編集のたび:危険な呼び出しのパターン照合です。モデルは呼ばず、追加コストはかかりません。
  • 各ターンの終わり:そのターンの変更全体を、バックグラウンドのモデルレビューにかけます。
  • Claude が行うコミットやプッシュの時:周辺コードまで読む、より深い agentic(自律的に調べながら進める)レビューです。

導入:前提条件とインストール

公式ドキュメントでは、前提として Python 3.7 以上が PATH 上にあること、作業ディレクトリが git リポジトリであることが挙げられています。git リポジトリ外では、ターン終了時とコミット時のレビューは通知なしにスキップされ、編集時のパターン照合だけが動きます。

agentic なコミットレビューには Python 3.10 以上が必要です。Amazon Bedrock などサードパーティのプロバイダーを使う場合は、モデルを使うレビューすべてが 3.10 以上を必要とします。初回起動時には ~/.claude/security/ の下に仮想環境を作って Claude Agent SDK を入れるため、pip とネットワーク接続が要ります。

ターミナルの Claude Code セッションで、公式の Anthropic マーケットプレイスから入れます。

/plugin install security-guidance@claude-plugins-official

スコープを聞かれるので、ユーザースコープを選ぶと、このマシンで新しく始めるローカルセッションすべてで読み込まれます。クラウドセッションはユーザー設定やリポジトリの .claude/settings.json からプラグインを読み込まないため、扱いは公式ドキュメントで確認してください。

チームで使うには、リポジトリにチェックインするプロジェクト設定に次を書きます。管理者は管理設定の enabledPlugins で、組織全体にも有効化できます。

{
  "enabledPlugins": {
    "security-guidance@claude-plugins-official": true
  }
}

各チェックの中身と上限

編集時の照合例は、eval( や os.system などの動的コード実行、pickle、dangerouslySetInnerHTML、.innerHTML =、.github/workflows/ 配下の編集です。警告は、同じパターンにつき1ファイル・1セッションで1回だけ出ます。

ターン終了時のレビューは、そのターンの git diff を、セキュリティに特化した別の Claude に送ります。認可の回避やサーバーサイドリクエストフォージェリのように、文字列照合では拾えないものが対象です。1ターン最大30ファイルまでで、連続で最大3回までです。

コミット時のレビューは、Claude が Bash ツールで git commit や git push を実行したときだけ動きます。自分のシェルで実行したコミットは、セッション内の ! シェルエスケープも含め、レビューされません。上限はローリング1時間あたり20回です。

独自ルールの追加と、その限界

拡張点は2つで、どちらも追加のみです。組み込みのチェックを、これらのファイルから外すことはできません。

  • モデルを使うレビュー向け:.claude/claude-security-guidance.md に、脅威モデルやレビュー観点を自然な文章で書きます。
  • 編集時パターン向け:.claude/security-patterns.yaml に、正規表現か部分文字列のルールを書きます。同じ形式の .claude/security-patterns.yml と .claude/security-patterns.json も読まれます。

ガイダンスはレビュー担当への指針で、強制力はありません。ある種類の脆弱性を無視せよと書いても、指摘は抑えられません。強制したい場合は、編集をブロックするフックや CI と組み合わせてください。

YAML 形式は PyYAML が import できる必要があり、プラグインは入れてくれません。無い場合ファイルは無視されるため、security-patterns.json なら Python の環境を問わず使えます。カスタムルールは最大50件です。

置き場所は、ユーザー用の ~/.claude/claude-security-guidance.md、プロジェクト用、個人用の .claude/claude-security-guidance.local.md です。存在するものがすべて連結され、ガイダンスは合計 8 KB までです。

コスト・止め方・限界

ターン終了時とコミット時のレビューは追加のモデル利用が発生し、通常のリクエストと同様に利用量へ加算されます。コミットレビューは、1コミットで複数のモデルターンを使うことがあります。既定は Claude Opus モデルで、SECURITY_REVIEW_MODEL と SG_AGENTIC_MODEL で変えられます。プラグインは全プランで使えます。金額や利用量の枠は、公式の料金ページで確認してください。

層ごとに、環境変数で止められます。

  • ENABLE_PATTERN_RULES=0:編集時パターン照合を止めます。
  • ENABLE_STOP_REVIEW=0:ターン終了時レビューを止めます。
  • ENABLE_COMMIT_REVIEW=0:コミット時レビューを止めます。
  • ENABLE_CODE_SECURITY_REVIEW=0:モデルを使うレビューをまとめて止めます。
  • SECURITY_GUIDANCE_DISABLE=1:アンインストールせずに全体を止めます。

どの層も書き込みやコミットを止めず、レビューモデルが見逃すこともあります。公式ドキュメントは、完全な対策ではなく多層防御の1層として扱うよう書いており、既存の静的解析や依存関係スキャナーなどの CI は別に必要です。

よくある質問

プラグインを入れると、自分のシェルで行ったコミットもレビューされますか?

されません。公式ドキュメントによると、コミット時のレビューは Claude が Bash ツールで実行した git commit や git push だけが対象です。自分のシェルで実行したコミットは、セッション内の ! シェルエスケープも含めてレビューされません。

レビューが表示されないとき、何を確認しますか?

公式ドキュメントによると、まず ~/.claude/security/log.txt の診断ログを見ます。メッセージなしにスキップされる理由として、git リポジトリでないこと、Anthropic 認証もサードパーティプロバイダーもないセッション(この場合は編集時のパターン照合だけが動きます)、PyYAML が無いのに YAML のパターンファイルがあることが挙げられています。

出典: Catch security issues as Claude writes code

危険なコードの書き込みを、プラグインで止められますか?

止められません。公式ドキュメントによると、どの層も書き込みやコミットをブロックせず、指摘は Claude への指示として渡されます。ブロックして強制したい場合は、編集をブロックするフックや CI のチェックと組み合わせてください。
