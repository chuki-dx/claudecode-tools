Claude Code が上限で止まったら:リセット後に自動で続ける設定と、続かない場合

公開: 2026年11月26日 ・ 中小DXラボ ・ 内容は執筆時点(2026年11月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、claude.ai のサブスクリプションでサインインした対話セッションなら、使用量の上限で止まってもリセット後に自動で続きを進めます。既定でオンで、v2.1.234 以降が必要です。
  • 自動で続けるには、待っている間セッションを開いたままにします。自動で続かない場合や、3回続けて上限に当たった場合は、/rate-limit-options で次の動きを選びます。
  • 続きの作業でも権限の確認は通常どおり出ます。席を外す前に、確認で止まる可能性を見込んでおいてください。止めたいときは Esc、無効にするなら /config で設定します。

何ができるか:上限のリセット後に自動で続きます

公式ドキュメントによると、claude.ai の使用量の上限でタスクの途中に止まったとき、Claude Code は開いているセッションで待ち、リセット後に自分でタスクを続けます。claude.ai のサブスクリプションでサインインした対話セッションでは既定でオンで、v2.1.234 以降が必要です。執筆時点(2026年11月)の公式ドキュメントに基づく内容です。

続きは、最後のメッセージを再送するのではなく、止まったところから進めるよう Claude に促す形で始まります。

出典: Interactive mode

待っている間の表示と、待ちの終わり方

待っている間、セッション下部の2行に、上限が戻る時刻と続きを始める時刻が出ます。

Usage limit reached · limit resets 3:45pm
Continuing automatically at 3:45pm · Esc to cancel

どちらの行にも、1行目にヘルプのリンク、2行目に /usage-credits to continue now のような続きが付くことがあります。待ちの終わり方は次のとおりです。

  • リセット時:2行目が Continuing shortly · Esc to cancel に変わり、会話に Usage limit reset · Continuing automatically と出て、続きが始まります。
  • PC がスリープした後:約30分を超えるスリープ中にリセットされた場合、1行目が Your usage limit has reset、2行目が Press enter to continue になるので Enter を押します。それより短いスリープ、またはリセット前に終わったスリープなら自動で続きます。
  • 早めに再開:待っている間に /usage-credits での追加を終える、/upgrade の後に再サインインする、/model でモデルを切り替えると、使用量が戻ったか確認し、戻っていればすぐ続きます。ブラウザで自分で行ったアップグレードや購入は確認の対象外です。opusplan のようにプランモードを別のモデルで動かす設定では、リセットまで待ちます。

出典: Interactive mode

席を外す前の注意と、取り消し方

続きのタスクでも、権限の確認は通常どおり出ます。席を外している間に確認の表示で止まることがあります。また、続きの作業がもう一度上限に当たれば、待機が再び始まります。

自動で続けるのは3回までです。3回続けると止まり、Automatic continue stopped after repeated usage-limit hits の通知が出るので、/rate-limit-options で次の動きを選びます。次のプロンプトを送るか、そのメニューで待機を選ぶと、回数は数え直しです。

取り消し方

表示中に、空のプロンプトで Esc か Ctrl+C を押すか、/rate-limit-options で Don't continue automatically を選びます。Automatic continue cancelled で始まる行が出ます。取り消した後は、プロンプトを送るか、/rate-limit-options の Wait here, then continue automatically で始まる行を選ぶまで続きません。

次の場合も、続きを実行せずに待機が終わります。

  • プロンプトを送った場合(待機の代わりにそのプロンプトが送られます)
  • Claude Code を終了した場合(セッションを再開しても待機は再開しません)
  • /login でのアカウント切替、会話の消去や巻き戻し、別セッションの /resume など、会話が入れ替わった場合

出典: Interactive mode

自動で続かない場合と、オフにする設定

次の場合、Claude Code は待機を自分では始めません。

  • Remote Control とエージェントチームのチームメイトのセッション(その端末の人が手動で始めることはできます)
  • リセットが24時間より先の場合(週の上限は数日先になることがあります)
  • Opus または Sonnet の上限に当たったが、その系統外のモデルで動かしている場合(次のターンは上限に当たらない可能性があるため)

これらの場合や、自動で続ける設定がオフの場合、自分の端末で上限に当たると、リセット枠ごとに1回、使用量上限のオプションメニューが開きます。Wait here, then continue automatically で始まる行を選ぶと待機が始まります。Remote Control やチームメイトのセッションでは、/rate-limit-options を自分で実行します。

待機の選択肢自体が出ない場合もあります。バックグラウンドセッションと -p 実行、API キー・クラウドプロバイダー・従量課金(リクエスト単位の計測で、待つべきリセットがないため)、保存された claude.ai ログインがない LLM ゲートウェイです。

オフにする

/config で Continue automatically at usage limit をオフにするか、ユーザー設定で autoContinueAtUsageLimit を false にします。/config autoContinueAtUsageLimit=false も使えますが、key=value 形式では元に戻せません。この設定が無人での実行を許すためです。読み込まれる設定ファイルは、公式の設定リファレンスで確認してください。

出典: Interactive mode

待たずに進める選択肢:/model・/usage・/usage-credits

公式ドキュメントでは、上限の種類で対応が変わるとしています。セッションと週の上限は全モデル共通なので、/model で切り替えても戻りません。Opus と Sonnet の上限はそのモデル系統だけが対象なので、/model で系統外のモデルに切り替えれば作業を続けられます。ただしモデルごとにプロンプトキャッシュがあり、次のリクエストでは会話全体が再び読み込まれます。

  • /usage:プランの上限とリセット時刻を確認します。
  • /usage-credits:Pro、Max、Ultra では追加の使用量を購入でき、Team と Enterprise では管理者に依頼します。請求の扱いは公式ヘルプセンターで、最新の金額は公式の料金ページで確認してください。
  • Desktop アプリの Code タブ:セッション上限のカードに Auto-continue when limits reset のチェックボックスがあります(週の上限のカードにはありません)。CLI の設定とは別なので、オフにするときはそれぞれ行います。

よくある質問

自動で続ける設定を止めたいときは?

/config で Continue automatically at usage limit をオフにするか、ユーザー設定の autoContinueAtUsageLimit を false にします。待機中にその場で止めるだけなら、空のプロンプトで Esc を押して取り消せます。

出典: Interactive mode

3回続けても上限に当たったらどうなりますか?

自動で続けるのは止まり、通知が出ます。/rate-limit-options で次の動きを選びます。次のプロンプトを送るか、メニューで待機を選べば、回数は数え直しです。

出典: Interactive mode

社内の端末で、自動で待機を始めるかをまとめて決められますか?

公式ドキュメントでは、管理設定(managed settings)で autoContinueAtUsageLimit を設定すると、Claude Code が自動で待機を始めるかを全体で制御できるとしています。優先順位などの詳細は公式ドキュメントで確認してください。
