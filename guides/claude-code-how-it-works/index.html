Claude Code の仕組み:エージェントループと、Claude が触れる範囲

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、公式ドキュメントによると「文脈を集める」「行動する」「結果を確認する」を繰り返して進み、利用者はいつでも割り込めます。
  • 触れる範囲は、実行したディレクトリのファイル、ターミナルで実行できるコマンド、git の状態、CLAUDE.md などです。試す前に、どのディレクトリで起動するかを決めておくと安心です。
  • ファイル編集はチェックポイントで戻せますが、データベースや API、デプロイなど外部システムへの操作は戻せません。権限モードと権限ルールで制御します。

エージェントループ:文脈を集め、行動し、確認する

公式ドキュメントによると、Claude Code はターミナルで動くエージェント型のアシスタントです。コーディングが得意ですが、ドキュメント作成、ビルド、ファイル検索、調べものなど、コマンドラインでできることを手伝えます。

仕事を渡すと、Claude は「文脈を集める」「行動する」「結果を確認する」の3段階で進めます。段階は混ざり合い、検索、編集、テスト実行のどこでもツールを使います。

ループは依頼に合わせて変わります。コードベースへの質問なら文脈集めだけで済むことがあり、バグ修正では3段階を何度も回ります。Claude は直前の手順で分かったことをもとに、次の手順を決めます。利用者もループの一部で、途中で割り込んで方向修正や追加の文脈の提供ができます。

ループは、推論するモデルと、実際に動くツールで成り立ちます。Claude Code は、モデルにツールを提供し、モデルが見る文脈を管理する周辺の層で、公式ドキュメントでは agentic harness(モデルの周りでツールと文脈を扱う層)と呼ばれています。モデルは複数から選べ、/model で切り替えられます。

ツール:Claude が実際にできること

公式ドキュメントでは、ツールがあることで Claude Code はエージェントとして動く、と説明されています。ツールがなければ文章で返すだけですが、あれば読む、編集する、実行する、Web を検索する、外部サービスとやり取りするといった行動ができます。組み込みツールは大きく5分類です。

  • ファイル操作:ファイルの読み取り、コード編集、新規作成、名前変更や整理
  • 検索:パターンでのファイル検索、正規表現での内容検索、コードベースの探索
  • 実行:シェルコマンド、サーバー起動、テスト、git
  • Web:Web 検索、ドキュメント取得、エラーメッセージの調査
  • コード インテリジェンス:編集後の型エラーや警告の確認、定義へのジャンプ、参照の検索(code intelligence plugins が必要)

「失敗しているテストを直して」と頼むと、テストを実行し、エラー出力を読み、関連ファイルを探して読み、編集し、再度テストで確認する、という流れになることがあります。各ツールの結果が次の手順の材料になります。

拡張として、skills で知識を足し、MCP で外部サービスに接続し、hooks でワークフローを自動化し、subagents にタスクを任せられます。いずれも基本のループの上に載る層です。

Claude が触れる範囲:ファイル・コマンド・git・CLAUDE.md

公式ドキュメントによると、ディレクトリで claude を実行すると、次のものにアクセスできるようになります。

  • プロジェクト:ディレクトリとサブディレクトリのファイル。ほかの場所のファイルは許可を得た場合
  • ターミナル:ビルドツール、git、パッケージマネージャー、スクリプトなど、コマンドラインでできること全般
  • git の状態:現在のブランチ、未コミットの変更、最近のコミット履歴
  • CLAUDE.md:プロジェクト固有の指示や規約を書いておく markdown ファイル。他のコーディングエージェント向けの AGENTS.md があるリポジトリでは、代わりにそれを読めます
  • 自動メモリ:作業中に自動で保存される学び。MEMORY.md の先頭200行または25KBの先に達した方が、セッション開始時に読み込まれます
  • 設定した拡張:MCP サーバー、skills、subagents、Claude in Chrome

Claude はプロジェクト全体を見るため、横断的に作業できます。「認証のバグを直して」と頼むと、関連ファイルを探し、複数ファイルを読み、まとめて編集し、テストで確認し、頼めばコミットまで行います。現在のファイルだけを見るインラインのコードアシスタントとの違いです。

セッションとコンテキスト:覚えていること、忘れること

公式ドキュメントによると、会話はローカルに保存され、各メッセージ、ツール使用、結果が平文の JSONL ファイルとして ~/.claude/projects/ 配下に書かれます。これにより巻き戻し、再開、分岐ができます。保存場所、保持期間、消去方法は公式ドキュメントで確認してください。

セッションは独立しており、新しいセッションは前の会話履歴を持たずに始まります。引き継げるのは、自動メモリと CLAUDE.md の内容です。claude --continue または claude --resume は同じセッションIDで再開し、--fork-session または /branch は履歴を新しいセッションIDにコピーします。

コンテキストウィンドウ(Claude が一度に保持できる作業領域)には、会話履歴、ファイルの内容、コマンド出力、CLAUDE.md、自動メモリ、読み込んだ skills、システム指示が入ります。いっぱいになると自動で圧縮され、会話序盤の指示は失われることがあります。守らせたいルールは CLAUDE.md に書き、/context で使用状況を確認します。

実行場所は、ローカル(自分のマシン、既定)、クラウド(Anthropic 管理の VM、または組織が運用するセルフホスト環境)、Remote Control(自分のマシンで実行し、ブラウザから操作)の3つです。使う画面が違っても、ループは同じです。

安全面:チェックポイントと権限モード

公式ドキュメントでは、安全のための仕組みとして、ファイル変更を戻すチェックポイントと、確認なしでできることを決める権限が挙げられています。編集の前にスナップショットが取られ、Esc を2回押すか Claude に頼むと戻せます。チェックポイントは git とは別物で、ファイル変更だけが対象です。データベース、API、デプロイなど外部システムへの操作は戻せません。

Shift+Tab で権限モードを切り替えます。

  • Auto:分類器が多くの操作をバックグラウンドで確認し、危険なものは確認を求めずにブロックします。Claude Code v2.1.283 以降では対話型ターミナルと VS Code セッションの組み込みの開始モードで、それより前のバージョンでは Pro、Max、Team プランに限られます
  • Manual:ファイル編集とシェルコマンドの前に確認します
  • Accept edits:ファイル編集と mkdir、mv などの一般的なファイルシステムコマンドは確認なしで実行し、ほかのコマンドは確認します
  • Plan:ソースを編集せず、調べて計画を提案します

.claude/settings.json で npm test や git status のような信頼できるコマンドを許可しておくこともできます。設定は組織全体のポリシーから個人の設定まで範囲を分けられます。詳細は公式ドキュメントの Permissions を参照してください。

よくある質問

Claude Code の「エージェントループ」とは何ですか?

公式ドキュメントによると、「文脈を集める」「行動する」「結果を確認する」の3段階を、ツールを使いながら繰り返す動き方です。段階は混ざり合い、依頼によって回り方が変わります。利用者は途中で割り込めます。

出典: How Claude Code works

途中で方向を変えたいときはどうしますか?

公式ドキュメントでは、Esc で Claude を止められ、実行中のツール呼び出しは取り消されて次の指示を待つとされています。止めずに修正を入力して Enter を押すと、メッセージはキューに入り、実行中のツール呼び出しが終わった後、同じターンの中で読まれて次の手順の前に調整されます。

出典: How Claude Code works

Claude が行った変更は元に戻せますか?

ファイル編集は、編集前のスナップショットにより Esc を2回押すか Claude に頼むことで戻せます。ただしファイル変更のみが対象で、復元ではシンボリックリンクとハードリンクのファイルがスキップされます。データベース、API、デプロイなど外部システムへの操作はチェックポイントできないため、権限モードと権限ルールで制御します。
