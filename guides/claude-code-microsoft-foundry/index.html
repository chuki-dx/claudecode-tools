Claude Code を Microsoft Foundry(Azure)経由で使う設定手順と注意点

公開: 2026年10月17日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、Azure の Microsoft Foundry に作った Claude のデプロイ経由で使えます。
  • 設定は環境変数だけで行い、CLAUDE_CODE_USE_FOUNDRY で有効化し、リソース名を指定します。対話式のセットアップはありません。
  • 複数人に配る前に、デプロイごとにモデルバージョンを固定してください。固定しないと、使えないモデルが選ばれて要求が失敗することがあります。

前提条件と、Foundry 経由で何ができるか

Claude Code を Microsoft Foundry 経由で使うと、Azure 側に作った Claude のリソースとデプロイへ接続して動かせます。公式ドキュメントによると、始める前に次の3点が必要です。

  • Microsoft Foundry にアクセスできる Azure サブスクリプション
  • Microsoft Foundry のリソースとデプロイを作成できる RBAC 権限(RBAC は Azure のロールベースのアクセス制御です)
  • Azure CLI のインストールと設定(任意。ほかに認証情報を得る手段がない場合にだけ必要)

複数人に展開する場合は、展開前にモデルバージョンを固定するよう注記されています。デプロイ作成時には、推論を Azure と Anthropic のインフラのどちらで行うかを決めるホスティングオプションも選びます。選択肢の詳細は公式ドキュメントで確認してください。

出典: Claude Code on Microsoft Foundry

手順1〜2:リソース作成と認証方式の選択

1. リソースとデプロイを作る

Microsoft Foundry のポータルで新しいリソースを作り、リソース名を控えます。続けて Claude Opus、Claude Sonnet、Claude Haiku のデプロイを作り、付けたデプロイ名を控えます。デプロイ名は手順4でモデル用の環境変数に使います。

2. 認証方式を選ぶ

公式ドキュメントによると、認証方式は3つです。

  • API キー:ポータルでコピーしたキーを ANTHROPIC_FOUNDRY_API_KEY に設定します。
  • Microsoft Entra ID:Azure SDK のデフォルトの認証情報チェーンでトークンを取得します。例は az login のセッションで、保存する API キーは不要です。
  • ベアラートークン:別のプロセスが取得した Entra ID のアクセストークンを ANTHROPIC_FOUNDRY_AUTH_TOKEN で渡します。

API キーは、ポータルでリソースを開き、Endpoints and keys から API Key をコピーして設定します。

export ANTHROPIC_FOUNDRY_API_KEY=your-azure-api-key

Entra ID を使う場合は、ANTHROPIC_FOUNDRY_API_KEY と ANTHROPIC_FOUNDRY_AUTH_TOKEN を未設定にし、手元の PC では Azure CLI でサインインします。

az login

ベアラートークンは Authorization: Bearer ヘッダーとして毎回送られます。ホストアプリやサインイン用スクリプトが取得済みのトークンを使う場合の方式です。

export ANTHROPIC_FOUNDRY_AUTH_TOKEN=your-entra-access-token

ANTHROPIC_FOUNDRY_AUTH_TOKEN は ANTHROPIC_FOUNDRY_API_KEY やデフォルトの認証情報チェーンより優先されます。また、認証を Azure の認証情報で処理するため、Microsoft Foundry 利用時は /logout コマンドが使えません。

出典: Claude Code on Microsoft Foundry

手順3〜5:環境変数、モデル固定、起動確認

3. 有効化の環境変数

# Enable Microsoft Foundry integration
export CLAUDE_CODE_USE_FOUNDRY=1

# Azure resource name (replace {resource} with your resource name)
export ANTHROPIC_FOUNDRY_RESOURCE={resource}
# Or provide the full base URL:
# export ANTHROPIC_FOUNDRY_BASE_URL=https://{resource}.services.ai.azure.com/anthropic

ANTHROPIC_FOUNDRY_RESOURCE にはリソース名だけ(例:my-resource)を設定します。URL やホスト名を入れると、メッセージ送信時に Claude Code が拒否します。

4. モデルバージョンを固定する

公式ドキュメントは、すべてのデプロイでバージョンを固定するよう警告しています。固定しないと、sonnet や opus などのエイリアスは Microsoft Foundry 向けの Claude Code の組み込みの既定値に解決されます。この既定値は最新リリースより遅れていることがあり、アカウントでまだ使えない場合もあります。起動時のモデル確認がないため、使えない場合は要求が失敗します。Azure でデプロイを作るときも、「auto-update to latest」ではなく特定のモデルバージョンを選びます。

モデル用の変数には、手順1のデプロイ名を合わせます。ANTHROPIC_DEFAULT_OPUS_MODEL を設定しないと、opus は Opus 4.6 に解決されます。公式ドキュメントの例は次のとおりです。

export ANTHROPIC_DEFAULT_OPUS_MODEL='claude-opus-4-8'
export ANTHROPIC_DEFAULT_SONNET_MODEL='claude-sonnet-5'
export ANTHROPIC_DEFAULT_HAIKU_MODEL='claude-haiku-4-5'

セッションタイトル生成などのバックグラウンド処理は、Haiku のデプロイがないアカウントもあるため、既定では主モデルが使われます。Haiku を使うには、利用できる Haiku デプロイを ANTHROPIC_DEFAULT_HAIKU_MODEL に設定します。

プロンプトキャッシュは自動で有効です。TTL(キャッシュの保持時間)を既定の5分から1時間にするには次の変数を設定しますが、1時間 TTL の書き込みは高い料金で課金されます。金額は公式の料金ページで確認してください。

export ENABLE_PROMPT_CACHING_1H=1

5. 起動して確認する

claude

Claude Code は環境変数を読み、最初のプロンプトで Azure のリソースに接続します。Microsoft Foundry には対話式のセットアップウィザードがなく、手順3と4の環境変数が唯一の設定方法です。確認は Claude Code 内で /status を実行し、API provider の行に Microsoft Foundry とリソース名またはベース URL が出ることを見ます。

出典: Claude Code on Microsoft Foundry

権限設定と1Mトークンのコンテキスト

公式ドキュメントによると、Azure AI User と Cognitive Services User の既定ロールに、Claude モデルの呼び出しに必要な権限がすべて含まれます。より絞りたい場合は、次の内容でカスタムロールを作ります。

{
  "permissions": [
    {
      "dataActions": [
        "Microsoft.CognitiveServices/accounts/providers/*"
      ]
    }
  ]
}

Claude Code がデプロイの提供モデルを判別できる場合、Fable モデル、Sonnet 5 以降、Opus 4.7 以降は既定で 1M token のコンテキストウィンドウで動き、[1m] は不要です。判別はモデル用変数のデプロイ名から行うため、claude-opus-4-8 のようにモデル ID を名前にするか、modelOverrides で対応付けます。判別できない名前では、別のウィンドウを宣言しない限り 200K と想定されます。

例えば settings.json に次を書くと、team-opus-prod という名前のデプロイが Opus 4.8 だと伝えられます。

{
  "modelOverrides": {
    "claude-opus-4-8": "team-opus-prod"
  }
}

200K に抑えるには CLAUDE_CODE_DISABLE_1M_CONTEXT=1 を設定します。Opus 4.6 と Sonnet 4.6 は、デプロイ名に [1m] を付けると 1M になります。v2.1.287 より前は、Fable モデルと Opus 4.7 以降もこの接尾辞が必要でした。

出典: Claude Code on Microsoft Foundry

つまずきやすい点と配布前の確認

公式ドキュメントのトラブルシューティングは次の2件です。

  • 「Failed to get token from azureADTokenProvider: ChainedTokenCredential authentication failed」が出る場合は、環境で Entra ID を構成するか、ANTHROPIC_FOUNDRY_API_KEY を設定します。
  • 最初のプロンプトで接続エラーが繰り返される場合は、ANTHROPIC_FOUNDRY_RESOURCE がプレースホルダーではなく実際のリソース名か確認します。この値からエンドポイント URL が作られるため、誤ると存在しないホストを指します。

社内に配る情シスの方は、モデルバージョンの固定、Haiku デプロイの有無、デプロイ名の付け方(1M の判別に影響します)を先に決めておくと安全です。執筆時点(2026年10月)の内容なので、導入前に公式ドキュメントで最新を確認してください。

よくある質問

Azure CLI は必須ですか?

公式ドキュメントでは任意とされています。ほかに認証情報を得る手段がない場合にだけ必要です。

出典: Claude Code on Microsoft Foundry

/logout が使えないのはなぜですか?

公式ドキュメントによると、Microsoft Foundry 利用時は認証が Azure の認証情報で処理されるため、/logout コマンドは使えません。

出典: Claude Code on Microsoft Foundry

モデルバージョンを固定しないとどうなりますか?

エイリアスが Claude Code の組み込みの既定値に解決され、アカウントでまだ使えないモデルになることがあります。起動時のモデル確認がないため、その場合は要求が失敗します。

出典: Claude Code on Microsoft Foundry
