Claude Code の fast モードとは:料金の考え方と使いどころ

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • fast モードは、Claude Opus の応答を最大 2.5x 速くする設定です。品質は同じで、トークン単価が高くなります。執筆時点(2026年10月)では研究プレビューで、機能・料金・提供状況は変わる可能性があります。
  • サブスクリプション(Pro/Max/Team/Enterprise)では usage credits のみで使え、プランのレート制限には含まれません。Team と Enterprise は Owner の有効化が先に必要です。
  • 素早い反復やライブデバッグ向けで、長い自律タスクや CI/CD は標準モードが向きます。社内に配るなら、セッションごとの有効化設定でコストを抑えられます。

fast モードとは:何ができるか

公式ドキュメントによると、fast モードは Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)で Claude Opus を高速に使う設定です。最大 2.5x 速くなる代わりに、トークン単価が高くなります。

別のモデルではなく、速度を優先する別の API 設定で Claude Opus を使うものです。品質と機能は同じです。対応は Opus 5.5、Opus 5、Opus 4.8 で、Sonnet や Haiku などでは使えません。Opus 4.7 は非対応で、切り替えると fast モードはオフになります。

研究プレビューのため、機能・料金・提供状況が変わる可能性があります。社内に案内するときは、この点を添えてください。

料金の考え方:単価と課金の仕組み

公式ドキュメントによると、fast モードは標準の Opus よりトークン単価が高く、MTok あたりの価格は次のとおりです。

  • Opus 5.5:入力 $8、出力 $40
  • Opus 5:入力 $10、出力 $50
  • Opus 4.8:入力 $10、出力 $50

価格は 1M トークンのコンテキストウィンドウ全体で一定です。標準の Opus との比較は、公式の料金ページで確認してください。

注意点は、会話で初めて有効にしたとき、その会話のコンテキスト全体に、キャッシュされない入力トークンの fast モード料金が全額かかることです。会話が深いほど高くなるため、セッションの最初に有効にするのが最も安く済みます。この費用は会話ごとに1回で、オフにして再度オンにしても繰り返されません。

サブスクリプションでは、プランに残りがあっても fast モードは usage credits から直接引かれます。Claude Console では、他の API 利用と同じく組織がトークン単位で支払います。

使った分はどこで確認するか

公式ドキュメントでは、まず /status を実行し、Login method の行があれば Claude サブスクリプション、API key の行があれば Claude Console 組織への課金と判断するとされています。

  • Pro と Max:claude.ai の Settings > Usage にある Usage credits 欄に今月の使用額が出ます。fast モード分を含みますが、別枠では表示されません。
  • Team と Enterprise:組織の usage credits から支払われます。自分の利用額は /usage で確認できます。
  • Claude Console:Usage と Cost のページで Group by メニューの Speed (Research Preview) を選ぶと分けて見られます。選べるのは、期間内に fast モードの利用がある場合だけです。

使いどころ:fast モードと標準モードの分け方

公式ドキュメントでは、応答の待ち時間がコストより重要な対話作業に向くとされています。

  • コード変更の素早い反復
  • ライブデバッグ
  • 期限が厳しい作業

標準モードが向くのは、速度があまり重要でない長い自律タスク、バッチ処理や CI/CD パイプライン、コストに敏感な処理です。

effort level との違い

effort level を下げると思考時間が減って応答は速くなりますが、複雑な作業では品質が下がる可能性があります。fast モードは品質が同じで、遅延が小さくなる代わりにコストが上がります。両方を組み合わせ、単純な作業で最大の速度を出すこともできます。

有効化の手順と前提条件

切り替え方

CLI では /fast を実行し、Space でオン・オフを切り替えて Enter で確定します。ユーザー設定ファイルに "fastMode": true を書く方法もあります。オンの間は、プロンプトの横に小さな ↯ アイコンが出ます。

VS Code 拡張では、選択中のモデルが対応していれば Toggle fast mode コマンドが使えます。オフにしても Opus のままなので、別のモデルに戻すときは /model を使います。

前提条件

  • Anthropic API かサブスクリプションのみです。Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry、Claude Platform on AWS では使えません。
  • サブスクリプションでは usage credits をオンにする必要があります。オンになるまで /fast は「Fast mode requires usage credits」と報告します。Pro と Max は Settings > Usage の Usage credits 欄か /usage-credits から、Team と Enterprise は請求権限のあるメンバーが Organization settings > Usage でオンにします。
  • Console は有料の組織が必要で、無料の Evaluation プランでは使えません。アクセスの提供設定も必要です。
  • Team と Enterprise は既定で無効で、Owner が有効化するまで使えません。

社内に配るときの注意

有効化の場所は、Console では管理者が Claude Code preferences、Team と Enterprise では Owner が Organization settings > Claude Code です。全面的に無効にしたい場合は CLAUDE_CODE_DISABLE_FAST_MODE=1 を設定します。

既定では、対話セッションでオンにした設定はセッションをまたいで保持されます。複数セッションを同時に使う組織でコストを抑えるには、設定ファイルで fastModePerSessionOptIn を true にします。各セッションがオフで始まり、/fast で明示的に有効にします。

{
  "fastModePerSessionOptIn": true
}

Team と Enterprise の Owner は、サーバー管理設定で組織全体に配れます。managed settings でこのキーを設定すると、/fast on は対話ターミナルセッション以外では拒否されます。

上限と通信の注意もあります。fast モードは標準 Opus と別のレート制限を持ち、対応する Opus モデルは1つのプールを共有します。上限に達すると標準速度・標準料金に自動で戻り、クールダウン後に再び有効になります。LLM ゲートウェイ経由で api.anthropic.com への直接通信を塞いでいる環境では、可用性チェックが失敗して標準速度になることがあります。回避策は公式ドキュメントで確認してください。

よくある質問

fast モードは Pro や Max の利用枠に含まれますか?

含まれません。公式ドキュメントによると、サブスクリプション(Pro/Max/Team/Enterprise)の Claude Code では usage credits のみで使え、プランのレート制限には含まれません。プランに残りがあっても usage credits から直接引かれます。

出典: Speed up responses with fast mode

会話の途中から fast モードを有効にしても問題ありませんか?

使えますが、初めて有効にしたときに、その会話のコンテキスト全体にキャッシュされない入力トークンの fast モード料金がかかります。会話が深いほど高くなるため、セッションの最初に有効にするのが最も安く済みます。

出典: Speed up responses with fast mode

/fast で「Fast mode has been disabled by your organization」と出る原因は何ですか?

公式ドキュメントでは、組織で fast モードが有効化されていない場合、managed settings で fastMode: false が設定されている場合、managed settings の fastModePerSessionOptIn: true により対話ターミナル以外で /fast on を実行した場合が挙げられています。管理者に確認してください。
