Claude Code をブラウザ(クラウド)で使う:できること・GitHub の接続・制限

公開: 2026年10月17日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、公式ドキュメントによるとクラウド上のセッションとして使えます。各セッションは、ネットワークアクセスなどを定めたクラウド環境で動きます。
  • GitHub との接続は、GitHub App と /web-setup の2通りです。到達できるリポジトリの範囲が違うので、社内の運用に合わせて選びます。
  • 導入前に、レート上限の共有、GitHub 前提、IP 許可リストなどの制限を確認してください。内容は執筆時点(2026年10月)の公式ドキュメントに基づきます。

クラウド環境:セッションが動く場所

公式ドキュメントによると、クラウドのセッションはすべてクラウド環境で動きます。クラウド環境は、ネットワークアクセス、環境変数、セットアップスクリプトを制御する保存済みの設定です。

  • 最初の環境:未作成の場合、オンボーディングで Default 環境(Trusted ネットワークアクセス)が作られるか、作成を求められます。どちらになるかはプランで異なるため、公式ドキュメントで確認してください。
  • 複数ある場合の選ばれ方、起動時に到達できる先や実行内容の変更、設定なしで入っているツールは、公式ドキュメントの各ページで確認してください。

GitHub の接続方法

クラウドのセッションは、コードのクローンとブランチのプッシュのために GitHub リポジトリへのアクセスが必要です。公式ドキュメントでは次の2通りが示されています。

  • GitHub App:Web のオンボーディングで Claude GitHub App を認可します。到達できるのは、公開リポジトリすべてと、Claude GitHub App を入れた非公開リポジトリです。ブラウザでのオンボーディングや Auto-fix を使いたいチーム向けとされています。
  • /web-setup 方式:ターミナルで /web-setup を実行し、ローカルの gh CLI のトークンを Claude アカウントに送ります。gh トークンでアクセスできるリポジトリなら、Claude GitHub App の有無を問わず到達できます。すでに gh を使っている個人の開発者向けです。

Auto-fix と Projects は Claude GitHub App がリポジトリに入っていることが前提です(Projects は接続方法を問わず、クローンする各リポジトリに必要です)。

Anthropic がホストする環境では、GitHub の認証情報は Anthropic のサーバー上で暗号化され、セッションの VM には入りません。VM からの GitHub 操作は GitHub プロキシを通り、サーバー側で認証情報が付きます。

Team・Enterprise の Quick setup

Quick setup は組織の設定で、Team と Enterprise プランでは既定でオフです。オンにすると、/web-setup が使えるようになり(オフの間はコマンドが非表示)、ブラウザのオンボーディングで GitHub App のインストール案内が省かれ、Default 環境が自動で作られます。オンにするのは Owner で、Organization settings > Claude Code の Quick setup トグルです。

注意:Zero Data Retention が有効な組織、または HIPAA 構成を適用した組織は、/web-setup を含むクラウドセッション機能を使えません。顧客管理の暗号鍵(CMEK)を使う組織もクラウドセッションを開始できません。

セッションの操作:差分確認・コマンド・共有

セッションはブラウザ版のサイドバーに並び、変更の確認、チームへの共有、完了分のアーカイブ、完全削除ができます。

  • 差分確認:各セッションに +42 -18 のような追加・削除行数の表示が出ます。開くと差分を見て、行にコメントを付け、次のメッセージと一緒に Claude へ送れます。既定ではベースブランチと比較します。差分は生の git blob から計算されるため、リポジトリ側の diff ドライバーや textconv フィルターは適用されません。
  • 権限モード:タスク作成時も実行中も、モードのドロップダウンで選びます。
  • コマンド:テキストを出力するビルトインコマンドが使えます。/plugin や /resume のような端末専用のものは使えません。/model sonnet のように値を引数で渡す形になるコマンドもあります。
  • コンテキスト:/compact と /context は使えますが、/clear は使えません。新しいセッションをサイドバーから始めます。

共有の公開範囲はアカウントで異なります。Enterprise・Team は Private と Team、Max・Pro は Private と Public です。Public は claude.ai にログインした利用者なら見られる状態で、セッションには非公開リポジトリのコードや認証情報が含まれうるため、共有前に内容を確認してください。

削除はセッションとデータを完全に消し、元に戻せません。整理だけならアーカイブを使います。

セキュリティと分離

公式ドキュメントによると、セッションは複数の層で自分のマシンや他のセッションから分離されます。

  • 各セッションは Anthropic 管理の隔離された VM で動きます。自社の self-hosted 環境に回したセッションは自社インフラで動き、分離は自社の構成の責任になります。
  • Anthropic ホストの環境ではネットワークアクセスは既定で制限され、無効にもできます。ただしネットワークを無効にしても、Claude Code は Anthropic API と通信でき、データが VM の外へ出る可能性があります。
  • Anthropic ホストの環境では、git の認証情報と署名鍵はサンドボックスの外にあり、プロキシが範囲を絞った認証情報で代行します。

導入前に確認したい制限

  • レート上限:クラウドセッションは、同じアカウントの他の Claude・Claude Code の利用と上限を共有します。並列で複数タスクを走らせると、その分だけ多く消費します。
  • 時間制限:コマンドと SessionStart フックには変更できる既定のタイムアウトがあり、セットアップスクリプトは、おおよそ5分で終わる場合だけキャッシュされます。
  • 認証:クラウドのセッションをターミナルに取り込めるのは、同じアカウントで認証している場合だけです。
  • プラットフォーム:リポジトリのクローンと PR 作成には GitHub が必要です。自社運用の GitHub Enterprise Server は Team・Enterprise プランで対応します。
  • IP 許可リスト:組織で IP 許可リストを有効にしていると、Anthropic ホストのクラウドセッションはすべて認証エラーになります。Code Review や、Anthropic ホスト環境で動くルーチンも同様です。

よくある質問

GitLab や Bitbucket のリポジトリで使えますか?

リポジトリのクローンと PR 作成には GitHub が必要です。GitLab、Bitbucket などは CCR_FORCE_BUNDLE=1 を設定するとローカルバンドルとしてセッションに送れますが、結果をそのリモートへプッシュすることはできません。

出典: Use Claude Code in the cloud

/web-setup が表示されないのはなぜですか?

Team・Enterprise プランでは Quick setup が既定でオフで、オフの間はコマンドが非表示です。Owner が組織設定でオンにします。Zero Data Retention が有効な組織や HIPAA 構成の組織では、そもそも使えません。

出典: Use Claude Code in the cloud

IP 許可リストを使っている組織でも使えますか?

有効にしていると、Anthropic ホストのクラウドセッションは認証エラーになります。Anthropic のサポートに連絡して、Anthropic ホストのサービスを許可リストの対象外にしてもらう必要があります。self-hosted 環境のセッションは、自社ネットワークから API を呼びます。
