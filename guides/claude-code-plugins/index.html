Claude Code のプラグインの入れ方と、マーケットプレイスを選ぶときの注意

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のプラグインは、セッションで /plugin を実行し、Discover タブから選んで入れるのが基本です。
  • マーケットプレイスは名前で公式・コミュニティ・サードパーティに分かれますが、どの段階でも、入れたプラグインは利用者の権限でコードを実行できます。入れる前の確認が必要です。
  • 有効なプラグインは全セッションに影響します。社内に配る前に、スコープと Context cost を確認し、使わないものは無効化する運用を決めてください。

プラグインでできること

公式ドキュメントによると、プラグインは、スキル、エージェント、フック、MCP サーバーなどを入れたディレクトリで、Claude Code がひとまとめの単位としてインストールし、読み込みます。多くはマーケットプレイスから入れます。マーケットプレイスはプラグインの一覧と取得先を載せたカタログで、ストアではありません。

スキルは SKILL.md に書く指示、フックは編集後など Claude Code の動作の節目で実行されるコマンド、MCP サーバーは Claude Code が接続するツールのサーバーです。

これらはプラグインなしでも単体で使えます。公式ドキュメントでは、複数をひとまとめにしたいときや、他の人が作った構成をコマンド1つで入れてマーケットプレイスから更新を受けたいときに、プラグインを使うとしています。

ターミナルでの入れ方

公式ドキュメントの例は、Anthropic 公式マーケットプレイスの commit-commands で、コミット、プッシュ、プルリクエスト作成のコマンドを追加します。公式マーケットプレイスは、対話型のターミナルセッションを初めて起動したときに自動で追加されます(管理ポリシーでブロックされている場合を除く)。

claude で起動し、次のコマンドを実行します。セッション内ではすぐには入らず、/plugin パネルがそのプラグインの詳細で開き、確認とスコープ選択ができます。

/plugin install commit-commands@claude-plugins-official
  1. 詳細画面で、追加されるコマンド、エージェント、スキル、フック、MCP や LSP のサーバーを確認します。フックと MCP サーバーを実行できるため、読んでから入れてください。
  2. スコープを選びます(次の節で説明します)。
  3. インストール後の概要の最後の1文で、今のセッションで使えるかを確認します。Plugin is now active. なら再読み込みは不要です。Run /reload-plugins to apply. なら Claude Code が再読み込みを実行しますが、再読み込みがプロンプトキャッシュを無効にする場合は警告を出し、プラグインを保留のままにします。
  4. / を入力して /commit-commands:commit が出るか見ます。claude plugin list でも一覧を確認できます。

探して入れたいときは、プラグイン名なしで /plugin を実行すると Discover タブが開きます。デスクトップアプリと VS Code にはそれぞれ別の手順があり、クラウドセッションにはプラグインのブラウザがなく、手元のマシンで入れたプラグインも読み込まれません。詳しくは公式ドキュメントで確認してください。

スクリプトからは、シェルで claude plugin install を実行します。既定はユーザースコープで、読み込みは次回起動時か /reload-plugins の実行時です。

スコープの選び方

インストール時に選ぶスコープで、誰に有効になるかが決まります。

  • ユーザースコープ: 自分用で、このマシンの全プロジェクトで有効です。設定は ~/.claude/settings.json に入ります。
  • プロジェクトスコープ: そのリポジトリで働く全員に有効です。設定は .claude/settings.json に入り、コミットします。ただしコミットしても各自のマシンには入らないため、各自がプロジェクトスコープを指定してインストールを1回実行する必要があります。
  • ローカルスコープ: 自分用で、そのリポジトリだけで有効です。設定は .claude/settings.local.json に入ります。

同じプラグインが複数のスコープで設定されたときは、ローカルがプロジェクトを、プロジェクトがユーザーを上書きします。また、作者の設定で最初は無効のプラグインがあり、その場合は Installed タブなどから有効にします。

マーケットプレイスを選ぶときの注意

公式ドキュメントでは、マーケットプレイスを名前で3段階に分けています。公式とコミュニティの名前は、github.com/anthropics/ のリポジトリを元にしたマーケットプレイスにだけ Claude Code が認めます。

  • 公式: claude-plugins-official などです。デモ用の claude-code-plugins も含みます。
  • コミュニティ: claude-community など、Anthropic のコミュニティ名です。
  • サードパーティ: それ以外すべてです。同僚や自社が公開するものもここに入ります。

どの段階でも、入れたプラグインはユーザー権限でコードを実行できます。入れる前に、公式ドキュメントの Plugin security and trust で確認方法を読んでください。

公式以外から入れるときは、先に /plugin marketplace add で追加します。指定できるのは GitHub リポジトリ、git リポジトリ、ローカルのディレクトリやファイル、https:// の marketplace.json です。コミュニティとデモのマーケットプレイスは自動では追加されません。執筆時点(2026年10月)の公式ドキュメントでは、追加とインストールを一度に行う --marketplace は、セッション内では Claude Code v2.1.275 以降、シェルからは v2.1.292 以降で使えるとされています。

自動更新は、公式マーケットプレイスなどで既定で有効です(knowledge-work-plugins と first-party-plugins を除く)。コミュニティ、サードパーティ、ローカル開発用では既定で無効です。組織は管理設定で、マーケットプレイスの許可・ブロックや、プラグインの強制インストールができます。

入れたあとの影響と管理

公式ドキュメントによると、有効なプラグインは使わないセッションでも常に含まれます。呼び出せるスキルなどの名前と説明が毎ターン文脈に入り、トークン使用量に数えられ、コンテキストウィンドウの余地も減ります。MCP サーバーはセッションごとに動き、フックはそのイベントで動きます。

  • 入れる前: /plugin の Marketplaces タブでプラグインを開くと、公式マーケットプレイスのものには Context cost の目安が出ます。
  • 入れた後: Installed タブの Not used recently に、止められそうなプラグインが並びます。
  • 止めたいとき: アンインストールせずに、/plugin か、シェルの claude plugin disable で無効化できます。

マーケットプレイスを削除すると、そこから入れたプラグインもすべてアンインストールされます。操作の前に Marketplaces タブで対象のプラグイン名を確認してください。

よくある質問

プラグインを使わず、スキルだけ入れることはできますか?

できます。公式ドキュメントによると、スキル、サブエージェント、フック、MCP サーバーはプラグインなしでも単体で動きます。例として、~/.claude/skills/ に保存したスキルは、そのマシンの全プロジェクトで使えます。

出典: Plugins overview

知人から届いたインストールコマンドの @ 以降が claude-plugins-official ではないときは?

公式ドキュメントでは、先にそのマーケットプレイスを追加するよう案内しています。/plugin marketplace add に取得元を続けて実行し、追加してから入れてください。同僚や自社が公開するものはサードパーティ扱いなので、入れる前の確認が必要です。

出典: Install and manage plugins

使わないプラグインを一時的に止めるには?

アンインストールせずに無効化できます。/plugin から、またはシェルで claude plugin disable を使います。Installed タブの Not used recently で、使っていないプラグインを探せます。
