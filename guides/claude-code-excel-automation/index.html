Claude Code で Excel の集計を自動化する手順:手作業をスクリプトに置き換える3ステップ

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 最初に置き換えるのは「毎月同じ形の Excel を集めて合計する」作業1つに絞ります。中小DXラボの記事では、全部を一度に置き換えようとすると例外対応に追われて挫折しがちだとされています。
  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)には、入力ファイルの形、出力の形、異常時の動きの3点を渡してスクリプトを書かせます。
  • 最初の1〜2か月は手作業の結果と突き合わせ、仕上げに実行用のバッチと手順書を残して担当者へ渡します。コードが正しいかどうかの確認は人が行います。

Excel の集計作業が減らない理由と、置き換え先の考え方

中小DXラボの記事では、月初に各部署から届く明細の Excel をまとめる作業を例にしています。ファイルを1つずつ開いて明細シートを集計用のブックに貼り、ピボットテーブルを更新して、部署別・品目別の合計を報告用にまとめる流れです。1回あたりの量は大きくありませんが、毎月必ず発生します。途中で列の順番が変わったファイルが混ざると、合計が合わない原因を探すだけで時間がかかる、と書かれています。

既存の手段について、記事は次のように整理しています。

  • マクロ(VBA。Excel 上の操作を自動化する仕組み)は、書ける人が限られ、作った人が異動すると誰も直せなくなりがちです。
  • Power Query(Excel に組み込まれたデータ取得・変換機能)は、定型の結合には強い一方、ファイルごとの不備を検知して知らせる処理は組みにくいと筆者は感じています。
  • RPA(Robotic Process Automation)で画面操作を記録する方法は、画面や列の位置が変わると止まりやすく、集計そのものの正しさは保証してくれません。

これに対し Claude Code では、処理の中身を文章で説明できれば、読みやすいスクリプトとして書いてもらえる状態になります。コードとして残るので、次の担当者も Claude Code に読ませて直せる点が、マクロとの大きな違いだと記事は述べています。

Step 1:置き換える作業を1つ選び、入力と出力をメモに書く

記事が挙げる、最初に選ぶ作業の条件は次の3つです。

  • 毎月(または毎週)発生する
  • 入力ファイルの形がだいたい決まっている(シート名・列名が同じ)
  • 結果が合っているかを、これまでの手作業の結果と突き合わせて確認できる

選んだら、入力と出力をメモに書き出します。記事では架空の例として、部署ごとの備品購入明細を集めて部署別・品目別に合計する作業を使っています。メモの内容は次のとおりです。

  • 入力:input/ フォルダの .xlsx(部署ごとに1ファイル)
  • シート:「明細」
  • 列:日付 / 部署 / 品目 / 数量 / 単価
  • 出力:集計結果.xlsx(シート「部署別」「品目別」)

記事には、手元で試せるように架空のサンプルデータを input/ に作るスクリプト make_sample.py も載っています。実データに触れる前に、流れを確認する材料になります。

出典: Claude Code で社内 Excel 地獄を脱出する3ステップ — 手作業の集計をスクリプトに置き換える

Step 2:入力・出力・異常時の動きを書いて Claude Code に依頼する

依頼のポイントは、「入力の形」「出力の形」「異常時の動き」の3点を必ず書くことです。異常時の動きを書かないと、列が欠けたファイルを黙って読み飛ばすようなコードになりがちだと記事は注意しています。記事で使われた依頼文は次のとおりです。

input/ フォルダにある .xlsx をすべて読み込んで集計する Python スクリプト aggregate.py を作ってください。

入力:
- 各ファイルのシート「明細」。1行目が見出しで、列は 日付 / 部署 / 品目 / 数量 / 単価
- 列の並び順はファイルによって違うことがあるので、見出しの名前で列を探す
- Excel が作る一時ファイル(~$ で始まるもの)は対象外

出力:
- 集計結果.xlsx に、シート「部署別」(部署, 金額)と「品目別」(品目, 数量, 金額)を作る
- 金額 = 数量 × 単価。金額列は桁区切りの書式にする

異常時:
- シートや列が無いファイル、数量・単価が数値でない行があるファイルは、集計に含めずにスキップする
- スキップしたファイルと理由を最後に画面へ出し、終了コードを 0 以外にする

制約:
- Python 3.10 以上と openpyxl だけで動くこと
- 入力フォルダと出力ファイルはコマンドライン引数で変えられること(省略時は上の既定値)

この依頼文には、列の並び順がファイルごとに違っても見出しの名前で列を探すこと、Excel が作る一時ファイルは対象外にすること、スキップしたファイルと理由を最後に画面へ出して終了コードを 0 以外にすること、が含まれています。

記事の筆者は、この依頼文をもとに出来上がったコードを整えて aggregate.py としています。Python と openpyxl(Python から Excel ファイルを扱うライブラリ)だけで動く作りで、実行は次のとおりです。

pip install openpyxl
python make_sample.py
python aggregate.py

ここで大事なのは確認です。最初の1〜2か月は手作業の結果と並べて突き合わせ、合計が一致することを確認してから手作業をやめます。Claude Code が書いたコードでも、正しさを保証するのは自分の確認だけだと記事は述べています。

Step 3:ダブルクリックで動く形にして担当者へ渡す

スクリプトができても自分しか動かせないなら、属人化の場所が変わっただけです。記事では、担当者がダブルクリックで実行できるように、次のバッチファイルを aggregate.py と同じフォルダに置く方法を紹介しています。

@echo off
rem 集計.bat  aggregate.py と同じフォルダに置いてダブルクリックで実行する
cd /d %~dp0
py aggregate.py
pause

py は python.org のインストーラで入る Python ランチャーだと記事は説明しています。あわせて、次の内容を1枚の手順書(README)にまとめます。手順書の下書きも、Claude Code に「担当者向けに、専門用語を使わずに書いて」と頼めば作ってくれるとのことです。

  • 毎月やること(input/ にファイルを入れて、集計.bat をダブルクリック)
  • 「スキップ」と表示されたときの対処(どの部署に何を確認するか)
  • 列や品目が増えたときの直し方(Claude Code にこのフォルダを開いて依頼する)

つまずきやすい点と、社内で試すときの注意

記事が挙げるつまずきポイントは、症状・原因・対処の順に次のとおりです。

  • PermissionError で保存できない:集計結果.xlsx を Excel で開いたまま実行したためです。ファイルを閉じてから再実行します。
  • 金額がすべて空になる:単価が数式で入っていて、一度も Excel で保存されていないためです。元ファイルを Excel で開いて保存し直します(openpyxl は数式を計算しないため)。
  • 「列が足りません」と出る:見出しの表記ゆれ(「単 価」「単価(円)」など)が原因です。入力側の様式を固定するか、見出しの別名を許すように Claude Code へ修正を依頼します。
  • py が見つからない:Python ランチャーが入っていないためです。py を python に書き換えるか、python.org版の Python を入れ直します。

社内で試す前に確認したい点

本記事は中小DXラボの記事の内容を整理したもので、執筆時点(2026年10月)で私が検証した結果ではありません。依頼文やコードは架空の備品購入明細を例にしているため、自社のファイルの形に合わせて、入力・出力・異常時の動きを書き直す必要があります。Claude Code の操作や設定の詳細は、公式ドキュメントで確認してください。

記事の筆者は、担当範囲で手作業の集計を1つ置き換えただけでも、月初の作業が体感で軽くなったと述べています。これは筆者個人の感想で、効果は職場によって異なります。最初の一歩として、毎月繰り返している Excel 作業を3つ書き出し、Step 1の条件に当てはまるものを1つ選ぶことが勧められています。

よくある質問

VBA のマクロで自動化する方法と、Claude Code でスクリプトを作る方法は何が違いますか?

中小DXラボの記事では、コードとして残るので次の担当者も Claude Code に読ませて直せる点を大きな違いとしています。マクロは書ける人が限られ、作った人が異動すると誰も直せなくなりがちだと説明されています。ただし、結果の正しさを保証するのは自分の確認だけとも書かれています。

出典: Claude Code で社内 Excel 地獄を脱出する3ステップ — 手作業の集計をスクリプトに置き換える

集計を実行したら、金額がすべて空になりました。原因は何ですか?

記事によると、単価が数式で入っていて、そのファイルが一度も Excel で保存されていないことが原因です。元ファイルを Excel で開いて保存し直すと対処できます。openpyxl は数式を計算しないためです。

手作業での集計は、いつまで並行して続ければよいですか?

記事では、最初の1〜2か月は手作業の結果と並べて突き合わせ、合計が一致することを確認してから手作業をやめるとしています。一致の判断基準の細かい設定までは書かれていないため、自社で決めてください。
