Claude Code を組織で導入する管理者設定の流れ:管理設定の配り方と制限項目

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の組織ポリシーは管理設定で配り、利用者のローカル設定より優先されます。
  • 判断の順番は、API プロバイダー、設定の届け方、制限する範囲、利用状況の把握、データの扱いです。
  • 設定後は利用者に /status を実行してもらい、管理設定が効いているか確かめます。

まず API プロバイダーを決める

公式ドキュメントでは、管理設定は Claude の管理コンソール、MDM(端末を一括管理する仕組み)、ディスク上のファイルのどれかで配るとされています。SSO、SCIM、シート割り当ては Claude アカウント側の設定で、別の管理者ガイドを参照する扱いです。

プロバイダーは課金、認証、引き継ぐコンプライアンス、使える機能に影響します。

  • Claude for Teams / Enterprise:Claude Code と claude.ai を席ごとの1契約にまとめたい場合。インフラ運用が不要で、既定の推奨です。
  • Claude Console:API 中心、または従量課金にしたい場合。
  • Amazon Bedrock、Google Cloud's Agent Platform、Microsoft Foundry:既存のクラウドの統制や課金を引き継ぎたい場合。

注意点として、クラウドセッション、Routines、Code Review、Remote Control、Chrome 拡張は claude.ai アカウントが要り、Console の API キーやクラウドプロバイダーの認証情報だけでは使えません。クラウド経由で展開する場合は、Teams / Enterprise の席も要るかを先に検討してください。

管理設定の届け方と優先順位

公式ドキュメントによると、次の4つが優先順に使われます。

  • サーバー管理(claude.ai の管理コンソール):最優先で、全プラットフォームが対象です。
  • plist / レジストリ:macOS は com.anthropic.claudecode、Windows は HKLM\SOFTWARE\Policies\ClaudeCode です。
  • ファイル:macOS は /Library/Application Support/ClaudeCode/managed-settings.json、Linux と WSL は /etc/claude-code/managed-settings.json、Windows は C:\Program Files\ClaudeCode\managed-settings.json です。
  • Windows ユーザーレジストリ HKCU\SOFTWARE\Policies\ClaudeCode:最も優先度が低く、Windows のみです。

サーバー管理設定は起動時に取得され、セッション中は1時間ごとに更新されます。管理コンソール経由は Claude for Teams または Enterprise プランが必要です。Bedrock などの利用では、Claude apps gateway を動かせば同じ遠隔配信ができ、ファイルや OS レベルの方式でも構いません。

プロバイダーが混在する場合は、サーバー管理設定にファイルや plist / レジストリの代替を組み合わせます。plist と HKLM は書き込みに管理者権限が要り改ざんされにくい一方、HKCU は昇格なしで書けるため、強制の手段ではなく便宜的な既定値として扱うよう書かれています。

管理値は一部の例外を除き、ユーザー設定とプロジェクト設定に優先します。permissions.allow や permissions.deny のような配列は全ソースを統合するため、開発者は追加できても管理側の項目は削除できません。

何を制限するか

管理設定では、ツール、コマンド、MCP サーバー、プラグイン元、フックなどを制御できます。代表的な項目は次のとおりです。

  • 権限ルール:permissions.allow、permissions.deny で、特定のツールやコマンドを許可・確認・拒否します。
  • 権限の固定:allowManagedPermissionRulesOnly で権限ルールの設定元を管理設定だけにし、permissions.disableBypassPermissionsMode で --dangerously-skip-permissions を無効にします。
  • サンドボックス:OS レベルのファイルとネットワークの隔離です。sandbox.enabled、sandbox.network.allowedDomains を使います。
  • MCP サーバー:allowedMcpServers、deniedMcpServers などで接続先を絞ります。
  • モデルとバージョン:availableModels で選べるモデルを絞り、minimumVersion で自動更新が下限を下回るのを防ぎます。requiredMinimumVersion は範囲外だと起動自体を拒否します。

注意点です。権限ルールとサンドボックスは別の層です。WebFetch を拒否しても、Bash が許可されていれば curl や wget は任意の URL に届くため、OS レベルのドメイン許可リストを持つサンドボックスで補う、と説明されています。

Claude Enterprise プランで claude.ai や Anthropic API からサインインしている場合は、管理設定を配らなくても、組織の管理画面からモデル制限、既定モデル、effort の上限を設定できます。ただし Bedrock、Google Cloud's Agent Platform、Microsoft Foundry には届かないため、そちらでは管理設定の availableModels、model、maxEffortLevel を使います。

利用状況の把握とデータの扱い

公式ドキュメントでは、Teams / Enterprise と Console で使える機能が異なるため、可用性の列を確認してから報告の計画を立てるよう案内しています。

  • 使用状況:OpenTelemetry で、セッション、ツール、トークンを出力できます。全プロバイダーが対象です。
  • 分析ダッシュボード:Teams / Enterprise と Console で別の画面です。ユーザー別の利用量と支出は、Teams / Enterprise ではダッシュボードではなくスペンドレポートで見ます。
  • 支出管理:Teams / Enterprise は組織設定、Console はワークスペースの上限です。サードパーティのクラウドでは、クラウド側の予算管理か Claude apps gateway を使います。

データについて、Team、Enterprise、Claude API、クラウドプロバイダーの各プランでは、Anthropic はコードやプロンプトでモデルを学習しないとされています。保持期間やコンプライアンスはプロバイダーで決まります。ゼロデータ保持(ZDR)は Claude for Enterprise の適格なアカウントが対象です。リクエスト単位の監査ログが必要ならゲートウェイの設置が推奨されていますが、ゲートウェイ経由のセッションは HIPAA 構成の対象外です。

設定後の確認と利用者への案内

公式ドキュメントによると、設定後は開発者に Claude Code 内で /status を実行してもらいます。Status タブの Setting sources 行に Enterprise managed settings と表示され、有効になった取得元がかっこ内に続きます。

ログインで困った場合の主な対処は、/logout のあと /login でアカウントを切り替える、企業向けの認証の選択肢が出ない場合は claude update を実行する、更新後はターミナルを再起動する、の3つです。「You haven't been added to your organization yet」と表示される場合は、席に Claude Code のアクセスが含まれておらず、管理コンソールでの更新が必要です。

本記事は執筆時点(2026年10月)の公式ドキュメントの記載にもとづきます。設定キーや対応バージョンは、導入前に公式ドキュメントで確認してください。

よくある質問

SSO や SCIM もこの管理設定で設定しますか?

いいえ。公式ドキュメントでは、SSO、SCIM、シート割り当ては Claude アカウント側で設定するとされています。手順は Claude Enterprise の管理者ガイドを参照してください。

出典: Set up Claude Code for your organization

Bedrock で使う場合、管理コンソールから設定を配れますか?

管理コンソール経由の配布は Claude for Teams または Enterprise プランが必要です。Bedrock などでは、Claude apps gateway で同様の遠隔配信をするか、ファイルや OS レベルの方式を使うとされています。

出典: Set up Claude Code for your organization

開発者は管理設定を上書きできますか?

管理値は一部の例外を除き、ユーザー設定とプロジェクト設定に優先します。配列の設定は追加できても、管理側の項目は削除できません。例外の詳細は公式ドキュメントで確認してください。
