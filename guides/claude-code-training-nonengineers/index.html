総務・経理など非エンジニアに Claude Code を教えるときの進め方

公開: 2026年10月14日 ・ 中小DXラボ ・ 製品の仕様にふれる部分は執筆時点(2026年10月)の公式ドキュメントにもとづきます

結論

  • プログラミングをしない人に渡すときは、設定を配るだけでなく、「頼み方」「確認画面の読み方」「結果の確かめ方」を練習してもらいます。
  • 研修は90分×3回(基本操作と安全なフォルダ → 業務ファイルの整理・集計 → 自分の業務で1つ作る)に分け、練習は架空のデータだけで行います。
  • 課題の正解は AI の文面ではなく、件数や合計などの確かめられる条件で判定します。広げるときは「自分 → 少人数 → 部署」の順に進めます。

設定を配るだけでは、使い続けてもらえない

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、プログラミングをしない人にも使われ始めています。情シスとしては、権限設定や CLAUDE.md(起動時に読まれる説明書きのファイル)をそろえて配れば準備完了、と考えたくなります。

設定は、読ませないファイルや実行させないコマンドを止めてくれます。ただ、設定では止められないものがあります。研修なしでそのまま渡したときに起きやすいのは、次の3つです。

  1. 確認画面を読まずに許可する: Claude Code はファイルを書き換える前などに確認を求めます。意味が分からないまま許可を続けると、元のファイルが上書きされても気づけません。
  2. 実データをそのまま渡す: 請求書や勤怠の実データを、試しに読ませてしまう。設定で止められるのは、決めておいたフォルダやファイルだけです。
  3. 結果を確かめずに使う: AI が出した合計や一覧を、元のデータと突き合わせずに使う。間違いに気づくのは、あとで誰かに指摘されたときになります。

こうしたつまずきで一度困ると、「やっぱり怖い」と使われなくなりがちです。社内にこうした場面が思い当たる方も多いのではないでしょうか。

勉強会1回では足りない理由

よくあるのは、1回の勉強会で機能を一通り紹介する形です。ただ、確認画面の読み方や結果の確かめ方は、説明を聞くだけでは身につきません。自分で操作して、間違いを見つける経験が要ります。

そのためには、受講者が実データを持ち込まずに何度でも試せる練習用の材料と、講師が「正しくできたか」をその場で判定できる基準が必要です。

90分×3回の組み立て方

研修は、続けて3日でも、週1回ずつでも組めるように、90分×3回に分けます。

回テーマ練習すること持ち帰るもの
1回目基本操作と安全なフォルダ起動と終了、ファイルを読ませる、確認画面を読む社内ルールの1枚
2回目業務ファイルの整理・集計CSV の点検、集計、突き合わせ、ファイル名の整理集計の仕組みと、結果の確かめ方
3回目自分の業務で1つ作る業務メモから依頼文を作り、仕組みを1つ作る自分の業務メモと依頼文

練習は架空のデータだけで行う

研修用のフォルダとサンプルのファイルは、スクリプトなどで作り直せるようにしておきます。失敗しても最初の状態に戻せると、受講者は安心して「断る」「やり直す」を試せます。実データを持ち込まないことは、そのまま社内ルールの練習にもなります。

正解は「条件」で判定する

AI の返答は毎回同じではありません。文面で正解を決めると、講師が判定に迷います。そこで「部署は4つ」「合計は○円」「元のファイルは変わっていない」のように、受講者自身が確かめられる条件で判定します。結果を元のデータと突き合わせる習慣も、ここで身につきます。

3回目は自分の業務を題材にする

事前に「毎月繰り返している作業を1つ」書いてきてもらい、それを題材にします。自分の業務が題材になると、研修のあとも使い続けやすくなります。業務メモには、AI に渡してよいデータかどうかも書いてもらうと、ルールの確認を兼ねられます。

講師が先に用意しておくもの

  • 社内ルールの1枚: 使ってよいアカウント、渡してはいけない情報、迷ったときの相談先。最初に読み合わせ、「迷ったら渡さずに相談」を伝えます。
  • 作業用フォルダのひな形: 読ませないファイルなどを決めた .claude/settings.json と、短い CLAUDE.md を入れたもの。全員が同じひな形から始めると、人によって設定が違う状態を防げます。
  • 架空のサンプルデータ: 名簿、請求と入金、勤怠のような、業務に近い形のファイル。
  • つまずきの記録先: 研修中に出たつまずきを書き留め、次の回やひな形の改善に使います。

研修のあと、広げる順番

いきなり全社に案内すると、問い合わせが一度に集まり、情シスが対応しきれなくなります。まず情シス自身が使い、次に興味のある2〜3人、そのあと部署へ、という順番で広げると、少人数のメンバーが身近な相談役になってくれます。最初の少人数には、手作業の繰り返しを抱えている人を選ぶと効果が見えやすくなります。

続けてもらうために、質問を書き込む場所を1つに決めておきます。同じ質問が来たら、答えを手順書やひな形に反映します。ひな形を直したときは、すでに配ったフォルダには自動で反映されないので、何を変えたかを質問の場所で知らせます。

組織として必ず守らせたいルールがある場合、公式ドキュメントでは、利用者が上書きできない管理用の設定(managed settings)で配る方法が案内されています。少人数のうちはひな形で始め、人数が増えてから検討する順番でも遅くありません。

効果は、体感と実測を分けて記録する

広げていくと「どれくらい効果があったのか」を聞かれます。このとき、体感と実測を混ぜないことが大切です。「楽になった」は本人にとって本当ですが、それを根拠のない時間の数字に置きかえると、説明を求められたときに困ります。

実測するなら、置き換える前に手作業の時間を2〜3回分記録しておきます。置き換えたあとの時間には、結果を確かめる時間と、うまくいかなかったときの対処の時間も含めます。数字にしにくい効果は、体感であることを明記して別の欄に書きます。

よくある質問

3回も時間を取れません。1回にまとめられませんか

まとめることはできますが、確認画面を読む練習と、結果を確かめる練習は省かないことをおすすめします。3回目の「自分の業務で1つ作る」は、後日の個別相談に回す形もあります。

受講者の PC に何を入れておけばよいですか

Claude Code と、全員共通の作業用フォルダのひな形です。Windows では文字化けや実行ポリシーなどでつまずきやすいので、研修の前に講師の PC と同じ手順で動くかを確かめておくと、当日の時間を練習に使えます。

研修中に受講者が実データを使おうとしたら、どうしますか

その場で止め、社内ルールの1枚の「渡してはいけない情報」を一緒に確認します。練習用のフォルダの外では使わない、と最初に決めておくと止めやすくなります。

研修の準備に使えるツール

作業用フォルダのひな形に入れる CLAUDE.md は CLAUDE.md テンプレート生成 で、選ぶだけで下書きを作れます。研修中によく出るつまずき(文字化け、許可したのに確認が出る、など)は、つまずき早見表 で症状から原因と対処を探せます。
