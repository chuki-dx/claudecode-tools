Claude Code のトークン使用量を減らす方法と、使用量の確かめ方

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code は API のトークン消費量で課金されます。使用量は /usage の Session ブロックで確認できますが、ドル表示は見積もりで、正式な請求は Claude Console の Usage ページで確認します。
  • 節約の基本は、コンテキストを小さく保つことです。無関係な作業の間に /clear を使い、簡単な作業ではモデルや拡張思考の effort level を見直すことが挙げられています。
  • 長く開いたままのセッション、キャッシュミス、定期タスク、サブエージェントは使用量を押し上げます。社内に配る前に、小さなパイロットで基準値を取る進め方が案内されています。

まず使用量を確かめる(/usage とスピナー横の表示)

執筆時点(2026年10月)の公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は API のトークン消費量で課金されます。費用はモデルの選び方、コードベースの大きさ、複数インスタンスや自動化といった使い方で大きく変わります。

エンタープライズ導入全体の平均は、開発者1人あたり稼働日1日で約$13、月で$150-250とされ、稼働日あたり$30未満の利用者が90%と書かれています。自社の見込みは、小さなパイロットで計測してから広げる進め方が案内されています。

/usage の Session ブロックに、現在のセッションのトークン使用量が出ます。ドル表示はトークン数から定価でローカル計算した見積もりで、正式な請求は Claude Console の Usage ページで確認します。Max・Pro の利用者は利用料がサブスクリプションに含まれるため、この費用額は請求の面では関係ありません。合計は /clear で新しいセッションを始めるとリセットされます。

v2.1.251 以降では Prompt cache (main) の行が加わり、キャッシュから供給された入力トークンの割合やキャッシュミスの回数が分かります。対象はメイン会話のみで、サブエージェントは含まれません。作業中にスピナーの横に出るトークン数は、そのターンの出力の概算で、/usage の合計とは一致しません。

コンテキストを小さく保つ

公式ドキュメントでは、トークンのコストはコンテキストが大きいほど増えると説明されています。Claude Code はプロンプトキャッシュと自動コンパクション(会話履歴の要約)で自動的に最適化しますが、次の習慣でさらに抑えられます。

  • 無関係な作業に移るときは /clear で新しく始めます。古いコンテキストは以降のメッセージごとにトークンを消費します。後で戻るなら、先に /rename、あとで /resume を使います。
  • /compact Focus on code samples and API usage のように、要約時に残す内容を指示できます。
  • プロジェクト直下の CLAUDE.md にも、要約時の方針を書けます。
# Compact instructions

When you are using compact, please focus on test output and code changes

CLAUDE.md はセッション開始時に読み込まれます。PR レビューやデータベース移行のような特定作業の詳細な手順は、呼び出したときだけ読み込まれるスキルに移すと、基本のコンテキストが小さくなります。CLAUDE.md は要点に絞り、200行未満が目安とされています。

モデルと拡張思考を見直す

公式ドキュメントによると、Sonnet は多くのコーディング作業をこなし、Opus より安価です。Opus は複雑な設計判断や複数ステップの推論に取っておきます。/model でセッション中に切り替え、/config で既定を設定できます。Opus に切り替えると、セッションのモデルを継承するサブエージェントにも適用されます。単純なサブエージェントの作業には model: haiku を指定できます。

拡張思考は既定で有効で、思考トークンは出力トークンとして課金されます。既定の予算は、モデルによっては1リクエストあたり数万トークンになりえます。簡単な作業では、/effort または /model で effort level を下げるか、/config で思考を無効にします。ただし Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 系のモデルは常に拡張思考を使い、オフにできません。

思考予算が固定のモデルでは、環境変数 MAX_THINKING_TOKENS で予算を下げられます(例: MAX_THINKING_TOKENS=8000)。適応的推論のモデルはゼロ以外の予算を無視するため、effort level を使います。

MCP・hooks・サブエージェント・依頼の書き方

  • MCP: ツール定義は既定で遅延読み込みされ、特定のツールを使うまでは名前とサーバーの指示だけがコンテキストに入ります。/context で何が容量を使っているか確認し、/mcp で使っていないサーバーを無効にします。
  • gh、aws、gcloud、sentry-cli などの CLI ツールは、ツール一覧を足さないため MCP サーバーよりコンテキスト効率が良いとされています。
  • hooks: 10,000行のログを Claude が読む代わりに、hook で ERROR を grep して該当行だけ返せば、コンテキストを数万トークンから数百トークンに減らせます。公式ドキュメントには、テスト出力を失敗だけに絞る PreToolUse hook の例があります。
  • サブエージェント: テスト実行やログ処理など出力の多い作業を任せると、要約だけがメインの会話に戻ります。ただしサブエージェント自身のリクエストも使用量に含まれます。
  • 依頼の書き方: 「improve this codebase」のような曖昧な依頼は広い走査を招きます。対象を具体的に書くと、ファイルの読み込みが少なくなります。

複雑な作業では、Shift+Tab でプランモードに切り替えて方針を確認してから実装すると、やり直しを防げます。違う方向に進んだら Escape で止め、/rewind で戻します。なお、エージェントチームはチームメイトがプランモードのとき標準セッションの約7倍のトークンを使うとされています。

使用量が増えやすい場面と、組織での管理

公式ドキュメントでは、長く開いたセッションで使用量が増える原因として次を挙げています。

  • 長いコンテキスト: リクエストごとに会話全体が送られるため、一行の質問でも会話全体分の使用量がかかります。
  • キャッシュミス: キャッシュの有効期間を超えた休憩後の最初のメッセージは、全コンテキストを再処理します。有効期間はサブスクリプションで1時間、usage credits を使い始めると5分です。API キーやクラウドプロバイダでは既定で5分です。
  • 定期タスクはセッションが待機中でも間隔どおりに全コンテキストを送ります。サブエージェントやチームメイトも別にリクエストを送ります。
  • コンパクト: /compact は要約対象の会話を読むため、大きなコンテキストでは大きなリクエストになります。仕切り直したいときの /clear は費用がかかりません。

Pro、Max、Team、Enterprise の /usage には、直近の使用量の10%以上を占める挙動(長いコンテキストやキャッシュミスなど)に、減らすヒント付きのフラグが出ます。

組織で管理する場合、Teams・Enterprise は管理画面の支出レポートと上限設定、Console はワークスペースの支出上限、クラウド経由は各クラウドの請求コンソールが中心です。OpenTelemetry はどの構成でも使えます。詳しい設定手順は公式ドキュメントで確認してください。

よくある質問

/usage のドル表示は請求額と一致しますか?

一致するとは限りません。公式ドキュメントによると、ドル表示はトークン数から定価でローカル計算した見積もりです。契約単価で支払う組織では、管理者が管理設定の modelPricing に単価を入れると、契約単価ベースの表示になります(v2.1.242 以降)。ただしそれも請求書ではなく見積もりで、正式な請求は Claude Console の Usage ページで確認します。

出典: Manage costs effectively

拡張思考は、どのモデルでもオフにできますか?

できません。拡張思考は既定で有効で、簡単な作業では /effort や /model で effort level を下げるか、/config で無効にできます。ただし公式ドキュメントによると、Opus 5.5、Sonnet 5.5、Haiku 5.5、Fable 系のモデルは常に拡張思考を使い、オフにできません。

出典: Manage costs effectively

席を外したあとの最初のメッセージで使用量が多くなるのはなぜですか?

公式ドキュメントによると、キャッシュの有効期間を超える休憩のあとの最初のメッセージはキャッシュミスになり、全コンテキストを再処理するためです。有効期間はサブスクリプションで1時間、usage credits を使い始めると5分で、API キーやクラウドプロバイダでは既定で5分です。
