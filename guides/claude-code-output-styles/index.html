Claude Code の出力スタイル(output styles)とは:変え方と作り方

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 出力スタイルは、Claude の役割・口調・応答形式をセッション全体で切り替える指示です。組み込みは Default のほか Proactive、Concise、Explanatory、Learning の4つです。
  • 切り替えは /output-style コマンド、/config のメニュー、設定ファイルの outputStyle で行えます。設定ファイルの値は大文字小文字を区別します。
  • 出力スタイルは従わせる指示であり、動作を保証しません。必ず実行したい処理は hook、プロジェクトの情報は CLAUDE.md が向いています。

出力スタイルでできること

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)には出力スタイルがあります。公式ドキュメントによると、セッション中のすべての応答について Claude の役割・口調・応答形式を定める指示のまとまりで、毎回のプロンプトで同じ依頼を繰り返さずに済みます。

応答を短くする、変更ごとに理由を説明させる、定型的な質問をせず作業を始めさせる、といった使い方ができます。自作すれば、文章作成の補助役やデータ分析役など、ソフトウェアエンジニア以外の役割にもできます。本記事は執筆時点(2026年10月)の公式ドキュメントに基づきます。

組み込みの4スタイルと選び方

公式ドキュメントでは、スタイルを選ばない状態が Default で、ソフトウェアエンジニアリング向けの標準の指示で動きます。ほかの4つはその指示を保ったまま、独自の指示を足します。

  • Proactive:定型的な判断では質問せず、妥当な仮定を置いてすぐ実装します。依頼しない限りプランモードには切り替えません。データ削除や共有・本番システムの変更の前には、会話で確認するよう指示されています。
  • Concise:最初の文で結果を述べ、前置き・経過の説明・最後の要約を省きます。簡単な質問は1〜3文で答えます。v2.1.237 以降が必要です。
  • Explanatory:通常どおり作業し、選択の理由を Insight ブロックとして会話内に添えます。ファイルにコメントとしては書き込まれません。
  • Learning:Insight に加え、設計判断のある小さな部分を利用者に書かせます。ファイルに TODO(human) コメントを置いて待ち、書き終えたと伝えると続きを進めます。

注意点です。Proactive に切り替えても権限モードは変わらず、許可の確認は従来どおり表示されます。Proactive の確認は Claude への指示であり、許可プロンプトとは別です。Concise でも、エラー報告、失敗したテストの出力、セキュリティ警告、破壊的操作の確認は全文で出ます。

出力スタイルの切り替え方

公式ドキュメントによると、コマンド、メニュー、設定ファイルのいずれかで選べます。コマンドとメニューでの選択は、ローカルプロジェクトレベルの .claude/settings.local.json に保存されます。

  • /output-style コマンド:/output-style concise のように指定します。引数なしだと選べるスタイルの一覧が出ます。非対話モードや Agent SDK でも使え、v2.1.269 以降が必要です。
  • ターミナル:/config を実行し、Output style を選びます。
  • VS Code 拡張:/ でコマンドメニューを開き、Output styles を選びます。カスタムスタイルも選べます。v2.1.257 以降が必要です。
  • デスクトップアプリ:設定ファイルの outputStyle を直接書きます。

設定ファイルを直接編集する場合の例です。

{
  "outputStyle": "Explanatory"
}

値は大文字小文字を区別し、explanatory のように名前と一致しない値は Default になります。コマンドは大文字小文字を無視します。全プロジェクト共通の既定は ~/.claude/settings.json の outputStyle で設定でき、プロジェクトの設定ファイルが優先されます。セッション途中で切り替えると、次のメッセージから新しいスタイルが使われます。

カスタムスタイルの作り方

カスタムスタイルは、メタデータの frontmatter と Claude への指示を書いた Markdown ファイルです。

  1. ファイルを保存します。場所はユーザー(~/.claude/output-styles)、プロジェクト(.claude/output-styles)、管理ポリシーのいずれかです。name を指定しなければ、ファイル名がスタイル名になります。
  2. frontmatter と指示を書きます。公式ドキュメントの例は次のとおりです。
  3. ターミナルでは /config から自作のスタイルを選びます。Claude Code は起動時にスタイルファイルを読むため、実行中に作成・編集した場合は再起動が必要です。
---
name: Diagrams first
description: Lead every explanation with a diagram
keep-coding-instructions: true
---

When explaining code, architecture, or data flow, start with a Mermaid diagram showing the structure, then explain in prose.

## Diagram conventions

Use `flowchart TD` for control flow and `sequenceDiagram` for request paths. Keep diagrams under 15 nodes.

コーディングの指示を残すかは keep-coding-instructions で決めます。話し方だけを変えたいなら keep-coding-instructions: true を設定し、ソフトウェアエンジニアリングをしない用途なら省略します。同名のプロジェクトスタイルが複数ある場合は、作業ディレクトリに最も近いものが使われます。

frontmatter の項目

項目はすべて任意で、綴りを間違えるとエラーなしで無視されます。YAML が解析できない場合はファイル名で読み込まれ、項目は未設定になります。原因は claude --debug で確認できます。

  • name、description:/config の選択画面に表示されます。
  • keep-coding-instructions:既定は false です。
  • force-for-plugin:プラグインのスタイル専用です。true にすると、プラグインが有効なときに自動で適用され、利用者の outputStyle 設定を上書きします。

他の機能との使い分けと注意点

公式ドキュメントでは、出力スタイルは Claude が従う指示であり、強制する仕組みはないとされています。用途別の使い分けは次のとおりです。

  • プロジェクトの規約やコマンドを知らせたい場合:CLAUDE.md。どのスタイルでも読み込まれたままです。
  • 特定の作業だけの手順(リリースチェックリストなど):skill。呼び出したとき、またはタスクが合うときだけ読み込まれます。
  • 毎回例外なく実行したい処理(編集後の整形、コマンドのブロックなど):hook。Claude Code 自身が実行するため、指示に従うかどうかに左右されません。
  • 専用の指示・モデル・ツールを持つ補助役:subagent。別のコンテキストで動きます。

これらは組み合わせられます。仕組みとして、スタイルの指示は毎回のリクエストで送られるため入力トークンが増えますが、プロンプトキャッシュで軽減されます。Explanatory と Learning は応答が長くなり、Concise は短くなります。スタイルはメインの会話とフォークに適用され、ほかの subagent の応答は変わりません。

完全なシステムプロンプトでは、カスタムスタイルは組み込みのソフトウェアエンジニアリング指示を省きます。ただし keep-coding-instructions が true の場合は残ります。短いシステムプロンプトではこの項目は効かないため、詳細は公式ドキュメントで確認してください。

よくある質問

Concise スタイルにすると、エラーや警告も省略されますか?

省略されません。公式ドキュメントによると、依頼した説明や詳細、エラー報告、失敗したテストの出力、セキュリティ警告、破壊的操作の確認は全文のままです。Concise には v2.1.237 以降が必要です。

出典: Output styles

設定ファイルの outputStyle に explanatory と小文字で書くとどうなりますか?

公式ドキュメントによると、値は大文字小文字を区別するため、名前と一致しない explanatory は Default になります。Explanatory と書いてください。/output-style コマンドは大文字小文字を無視します。

出典: Output styles

自作スタイルのファイルを編集したら、すぐ反映されますか?

ターミナルの Claude Code はスタイルファイルを起動時に読むため、実行中に作成・編集した場合は再起動が必要です。切り替えた後の新しいスタイルは、次のメッセージから使われます。
