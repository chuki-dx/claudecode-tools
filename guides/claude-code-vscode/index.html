Claude Code を VS Code で使う:拡張機能の入れ方と CLI との違い

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、VS Code 拡張は Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)を VS Code 内のグラフィカルなパネルで使うもので、VS Code での推奨の使い方とされています。
  • 前提は VS Code 1.94.0 以降と Anthropic アカウントです。拡張は CLI(コマンドラインで使う版)を内蔵しますが、統合ターミナルで claude を使うには別途 CLI のインストールが必要です。
  • 自動編集の権限では VS Code の設定ファイルも変更されうるため、信頼できないコードを扱うときは Manual モードと制限モードの併用を検討してください。

何ができて、何が要るか

以下は執筆時点(2026年10月)で参照した公式ドキュメントの内容です。拡張では、Claude の計画を受け入れる前にレビュー・編集する、編集を自動で受け入れる、選択範囲の行番号つきでファイルを @ メンション(@ を付けてファイルを指定する書き方)で渡す、会話履歴を開く、複数の会話を別々のタブやウィンドウで開く、といったことができます。

前提は次の2つです。

  • VS Code 1.94.0 以降
  • Anthropic アカウント。有料の Claude サブスクリプション(Pro、Max、Team、Enterprise)か Claude Console アカウントで使え、API キーは不要です。Amazon Bedrock などの第三者プロバイダー経由の場合は、別の設定手順があります。

インストールは、VS Code で Ctrl+Shift+X(Mac は Cmd+Shift+X)を押して拡張機能の画面を開き、「Claude Code」を検索して Install をクリックします。表示されない場合は VS Code を再起動するか、コマンドパレットから「Developer: Reload Window」を実行します。

Cursor 向けのリンクもあり、Devin Desktop や Kiro など他の VS Code フォークにも入れられます。拡張を入れられないエディターでは、統合ターミナルで CLI の claude を動かす方法が案内されています。

起動から最初の依頼まで

最も手早い開き方は、エディター右上のツールバーにある Spark アイコンのクリックです。ファイルを開いているときだけ表示されます。ステータスバーの ✻ Claude Code なら、ファイルを開いていなくても使えます。

初回はサインイン画面が出るので Sign in を押し、ブラウザーで認可します。シェルに ANTHROPIC_API_KEY を設定していてもサインイン画面が出る場合は、VS Code がシェルの環境変数を引き継いでいない可能性があります。ターミナルから code . で起動するか、Claude アカウントでサインインしてください。

選択したテキストは Claude に自動で見えます。Option+K(Windows/Linux は Alt+K)で、@file.ts#5-10 のような参照をプロンプトに入れられます。ファイルやフォルダーは @ に続けて名前を入力して指定でき、あいまい一致にも対応しています。

Explain the logic in @auth (fuzzy matches auth.js, AuthService.ts, etc.)

ファイル編集の動きは権限モードで変わります。Manual モードでは、元の内容と変更案の左右比較が出て、承認・拒否・別の指示を選べます。変更ごとの Accept this change / Reject this change ボタンは Claude Code v2.1.275 以降が必要で、変更が 100 を超える差分では出ないため、ファイル単位で確認します。

権限モードと社内で使うときの注意

プロンプト欄の下のモード表示から、権限モードを切り替えられます。

  • Auto:分類器がほとんどの操作を確認し、都度の確認の代わりにします。Claude Code v2.1.283 以降では組み込みの開始モードで、それより前は Pro、Max、Team プランのみです。
  • Manual:ファイル編集とほとんどのシェルコマンドの前に許可を求めます。
  • Plan:実行内容を説明し、承認を待ちます。VS Code が計画を Markdown 文書として開き、実行前にインラインコメントで意見を返せます。
  • Edit automatically:確認なしで編集します。

公式ドキュメントは、自動編集の権限では、VS Code が自動実行しうる settings.json や tasks.json なども Claude Code が変更できると注意しています。信頼できないコードを扱うときは、VS Code の制限モードを有効にする、Auto や Edit automatically ではなく Manual モードを使う、承認前に変更をよく確認する、の対策が挙げられています。

選択テキストの除外にも条件があります。ワークスペース内にあり、files.exclude や search.exclude に一致するファイルでは、Claude に渡るのは最大でパスだけです。ただしこれはチャットパネルだけが対象で、統合ターミナルの CLI は選択テキストをファイルを問わず送ります。守りたいファイルには Read の deny ルールを追加するよう案内されています。

コードの扱いについて、公式ドキュメントでは、Claude Code はコードを処理するがモデルの学習には使わないとされています。詳細は公式の Data and privacy のページで確認してください。

CLI との違いと、動かないとき

拡張を入れても claude は PATH に追加されません。拡張が内蔵するのはチャットパネル用の CLI のコピーなので、統合ターミナルで claude を動かすにはスタンドアロンの CLI を別途インストールします。

  • コマンドとスキル:CLI はすべて、拡張は一部です。! Bash ショートカットとタブ補完は CLI のみです。
  • MCP(Claude を外部のツールや API につなぐ仕組み)のサーバー設定とチェックポイント(Claude のファイル編集を記録し、以前の状態に戻す機能)は、どちらでも使えます。

拡張と CLI は同じ会話履歴を共有し、拡張の会話は claude --resume で CLI から続けられます。

Spark アイコンが見えないときは、ファイルを開いているか、VS Code が 1.94.0 以降か、他の AI 拡張と競合していないかを確認してください。制限モードでは拡張は動きません。拡張をアンインストールしても、統合ターミナルで claude を実行すると自動で再インストールされるため、止めたい場合は /config の Auto-install IDE extension をオフにします。

ここに書いていない設定や挙動は、公式ドキュメントで確認してください。

よくある質問

Claude Code の VS Code 拡張に API キーは必要ですか?

公式ドキュメントでは不要とされています。有料の Claude サブスクリプション(Pro、Max、Team、Enterprise)か Claude Console アカウントでサインインして使います。

出典: Use Claude Code in VS Code

拡張を入れたのに、ターミナルで claude が見つかりません。

拡張は claude を PATH に追加しないためです。統合ターミナルで使うには、スタンドアロンの CLI のインストールが必要とされています。

出典: Use Claude Code in VS Code

拡張で始めた会話を CLI で続けられますか?

拡張と CLI は同じ会話履歴を共有しています。ターミナルで claude --resume を実行すると、一覧から会話を選んで続けられます。
