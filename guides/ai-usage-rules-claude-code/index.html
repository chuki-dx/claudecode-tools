中小企業で Claude Code を使う前に決める生成AI利用ルールの考え方

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 使い始める前に、確認なしでやらせる範囲・外部の文章の扱い・秘密情報の置き場所・データの扱い・設定の共有の5点を決めておきます。
  • 「学習に使われないか」は、規約(契約プラン)・持ち込むデータ・ツールの設定の3層に分けて確認します。
  • 公式ドキュメントによると、個人向けプランは設定で学習利用を選ぶ形で、法人向けは商用規約のもとで原則学習に使われません。ただし条件があり、仕様も変わるため、導入時に最新版を確認します。

最初に決めること:ルールは3層で考える

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、自分でファイルを読み書きしコマンドを実行できる AI エージェントです。チャット型の AI より「できること」が広いぶん、使う前に決めることも増えます。

中小DXラボの記事では、「学習させない」は1つの設定で片付く話ではないとして、次の3層で整理しています。

  1. 規約(契約)の層:どのプラン・アカウントで使うかを決め、データの扱いを公式ページで確認して記録する。
  2. データの層:Claude Code が読めるフォルダに、そもそも何を置かないかを決める。
  3. 設定の層:読ませたくないファイルを設定で読めなくし、使い方のルールを文書にする。

規約は自社で変えられませんが、データと設定は自社で決められます。そもそも機密を渡さない設計にしておけば、規約が変わっても被害の範囲を小さくできる、とされています。同記事は、全面禁止はシャドーAI(会社が把握していない AI 利用)を招きやすいとも述べています。なお本記事は執筆時点(2026年10月)の内容で、仕様は変わることがあります。

確認なしでやらせる範囲と、外部の文章の扱い

中小DXラボの記事によると、Claude Code では確認なしで実行できる操作の範囲を権限モードで選べ、コマンドごとに許可・禁止のルールも個別に設定できます。たとえば Web から内容を取ってくる curl のようなコマンドは、既定では自動では許可されません。

同記事は、情シスが次の3つに線引きしておくことを挙げています。いずれも例です。

  • 自動で許可する操作(例:ファイルの読み取り、テストの実行)
  • 毎回確認する操作(例:ファイルの削除、外部への通信)
  • 禁止する操作(例:本番サーバーへの接続、社外へのファイル送信)

「便利だから全部自動」にすると、AI が誤った操作をしたときに止める場所がなくなる、とも書かれています。

もう一つの注意点がプロンプトインジェクションです。Web ページやメール、外部から届いたファイルに「この指示に従え」という文章が仕込まれ、AI が指示だと思って動いてしまう攻撃です。公式ドキュメントでも、実行前に提案されたコマンドを確認する、信頼できない内容を AI に直接流し込まない、重要なファイルへの変更は確認してから受け入れる、といった点が挙げられているとされています。

社内ルールとしては、取引先のファイルや Web からコピーした文章を読ませるときは、提案をうのみにせず実行前に人が確認する、と決めておく案が示されています。

秘密情報の置き場所と、設定のチーム共有

AI エージェントは作業フォルダ内のファイルを読むため、そこにパスワードや API キーがあれば、作業の中で読まれる可能性があります。記事では次の対策が挙がっています。

  • 専用の設定ファイル(例:.env)にまとめる
  • そのファイルをバージョン管理に入れない(.gitignore に書く)
  • コード・メモ・手順書にキーを直接書かない
  • AI への依頼文にも、キーそのものを貼らない

また、設定が個人任せだと「Aさんは何でも自動で許可」「Bさんは毎回確認」のようにばらつきます。Claude Code には、組織として強制する設定(managed settings)や、プロジェクトごとの権限設定をファイルとして共有する仕組みがあります。公式ドキュメントでも、承認した権限設定をバージョン管理で共有することや、定期的に見直すことが勧められているとされています。最低限、標準の権限設定ファイルを1つ作り、各自の環境に配るところから始める案です。

プランで変わる会話データの扱い

公式ドキュメントでは、学習方針をプランで分けて説明しています。

  • 個人向け(Free・Pro・Max):将来のモデル改善にデータを使うかどうかを利用者が選べます。設定がオンのときは、これらのアカウントから使う Claude Code のデータも学習に使われます。
  • 法人向け(Team・Enterprise、API、サードパーティのプラットフォーム、Claude Gov):商用規約のもとで Claude Code に送ったコードやプロンプトでは、生成モデルを学習しないとされています。ただし、顧客がモデル改善のためにデータ提供を選んだ場合(例:Development Partner Program)は別です。

Development Partner Program は、組織の管理者が明示的にオプトインするものです。Anthropic 自社の API のみが対象で、Amazon Bedrock や Google Cloud の Agent Platform の利用者は対象外と書かれています。

保存期間も違います。個人向けは、モデル改善を許可すると5年、許可しないと30日です。法人向け(Team・Enterprise・API)の標準は30日です。ゼロデータ保持(ZDR)は、Claude for Enterprise の Claude Code について、要件を満たすアカウント向けに提供されます。標準の Enterprise プランには含まれず、確認のうえ組織ごとに有効化されます。

個人向けプランで始めるなら、導入時に設定を確認し、スクリーンショットで証跡を残す案が中小DXラボの記事に書かれています。どのプランで使うかを先に決め、公式ページで確認して記録してください。

フィードバック・アンケート・ローカル保存の注意

公式ドキュメントでは、学習方針とは別に、利用者が送る情報やローカルに残る情報の扱いも説明されています。

  • /feedback で共有した会話の記録は、同じ経路で報告される /bug や /share も含め、5年間保持されます。
  • セッション品質アンケートの評価そのものでは、記録されるのは評価だけです。その後に、セッションの記録を Anthropic が見てよいかを尋ねる追加の質問が出ることがあり、「Yes」を選んだときだけ会話の記録などがアップロードされます(Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry、サインインした Claude apps gateway のセッションでは、アップロードせず ~/.claude/feedback-bundles/ のローカルアーカイブに書き出され、そのファイルを転送するまで手元から出ません)。既知の API キーやトークンのパターンは伏せられますが、ソースコードやファイルの内容はそのまま送られ、共有された記録は最大6か月保持されます。
  • アンケートを無効にするには CLAUDE_CODE_DISABLE_FEEDBACK_SURVEY=1 を設定します。
  • セッションの記録は手元にも平文で保存され、既定では30日間 ~/.claude/projects/ に置かれます。期間は cleanupPeriodDays で調整できます。

詳細は、商用規約・消費者向け利用規約・プライバシーポリシーで確認するよう案内されています。社内に配る前に、利用するプランに合う内容を公式ドキュメントで確認してください。

よくある質問

個人向けプランと法人向けプランで、学習の扱いはどう違いますか?

公式ドキュメントによると、Free・Pro・Max は利用者が設定で選び、オンのときは Claude Code のデータも学習に使われます。Team・Enterprise や API などは、商用規約のもとで原則学習されません。ただし、顧客がモデル改善のためにデータ提供を選んだ場合は別です。

出典: Data usage

生成AIを全面禁止にすれば安全ですか?

中小DXラボの記事では、全面禁止は一番安全に見えても、個人のスマホやアカウントで隠れて使われるシャドーAIを招きやすいと述べています。「この順番で確認し、この範囲でだけ使う」と説明できる設計が必要だとしています。

API キーやパスワードは、どう扱えばよいですか?

中小DXラボの記事では、.env のような専用の設定ファイルにまとめ、.gitignore に書いてバージョン管理に入れないことが挙がっています。コード・メモ・手順書・AI への依頼文には、キーそのものを書かないようにします。
