CLAUDE.md の書き方:置き場所の違いと短く保つコツ

公開: 2026年10月14日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントにもとづきます

結論

  • CLAUDE.md は、Claude Code がセッションの最初に読む「説明書き」です。最初は「立場・道具・優先順位」の3行で十分です。
  • 置き場所で効く範囲が変わります。誰のためのルールかで、組織用・自分用・プロジェクト用・ローカル用を使い分けます。
  • 公式ドキュメントの目安は1ファイル200行以下です。禁止したいことは CLAUDE.md ではなく権限設定に書きます。

CLAUDE.md とは

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、新しいセッションを前回の会話を覚えていない状態で始めます。毎回同じ説明を打ち込まなくて済むように、最初に読ませる説明を書いておくファイルが CLAUDE.md です。中身はふつうの Markdown(見出しや箇条書きを書けるテキスト)です。

大事なのは、CLAUDE.md は強制力のある設定ではないという点です。Claude は書かれた内容に従おうとしますが、操作を止める仕組みではありません。「このファイルは読まない」「このコマンドは実行しない」を確実にしたいなら、settings.json の権限設定に書きます。

置き場所と効く範囲

執筆時点の公式ドキュメントでは、CLAUDE.md の置き場所は次の4種類です。

種類置き場所効く範囲と書く内容
組織用Windows: C:\Program Files\ClaudeCode\CLAUDE.mdその PC の利用者全員。管理者が置く、組織全体のルール
自分用(全プロジェクト)~/.claude/CLAUDE.md自分が使うすべてのプロジェクト。自分の好みや共通の習慣
プロジェクト用作業フォルダの CLAUDE.md または .claude/CLAUDE.mdそのフォルダで作業する全員。チームで共有する前提や手順
ローカル用作業フォルダの CLAUDE.local.md自分だけ、このプロジェクトだけ。.gitignore に入れて共有しない

同じ1行でも、置き場所は「誰のためのルールか」で決まります。「コードは他の人が読んで直せることを優先する」がチームの方針ならプロジェクト用、自分の書き方の好みなら自分用です。この振り分けをしておくと、プロジェクト用の CLAUDE.md を新しいメンバーに渡したときに、個人の好みまで持ち込まずに済みます。

読み込まれ方

公式ドキュメントによると、起動したフォルダとその上の階層にある CLAUDE.md と CLAUDE.local.md は、起動時にすべて読み込まれます。複数ある場合は上書きではなくつなげて読み込まれ、起動したフォルダに近いものほど後に読まれます。同じ階層では、CLAUDE.local.md が CLAUDE.md の後に足されます。

一方、起動したフォルダより下の階層にある CLAUDE.md は、起動時には読まれません。Claude がそのフォルダのファイルを読んだり書いたりしたときに読み込まれます。「サブフォルダに書いたのに効かない」と感じたら、この違いを思い出してください。

最初に書く3行

何を書けばよいか迷ったら、次の3つを1行ずつ書くところから始めます。

  1. 自分の立場(何のために使うか)
  2. よく使う道具
  3. 判断に迷ったときの優先順位
# 業務環境メモ

- 私は中小企業の情シス担当で、社内の業務改善ツールを作っています
- よく使うのは Microsoft 365、Power Automate、Excel、Python です
- コードは「短さ」より「他の人が読んで直せること」を優先してください

すでにファイルがあるフォルダなら、Claude Code の中で /init を実行すると、フォルダの中身から最初の CLAUDE.md を作ってくれます。CLAUDE.md がすでにある場合は、上書きせずに改善案を出す、と公式ドキュメントに書かれています。

書き足すタイミングの目安は、同じ説明を2回打ち込んだと気づいたときです。そのつど1行足していくと、自分の業務に合った内容に育っていきます。

短く保つコツ

公式ドキュメントでは、1ファイルあたり200行以下が目安とされています。長くなるほど読み込みの負担が増え、守られにくくなるためです。短く保つために、次の書き方を意識します。

  • 具体的に書く: 「きれいに整形する」ではなく「日付は yyyy/mm/dd 形式で出力する」。あいまいな1行は補足の行を呼び込みます。
  • 確かめられる形で書く: 「テストする」ではなく「完成したら、サンプルの Excel で結果が合うか確認する」。
  • 矛盾させない: 食い違う指示があると、Claude はどちらかを選んでしまいます。1行足すときは、同じ話題の行がないかを探し、あれば書き換えます。

200行を超えそうになったら、まず削れる行を探します。言われなくても守られていること、もう使っていない道具や手順、ほかの置き場所に移すべき個人の好みが候補です。

それでも長い場合、公式ドキュメントには2つの方法があります。.claude/rules/ にテーマごとのファイルを分けると、特定のファイルを扱うときだけ読み込ませる指定ができます。CLAUDE.md の中に @パス と書いて別のファイルを読み込む方法もありますが、こちらは起動時に一緒に読み込まれるため、読み込む量は減りません。

書いてはいけないもの

プロジェクト用の CLAUDE.md は Git などで共有されることが多いファイルです。パスワード、API キー、トークン、個人情報、顧客名、取引金額などは書きません。これらは共有の対象から外したファイルで管理し、Claude Code に読ませたくないものは権限設定の deny で止めます。

よくある質問

自分の PC と他の人の PC で、返答の傾向が違います

自分用の ~/.claude/CLAUDE.md も一緒に読み込まれているためと考えられます。チームで共有したい内容はプロジェクト用に移し、配る前の確かめは利用者と同じ条件のアカウントで行います。

CLAUDE.md とスキルはどう使い分けますか

CLAUDE.md は毎回読ませる前提、スキルはその作業を頼まれたときに使う手順書です。議事録の要約のように、決まった作業の手順と出力の形はスキルに分けると、CLAUDE.md を短く保てます。

CLAUDE.md があるフォルダで /init を実行すると上書きされますか

公式ドキュメントでは、すでに CLAUDE.md がある場合は上書きせず、改善案を出すとされています。定期的な見直しのたたき台として使う方法もあります。

CLAUDE.md のひな形を作る

CLAUDE.md テンプレート生成 で、用途・言語・守ってほしいことを選ぶと、ひな形を出力できます。最初の3行版にも切り替えられ、200行以内に収まっているかを行数で表示します。
