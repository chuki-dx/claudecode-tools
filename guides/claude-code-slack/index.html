Claude Code を Slack から使う方法:設定の流れ・権限・制限

公開: 2026年10月17日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • この記事の Slack 連携は、個人アカウントで動く旧来の版で、対象は Pro と Max、かつ Claude Tag に接続されていない Slack ワークスペースです。
  • 設定は、管理者による Claude アプリの導入、各自のアカウント連携、GitHub とクラウドセッションの準備、チャンネルへの招待の順です。
  • セッションは各利用者のアカウントと上限で動き、DM では使えず、GitHub のみ・1セッション1PRの制限があります。

何ができて、どのプランで使えるか

公式ドキュメントによると、Slack で @Claude にコーディング作業を頼むと、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のクラウドセッションが作られます。チームの会話から離れずに開発作業を任せられる機能です。本記事は執筆時点(2026年10月)の公式ドキュメントだけを根拠にしています。

  • バグの調査と修正の依頼
  • チームの意見を受けた小さな機能の実装やリファクタリング
  • 会話にある再現手順やユーザー報告を踏まえたデバッグ
  • Slack で依頼して別作業を続け、完了時に通知を受け取る

対象の条件

公式ドキュメントでは、この版は各セッションを個人の Claude アカウントで動かし、チャンネルでの @mention に応答するのは Pro と Max のアカウントだけです。さらに、どの組織も Claude Tag(組織の共通の ID で @Claude を動かす仕組み)に接続していないワークスペースに限られます。

Team・Enterprise プランでは既存の Slack アプリと @Claude のハンドルは残り、新しいワークスペースでは Claude Tag を設定する、とされています。その手順は出典に無いため、公式ドキュメントで確認してください。

出典: Claude Code in Slack

設定の流れ

公式ドキュメントが示す前提は、Pro または Max、Slack 側の条件、クラウドセッションの有効化、claude.ai/code での GitHub 接続とリポジトリ認証、Slack と Claude アカウントの連携です。手順は次のとおりです。

  1. Slack ワークスペースの管理者が、Slack App Marketplace から Claude アプリを導入します。
  2. 各利用者が Slack の Claude アプリの App Home タブで「Connect」を押し、ブラウザで認証を完了します。
  3. 同じアカウントで claude.ai/code にサインインし、GitHub を接続して、使わせたいリポジトリを1つ以上認証します。
  4. App Home の Routing Mode を選びます。
  5. チャンネルで /invite @Claude と入力して招待します。

Routing Mode は2種類です。「Code only」はすべての @mention を Claude Code に回します。「Code + Chat」は内容を見て、コーディングは Claude Code、文章作成や分析、一般的な質問は Claude Chat に振り分けます。Chat に振られたときは「Retry as Code」で Claude Code に切り替えられ、逆の場合もスレッドで選べます。

出典: Claude Code in Slack

使い方と画面の操作

Code + Chat では、コーディング作業と判断されたものがクラウドセッションになり、それ以外は通常のチャット返信です。Code only ではすべて Claude Code に渡ります。コーディング作業として扱うよう明示することもできます。

文脈は、スレッドで呼べばスレッド内の全メッセージ、チャンネルで直接呼べば最近のチャンネルメッセージから集められます。完了時には、次のボタンが表示されます。

  • View Session:ブラウザでセッション全体を開き、続きの依頼もできます。
  • Create PR:セッションの変更からプルリクエストを作ります。
  • Retry as Code:チャット応答だったものを Claude Code で再実行します。
  • Change Repo:選ばれたリポジトリが違うときに変更します。

依頼は、ファイル名や関数名、エラーメッセージを入れ、リポジトリと完了条件(テストや PR 作成の要否など)を書き、スレッドで会話すると意図が伝わりやすいと公式ドキュメントにあります。ファイルのアップロードやリアルタイムのやり取りが要る作業、長く複雑な作業は、Web を直接使う方がよいとされています。

出典: Claude Code in Slack

権限・アクセス制御と注意点

  • セッションは各利用者が自分の Claude アカウントで実行し、利用量とレート上限は個人のプランの上限に数えられます。具体的な数値は出典に無いため、公式で確認してください。
  • リポジトリは、本人が接続したものだけ使えます。
  • セッションは claude.ai/code の履歴に残ります。Team・Enterprise のアカウントでは、Slack から作ったセッションは組織から自動で見えます。

ワークスペースでは、管理者がアプリを導入するかを決めます。Enterprise Grid では組織の管理者が、どのワークスペースで使えるかを管理できます。アプリを削除すると、そのワークスペースの全利用者のアクセスがすぐに失効します。

チャンネルについては、導入しただけでは Claude はどのチャンネルにも入りません。招待したチャンネルの @mention にだけ応答し、公開・非公開の両方で動きます。管理者は招待先と参加者を管理することで、利用範囲を絞れます。

注意点が2つあります。DM では動きません。また、呼び出された会話の文脈を Claude が参照し、他のメッセージの指示に従うことがあるため、信頼できる Slack の会話でだけ使うよう公式ドキュメントは求めています。

出典: Claude Code in Slack

制限と、通知・エラーが出たとき

  • GitHub のリポジトリのみ対応
  • 1セッションで作れるプルリクエストは1つ
  • クラウドセッションへのアクセスが必要

通知が返ってきたとき

「This workspace isn't set up for Claude Tag yet」は、組織が Claude Tag に接続しておらず、連携したアカウントが Pro・Max でない場合に @Claude が返す通知です。通知にある @Claude connect から始め、Claude Tag の設定に進みます。

退役の通知は The legacy Claude in Slack bot is retired effective October 5, 2026 and no longer responds in channels. で始まります。ワークスペースが Claude の組織に接続され、その組織の Claude Tag 設定で旧版が選ばれたままの状態で、自分のプランに関係なく Pro・Max にも出ます。組織の Owner が管理設定で Claude Tag をオンにする必要があり、Owner でなければ Owner に伝えます。

その他のエラー

  • 「Claude Code is not enabled for your account」:claude.ai/code に一度サインインして web onboarding を終えると、次の @mention で解消します。利用者ごとに必要です。
  • セッションが始まらない:App Home での接続、クラウドセッションの有効化、GitHub リポジトリの接続を確認します。
  • リポジトリが違う・出ない:「Change Repo」や依頼文へのリポジトリ名、claude.ai/code での接続、GitHub 権限を確認します。

よくある質問

Team プランの会社でもこの連携を使えますか?

公式ドキュメントによると、この版は Pro と Max のアカウントだけが対象で、Team・Enterprise プランでは Claude Tag を設定します。手順は公式ドキュメントで確認してください。

出典: Claude Code in Slack

DM で使えますか?

使えません。公開または非公開のチャンネルで、/invite @Claude で招待したあとの @mention にだけ応答します。

出典: Claude Code in Slack

利用量は誰の分に数えられますか?

各セッションは利用者本人のアカウントで動き、本人のプランの上限に数えられます。金額や回数は出典に無いため、最新の内容は公式の料金ページで確認してください。
