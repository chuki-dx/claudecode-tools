Claude Code のステータスライン設定方法と、表示されないときの確認点

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のステータスラインは、/statusline コマンドで作るか、設定ファイルに statusLine を書いて設定します。
  • ステータスラインはスクリプトの標準出力を表示する仕組みで、ローカルで動き、API トークンは消費しないと公式ドキュメントにあります。
  • 表示されないときは、実行権限、標準出力、ワークスペースの信頼、管理設定の順に確認します。本記事は執筆時点(2026年10月)の公式ドキュメントに基づきます。

ステータスラインでできること

公式ドキュメントによると、Claude Code は JSON 形式のセッションデータをスクリプトの標準入力に渡し、スクリプトが標準出力に出したものをそのまま表示します。ローカルで動作し、API トークンは消費しません。ヘルプメニューや権限確認のプロンプトの間は、一時的に非表示になります。

出力は複数行にでき、ANSI エスケープコード(文字色などを変える制御コード)で色も付けられます。色はターミナル側の対応が必要です。OSC 8 エスケープシーケンスでクリックできるリンクも作れますが、iTerm2、Kitty、WezTerm のようなハイパーリンク対応のターミナルが必要です。

端末サイズは tput cols では読めず、COLUMNS と LINES の環境変数を読みます。

出典: Customize your status line

設定方法1:/statusline コマンドで作る

設定方法は大きく2つあります。1つ目は、表示したい内容を自然言語で伝える方法です。Claude Code が ~/.claude/ にスクリプトを生成し、設定も自動で更新します。公式ドキュメントの例です。

/statusline show model name and context percentage with a progress bar

ファイル編集の許可を求められたら承認します。社内で配る前に、生成されたスクリプトの中身は確認してください。

出典: Customize your status line

設定方法2:settings.json に statusLine を書く

手動の場合は、ユーザー設定(~/.claude/settings.json)またはプロジェクト設定に statusLine フィールドを追加します。type は "command" にし、command にはスクリプトのパスかインラインのシェルコマンドを指定します。

{
  "statusLine": {
    "type": "command",
    "command": "~/.claude/statusline.sh",
    "padding": 2
  }
}

command はシェルで実行されるため、公式の例のように jq で JSON の入力を解析し、モデル名とコンテキストの割合を表示するインラインのコマンドも書けます。任意のフィールドは次のとおりです。

  • padding:内容に横方向の余白を文字数で足します。既定値は 0 です。端末の端からの距離そのものではなく、相対的なインデントを調整します。
  • refreshInterval:イベントによる更新に加えて、N 秒ごとにコマンドを再実行します。最小値は 1 です。時計のような時間に関わる表示向けで、未設定ならイベント時だけ実行されます。
  • hideVimModeIndicator:-- INSERT -- の組み込み表示を隠します。スクリプトで vim.mode を表示するとき、二重表示を避けるために true にします。

無効にするには、/statusline delete のように削除を頼むか、settings.json から statusLine フィールドを消します。

更新タイミングと運用のコツ

スクリプトはセッション開始時に1回実行され、その後は新しいアシスタントのメッセージが届いたとき、/compact が終わったとき、権限モードや Vim モードが変わったとき、command を変更したとき、refreshInterval のタイマーが経過したときなどに再実行されます。更新は 300ms でまとめられ、実行中に次の更新が起きると実行中のスクリプトは中止されます。スクリプトを編集した場合、変更は次の更新のきっかけで反映されます。

運用のコツは、出力を短くすること、遅い処理をキャッシュすることです。実行は頻繁なので、git status のようなコマンドは遅延の原因になります。コンテキストの割合は used_percentage を使うのが最も簡単で正確と書かれています。テスト用のモック入力の例も公式ドキュメントにあります。

ccstatusline や starship-claude というコミュニティのプロジェクトが、テーマ付きの設定を提供していると紹介されています。利用する場合は各プロジェクトの内容を確認してください。

表示されないときの確認点

公式ドキュメントのトラブルシューティングには、次の確認項目があります。

  • chmod +x ~/.claude/statusline.sh で実行権限を付ける
  • 出力が標準エラーではなく標準出力に出ているか確認する
  • スクリプトを手で実行して出力を確認する
  • Windows で Git Bash を入れている場合は、command のパスにスラッシュを使う
  • 設定の優先順位を適用した結果、管理設定以外で disableAllHooks が true になっていると、管理設定の statusLine だけが動き、無ければ無効になる
  • 組織が allowManagedHooksOnly を管理設定で使っていると、独自のステータスラインは警告なしに消える。自分に当てはまるか管理者に確認する
  • claude --debug で、毎回の実行時のスクリプトの標準エラー出力と、セッション内の最初の実行時の終了コードを確認する

ワークスペースの信頼ダイアログを承認するまでも空白のままです。statusLine はシェルコマンドを実行するため、設定ファイル内のフックと同じ信頼のルールが適用されます。Claude Code を再起動し、信頼ダイアログを承認すると有効になります。また、スクリプトが終了コード 0 で終わった後にだけ表示され、非ゼロや出力なしだと空白になります。

値や表示がおかしいとき

  • -- や空の値:最初の API 応答の前は null のことがあります。// 0 のようなフォールバックをスクリプトに書きます。
  • コンテキストの割合が違う:/context は直近の応答以降のメッセージの推定を足すため、次の応答まで高く出ることがあります。
  • 表示が乱れる:複雑なエスケープシーケンスは他の UI 更新と重なると乱れることがあり、複数行ほど起きやすいです。平文に単純化して試します。
  • リンクがクリックできない:Terminal.app は対応していません。SSH や tmux は OSC のシーケンスを取り除くことがあります。
  • 通知との同居:フルスクリーン表示以外では通知が同じ行に出るため、狭い端末ではステータスラインが切れることがあります。

よくある質問

ステータスラインを使うと API トークンは消費しますか?

公式ドキュメントによると、ステータスラインはローカルで動き、API トークンを消費しません。

出典: Customize your status line

設定したステータスラインを消すにはどうしますか?

/statusline で削除や消去を頼むか、settings.json から statusLine フィールドを手で消します。頼み方の例として /statusline delete が挙げられています。

出典: Customize your status line

時刻のように時間で変わる表示を更新し続けるには?

refreshInterval を設定します。N 秒ごとにコマンドが再実行され、最小値は 1 です。未設定の場合はイベント時だけ実行されます。
