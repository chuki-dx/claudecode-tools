VS Code の Claude Code 拡張の設定:Manual など権限モードと CLI の使い方

公開: 2026年11月26日 ・ 中小DXラボ ・ 内容は執筆時点(2026年11月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 拡張は、公式ドキュメントの「Install for VS Code」リンクか、拡張機能ビューでの「Claude Code」検索で入れます。ターミナルで claude を使うには、別に CLI の単体インストールが必要です。
  • Manual は default の別名です。権限モードは出典の「Best for」の範囲で選び、新しい会話の開始モードは initialPermissionMode や Claude Code のバージョンで変わります。
  • ターミナル風の画面にしたいときは useTerminal を使います。拡張の会話は claude --resume で CLI に引き継げます。

インストールの方法と前提条件

公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の拡張には、VS Code 1.94.0 以降と Anthropic のアカウントが必要です。アカウントは有料の Claude サブスクリプション(Pro、Max、Ultra、Team、Enterprise)か Claude Console アカウントで、API キーは不要とされています。Amazon Bedrock などの外部プロバイダーを使う場合は、公式ドキュメントで確認してください。

インストールは二通りです。「Install for VS Code」のリンク(リンク先は vscode:extension/anthropic.claude-code)を開くか、Ctrl+Shift+X(Mac は Cmd+Shift+X)で拡張機能ビューを開き、「Claude Code」を検索して Install を押します。

拡張機能のマーケットプレイスはサードパーティのソフトウェアで、Anthropic は推奨・保守・監査をしないと注記されています。インストール後に拡張が表示されない場合は、VS Code の再起動か、コマンドパレットの「Developer: Reload Window」を試します。

拡張の設定の場所と主な項目

公式ドキュメントでは、設定を二か所に分けています。VS Code の拡張機能設定(Ctrl+,(Mac は Cmd+,)から Extensions > Claude Code)は、拡張の動作用です。~/.claude/settings.json は拡張と CLI で共有し、許可するコマンド、環境変数、フック、MCP サーバーなどに使います。

主な拡張設定は次のとおりです。

  • useTerminal(既定は false):グラフィカルなパネルではなく、ターミナルモードで Claude を起動します。
  • initialPermissionMode(既定は未設定):新しい会話の承認プロンプトを制御します。値は default、plan、acceptEdits、bypassPermissions です。
  • preferredLocation(既定は panel):Claude を開く場所で、sidebar(右)か panel(新しいタブ)です。
  • allowDangerouslySkipPermissions(既定は false):モード選択に Bypass permissions を追加します。インターネットに接続できないサンドボックスでのみ使うよう書かれています。

initialPermissionMode は、ユーザー設定の値だけが読まれ、ワークスペースの値は無視されます。v2.1.225 より前は、既定が default でワークスペースの値も適用されていました。

権限モードと Manual の位置づけ

公式ドキュメントによると、各モードは便利さと監督のトレードオフです。Manual モードは設定値では default と書かれます。拡張の initialPermissionMode でも manual は default の別名で、モード表示の Manual を選びます。CLI でも claude --permission-mode manual や "defaultMode": "manual" と書けます。

出典の表にある「Best for」(向いている用途)は次のとおりです。どれが良いかは断定せず、用途と社内ルールに合わせて選ぶ材料としてください。

  • default(Manual):機微な作業、不慣れなコード
  • acceptEdits:レビューしているコードの反復作業
  • plan:変更前にコードベースを調べる作業
  • auto:長いタスク、承認の手間を減らしたい場合
  • dontAsk:ロックダウンした CI やスクリプト
  • bypassPermissions:隔離されたコンテナと VM のみ

拡張の initialPermissionMode で指定できるのは、前節の4つの値です。拒否ルールは bypassPermissions を含む全モードで効き、許可ルールは bypassPermissions では効果がありません。

出典: Choose a permission mode

新しい会話がどのモードで始まるか

initialPermissionMode を未設定にすると、拡張が開始モードを決めます。執筆時点(2026年11月)の公式ドキュメントでは、ターミナルまたは VS Code 拡張で始めた場合の組み込みの既定は、Claude Code v2.1.283 以降なら auto です。それより前は、Pro、Max、Ultra、Team プランで機能フラグを取得するセッションなら auto、それ以外は default です。

ただし auto が選ばれても、そのセッションで auto mode が使えなければ Manual で始まります。いずれかの設定ファイルで disableAutoMode が "disable" の場合も、default です。

拡張でも、v2.1.283 以降は ~/.claude/settings.json を開始モードの入力の一つにできます(それより前は Pro、Max、Ultra、Team プランのみ)。一方、拡張が開始モードを決めるときは、プロジェクトの設定を読みません。詳しい順序は公式ドキュメントの「Switch permission modes」で確認してください。

ターミナルのセッションを毎回 Manual で始めたい場合は、~/.claude/settings.json に次を保存します。

{
  "permissions": {
    "defaultMode": "default"
  }
}

次のセッションでは、ステータスバーに ⏸ manual mode on と表示されます。

拡張と CLI の違い、統合ターミナルで claude を使う方法

公式ドキュメントによると、拡張はグラフィカルなパネル、CLI はターミナルのコマンドラインで、CLI だけの機能があります。コマンドとスキルは CLI がすべて、拡張は一部(/ で確認)です。! Bash ショートカットとタブ補完は CLI のみです。

CLI 風の画面にしたい場合は、Extensions > Claude Code の Use Terminal(useTerminal)にチェックを入れます。

統合ターミナルで claude を使うには、CLI の単体インストールが必要です。拡張は claude を PATH に追加せず、同梱の CLI はチャットパネル用の非公開のコピーです。入れても claude が見つからない場合は、公式ドキュメントの PATH の確認手順を見てください。

統合ターミナルから拡張に接続するには、拡張を入れてから claude を起動すると自動で接続されます。Claude Code v2.1.318 以降は拡張を自動では入れないため、入れるまでは /ide が「No available IDEs detected」と報告します。外部ターミナルでは /ide で VS Code に接続します。

拡張と CLI は会話履歴を共有します。拡張の会話を CLI で続けるには、ターミナルで claude --resume を実行し、選択画面から選びます。

よくある質問

Manual モードは default と別のモードですか?

別のモードではなく、manual は default の別名です。公式ドキュメントでは、Manual モードは設定値では default と表記され、拡張の initialPermissionMode では manual がモード表示の Manual を選びます。

出典: Choose a permission mode

拡張を入れれば、ターミナルで claude コマンドも使えますか?

使えません。拡張は claude を PATH に追加しないため、ターミナルで使うには CLI の単体インストールが必要です。入れても見つからない場合は、公式ドキュメントの PATH の確認手順を参照してください。

出典: Use Claude Code in VS Code

ワークスペースの設定で initialPermissionMode を指定できますか?

公式ドキュメントでは、VS Code は initialPermissionMode をユーザー設定から読み、ワークスペースの値は無視すると書かれています。v2.1.225 より前はワークスペースの値も適用されていました。
