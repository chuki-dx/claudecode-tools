Claude Code の定期実行:/loop とデスクトップ予約タスクの違いと使い分け

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の予約実行はクラウド・デスクトップ・/loop の3種類で、マシンなしで動かすならクラウド、ローカルファイルが要るならデスクトップ、セッション中の確認なら /loop が目安です。
  • /loop はセッションが開いている間の仕組みで、固定間隔のループは Esc や Ctrl+C では止まらず、Claude に取り消しを頼みます。
  • デスクトップの予約タスクは、アプリ起動中かつ PC が起きている間だけ動きます。権限確認で止まらないよう、作成後に Run now で試します。

3つの予約方法は何が違うのか

本稿は執筆時点(2026年10月)の公式ドキュメントに基づきます。公式ドキュメントによると、定期的な作業や一度きりの作業を予約する方法は3つあります。

  • クラウド:標準では Anthropic が管理するクラウドで動き、マシンの電源もセッションも不要です。ローカルファイルは使えず(新規クローン)、最短間隔は1時間です。
  • デスクトップ:自分のマシンで動き、電源は必要ですがセッションは不要です。ローカルファイルを使えます。最短間隔は、Claude が設定する場合は1分、フォームからは1時間です。
  • /loop:自分のマシンで動き、電源と開いているセッションの両方が必要です。最短間隔は1分で、権限確認や MCP サーバーはセッションから引き継ぎます。

使い分けの目安は、マシンなしで確実に動かす作業はクラウド、ローカルのファイルやツールが要る作業はデスクトップ、セッション中の素早い確認は /loop とされています。

/loop の基本:間隔とプロンプトの指定

/loop は同梱スキル(Claude Code に最初から入っている機能)で、セッションを開いたまま同じプロンプトを繰り返す最も手早い方法です。間隔とプロンプトはどちらも省略でき、指定内容で動きが変わります。

  • /loop 5m check the deploy:間隔とプロンプトを指定。固定のスケジュールで実行されます。
  • /loop check the deploy:プロンプトのみ。反復ごとに Claude が間隔を選びます。
  • /loop:間隔のみ、または何も指定しない場合。組み込みの保守用プロンプト、または loop.md があればそれが動きます。

固定間隔で動かす

間隔を指定すると、Claude が cron 式(定期実行の指定形式)に変換して登録し、間隔とジョブ ID を知らせます。

/loop 5m check if the deployment finished and tell me what happened

間隔は 30m のように先頭に置くか、every 2 hours のように後ろに付けます。単位は s、m、h、d です。秒は1分に切り上げられ、7m や 90m のようにきれいに割れない間隔は近い値に丸められ、Claude が選んだ値を知らせます。

間隔を Claude に任せる

間隔を省くと、Claude が反復ごとに1分から1時間の範囲で待ち時間を選び、その理由とともに表示します。

/loop check whether CI passed and address any review comments

スキルも渡せます(例:/loop 20m /review-pr 1234)。ただし Claude が自分で呼び出せるスキルだけが実行されます。/model などの組み込みコマンド、disable-model-invocation: true のスキル、MCP プロンプトは、実行されずにテキストとして渡ります。

loop.md で既定の動きを変える・止め方

引数なしの /loop の既定は保守用プロンプトです。未完了の作業の続き、現在のブランチの PR(レビューコメント、失敗した CI、マージコンフリクト)の対応、保留がなければ整理作業の順に進みます。プッシュや削除のような元に戻せない操作は、会話で既に許可された作業の続きの場合だけ進みます。

自分の指示に置き換えるには loop.md を作ります。.claude/loop.md(プロジェクト単位)が ~/.claude/loop.md(ユーザー単位)より優先され、どちらも無ければ組み込みのプロンプトに戻ります。複数タスクの一覧ではなく既定プロンプト1つで、コマンドラインにプロンプトを書いた場合は無視されます。

  • 間隔を省いたループ:次の反復を待っている間に Esc で止められます。
  • 固定間隔のループ:Esc や Ctrl+C では止まらず、Claude に取り消しを頼みます。取り消さない場合は7日で終わります。

/loop の制約:セッションが前提

公式ドキュメントでは、セッション単位のスケジュールの制約が挙げられています。

  • Claude Code が起動していて待機中のときだけ発火します。ターミナルを閉じると止まります。
  • 見逃した分の追いかけ実行はなく、待機状態に戻った時点で1回だけ実行されます。
  • claude --resume で再開すると、CronCreate で予約したタスクは復元されます(期限切れの繰り返しタスクなどを除く)。間隔を省いた /loop は復元されないため、再実行します。

無人で動かす用途には、クラウドの予約タスク、GitHub Actions の schedule トリガー、デスクトップの予約タスクが挙げられています。

デスクトップの予約タスクの作り方と注意点

公式ドキュメントによると、ローカルの予約タスクには Claude Desktop 1.1.5368 以降が必要です。Code タブの Scheduled から New task を開き、メニューが出た場合は Set up manually を選びます。

  1. Name に名前を入力します。小文字のケバブケースに変換されてディスク上のフォルダー名になるため、タスク間で重複させません。
  2. 指示欄に実行内容を書きます。
  3. Advanced settings の General タブで Only on this computer をオンにします。スイッチが使えない場合は、リポジトリや GitHub イベント・API のトリガーを外します。これらがあるとクラウドの予約タスクになるためです。
  4. Local folder でフォルダーを選びます。選ぶまで Create は押せません。
  5. Trigger でスケジュールのプリセットを選び、権限モードとモデルを選んで Create を押します。

ダイアログの上部に Only on this computer がある場合は、入力前にそれをオンにします。

Desktop はアプリが開いている間、1分ごとに予定を確認し、期限のタスクを新しいセッションで始めます。実行はアプリ起動中かつ PC が起きている間だけで、スリープ中に予定時刻が過ぎるとその回はスキップされます。Settings > This computer > System の Keep computer awake でアイドルスリープは防げますが、ノート PC の蓋を閉じるとスリープします。

権限はタスクごとに設定します。Manual モードで権限のないツールが必要になると、承認するまで実行が止まります。止まりを避けるには、作成後に Run now を押し、権限確認で「always allow」を選びます。以後の実行は同じツールを自動承認し、詳細ページで取り消せます。requiresUserInteraction の MCP ツールは毎回確認が出て、実行のたびに止まります。

よくある質問

PC を閉じても動かしたい定期実行はどれですか?

公式ドキュメントによると、マシンの電源が不要なのはクラウドの予約タスクです。デスクトップと /loop は、マシンが起動している必要があります。

出典: Run prompts on a schedule

固定間隔の /loop はどう止めますか?

Claude に「cancel the deploy check loop」のように取り消しを頼みます。Esc と Ctrl+C では止まりません。取り消さない場合は7日で終わります。

出典: Run prompts on a schedule

デスクトップの予約タスクが途中で止まるのはなぜですか?

Manual モードで権限のないツールが必要になると、承認するまで止まります。履歴からその実行のセッションを開いて承認するか、作成後に Run now で「always allow」を選びます。
