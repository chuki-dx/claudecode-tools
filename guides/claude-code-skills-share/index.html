Claude Code のスキルをチームで共有する方法と、動かないときの確認順

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のスキルは、プロジェクト、プラグイン、管理設定の3つの範囲で配布できます。
  • 小さく始めるなら、.claude/skills/ をバージョン管理にコミットする方法があります。同梱スクリプトの実行環境(公式の例では Python 3)も、配布前に確認してください。
  • 動かないときは、description のキーワード、What skills are available? での表示、/skill-name での直接呼び出しの順に確認します。

スキルをチームで共有する3つの範囲

スキル(SKILL.md に説明と手順を書き、Claude が必要に応じて使う仕組み)は、配る相手に応じて範囲を選べます。公式ドキュメントによると、次の3つです。

  • プロジェクトのスキル: .claude/skills/ をバージョン管理にコミットします。
  • プラグイン: プラグインの中に skills/ ディレクトリを作ります。
  • 管理(Managed): 管理設定を通じて、組織全体に配布します。

プラグインや管理設定の具体的な手順は今回の出典に書かれていないため、公式ドキュメントで確認してください。本記事は執筆時点(2026年10月)の公式ドキュメントに基づきます。

出典: Extend Claude with skills

公式の例でスキルの作りと動作確認を見る

公式ドキュメントには、コードベースを HTML で見せる codebase-visualizer というスキルの例があります。最初に作るディレクトリは次のとおりです。

mkdir -p ~/.claude/skills/codebase-visualizer/scripts

SKILL.md ではスクリプトのパスに ${CLAUDE_SKILL_DIR} を使っており、個人用・プロジェクト用・プラグイン用のどこに入れても正しく解決されます。チームで配るスキルでは参考になる書き方です。同梱の visualize.py は Python 3 が必要ですが、組み込みライブラリだけを使うため、追加のパッケージは要りません。

確認は、任意のプロジェクトで Claude Code を開き「Visualize this codebase.」と頼みます。ブラウザが開かない環境では、表示された生成ファイルのパスで成功を確認できます。

スキルが呼ばれないときの確認順

公式ドキュメントが挙げる確認手順は次のとおりです。

  1. description に、利用者が自然に言うキーワードが入っているか確認する。
  2. What skills are available? でスキルが一覧に出るか確認する。
  3. 依頼の言い方を description に近づけて言い直す。
  4. ユーザーが呼び出せるスキルなら /skill-name で直接呼ぶ。
  5. /skill-name も認識されない場合は、Claude Code がスキル名を受け付けなかった可能性を確認する。
  6. paths を設定している場合は、Claude が読む・編集・書くファイルが現在の作業ディレクトリ内にあるか確認する。兄弟の git worktree のファイルは、/add-dir で追加していても有効になりません。その worktree で Claude Code を起動するか、/cd でセッションを移します。

フロントマター(ファイル先頭の設定部分)の YAML が壊れていると、本文は空のメタデータで読み込まれます。/skill-name は動いても、Claude は description と照合できません。--debug で解析エラーを確認できます。

解析できない SKILL.md を探すには claude plugin validate を使います。たとえば claude plugin validate .claude/skills です。Claude Code v2.1.233 以降が必要です。逆に呼ばれすぎる場合は、description を具体的にするか、disable-model-invocation: true を追加して手動呼び出しだけにします。

最初は従うのに、途中から従わなくなるとき

最初の応答では従うのに後から従わなくなる場合、公式ドキュメントは状況別に次を示しています。

  • 必ず守らせたいルールを飛ばす場合: hook(イベントのたびに実行される仕組み)に移します。Claude Code は、スキルに従っているかに関係なく hook を実行します。
  • 判断を伴う指針を飛ばす場合: 「テストを実行する」ではなく「編集のたびにテストを実行する」のように、作業全体に当てはまる書き方にします。Claude Code はスキルの内容を呼び出し時に会話へ追加し、後のターンでファイルを再読み込みしないためです。
  • 会話が圧縮された場合: スキルをもう一度呼び出して全文を戻します。圧縮後は冒頭部分しか保持できないことがあるため、重要な指示は SKILL.md の上のほうに書きます。

スキルが多いと description が切れる

公式ドキュメントによると、Claude Code はスキル名と description の一覧をコンテキストに読み込みます。名前は全件載りますが、スキルが多いと文字数の予算に収めるため一部の description が省かれ、照合に必要なキーワードが失われます。予算は、モデルのコンテキストウィンドウの 1% を基準に決まります。あふれると、呼び出す頻度の低いスキルから省かれます。

状況は /doctor で見積もりを確認できます。予算を上げるには skillListingBudgetFraction か環境変数 SLASH_COMMAND_TOOL_CHAR_BUDGET を設定します。優先度の低いスキルは skillOverrides で "name-only" にすると、説明なしで一覧に載ります。description と when_to_use は主な用途を先頭に書きます。各エントリの合算テキストは 1,536 文字が上限です。

会話が長くなると、スキルの指示が効かなくなるのはなぜですか?

公式ドキュメントによると、Claude Code はスキルの内容を呼び出し時に会話へ追加し、後のターンでファイルを再読み込みしません。会話が圧縮された場合は、スキルをもう一度呼び出して全文を戻してください。
