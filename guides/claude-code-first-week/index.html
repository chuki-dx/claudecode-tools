Claude Code を入れて最初の1週間にやること(兼任の情シス向け)

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code の最初の1週間は、成果を求めず「1日30分の固定ルーティン」と「3行の CLAUDE.md」を身につけることが目標です。
  • 1日30分は朝10分・昼5分・夜15分に分けます。朝は CLAUDE.md に1行足し、昼は小さな作業を頼み、夜は翌日の整理と自動化を1つだけ試します。
  • 注意点は入力する情報です。CLAUDE.md や渡すファイルには社内ルールで認められた情報だけを入れ、パスワードや顧客名は書きません。確実に止めたい操作は権限設定で止めます。

最初の1週間は成果を求めない:まず何を身につけるか

中小DXラボの記事では、Claude Code を入れても数日触って業務に組み込めないまま止まる流れを、情シスの兼任担当によくあるものとして挙げています。止まる理由は「時間がない」ことよりも、組み込む順番と、1回に使う時間の決め方にあると書かれています。

そこで記事が勧めるのが、最初の1週間は成果を求めず、「1日30分の固定ルーティン」と「3行の CLAUDE.md」だけを身につけることです。毎日決まった時間に決まったことをするので、何をするか考える時間がいらない、という考え方です。

この記事は、上記の記事の記載をまとめたもので、私が自社で試した結果ではありません。執筆時点(2026年10月)の内容として、社内に配る前に小さく試し、インストール手順や料金は公式ドキュメントで確認してください。

1日30分を朝・昼・夜に分ける

記事が示す形は、1日30分を3つに分ける方法です。

  • 朝(始業直後)10分:CLAUDE.md に1行足す(昨日の作業で分かった前提を書く)
  • 昼(昼休みの終わり)5分:午後の小さな作業を Claude Code に頼んでおく
  • 夜(終業前)15分:翌日の作業を整理し、1つだけ自動化を試す

ポイントは、時間ができたときにまとめて使うのではなく、業務の合間に少しずつ育てることだと記事は説明しています。

朝10分:CLAUDE.md に1行足す

朝は次の3つを行います。

  1. 昨日の作業で「最初から知っておいてほしかった」前提を1つ思い出す
  2. CLAUDE.md に1行追加する
  3. その状態で Claude Code を起動し、今日の作業の相談を1つする

たとえば、前日に業務システムの話をしたら画面の種類を取り違えられたなら、自社で使っている画面や設定を1行書いておきます。これを続けると、毎回の説明が減っていくとのことです。

昼5分と夜15分の頼み方

昼5分:小さな作業を頼んでおく

結果は午後に確認する前提で、指示は最低限にします。記事の例は、先月のヘルプデスクの問い合わせ記録を整理する依頼です。

午後の会議までに、先月のヘルプデスクの問い合わせを以下の観点で整理してください。

- @docs/helpdesk_log.csv を読む
- 質問内容を10カテゴリに分類
- 各カテゴリで最も多い質問を抜粋
- 「マニュアル化すべき度」を高/中/低で評価
- 結果は reports/helpdesk_faq.md に保存

@ に続けてファイルのパスを書くと、そのファイルを指定して読ませられます。扱うファイルは、記事の第1章で決めた「AI に入力してよい情報の範囲」に収まるものだけにします。個人名や顧客名が入った記録なら、その列を外したものを用意してから渡します。

夜15分:翌日の整理と自動化を1つ

夜の15分は2つに分けます。前半の7分は、翌日の作業一覧を貼り付けて分類を頼む時間です。

明日の作業一覧:(以下に箇条書きで貼り付け)

これを以下の観点で分類してください:

1. 私が手を動かす必要があるもの
2. Claude Code に任せられるもの(具体的にどう指示すべきかも)
3. 優先度が低くて翌週以降に回せるもの

後半の8分は、その日の作業のうち機械的だったものを1つだけ自動化してみます。時間を8分に区切るのが大事で、動かなかったら翌日やり直す前提で、まず試します。

出典: 第2章 最初の1週間の使い方 — 1日30分のルーティンと、3行の CLAUDE.md

CLAUDE.md を3行から始める

Claude Code は、会話を始めるたびに前回の中身を覚えていない状態から始まります。そこで、毎回同じ説明をしなくて済むように、セッションの最初に読ませる説明書きが CLAUDE.md です。中身は Markdown(見出しや箇条書きを書けるテキスト)です。

置き場所によって効く範囲が変わります。最初の1週間は、作業用フォルダの直下に置くプロジェクト用だけで十分とされています。自分用やチーム共有の使い分けは、記事の第5章で扱われています。

最初は次の3つを1行ずつ書きます。

  1. 自分の立場(何のために使うか)
  2. よく触る道具
  3. 判断に迷ったときの優先順位

情シスの例として、記事は次の内容を挙げています。

# 業務環境メモ

- 私は中小企業の情シス担当で、社内の業務改善ツールを作っています
- よく使うのは Microsoft 365、Power Automate、Excel、Python です
- コードは「短さ」より「他の人が読んで直せること」を優先してください

すでにファイルがあるフォルダなら、Claude Code の中で /init と入力すると、フォルダの中身を見て最初の CLAUDE.md を作ってくれます。作られたものに、自分しか知らない社内の前提を書き足す使い方も勧められています。

1行足すタイミング

記事は、公式ドキュメントでは次のようなときに書き足すとよいとされていると紹介しています。

  • Claude が同じ間違いを2回したとき
  • 前回と同じ説明を、もう一度チャットに打ち込んでいると気づいたとき
  • 新しいメンバーにも同じ説明が必要になりそうなとき

注意点:書いてはいけないものと、CLAUDE.md の限界

CLAUDE.md は共有されることが多いファイルです。パスワード、API キー、トークン、個人情報、顧客名、取引金額などは書かないようにします。

また、CLAUDE.md は強制力のある設定ではなく、Claude が読んで従おうとする説明書きです。確実に止めたい操作は、記事の第4章で扱う権限の設定で止めます。権限設定の書き方は出典に無いため、公式ドキュメントで確認してください。

渡すファイルと CLAUDE.md には、社内ルールで認められた情報だけを入れます。

1週間の進め方と、情報の扱い・効果の見方

1週間の進め方は次のとおりです。

  • 1日目:作業用フォルダを作り、3行の CLAUDE.md を書く(別の記事の1日目には、Claude Code のインストールも含まれています)
  • 2日目:朝10分を試す。CLAUDE.md に1行足す
  • 3日目:昼5分を試す(小さな作業で)
  • 4日目:夜15分を試す
  • 5日目:1週間分の CLAUDE.md を見直す。重複や矛盾を整理する
  • 6〜7日目:休み(続けるためのリセット)

最初の1週間は成果を求めず、ルーティンを身につけることだけを目標にします。30分取れない日は朝10分だけでも続け、欠けた日があっても翌日に戻れば問題ない、とされています。

業務情報の扱いについて、記事の筆者は、機密データそのものは入れず、業務プロセス・運用ルール・使っているツール構成は入れる方針で使っています。不安なときは、まず情シス責任者に「業務情報をAIに渡せる範囲」を確認する、という進め方です。

また記事には、個人向けプラン(Pro/Max)では Claude のプライバシー設定で会話をモデルの改善に使わない設定にでき、法人プラン(Team/Enterprise)は既定で学習に使われないとあります。最新の仕様は公式ページで確認してください。

効果について、筆者は自業務の作業時間が体感で月20時間ほど減ったと書いています。あくまで筆者の体感であり、同じ結果になる保証ではありません。

記事では、最初の1週間は成果を求めず、ルーティンを身につけることだけを目標にするとされています。30分取れない日は朝10分だけでも続け、欠けた日があっても翌日に戻れば問題ないという考え方です。

CLAUDE.md には最初に何を書けばよいですか。

自分の立場、よく触る道具、判断に迷ったときの優先順位を1行ずつ、計3行書きます。迷ったときは、Claude が同じ間違いを2回したときや、同じ説明をもう一度打ち込んでいると気づいたときに1行足します。
