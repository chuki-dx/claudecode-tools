Claude Code を Windows に入れる手順:ネイティブと WSL・インストール後の確認

公開: 2026年10月17日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Windows ではネイティブ(PowerShell か CMD)と WSL のどちらでも動かせます。サンドボックス実行が必要なら WSL 2、Windows 側のプロジェクトならネイティブが目安です。
  • コマンドは環境ごとに違います。PowerShell と CMD は別のコマンドで、WSL は WSL のターミナルで Linux 用のコマンドを実行します。
  • 終わったら新しいターミナルで claude --version を実行し、必要なら claude doctor で診断します。

まず決めること:ネイティブ Windows か WSL か

本記事は Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)を Windows に入れる手順を、公式ドキュメントの記述から整理したものです。執筆時点(2026年10月)の内容で、自分で試した結果ではないため、最新は公式ドキュメントで確認してください。

公式ドキュメントによると、対応 OS は Windows 10 1809+ または Windows Server 2019+ で、4 GB+ RAM、x64 または ARM64 プロセッサ、インターネット接続が必要です。Anthropic の対応国で使う必要もあります。

公式ドキュメントでは、プロジェクトの場所と必要な機能で選ぶとされています。

  • ネイティブ Windows:前提なし(Git for Windows は任意)。サンドボックスは非対応。Windows ネイティブのプロジェクトやツール向けです。
  • WSL 2:WSL 2 の有効化が前提。サンドボックス対応。Linux のツールチェーンやサンドボックス実行向けです。
  • WSL 1:WSL 1 の有効化が前提。サンドボックスは非対応。WSL 2 が使えない場合の選択肢です。

出典: Advanced setup

ネイティブ Windows に入れる手順

公式ドキュメントでは、ネイティブインストールが推奨されています。PowerShell か CMD で実行し、管理者として実行する必要はありません。違いは実行するコマンドだけで、プロンプトが PS C:\ なら PowerShell、PS が付かない C:\ なら CMD です。PowerShell では次を実行します。

irm https://claude.ai/install.ps1 | iex

CMD では次を実行します。

curl -fsSL https://claude.ai/install.cmd -o install.cmd && install.cmd && del install.cmd

インストール中は進捗が表示されません。終わったら新しいターミナルを開いて確認します。ネイティブ版はバックグラウンドで自動更新されます。

コマンドを取り違えると、次のエラーになると書かれています。

  • The token '&&' is not a valid statement separator:PowerShell で CMD 用を実行しています。
  • 'irm' is not recognized as an internal or external command:CMD で PowerShell 用を実行しています。

それ以外のエラー(403 など)は、公式のインストールのトラブルシューティングで対処を確認してください。

Git for Windows は任意

Git for Windows は任意で、Bash ツールと Monitor ツールが使う Git Bash を提供します。入れない場合、Claude Code はシェルツールとして PowerShell を使います。入れても Git Bash が見つからないときは、settings.json の env でパスを指定します。

{
  "env": {
    "CLAUDE_CODE_GIT_BASH_PATH": "C:\\Program Files\\Git\\bin\\bash.exe"
  }
}

WinGet で入れる場合

WinGet でも入れられますが、自動更新されません。定期的に winget upgrade Anthropic.ClaudeCode を実行する必要があります。

winget install Anthropic.ClaudeCode

出典: Advanced setup

WSL に入れる手順

WSL のディストリビューションを開き、Linux 用のインストールコマンドを実行します。インストールも claude の起動も WSL のターミナル内で行い、PowerShell や CMD からは行いません。WSL では Git for Windows は不要です。

curl -fsSL https://claude.ai/install.sh | bash

サンドボックスが必要なら WSL 2 にします。WSL 2 が使えないときは WSL 1 を選べますが、サンドボックスは使えません。

出典: Advanced setup

インストール後の確認

新しいターミナルを開き、次を実行します。

claude --version

正常なら 2.1.211 (Claude Code) のようにバージョン番号が表示されます。claude が見つからない、認識されないと出る場合は、インストール先が PATH に入っていません。公式のトラブルシューティングで PATH の直し方を確認してください。

より詳しく見るには、次のコマンドを使います。セッションを開始せず、インストールの状態、設定ファイルの検証エラー、修正案つきの警告を読み取り専用で表示します。

claude doctor

問題なければ、作業したいプロジェクトでターミナルを開き、次を実行すると対話セッションが始まります。

claude

出典: Advanced setup

デスクトップアプリで WSL を使う場合

公式ドキュメントによると、Windows のデスクトップアプリの Code タブは、WSL 2 のディストリビューション内でセッションを実行できます。要件は次のとおりです。

  • Windows 10 または 11 と WSL 2(WSL 1 は非対応)
  • ディストリビューションが1つ以上(例:Ubuntu)
  • ディストリビューション内に git がインストール済み

リポジトリがディストリビューション内のファイルシステムにある場合に向きます。Windows から触るとネットワークファイルシステム経由になり、遅く、ファイル監視も壊れるためです。

まだ使えない機能として、統合ターミナル、コネクターとプラグイン、セッションの分岐、ファイルブラウザペイン、@ 入力時のファイル候補が挙げられています。組織管理のデバイスでは WSL セッションが使えないことがあり、管理者の設定によります。

よくある質問

WSL に入れる場合、Git for Windows は必要ですか?

公式ドキュメントによると、WSL の構成では Git for Windows は不要です。Git for Windows が推奨されるのは、ネイティブ Windows で Bash ツールを使いたい場合です。入れなくても、Claude Code は PowerShell をシェルツールとして使います。

出典: Advanced setup

インストールできたかどうか、どう確認しますか?

新しいターミナルを開いて claude --version を実行します。公式ドキュメントによると、バージョン番号が表示されれば正常です。より詳しい診断には claude doctor があり、インストールの状態や設定ファイルのエラーを読み取り専用で表示します。

出典: Advanced setup

デスクトップアプリの Code タブでも WSL は使えますか?

公式ドキュメントによると、WSL 2 のディストリビューション内でセッションを実行できます。WSL 1 は非対応で、ディストリビューション内に git が必要です。統合ターミナルなど、まだ使えない機能もあります。
