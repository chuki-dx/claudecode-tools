Claude Code のプラグインは安全?入れる前の確認手順と公式マーケットプレイスの見分け方

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code のプラグインは利用者の権限で任意のコードを実行できます。入れる前の確認が前提です。
  • マーケットプレイスの名前で分かるのは、カタログの公開元だけです。個々のプラグインの動作は分からないため、どの取得元でも入れる前に確認します。
  • 確認は、取得元、/plugin の詳細画面、ソース、構成一覧の4段階です。信頼できなくなったら claude plugin uninstall <plugin> で削除します。

プラグインが手元のマシンでできること

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のプラグインについて、公式ドキュメントの内容を整理します。執筆時点(2026年10月)の公式ドキュメントによると、インストールしたプラグインは、利用者の権限で任意のコードを実行できます。プラグインは、マーケットプレイス(Claude Code がプラグインを取得するカタログ)からインストールします。

公式ドキュメントでは、インストール後のプラグインにできることとして、次のものを挙げています。

  • フック:ツール呼び出しの前後など、Claude Code の動作の節目でシェルコマンドとして実行されます。
  • モニター:バックグラウンドのシェルコマンドで、セッション開始時、プラグインの再読み込み時、名前付きスキルの初回実行時に Claude Code が自動で起動します。
  • Mod:Claude Code の中で、利用者の権限で JavaScript を実行します。
  • MCP / LSP サーバー:有効なプラグインが宣言したサーバーに接続します。stdio 型の MCP サーバーは、利用者のマシン上でプロセスとして起動します。
  • bin/ ディレクトリ:有効なプラグインの bin/ が Bash ツールの PATH に追加され、Claude の Bash コマンドからそこの実行ファイルを動かせます。
  • スキル・コマンド・エージェント:Claude への指示として文脈に入ります。
  • 更新:マーケットプレイスの自動更新が有効だと、確認したファイルが後から変わることがあります。

インストールすると有効にもなります。ただし、マニフェストやマーケットプレイスの項目が defaultEnabled: false を設定していて、利用者が自分で有効にしていない場合は除きます。

権限ルールとサンドボックスが及ばない範囲

公式ドキュメントによると、権限ルールとサンドボックスの対象は Claude が行うツール呼び出しで、プラグインが単独で実行するコードではありません。フック、モニター、MCP サーバー、LSP サーバー、Mod が起動するプロセスは、サンドボックスの外で動きます。プラグインの MCP ツールの呼び出しや、bin/ の実行ファイルを動かす Bash コマンドは、ツール呼び出しなので権限ルールが適用されます。

公式マーケットプレイスの見分け方

公式ドキュメントによると、マーケットプレイスの名前は、公式・コミュニティ・サードパーティの3段階のどれかに分かれます。公式とコミュニティの名前は、github.com/anthropics/ のリポジトリを取得元とするものだけ Claude Code が受け付けるため、サードパーティが Anthropic のものを名乗ることはできません。同僚や自社が公開するマーケットプレイスはサードパーティです。

  • 公式:claude-plugins-official など、公式名の一覧にあるもの
  • コミュニティ:claude-community、claude-plugins-community、healthcare
  • サードパーティ:それ以外のすべて

公式名の一覧には、ほかにも claude-code-marketplace や anthropic-marketplace などがあります。全体は公式ドキュメントで確認してください。なお claude-community のカタログは、ほぼすべての項目でコミットの SHA(Git の特定の版を指す識別子)を固定しており、異なるコミットのインストールを Claude Code が拒否します。

注意点として、名前から分かるのはカタログの公開元で、中の各プラグインが何をするかではありません。

入れる前の確認手順

  1. 取得元を確認する:シェルで claude plugin marketplace list を実行すると、各マーケットプレイスの追加元(GitHub リポジトリやディレクトリなど)が表示されます。
  2. 詳細画面を読む:セッション内で /plugin を実行してプラグインを選ぶと、Will install 欄に、コマンド、エージェント、スキル、フック、MCP / LSP サーバーが並びます。Anthropic が構成データを公開していないプラグインでは、マーケットプレイスの項目の宣言内容か、注記が出ます。
  3. ソースを読む:詳細画面の Open homepage か View on GitHub から開きます。どちらも無ければ、手順1で分かったリポジトリを見ます。Will install はフックの存在を示しますが実行内容は示さないため、hooks/hooks.json(各フックの実行コマンド)、.mcp.json(各サーバーのコマンドか URL)、bin/(中のすべてのファイル)を読みます。
  4. 構成を一覧にする:リポジトリをクローンし、claude --plugin-dir <plugin directory> plugin details <plugin name> を実行します。セッションを開始せずにファイルを読み、Component inventory を表示します。

インストール後は、claude plugin details <plugin name> で、インストール済みのコピーについて同じ一覧を表示できます。

警告・拒否と、削除の手順

公式ドキュメントによると、/plugin の詳細画面には、どのマーケットプレイスでも同じ信頼警告が出ます。内容は、インストール・更新・使用の前に信頼できるか確かめること、Anthropic はプラグインに含まれる MCP サーバーやファイルなどを管理せず、意図どおり動くことや変更されないことを検証できない、というものです。

Claude Code が警告でなく拒否する場合もあります。公式・コミュニティの名前を使いながら取得元が github.com/anthropics/ の外にあるときは、そのマーケットプレイスと、そこからインストールしたプラグインの読み込みを止めます。archive ソースに sha256 ダイジェストが固定され、ダウンロードしたファイルと一致しないときも、インストールを拒否します。

信頼できなくなったプラグインを削除する

シェルで claude plugin uninstall <plugin> を、インストールしたときの --scope を付けて実行します。そのうえで、削除されたものと残るものを確認します。

  • 永続データ:既定では、最後のスコープのときに削除されます。--keep-data などは公式ドキュメントで確認してください。
  • キャッシュ:ファイルは ~/.claude/plugins/cache/ に14日間残り、その後バックグラウンドで削除されますが、最後のプラグインをアンインストールした場合は、別のプラグインをインストールするまで残ります。すぐ消すなら ~/.claude/plugins/cache/<marketplace>/<plugin>/ を自分で削除します。
  • マーケットプレイス:所有者も信頼しないなら、マーケットプレイスを削除します。そこからインストールしたプラグインはすべてアンインストールされます。

組織で配る場合の管理設定

公式ドキュメントによると、管理者は管理設定で、マーケットプレイスの取得元の許可リスト・ブロックリスト、プラグインの強制有効化、--plugin-dir と --plugin-url フラグや CLAUDE_CODE_PLUGIN_DIRS 変数の無効化、フックの限定を強制できます。組織が pluginTrustMessage を設定すると、信頼警告にその文面が追記されます。各キーが何を対象にするかは、公式ドキュメントの control matrix で確認してください。

公式マーケットプレイスのプラグインなら、確認しなくてよいですか。

いいえ。公式ドキュメントによると、マーケットプレイスの名前は、カタログの公開元を示すだけで、中の各プラグインの動作を示しません。どのマーケットプレイスのものでも、入れる前に確認します。

プラグインはインストールするとすぐ有効になりますか。

公式ドキュメントによると、インストールすると有効になります。ただし、マニフェストやマーケットプレイスの項目が defaultEnabled: false を設定していて、利用者が自分で有効にしていない場合は除きます。

アンインストールすれば、プラグインのファイルもすぐ消えますか。

すぐには消えません。公式ドキュメントによると、ファイルは ~/.claude/plugins/cache/ に14日間残ってから、バックグラウンドで削除されます(最後のプラグインをアンインストールした場合は、別のプラグインをインストールするまで残ります)。すぐ消したい場合は、該当ディレクトリを自分で削除します。
