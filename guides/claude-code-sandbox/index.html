Claude Code のサンドボックスとは:制限できる範囲・組織での設定・限界

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • サンドボックスはデフォルトでオフです。/sandbox の実行か sandbox.enabled を true にして有効にし、対象は Claude が実行するシェルコマンドとその子プロセスです。
  • Read や WebFetch などの組み込みツール、フック、ローカルの MCP サーバーは対象外です。組織で必須にするなら managed settings で sandbox のキーを配布します。
  • 公式ドキュメントでは、サンドボックスは完全な隔離境界ではないとされています。執筆時点(2026年10月)の内容に基づくため、導入前に最新の公式ドキュメントも確認してください。

サンドボックスが制限する範囲(既定値)

公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のサンドボックスは、Claude が実行するシェルコマンドと、そこから起動するプロセスを境界の内側で動かします。有効にするには、セッションで /sandbox を実行するか、~/.claude/settings.json などの設定ファイルで sandbox.enabled を true にします。

サンドボックス内のコマンドの既定の到達範囲は次のとおりです。

  • 書き込み:作業ディレクトリ、利用者ごとの一時ディレクトリ、追加したディレクトリ。保護対象のパスは書き込み拒否のままです。調整は filesystem.allowWrite と filesystem.denyWrite です。
  • 読み取り:マシンの大半が読めます。~/.ssh や ~/.aws/credentials などの認証情報ファイルも含まれます。調整は filesystem.denyRead と credentials です。
  • ネットワーク:直接の外向き経路はなく、マシン上のプロキシが許可ドメイン(最初は空)と照合します。許可外のホストの扱いは権限モードで決まります。調整は network.allowedDomains と network.deniedDomains です。
  • 環境変数:Claude Code から引き継がれ、環境内のシークレットも含みます。調整は credentials と CLAUDE_CODE_SUBPROCESS_ENV_SCRUB です。

出典: Configure the sandboxed Bash tool

サンドボックスの外で動くもの

公式ドキュメントによると、サンドボックスが包むのはシェルコマンドです。次のものは外で動きます。

  • Read、Edit、Write、WebFetch、WebSearch などの組み込みツール:権限ルールに従います。denyRead は Read ツールを止めず、allowedDomains は WebFetch を制限しません。
  • コマンド型フック、ローカルの MCP サーバー、プラグインモニター、LSP サーバー、ステータスラインのコマンドや apiKeyHelper など:利用者のフルアクセスで動きます。
  • 設定によってはシェルコマンドも外で動きます。! のシェルモードで自分で入力したコマンド(ほとんどのセッション)、excludedCommands に一致するコマンド、Claude が求める非サンドボックスでの再試行(通常はサンドボックス内で失敗した後)です。

これらを一つの境界に入れたい場合、Claude Code のプロセス自体をコンテナ、仮想マシン、サンドボックスランタイムで動かします。

出典: Configure the sandboxed Bash tool

権限ルール・権限モードとの関係

公式ドキュメントでは、サンドボックス、権限ルール、権限モードは補完し合う層とされています。権限ルールは使えるツールを制御し、実行前に評価されます。サンドボックスは OS レベルで、Bash、PowerShell、Monitor ツールのコマンドとその子プロセスのファイルシステムとネットワークを制限します。

権限の判断はコマンド文字列(auto モードでは分類器の判断も)に基づきますが、サンドボックスの境界は OS が実行中のプロセスに強制します。そのため、モデルが何を選んでも、許可したコマンドが名前以上のことをしても保たれます。サンドボックス設定と権限ルールのパスやドメインは、最終的な設定にマージされます。

/sandbox は権限モードではありません。auto-allow モードではサンドボックスの境界そのものが確認プロンプトの代わりになります。--dangerously-skip-permissions は代わりになるものが無く、保護パスのチェックも省かれます。

組織でサンドボックスを必須にする設定

公式ドキュメントによると、管理者は sandbox のキーを managed settings として、MDM で管理するファイル、または claude.ai のサーバー管理設定で配布します。次の設定は、サンドボックスを有効にし、非対応環境や依存の欠落では Claude Code を起動させず、サンドボックス外での再試行を禁じます。

{
  "sandbox": {
    "enabled": true,
    "failIfUnavailable": true,
    "allowUnsandboxedCommands": false
  }
}
  • failIfUnavailable:Linux の bubblewrap などの依存が無い場合、非サンドボックスで動かさず Claude Code の起動を止めます。
  • allowUnsandboxedCommands: false:dangerouslyDisableSandbox が無視され、サンドボックスで失敗したコマンドを非サンドボックスで再試行できません。

併せて、組織承認ツール用の excludedCommands と、~/.aws や ~/.ssh などの sandbox.credentials を検討します。既定の読み取りは認証情報を許すためです。この設定ではリポジトリの設定でコマンドをサンドボックス外に出せなくなる(admin-required)ので、承認ツールに要る excludedCommands、allowWrite、ソケットのエントリは managed settings に書きます。v2.1.285 以降が必要です。

開発者側の緩め方にも注意が要ります。Boolean は managed の値が優先されますが、allowRead のような配列は各スコープがマージされ、開発者が追記できます。allowManagedReadPathsOnly や allowManagedDomainsOnly で managed のみに固定できます。

ネイティブ Windows ではサンドボックスが動かず、failIfUnavailable を設定すると起動時に終了します。macOS と Linux だけに配布するか(サーバー管理設定は組織の全利用者に適用されます)、WSL2 かコンテナへ移す対応が示されています。なお、開発者が ! のシェルモードで打つコマンドは、ほとんどのセッションでサンドボックスの外で動きます。

出典: Configure the sandboxed Bash tool

限界と注意点

公式ドキュメントは、サンドボックスはリスクを減らすものの完全な隔離境界ではないとしています。主な点は次のとおりです。

  • ネットワーク:既定のプロキシは TLS を終端も検査もしません。github.com のような広いドメインの許可はデータ持ち出しの経路になり得ます。強い保証が要る場合は、TLS を検査するカスタムプロキシを使います。
  • Unix ソケット:allowUnixSockets で /var/run/docker.sock を許すと、実質ホストへのアクセスになります。
  • 書き込み:$PATH 上の実行ファイルのディレクトリや .bashrc、.zshrc への広い書き込み許可は、権限昇格につながり得ます。
  • 弱める設定:enableWeakerNestedSandbox は安全性を大きく下げ、他の隔離がある場合だけ使うものです。allowAppleEvents や allowNestedUserNamespaces も隔離を外します。
  • 対象外:Computer use は実際のデスクトップで動きます。サブエージェントは親セッションと同じ設定を使います。

また、ファイルシステムとネットワークの両方の隔離が必要とされています。allowWrite や広い allowedDomains、excludedCommands の例外が、反対側の制限を打ち消していないか確認してください。

よくある質問

サンドボックスは最初から有効ですか。

公式ドキュメントによると、デフォルトではオフです。/sandbox を実行するか、sandbox.enabled を true にして有効にします。

出典: Configure the sandboxed Bash tool

サンドボックスを有効にすれば Read ツールや WebFetch も制限されますか。

いいえ。これらは権限ルールに従います。公式ドキュメントでは、denyRead は Read ツールを止めず、allowedDomains は WebFetch を制限しないとされています。

出典: Configure the sandboxed Bash tool

Windows の端末にもサンドボックスを必須にできますか。

ネイティブ Windows ではサンドボックスが動かず、failIfUnavailable を設定すると起動時に終了します。公式ドキュメントでは、WSL2 かコンテナで動かす方法が示されています。

出典: Configure the sandboxed Bash tool
