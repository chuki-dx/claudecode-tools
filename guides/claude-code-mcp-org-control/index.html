Claude Code の MCP を社内で制限する方法:許可・拒否リストと managed-mcp.json

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の MCP サーバーは、全面無効・固定配布・許可制・拒否のみなど、複数の制限パターンから選べます。
  • 同じサーバーを全員に固定で配るなら managed-mcp.json、利用者が追加するものを絞るなら allowedMcpServers と deniedMcpServers を使います。
  • 許可リストを利用者が広げられない決定的なものにするには、管理設定に allowedMcpServers と allowManagedMcpServersOnly: true を一緒に置きます。serverName はセキュリティ対策になりません。

まず決めること:どこまで制限するか

本記事は執筆時点(2026年10月)の公式ドキュメントに基づきます。MCP サーバー(Claude Code に追加して使う接続先のサーバー)の制限には、三つの仕組みがあります。managed-mcp.json は固定のサーバー一式を配り、managedMcpServers は利用者が追加したものに加えて会社がサーバーを提供し、allowedMcpServers/deniedMcpServers は利用者が設定したものを絞り込みます。

公式ドキュメントが挙げる制限パターンは次のとおりです。

  • 全面無効: 空のサーバー定義を入れた managed-mcp.json。ただし、排他的制御の下で読み込まれる一部のサーバーは例外です。
  • 固定配布: 欲しいサーバーを書いた managed-mcp.json。全員が同じサーバーを使い、追加できません。
  • 提供サーバー: managedMcpServers。会社が挙げたリモートサーバーを配り、利用者自身のものも残ります。
  • 承認カタログ: allowedMcpServers と allowManagedMcpServersOnly: true。承認済み以外はブロックされます。
  • プラグインのサーバーのみ: strictPluginOnlyCustomization のリストに mcp を含めます。
  • ゆるい許可リスト: allowManagedMcpServersOnly なしの allowedMcpServers。利用者が自分の設定で広げられます。
  • 拒否リストのみ: deniedMcpServers。問題のあるサーバーだけを止め、他は許可します。

Claude Code には、利用者が閲覧してインストールできる組み込みの MCP サーバーレジストリはありません。承認カタログ方式では、承認済み一覧と claude mcp add のコマンドを社内 wiki など利用者が見つけやすい場所で共有するか、管理されたプラグインマーケットプレイスでプラグインとして配布します。

managed-mcp.json でサーバーを固定配布する

公式ドキュメントの設定一覧によると、managed-mcp.json は /Library/Application Support/ClaudeCode/、/etc/claude-code/、C:\Program Files\ClaudeCode\ のいずれかのシステムパスに置きます。配布は MDM、GPO、フリート管理、または管理者権限を持つプロセスで行い、サーバー管理設定(server-managed settings)では設定できません。

配布後に利用者が claude mcp add を実行すると、追加できない旨のメッセージが表示されます。また、Claude in Chrome を使える利用者が claude --chrome を実行すると、起動時に終了します。許可するには allowClaudeInChromeWithManagedMcp を端末側の管理設定(MDM プロファイル、HKLM レジストリ、managed-settings.json のみ有効)で設定します。

許可リストと拒否リストの設定

許可リストと拒否リストは、読み込みを許すサーバーを絞るフィルタです。レジストリではないため、サーバーは利用者・プラグイン・組織のいずれかに追加されて初めて対象になります。

許可リストを管理側で固定する

allowedMcpServers と allowManagedMcpServersOnly: true を、server-managed settings や配布した managed-settings.json などの管理設定に一緒に置きます。複数の管理ソースをまたいでロックと許可リストを読むには、Claude Code v2.1.273 以降が必要です。

{
  "allowManagedMcpServersOnly": true,
  "allowedMcpServers": [
    { "serverUrl": "https://api.githubcopilot.com/*" },
    { "serverUrl": "https://*.internal.example.com/*" }
  ]
}

true の間、ユーザー・プロジェクト・ローカルの許可リストは無視されます。拒否リストは全スコープで統合されるため、利用者は自分用にブロックできます。

allowManagedMcpServersOnly を付けないと、許可リストは全スコープで統合され、利用者自身の ~/.claude/settings.json でも広げられます。なお allowManagedPermissionRulesOnly はパーミッションルールだけを固定するもので、MCP の許可リストは強制されません。

未設定と空配列の違い

  • allowedMcpServers が未設定なら全サーバーを許可、空配列 [] なら許可なし(許可リストの確認を省くサーバーを除く)、中身があれば一致したものだけ許可です。
  • deniedMcpServers は未設定でも空配列でもブロックなしです。中身があれば一致したものを、他の設定に関係なくブロックします。

エントリの書き方と照合の注意点

各エントリは、次のいずれか一つのキーで書きます。

  • serverUrl: HTTP・SSE のリモートサーバー用。URL は完全一致か * のワイルドカードで書きます。
  • serverCommand: stdio サーバー用。コマンドと引数が順序も含めて完全一致する必要があり、env は比較されません。
  • serverName: 利用者が付けたラベルとの完全一致のみで、ワイルドカードは使えません。

公式ドキュメントは、serverName はセキュリティ対策ではないと警告しています。名前は利用者が付けるラベルで、どのサーバーにも github と名付けられるためです。実際に動くサーバーを制御するには serverCommand か serverUrl を使います。

URL のポートにも注意が必要です。ポートを省略してホスト名を全部書くと既定ポートのみ(https は 443、http は 80)、ホスト名に * を含めると全ポートが対象です。拒否リストも同じで、https://staging.example.com/* は https://staging.example.com:8443/api をブロックしません。

許可リストに serverUrl が一つでもあれば、リモートサーバーは URL に一致する必要があり、serverName の一致は serverUrl が無い場合だけ有効です。stdio も serverCommand について同様です。強制に頼るエントリは、リテラルの URL とコマンドで書くよう公式ドキュメントは勧めています。

許可リストを通らないサーバーと、利用者への見え方

許可リストの確認を通らないサーバーがあります。組織自身のサーバー(managedMcpServers のすべてと、env の外で ${VAR} 展開を使わない managed-mcp.json のエントリ)、Claude in Chrome や ide サーバーなどの組み込みサーバー、Claude Tag セッションの Slack ツールです。拒否リストは、type: "sdk" のインプロセスのものを除き、出どころを問わず適用されます。

利用者への見え方も事前に確認してください。以前設定したサーバーがポリシーでブロックされると、/mcp と claude mcp list から消えます。理由は利用者に表示されないため、新しい制限を展開するときは、ブロック対象を周知する必要があります。

よくある質問

利用者が許可リストを自分で広げることはできますか?

allowManagedMcpServersOnly を付けない場合は可能です。許可リストは全スコープで統合され、利用者自身の ~/.claude/settings.json でも広げられます。allowedMcpServers と allowManagedMcpServersOnly: true を管理設定に置けば、ユーザー・プロジェクト・ローカルの許可リストは無視されます。

出典: Control MCP server access for your organization

serverName だけで許可や拒否を管理してよいですか?

公式ドキュメントによると、serverName はセキュリティ対策ではありません。名前は利用者が付けるラベルであり、実体のサーバーではないためです。実際に動くサーバーを制御するには、serverCommand か serverUrl のエントリを追加してください。

出典: Control MCP server access for your organization

managed-mcp.json を配ると、利用者は MCP サーバーを追加できなくなりますか?

公式ドキュメントでは、固定配布のパターンは全員が同じサーバーを使い、他は追加できないとされています。claude mcp add を実行すると、企業の MCP 設定が有効で排他的に制御している旨のエラーが表示されます。
