Claude Code の使い方の例:公式の作業レシピと基本ワークフロー

公開: 2026年10月15日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントの Common workflows は、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)で、コード理解、バグ修正、リファクタリング、テスト、PR 作成、ドキュメント整備を行うための短いプロンプト例を集めています。
  • 会話の再開、worktree での並行作業、plan mode での事前確認、スクリプトへの組み込みも、短いコマンドで始められます。
  • 社内に配るときは、プロンプトを自社のプロジェクトに合わせて言い換えてください。定期実行のように途中で質問できない使い方では、成功条件を文面に書いておくのが要点です。

コードの理解とバグ修正の進め方

本記事は、執筆時点(2026年10月)の公式ドキュメント「Common workflows」だけを根拠にしています。公式ドキュメントによると、このページは日常的な開発向けの短いレシピ集です。各プロンプトはどの Claude Code の利用画面でも使え、文面はプロジェクトに合わせて調整する前提です。

新しいコードベースを把握する

公式ドキュメントでは、プロジェクトのルートへ移動し、claude で起動して、全体像を尋ねる流れを紹介しています。最初の質問は次の例です。

give me an overview of this codebase

続けて how is authentication handled? のように、広い質問から具体的な部分へ絞ります。コーディング規約の確認や、プロジェクト固有の用語集の依頼も勧められています。

関連コードを探す

find the files that handle user authentication のように探す対象を具体的に書き、trace the login process from front-end to database で処理の流れまで追います。プロジェクトで使われている言葉を使うのがコツとされています。利用言語向けのコードインテリジェンスプラグインを入れると、定義へのジャンプや参照の検索が正確になるとも説明されています。

バグを直す

エラーを共有し、修正案を尋ね、適用させる三段階です。最初は I'm seeing an error when I run npm test のように状況を伝えます。再現するコマンドとスタックトレース、再現手順、エラーが断続的か常に起きるかを伝えるとよい、とされています。

リファクタリング・テスト・PR・ドキュメント

リファクタリングは、古い API の使用箇所を探す、改善案を出させる、変更を適用する、テストで確認する、の順です。find deprecated API usage in our codebase から始め、最後に run tests for the refactored code で確かめます。小さくテスト可能な単位で進めること、必要なら後方互換性を保つよう依頼することが助言されています。

テストの追加では、未カバーの関数を探し、雛形を作り、境界条件のケースを足し、実行して失敗を直します。公式ドキュメントによると、Claude は既存のテストファイルを調べ、使われているスタイルやフレームワークに合わせます。何を検証したいかを具体的に伝えることが前提です。

PR 作成は create a pr と頼むだけでも、変更の要約から順に進めても構いません。Claude が gh pr create や glab mr create で PR を作成したときや、既存の PR で作業したときにはセッションがその PR に紐づき、後から claude --from-pr 1234(数字は自分の PR 番号)で探せます。公式ドキュメントは、生成された PR を提出前に確認し、リスクや注意点を挙げさせるよう案内しています。

ドキュメント整備では、find functions without proper JSDoc comments in the auth module のように不足箇所を探し、コメントを追加させます。JSDoc や docstring など、希望する書式を指定します。

ファイル参照・画像・ノートフォルダの使い方

@ を使うと、Claude の読み込みを待たずにファイルやディレクトリを会話に含められます。例は次のとおりです。

Explain the logic in @src/utils/auth.js

公式ドキュメントによると、ファイルの内容は Read tool のトークン上限(既定は 25,000 tokens)に収まる場合に含まれ、256KB を超えるテキストファイルは含まれません。ディレクトリを指定するとファイル一覧だけが入り、中身は入りません。パスは相対でもフルパスでもよく、ファイル参照ではそのディレクトリと親ディレクトリの CLAUDE.md も文脈に加わります。

接続済みの MCP サーバーのデータは @server:resource の形式で参照できます。内容の埋め込みを止めたい場合は、CLAUDE_CODE_DISABLE_FILE_MENTIONS=1 をシェルかユーザー設定で指定します。この変数は Claude Code v2.1.299 以降が必要で、プロジェクト設定とローカル設定では無視されます。

画像とノートのフォルダ

画像は、ウィンドウへのドラッグ&ドロップ、Ctrl+V での貼り付け(Windows と WSL では Alt+V)、画像パスの指定で渡せます。エラー画面のスクリーンショットを見せて原因を尋ねる例が示されています。

また、Claude Code はどのディレクトリでも動くため、markdown のノートや文書のフォルダでも、コードと同じように検索・編集・整理ができます。

会話の再開・並行作業・plan mode

作業が複数回にまたがる場合、公式ドキュメントでは会話の再開を勧めています。会話はローカルに保存されます。

claude --continue

現在のディレクトリの直近のセッションを再開し、まだ無ければ No conversation found to continue と表示して終了します。一覧から選ぶ場合は claude --resume、実行中のセッション内からは /resume を使います。

worktree で並行作業する

一方の端末で機能開発を進めつつ、もう一方で Claude にバグを直させる場合、worktree を使うと編集が衝突しません。worktree はブランチごとの別のチェックアウトで、既存のコミットから作られるため、リポジトリに最低1つのコミットが必要です。

claude --worktree feature-auth

二つ目の端末で別の名前を付けて同じコマンドを実行すると、独立した並行セッションが始まります。コミットが無いリポジトリでは Failed to resolve base branch "HEAD": git rev-parse failed で失敗します。

plan mode で編集前に確認する

変更をディスクに反映する前に確認したい場合は plan mode を使います。Claude はファイルを読んで計画を示しますが、承認するまで編集しません。

claude --permission-mode plan

セッション中に Shift+Tab で切り替えることもでき、有効な間はステータスバーに ⏸ plan mode on と表示されます。

サブエージェント・スクリプト連携・定期実行

大きなコードベースの調査は、ファイルの読み込みで文脈を埋めがちです。公式ドキュメントでは、調査をサブエージェントに任せ、結果だけを受け取る方法を示しています。サブエージェントは自分の文脈ウィンドウでファイルを読み、要約を返します。

use a subagent to investigate how our auth system handles token refresh

CI、コミット前のフック、一括処理では、非対話で実行できます。標準入出力は一般的な Unix のツールと同じように使えます。

git log --oneline -20 | claude -p "summarize these recent commits"

定期実行は動かす場所で選ぶ

  • Routines:クラウドで動き、既定では Anthropic が管理します。PC の電源が切れていても動かしたい作業向けで、API 呼び出しや GitHub イベントでも起動できます。
  • Desktop scheduled tasks:デスクトップアプリ経由で自分のマシン上で動きます。ローカルファイルやツール、未コミットの変更に直接触れる作業向けです。
  • GitHub Actions:CI パイプライン上で動き、PR の作成などリポジトリのイベントや cron に紐づく作業向けです。
  • /loop:現在の CLI セッション上で動き、セッションを開いている間の簡易な確認向けです。

公式ドキュメントによると、定期実行のタスクは自律的に動くため、途中で質問できません。成功の条件と結果の扱いを、プロンプトに明記してください。

よくある質問

前回の続きから Claude Code を再開するには?

claude --continue で、現在のディレクトリの直近のセッションを再開できます。一覧から選ぶ場合は claude --resume、実行中のセッションでは /resume です。

出典: Common workflows

複数の作業を同時に進めても、編集は衝突しませんか?

公式ドキュメントでは、claude --worktree feature-auth のように worktree を使う方法が示されています。別の端末で名前を変えて同じコマンドを実行すると、独立した並行セッションになります。リポジトリに最低1つのコミットが必要です。

出典: Common workflows

ファイルを書き換えられる前に内容を確認できますか?

plan mode を使います。claude --permission-mode plan で起動すると、Claude は計画を示すだけで、承認するまで編集しません。セッション中は Shift+Tab でも切り替えられます。
