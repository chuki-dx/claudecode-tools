Claude Code に作業フォルダの外を扱わせる:--add-dir と additionalDirectories

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、既定では起動したフォルダ内のファイルにアクセスします。外のフォルダを扱わせる方法は、起動時の --add-dir、セッション中の /add-dir、設定ファイルの additionalDirectories の3つです。
  • 追加したフォルダは、元の作業ディレクトリと同じ権限ルールで扱われます。読み取りは確認なしでできるようになり(ネットワークパスの確認を除く)、編集は現在の権限モードに従います。
  • 追加はファイルアクセスを広げるもので、設定の読み込み先を広げるものではありません。設定ファイルの permissions.additionalDirectories で足したフォルダは、ファイルアクセスのみです。

作業フォルダの外を扱わせる3つの方法

執筆時点(2026年10月)の公式ドキュメントによると、Claude Code は既定で、起動したディレクトリにあるファイルにアクセスできます。このディレクトリが、そのセッションの主な作業ディレクトリです。/cd で移動するまでは、これが主な作業ディレクトリのままです。

このアクセス範囲を広げる方法は、次の3つです。

  • 起動時:--add-dir <path> という CLI 引数を使います
  • セッション中:/add-dir コマンドを使います
  • 常時の設定:設定ファイルの additionalDirectories に追加します

どの方法で足すかによって、読み込まれる設定が変わります。詳しくは後の節で説明します。

出典: Configure permissions

追加したフォルダの権限は元のフォルダと同じ

公式ドキュメントでは、追加ディレクトリ内のファイルは元の作業ディレクトリと同じ権限ルールに従うと説明されています。読み取りは、ネットワークパスの確認を除いて、確認なしでできるようになります。ファイル編集の権限は、現在の権限モードに従います。

作業ディレクトリの外への読み取りを止めたい場合は、permissions.blockReadsOutsideWorkingDirectories を設定します。ファイルツールが、対象のパスをどの権限モードでも拒否するようになります。auto モードでは、Claude が作業ディレクトリの外を初めて読むときに、Claude Code がこの設定を有効にするか提案します。

追加したフォルダは読み取りに確認が出なくなる点を前提に、どのフォルダを渡すかを決めてください。

出典: Configure permissions

追加できないパスと macOS の注意点

公式ドキュメントによると、UNC 共有を含む、ほとんどのネットワークパスは作業ディレクトリとして追加できません。パスを調べる際に、指定されたホストへ接続する可能性があるためです。Windows では、共有をドライブレターに割り当て、起動時にそのドライブを --add-dir で渡すよう案内されています。

macOS のバックグラウンドセッションでは、Claude が ~/Desktop、~/Documents、~/Downloads などの保護されたフォルダを読み書きするとき、セッションのホストがターミナルとは別にアクセスを求めます。そこでの読み取りが Operation not permitted で失敗する場合は、公式ドキュメントのバックグラウンドセッションの項目を確認してください。

出典: Configure permissions

追加フォルダから読み込まれる設定とされない設定

公式ドキュメントでは、ディレクトリを追加すると読み書きできる範囲は広がるが、そのディレクトリが設定のルートになるわけではないと説明されています。.claude/ 配下の設定の多くは検出されず、一部だけが例外として読み込まれます。

条件に注意してください。例外が適用されるのは、--add-dir フラグまたは /add-dir コマンドで追加したディレクトリだけです。permissions.additionalDirectories に書いたディレクトリは、ファイルアクセスのみで、以下の設定は読み込まれません。

--add-dir で追加したディレクトリから読み込まれるものは、次のとおりです。

  • .claude/skills/ のスキル:読み込まれます(ライブリロードあり)
  • .claude/commands/ のコマンドファイル:読み込まれます(ライブリロードなし)。追加ディレクトリとプロジェクトに同名のコマンドがある場合は、プロジェクト側が実行されます
  • .claude/agents/ のサブエージェント:読み込まれます(ライブリロードなし)
  • .claude/settings.json と .claude/settings.local.json:enabledPlugins と extraKnownMarketplaces のキーだけです
  • CLAUDE.md、.claude/rules/、CLAUDE.local.md:CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 を設定した場合だけです

設定を複数プロジェクトで共有したい場合、公式ドキュメントはユーザーレベルの設定、プラグインでの配布、設定のあるディレクトリから起動する方法を挙げています。

出典: Configure permissions

足すのではなく移るなら /cd

フォルダを足すのではなく、主な作業ディレクトリ自体を変えたい場合は /cd を使います。公式ドキュメントによると、会話は引き継がれ、新しいディレクトリの CLAUDE.md が読み込まれます。初めて作業するディレクトリでは、信頼するかどうかの確認が出ます。

移動すると、新しいディレクトリのプロジェクト設定(権限ルールやフックを含む)がすぐ適用されます。追加ディレクトリは新しいディレクトリの設定のものに切り替わりますが、--add-dir や /add-dir で足したものは維持されます。未信頼のディレクトリでは、確認画面に、その設定が有効にする許可ルールや追加ディレクトリなどが一覧されます。断れば、セッションはその場に留まります。

v2.1.246 より前は、/cd で移動しても、セッションを再開するまで新しいディレクトリの設定、フック、MCP サーバー、スキルが適用されませんでした。社内で使うバージョンを確認してください。移動先は Cd 権限ルールで制限または無効にできます。

よくある質問

--add-dir と permissions.additionalDirectories は何が違いますか?

どちらも別フォルダのファイルにアクセスできるようにしますが、設定の読み込みが違います。公式ドキュメントによると、--add-dir や /add-dir で追加したディレクトリからはスキル、コマンド、サブエージェントなどが読み込まれます。設定ファイルの permissions.additionalDirectories に書いたディレクトリは、ファイルアクセスのみです。

出典: Configure permissions

社内のネットワーク共有を作業ディレクトリに追加できますか?

公式ドキュメントによると、UNC 共有を含むほとんどのネットワークパスは追加できません。Windows では、共有をドライブレターに割り当て、そのドライブを起動時に --add-dir で渡すよう案内されています。それ以外の環境の扱いは、公式ドキュメントで確認してください。

出典: Configure permissions

追加したフォルダの CLAUDE.md は読み込まれますか?

公式ドキュメントによると、CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 を設定した場合だけ、--add-dir や /add-dir で追加したディレクトリの CLAUDE.md などが読み込まれます。CLAUDE.local.md は、さらに local 設定ソースが必要です。これは既定で有効です。
