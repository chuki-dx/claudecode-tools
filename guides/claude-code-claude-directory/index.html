Claude Code の .claude フォルダの構成:どのファイルに何を書くか

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の設定ファイルは、リポジトリの .claude/ に置くプロジェクト用と、~/.claude/ に置く全プロジェクト共通のグローバル用に分かれます。
  • どこに書くか迷ったら「やりたいこと」から選びます。規約は CLAUDE.md、権限・hooks・環境変数は settings.json、個人用の上書きは settings.local.json です。
  • 組織の managed settings は、一部の例外を除き、各設定ファイルや --settings より優先されます。設定が効かないときは、上書きの順序と公式のデバッグ手順を確認してください。

.claude フォルダの置き場所はプロジェクト用とグローバル用

執筆時点(2026年10月)の公式ドキュメントでは、プロジェクト用のファイルはリポジトリの .claude/ の下に置くと説明されています。ただし CLAUDE.md、.mcp.json、.worktreeinclude はリポジトリのルートに置きます。グローバル用は ~/.claude/ に置き、すべてのプロジェクトに適用されます。

ファイルごとに、プロジェクトとグローバルの両方に置けるもの、プロジェクトだけのもの、グローバルだけのものがあります。たとえば .mcp.json と settings.local.json はプロジェクトだけ、keybindings.json と themes/*.json はグローバルだけです。

一覧表の Commit 列に ✓ が付くのは、CLAUDE.md、settings.json、skills/<name>/SKILL.md などです。一方 settings.local.json には付いておらず、Claude Code が設定をそこへ保存した場合に gitignore されると書かれています。

何を変えたいか別に、編集するファイルを選ぶ

公式ドキュメントには、変更したい内容ごとの編集先を示す表があります。主なものは次のとおりです。

  • プロジェクトの文脈や規約を渡す:CLAUDE.md(プロジェクトまたはグローバル)
  • ツール呼び出しの許可・ブロック:settings.json の permissions または hooks
  • ツール呼び出しの前後でスクリプトを実行する:settings.json の hooks
  • セッションの環境変数を設定する:settings.json の env
  • 個人の上書きを git に入れない:settings.local.json(プロジェクトのみ)
  • /name で呼び出すプロンプトや機能を足す:skills/<name>/SKILL.md
  • 専用ツールを持つサブエージェントを定義する:agents/*.md
  • スクリプトから多数のサブエージェントを調整する:workflows/*.js
  • MCP で外部ツールをつなぐ:.mcp.json(プロジェクトのみ)
  • 応答の整え方を変える:output-styles/*.md

settings.json は権限、hooks、環境変数、モデルの既定値をまとめて持つファイルです。チームで共有する設定は settings.json、個人の上書きは settings.local.json と分けて考えると整理しやすくなります。

上の表に出てこない、その他のファイルの役割

ファイル一覧には、編集先の表に出てこないものもあります。公式ドキュメントの説明は次のとおりです。

  • rules/*.md:テーマ別の指示で、対象パスを絞ることもできます(プロジェクトとグローバル)
  • commands/*.md:1ファイルのプロンプトで、skills と同じ仕組みです
  • .worktreeinclude:新しい worktree にコピーする、gitignore 済みファイルを指定します(プロジェクトのみ)
  • agent-memory/<name>/:サブエージェントの永続メモリです
  • ~/.claude.json:アプリの状態、アカウント情報、UI の切り替え、個人の MCP サーバーを持ちます(グローバルのみ)
  • projects/<project>/memory/:Claude がセッションをまたいで自分用に残すメモ(auto memory)です(グローバルのみ)
  • keybindings.json:キーボードショートカットの設定です(グローバルのみ)
  • themes/*.json:配色テーマの設定です(グローバルのみ)

フロントマターで設定するファイルとフィールド

skills、commands、サブエージェント、output styles、rules は、ファイル先頭の YAML フロントマター(設定を書くヘッダー部分)から設定を読みます。受け付けるフィールドはファイルごとに違います。

  • skills/<name>/SKILL.md:name、description、allowed-tools、model、paths など
  • commands/*.md:skills のフィールドから name と paths を除いたもの
  • agents/*.md:name、description、tools、permissionMode など
  • output-styles/*.md:name、description、keep-coding-instructions、force-for-plugin
  • rules/*.md:paths

プラグインで配布されるエージェントは、サブエージェントのフィールドの一部だけが有効です。全フィールドの意味は、各リファレンスで確認してください。

.claude の外にあるファイルと、設定の上書き

公式ドキュメントによると、次のファイルは別の場所にあります。

  • managed-settings.json:システムレベルに置かれ、場所は OS によって異なります。組織が強制する設定で、自分の設定ファイルや --settings の値では、限られた例外を除いて上書きできません
  • CLAUDE.local.md:プロジェクトルートに置く、そのプロジェクト向けの個人的な好みです。CLAUDE.md と一緒に読み込まれます。手動で作り、.gitignore に追加します
  • AGENTS.md:プロジェクトルート、.claude/、または任意のディレクトリに置けます。CLAUDE.md の代わりに読み込めます
  • インストール済みプラグイン:~/.claude/plugins に入り、claude plugin コマンドで管理されます

~/.claude には、作業中に Claude Code が書き込むデータ(会話の記録、プロンプト履歴、ファイルのスナップショット、キャッシュ、ログ)も入ります。

上書きにも注意が必要です。組織の managed settings は、Settings precedence に挙げられた例外を除き、すべての設定ファイルと --settings の値より優先されます。--permission-mode や --settings といった CLI フラグは、そのセッションの間 settings.json を上書きします。一部の環境変数は対応する設定より優先されますが、変数ごとに異なるため、環境変数のリファレンスで確認してください。効かないときは、公式の Debug your configuration に確認コマンドと症状別の早見表があります。

よくある質問

個人用の設定をチームに共有したくないとき、どこに書けばよいですか?

公式ドキュメントによると、個人用の設定の上書きは settings.local.json(プロジェクトのみ)に書きます。個人的な好みの指示は、プロジェクトルートの CLAUDE.local.md に書きます。こちらは手動で作成し、.gitignore に追加します。

出典: Explore the .claude directory

組織として設定を強制できますか?

公式ドキュメントでは、組織が配布する managed settings は、すべての設定ファイルと --settings の値より優先されると説明されています。限られた例外があります。managed-settings.json の置き場所は OS によって異なるため、保存場所は公式の managed settings のページで確認してください。

出典: Explore the .claude directory

settings.json に書いたのに効かないときは、何を確認すればよいですか?

組織の managed settings、CLI フラグ、一部の環境変数が上書きしている可能性があります。完全な順序は公式の settings precedence に、確認用のコマンドは Debug your configuration にまとまっています。
