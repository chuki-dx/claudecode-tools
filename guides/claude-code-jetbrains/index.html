Claude Code を JetBrains の IDE で使う:入れ方と設定・注意点

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • プラグインは CLI を同梱しないため、claude コマンドとプラグインの両方を入れます。
  • IDE の統合ターミナルで claude を起動するか、外部ターミナルで /ide を実行すると連携機能が使えます。
  • acceptEdits モードは IDE 設定ファイル経由でリスクが増えうるため、編集は Manual モードでの運用を検討してください。

何ができるか:対応 IDE と主な機能

公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は専用プラグインで JetBrains の IDE と連携します。IntelliJ IDEA、PyCharm、Android Studio、WebStorm、PhpStorm、GoLand などが対象です。

主な機能は次のとおりです。

  • クイック起動:Cmd+Esc(Mac)または Ctrl+Esc(Windows/Linux)でエディタから開けます。
  • diff 表示:変更をターミナルではなく IDE の diff ビューアで開きます。
  • 選択範囲の共有:選択中の範囲や開いているタブが自動で共有されます。
  • ファイル参照:Cmd+Option+K(Mac)または Alt+Ctrl+K(Linux/Windows)で @src/auth.ts#L1-99 のような参照を挿入できます。
  • 診断の共有:Claude が getDiagnostics ツールで IDE の lint や構文エラーを読み取ります。編集後に Claude Code が自分から診断を要求することはありません。

導入手順:CLI とプラグインの両方を入れる

公式ドキュメントでは、プラグインは IDE の統合ターミナルで claude コマンドを実行して接続する仕組みで、CLI は同梱されないと説明されています。次の 2 段階で準備します。

  1. 公式のクイックスタートに従って CLI を入れます。claude が PATH に無いと、プラグインが「Cannot launch Claude Code」と通知します。
  2. JetBrains Marketplace から Claude Code プラグインを入れ、IDE を再起動します。

IDE が claude を見つけられない場所に入れた場合は、プラグインの Claude command 設定にフルパスを指定します。

有料の Claude サブスクリプション(Pro、Max、Team、Enterprise)または Claude Console アカウントで使え、API キーは不要です。初回の claude 実行時にログインを求められます。最新の料金やプランの条件は公式の料金ページで確認してください。

使い方と設定:接続、diff 表示、プラグイン設定

起動と接続

IDE の統合ターミナルで claude を実行すれば、連携機能がすべて有効になります。外部ターミナルからは、claude を起動してから /ide を実行します。

claude
/ide

成功すると Connected to IntelliJ IDEA. のようなメッセージが出ます。IDE と同じファイルを扱わせるには、IDE のプロジェクトルートと同じディレクトリから起動します。

diff 表示の切り替え

claude で /config を開き、Diff tool を auto にすると IDE に diff を表示し、terminal にするとターミナルのままです。この項目は IDE に接続しているときだけ表示されるため、JetBrains のターミナルから起動するか、先に /ide を実行してください。

プラグイン設定

Settings → Tools → Claude Code [Beta] で設定します。執筆時点(2026年10月)の公式ドキュメントでは、このプラグインの名称に [Beta] が付いています。Claude command には claude や /usr/local/bin/claude などの起動コマンドを指定できます。ESC キーで操作を中断できない場合は、Settings → Tools → Terminal で「Move focus to the editor with Escape」のチェックを外すか、「Switch focus to Editor」のショートカットを削除します。

リモート開発と WSL の注意点

リモート開発(JetBrains Remote Development)では、プラグインを手元のクライアントではなく、Settings → Plugin (Host) からリモートホストに入れる必要があると公式ドキュメントは警告しています。

WSL では、Claude command に wsl -d Ubuntu -- bash -lic "claude" を指定します(Ubuntu は使っているディストリビューション名に置き換えます)。

WSL2 で「No available IDEs detected」と出る場合、原因の多くは WSL2 の NAT ネットワークか Windows Firewall が接続を妨げていることです。WSL1 は影響を受けません。推奨の対処は、ネットワークモードを変えずにファイアウォールで WSL2 の通信を許可することです。まず WSL のシェルで次を実行します。

hostname -I

先頭 2 つのセグメントに .0.0/16 を付けたものがサブネットです(例:172.21.123.45 なら 172.21.0.0/16)。管理者権限の PowerShell で、IP 範囲を合わせて次を実行し、IDE と Claude Code を再起動します。

New-NetFirewallRule -DisplayName "Allow WSL2 Internal Traffic" -Direction Inbound -Protocol TCP -Action Allow -RemoteAddress 172.21.0.0/16 -LocalAddress 172.21.0.0/16

代替策として、Windows 11 22H2 以降ではミラーモードに切り替える方法もあります。Windows のユーザーディレクトリの .wslconfig に次を追記し、PowerShell で wsl --shutdown を実行します。Windows 10 では上のファイアウォール規則を使います。

[wsl2]
networkingMode=mirrored

セキュリティ上の注意:acceptEdits、選択範囲、ネットワーク

公式ドキュメントによると、JetBrains の IDE で acceptEdits 権限モードを使うと、IDE が自動実行しうる設定ファイルを Claude Code が変更できる可能性があります。その結果、acceptEdits モードのリスクが高まり、Bash 実行の許可確認を回避される恐れがあります。対策として、次の点が挙げられています。

  • 編集は Manual モードで行う。acceptEdits と auto モードは、保護されたパスを除き作業ディレクトリ内の編集を確認なしで承認します。
  • 信頼できるプロンプトだけで使う。
  • Claude Code が変更できるファイルを把握しておく。

IDE に接続している間、CLI は現在の選択範囲と開いているファイルのパスを、プロンプトごとにコンテキストへ含めます。.env のような機密ファイルは、そのパスの Read deny ルールで除外できます。

プラグインは ide という名前のローカル MCP サーバーを動かし、/mcp には表示されません。PreToolUse フックで MCP ツールを許可リスト化している組織では、この存在に注意が必要です。モデルから見えるツールは読み取り専用の mcp__ide__getDiagnostics だけです。

Settings → Tools → Claude Code [Beta] → Networking (Advanced) の Accept connections from all network interfaces を無効にすると、サーバーは 127.0.0.1 のみで待ち受けます。有効にするとローカルネットワークから到達でき、通信が暗号化されない ws:// のため、セッションの通信と認証トークンが平文で流れます。ループバックで接続できない場合だけ有効にし、WSL2 ではミラーモードを優先するよう勧められています。

よくある質問

プラグインだけ入れれば Claude Code を使えますか?

使えません。公式ドキュメントによると、プラグインは CLI を同梱せず、IDE の統合ターミナルで claude コマンドを実行して接続します。CLI とプラグインの両方を入れてください。

出典: JetBrains IDEs

IDE の外のターミナルから連携できますか?

できます。公式ドキュメントによると、外部ターミナルで claude を起動して /ide を実行すれば接続できます。「No available IDEs detected」と出た場合は、プラグインの有効化と IDE の完全な再起動を確認し、WSL ならファイアウォールの項を見てください。

出典: JetBrains IDEs

.env などの機密ファイルが Claude に共有されないようにできますか?

公式ドキュメントでは、そのファイルのパスに Read deny ルールを追加すると、選択したテキストも開いているファイルの通知も Claude に届かないとされています。
