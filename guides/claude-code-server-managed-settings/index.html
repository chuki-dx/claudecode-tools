Claude Code の設定を管理コンソールから配る方法(server-managed settings)

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)の設定は、Claude for Teams または Claude for Enterprise のプランであれば、管理コンソールから組織全体へ配れます。
  • MDM(端末をまとめて管理する仕組み)がない組織や、管理外の端末を使う利用者に向いた方式です。ただしクライアント側の制御であり、セキュリティ上の境界ではありません。
  • 設定は全員に一律で適用され、グループ別の設定は未対応です。Console の API キーやサードパーティのプロバイダ設定では、設定が届かない場合があります。

何ができるか:Anthropic のサーバーから設定を配る

公式ドキュメントによると、server-managed settings は Anthropic のサーバーから Claude Code の設定を配る方式です。クライアントは起動時にサーバーから設定を取得し、セッション中は1時間ごとに更新します。

settings.json で使える設定は、OS レベルのポリシー配信に限られるものを除いて対応しています。フック(特定のタイミングでコマンドを実行する仕組み)、環境変数、allowManagedPermissionRulesOnly のような管理専用の設定も含まれます。

使うには次の条件が必要です。

  • Claude for Teams または Claude for Enterprise のプラン
  • 設定の閲覧と編集には、Claude 組織の Owner または Primary Owner のロール
  • api.anthropic.com へのネットワークアクセス

Team や Enterprise の組織で画面に「アクセス権がない」と出る場合は、Owner または Primary Owner に変更を依頼します。設定の変更は組織の全利用者に適用されるため、公式ドキュメントは操作できる人を信頼できる担当者に限るよう求めています。

出典: Configure server-managed settings

サーバー管理とエンドポイント管理の選び分け

公式ドキュメントでは、集中管理の方式を2つ挙げています。server-managed settings は Anthropic のサーバーから配信します。endpoint-managed settings は、OS のポリシー(macOS の managed preferences、Windows のレジストリ)や managed settings ファイルで、端末に直接配ります。

  • server-managed settings:MDM がない組織、または管理外の端末を使う利用者に向く
  • endpoint-managed settings:MDM やエンドポイント管理がある組織に向く

端末が MDM などに登録済みなら、endpoint-managed settings のほうが強い保証になります。設定ファイルを OS レベルで利用者の変更から守れるためです。

ただし endpoint-managed settings は、Anthropic がホストする環境のクラウドセッションには届きません。開発者がクラウドセッションを使う組織では、server-managed settings も設定するよう案内されています。セルフホスト環境のセッションは、ランナーイメージ内の managed settings ファイルも読みます。どちらがいつ適用されるかは、公式ドキュメントの settings precedence で確認してください。

出典: Configure server-managed settings

設定手順:管理コンソールで JSON を書いて保存する

  1. claude.ai のコンソールで Organization settings > Claude Code > Managed settings を開く
  2. 設定を JSON で書く
  3. 保存する

公式ドキュメントの例は、権限の deny リストを強制し、権限のバイパスを禁止し、権限ルールを managed settings で定義したものだけに限定します。

{
  "permissions": {
    "deny": [
      "Bash(curl *)",
      "Read(./.env)",
      "Read(./.env.*)",
      "Read(./secrets/**)"
    ],
    "disableBypassPermissionsMode": "disable"
  },
  "allowManagedPermissionRulesOnly": true
}

注意点として、Bash(curl *) のルールは、Claude が書いたとおりの curl に一致します。/usr/bin/curl や sh -c 'curl …' には一致しません。コマンドの文字列に頼らないネットワーク制限は、sandbox ブロックと allowManagedDomainsOnly を使う方法が案内されています。詳細は公式ドキュメントで確認してください。

フックも settings.json と同じ形式で書けます。フックはシェルコマンドを実行するため、対話セッションでは適用前にセキュリティ承認ダイアログが表示されます。

保存後、クライアントは次の起動時か、1時間ごとの取得で新しい設定を受け取ります。エディタは Claude Code 設定の JSON スキーマで内容を検査し、問題があると警告を出してボタンの表記を変えます。設定が保存済みなら Update with errors、未保存なら Add with errors です。警告があっても保存はできます。

スキーマは最新リリースに遅れることがあり、設定リファレンスにあるキーが警告されることがあります。Claude Code は受け取ったあとで、独自の検証をします。

出典: Configure server-managed settings

配信の確認方法

公式ドキュメントによると、確認の方法は次のとおりです。

  • 利用者に Claude Code を再起動してもらう。承認ダイアログが出る設定を含む場合は、次の取得時にダイアログで内容が表示される
  • 利用者に /permissions を実行してもらい、有効な権限ルールを確認する
  • 特定の端末の取得結果は、利用者に claude doctor を実行してもらい、Managed settings (remote) の行を読む(Claude Code v2.1.248 以降)

この行には、設定の読み込み成功、組織に設定がないこと、取得の失敗(原因とキャッシュの有無つき)、取得のスキップ(理由つき)のいずれかが出ます。実行中のセッションでは、取得失敗後などに /status でも同じ行を確認できます。

制限と注意点:届かない条件を先に知っておく

現時点の制限

  • 設定は組織の全利用者に一律で適用される。執筆時点(2026年10月)の公式ドキュメントでは、グループ別の設定は未対応
  • managed-mcp.json は配れない。代わりに allowedMcpServers と deniedMcpServers を配る
  • policyHelper や wslInheritsWindowsSettings のように OS レベルのポリシー限定の設定は効かない。MDM か system の managed-settings.json で配る

配信されない条件

配信には api.anthropic.com への直接接続が必要です。認証は、Team または Enterprise の OAuth ログイン、CLAUDE_CODE_OAUTH_TOKEN、直接設定した API キーなどが対象です。apiKeyHelper が返すキーや Workload Identity Federation の認証情報では、取得は行われません。

Console の API キーは、claude.ai の組織とは別の組織に属します。そのため、そのキーで認証する CI ジョブには、管理コンソールの設定が届きません。CLAUDE_CODE_USE_* 系の変数や、デフォルト以外の ANTHROPIC_BASE_URL をシェルで設定している場合も、取得はスキップされます。Claude Desktop の Cowork セッションでも取得されません。

セキュリティ上の位置づけ

公式ドキュメントは、server-managed settings を「クライアント側の制御であり、セキュリティ境界ではない」としています。管理外の端末では、管理者権限がなくても回避できます。古いバージョンの Claude Code は設定を取得せず、API が使えないときはキャッシュが使われ、キャッシュがなければ適用されません。強い保証が必要なら、MDM 登録済みの端末で endpoint-managed settings を使います。設定変更の監査ログは、Anthropic のアカウントチームへの問い合わせが必要です。

よくある質問

グループごとに違う設定を配れますか?

公式ドキュメントによると、設定は組織の全利用者に一律で適用され、グループ別の設定はまだ対応していません。

出典: Configure server-managed settings

設定が端末に届いているかは、どう確認しますか?

利用者に Claude Code を再起動してもらい、/permissions で有効な権限ルールを見ます。取得結果は claude doctor の Managed settings (remote) の行で確認でき、Claude Code v2.1.248 以降が必要です。

出典: Configure server-managed settings

Console の API キーで動く CI ジョブにも、管理コンソールの設定は効きますか?

効きません。Console の API キーは別の組織に属するためです。公式ドキュメントは、claude setup-token で作った OAuth トークンを使う方法と、endpoint-managed settings を使う方法を挙げています。--bare で動くジョブでは OAuth トークンは使えません。
