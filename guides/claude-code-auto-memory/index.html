Claude Code の自動メモリ(auto memory)とは:保存場所・止め方・確認方法

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 自動メモリは、Claude が自分用にメモを残す仕組みです。ローカルのセッションでは既定でオンで、人が書く CLAUDE.md とは役割が別です。
  • 保存先は ~/.claude/projects/<project>/memory/ で、マシンローカルです。中身は普通のマークダウンなので、/memory から確認・編集・削除できます。
  • 止めるときは /memory のトグル、autoMemoryEnabled、環境変数 CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 のいずれかです。オンに戻せないセッションがある点に注意してください。

自動メモリとは:CLAUDE.md との違い

執筆時点(2026年10月)の公式ドキュメントによると、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)には補い合う2つの記憶の仕組みがあり、どちらも会話の開始時に読み込まれます。1つは人が書く CLAUDE.md(Claude への指示やルールを書くファイル)、もう1つが自動メモリです。

自動メモリは、利用者が何も書かなくても、Claude がセッションをまたいで学びやパターンをためていく仕組みです。CLAUDE.md は利用者が書くコーディング規約やワークフロー向け、自動メモリは利用者の好みや Claude への訂正、コードから読み取れないプロジェクトの背景向けとされています。範囲も異なり、自動メモリはリポジトリ単位で、ワークツリー間で共有されます。

なお、どちらも Claude は強制される設定ではなく文脈として扱います。操作を確実に止めたい場合は、PreToolUse フックを使うよう公式ドキュメントで案内されています。

保存される内容と、保存されない内容

Claude は作業中に4種類のメモを自分用に保存し、種類はメモファイルの frontmatter の type フィールドに記録されます。

  • user:利用者の役割、専門性、作業上の好み
  • feedback:Claude への訂正と、確認したやり方
  • project:進行中の作業、期限、コードや git の履歴からは分からない決定事項
  • reference:課題管理ツールやダッシュボードなど、プロジェクト外の情報の場所

アーキテクチャ、ファイルパス、デバッグの修正のようにコードベースから分かることや、CLAUDE.md に既にある内容は保存しません。毎セッション保存するわけでもなく、将来の会話で役立つかどうかで判断します。

「always use pnpm, not npm」のように覚えるよう頼むと、自動メモリに保存されます。CLAUDE.md に入れたいときは「add this to CLAUDE.md」と頼むか、/memory から編集します。

保存場所とフォルダ構成

プロジェクトごとに ~/.claude/projects/<project>/memory/ というディレクトリができます。<project> は git リポジトリから決まるため、同じリポジトリのワークツリーとサブディレクトリは1つの自動メモリを共有します。git リポジトリの外ではプロジェクトのルートが使われます。

~/.claude/projects/<project>/memory/
├── MEMORY.md           # Index, one line per memory, loaded into every session
├── user_role.md        # One memory
├── feedback_testing.md # One memory
└── ...                 # Any other topic files Claude creates

MEMORY.md は索引で、メモ1件につき1行です。メモ本体はトピックごとのファイルに入ります。保存先を変えるには、settings.json に autoMemoryDirectory を設定します。

{
  "autoMemoryDirectory": "~/my-custom-memory-dir"
}

値はフルパスか ~/ で始まる必要があります。プロジェクトの設定ファイルに書く場合は、設定ファイル内のフックと同じワークスペースの信頼ルールで扱われます。また、permissions.blockReadsOutsideWorkingDirectories がオンの間は、リポジトリ側の設定ファイルが選んだディレクトリから自動メモリを読み込まず、保存もしません。

オン・オフの切り替え方

自動メモリはローカルのセッションでは既定でオンです。Claude Tag のセッション以外では、セルフホスト環境のセッションは既定でオフで動きます。

セッション内で /memory を開いて自動メモリのトグルを使うと、autoMemoryEnabled がユーザー設定の ~/.claude/settings.json に保存されます。1つのプロジェクトだけオフにするなら、そのプロジェクトの設定に次を書きます。

{
  "autoMemoryEnabled": false
}

環境変数で止める場合は CLAUDE_CODE_DISABLE_AUTO_MEMORY=1 を設定します。

オンに戻せないセッション

次のセッションでは、トグルでオフにはできますが、オンには戻せません。

  • バックグラウンドセッション
  • 別の Claude Code セッションが起動したセッション(例:Claude が Bash ツール経由で claude を実行した場合)

その間、トグルには off · can't be turned on here; use a session started outside Claude Code と表示されます。戻すには、ターミナルで直接 claude を実行し、そのセッションで /memory のトグルを使います。

読み込みの仕組みと注意点

MEMORY.md は先頭200行、または先頭25KBのどちらか先に達するところまでが会話の開始時に読み込まれ、超えた分は読み込まれません。Claude は詳細をトピックファイルへ移して索引を短く保ちます。user_role.md などのトピックファイルは起動時には読み込まれず、必要なときに Claude が読みます。

上限を超えても書き込み自体は成功しますが、Claude Code は索引を書き直すようエラーを返します。次の読み込みで上限より後ろが落ちるためです。この上限は MEMORY.md だけに適用され、起動時に読み込まれる CLAUDE.md は4 MiB 以下なら全体が読まれます(サブディレクトリの CLAUDE.md とパス指定のルールには、別のより小さいファイルごとの上限があります)。

  • ファイルはマシン間やクラウド環境間で共有されません。
  • セッション記録は cleanupPeriodDays の保持期間後に削除されますが、メモリファイルは対象外です。利用者か Claude が編集・削除するまで残ります。
  • メインの会話の自動メモリは、サブエージェントには読み込まれません(fork は例外)。サブエージェント自身の自動メモリは別ディレクトリです。

中身の確認と編集

自動メモリのファイルは普通のマークダウンで、いつでも編集・削除できます。/memory を実行すると、CLAUDE.md や CLAUDE.local.md などの場所が一覧で出て、自動メモリのオン・オフの切り替えと、自動メモリのフォルダを開く選択肢もあります。

GUI エディタ(VS Code など)は別ウィンドウで開き、Vim などのターミナルエディタは終了までターミナルを占有します。「Saved 2 memories」「Recalled 2 memories」と表示されたら、Claude が ~/.claude/projects/<project>/memory/ を更新または読み込んでいます。

社内で配る前に、何が保存されているかをこの方法で確認しておくとよいでしょう。組織全体への設定配布など、出典に書かれていない点は公式ドキュメントで確認してください。

よくある質問

自動メモリは別の PC やチームメンバーと共有されますか?

公式ドキュメントによると、自動メモリはマシンローカルで、ファイルはマシン間やクラウド環境間で共有されません。共有されるのは、同じ git リポジトリ内のワークツリーとサブディレクトリの間です。

自動メモリをオフにしたのに、オンに戻せません。

バックグラウンドセッションや、別の Claude Code セッションが起動したセッションでは、トグルはオフにするだけでオンには戻せません。ターミナルで直接 claude を実行し、そのセッションで /memory のトグルを使います。

自動メモリに何が保存されたか分かりません。どう確認しますか?

/memory を実行して自動メモリのフォルダを選ぶと、Claude が保存した内容を見られます。すべて普通のマークダウンなので、読む・編集する・削除するのいずれもできます。
