Claude Code を LLM ゲートウェイ経由で使う:できることと導入の進め方

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • ゲートウェイは、組織が Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)とモデル提供元の間に置くプロキシです。認証・利用状況の記録・予算・監査ログを一か所で管理できます。
  • 選択肢は、claude バイナリに含まれる Claude apps gateway と、すでに運用中の LLM ゲートウェイです。ブラウザでのサインインが要る前者は、CI のような無人環境では認証できません。
  • ゲートウェイ資格情報を使うと、サブスクリプションではなく提供元アカウントに API 料金で課金されます。モデルの選択やその他の通信は、ゲートウェイとは別に設定します。

ゲートウェイとは何か:できること

公式ドキュメントによると、ゲートウェイは組織が Claude Code とモデル提供元の間で動かすプロキシ(通信の中継役)です。Claude Code は API 通信をゲートウェイに送り、ゲートウェイが組織の保有する資格情報で提供元へ転送します。開発者は提供元の資格情報を持たず、ゲートウェイに対して認証します。

認証・利用状況の記録・予算・監査ログを、組織が管理する一か所にまとめられます。資格情報は次の2種類です。

  • 開発者の資格情報:開発者ごとにゲートウェイが発行し、認証と利用状況での識別に使います
  • 提供元の資格情報:ゲートウェイが提供元アカウント用に1つ保持し、転送する通信全体で共有します

転送先はゲートウェイの設定で決まり、Anthropic の API のほか、Amazon Bedrock、Google Cloud の Agent Platform、Microsoft Foundry も選べます。Anthropic 形式のエンドポイントを1つ公開するゲートウェイなら、提供元を変えても開発者のマシンには触れずに済みます。

出典: Run Claude Code through a gateway

Anthropic 提供の Claude apps gateway を使う場合

Claude apps gateway は Anthropic の自社ホスト型ゲートウェイで、claude バイナリに含まれます。上流には Amazon Bedrock、Claude Platform on AWS、Google Cloud、Microsoft Foundry、Anthropic API を指定できます。開発者は /login で社内の IdP(ID 管理基盤)にサインインし、モデルへのアクセスと managed settings(管理者が配る設定)は IdP グループ単位で適用されます。利用状況は OTLP 形式のメトリクスとして自社の監視基盤へ出力されます。

Claude Code の各リリースと一緒に作られテストされるため、別管理のゲートウェイのように転送ルールを更新し続ける必要がありません。ゲートウェイ経由のセッションで挙動が異なる機能が少数あるため、公式ドキュメントの制限事項を確認してください。

注意点:サインインはブラウザでの SSO で、サービストークン方式はありません。承認する開発者がいない CI では認証できないため、CI は提供元に直接設定します。また、開発者がサインイン済みのマシンの claude -p や Agent SDK のセッションは、そのマシンのゲートウェイセッションを使い、そのポリシーの対象になります。

すでに運用中の LLM ゲートウェイを使う場合

執筆時点(2026年10月)の公式ドキュメントでは、サポートされる API 形式を公開していれば、すでに運用中のゲートウェイを使えるとされています。ただし Anthropic は他社製品を推奨・保守・監査せず、どのゲートウェイ経由でも Claude 以外のモデルへの振り分けをサポートしません。

管理できるのは、資格情報、利用状況(開発者・チーム別)、予算とレート制限、監査ログ、提供元の切り替えです。提供元の切り替えだけは、上流にかかわらず Anthropic 形式のエンドポイントを1つ公開している場合に限られます。

トレードオフは、ゲートウェイが組織で運用するインフラになる点です。Claude Code はリリースごとに機能が増え、ゲートウェイが転送しないと該当機能が動かなくなるため、製品側の更新が必要です。

導入の進め方

公式ドキュメントでは、どのゲートウェイ製品でも手順は次の順です。

  1. ゲートウェイを配置し、提供元の資格情報を渡します。
  2. 開発者ごとにゲートウェイの資格情報を発行します。利用状況が開発者に紐づき、退職時は1つの資格情報を失効させれば済みます。
  3. managed settings ファイルとシークレット管理の仕組みで、ベース URL と資格情報を全端末に配ります。両方配れば、開発者は何も設定しなくて済みます。
  4. 各開発者が Claude Code 上で設定が届いているかを確認し、配布の不具合を先に見つけます。

管理対象の端末でゲートウェイだけを唯一の接続先にするには、同じ managed settings ファイルで allowedProviders を ["customEndpoint"] に設定し、env ブロックにゲートウェイの ANTHROPIC_BASE_URL を入れます。Anthropic への直接接続や開発者個人のプロキシ向けのセッションは拒否されます。Claude Code v2.1.285 以降が必要です。

課金とゲートウェイ外の設定で注意すること

サブスクリプションと課金

ゲートウェイ資格情報で接続すると、利用分は組織の提供元アカウントに API 料金で課金され、開発者の claude.ai サブスクリプションは使われません。自前のゲートウェイで ANTHROPIC_AUTH_TOKEN を設定するか、Claude apps gateway に /login でサインインすると、そのセッションではサブスクリプションのログインが無効になります。例外は ANTHROPIC_BASE_URL だけを設定した場合で、通信はゲートウェイを通りますが、保存済みの claude.ai ログインが有効なままで、サブスクリプションの上限と課金が適用されます。最新の金額は公式の料金ページで確認してください。

ゲートウェイとは別に設定するもの

  • モデルの選択:/model コマンドやモデル用の環境変数で選びます。ゲートウェイは宛先を決めるだけです。Claude apps gateway は availableModels でグループごとに候補を絞れますが、その中で選ぶのは開発者です
  • その他の通信:バージョン確認やダウンロードは Anthropic へ直接送られます。必要なドメインへの外向き通信を許可するか、CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC で任意の通信を止めます
  • クライアントテレメトリ:Claude apps gateway にサインインしたセッションでは Anthropic 宛のクライアント分析が無効になります。サインイン前の起動時分析も止めるには、各端末のクライアント側 managed settings で DISABLE_TELEMETRY を配ります。他のゲートウェイは提供元によって異なるため、公式の既定値の表を確認してください
  • 社内の HTTP プロキシ:HTTPS_PROXY はゲートウェイを含む全通信の間に入るため、必要ならゲートウェイとは別にプロキシも設定します。自前ホストの Claude apps gateway では、サインイン時にプロキシのホストもプライベートネットワーク上にあるか確認され、そうでなければゲートウェイのホストを NO_PROXY に追加します

よくある質問

ゲートウェイ経由だと、claude.ai のサブスクリプションの枠は使われますか?

ゲートウェイ資格情報を使う場合は使われず、提供元アカウントに API 料金で課金されます。ANTHROPIC_BASE_URL だけを設定した場合は、保存済みの claude.ai ログインが有効なままで、サブスクリプションの上限と課金が適用されます。

出典: Run Claude Code through a gateway

CI から Claude apps gateway 経由で使えますか?

公式ドキュメントによると、サインインはブラウザの SSO でサービストークン方式がないため、承認する開発者がいない CI は認証できません。CI は提供元に直接設定します。

出典: Run Claude Code through a gateway

ゲートウェイ経由で Claude 以外のモデルに振り分けられますか?

公式ドキュメントでは、Anthropic はどのゲートウェイ経由でも Claude 以外のモデルへのルーティングをサポートしないとされています。
