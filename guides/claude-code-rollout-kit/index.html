Claude Code を社内に広める進め方:公式の周知キットと推進役の役割

公開: 2026年10月17日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントには、管理者向けの周知キット(告知文・ヒント配信・FAQ の下書き)と、利用者側の推進役(チャンピオン)向けキットの2つがあります。
  • 告知文は完成品ではなく下書きです。自社の言葉に直し、例を自社コードの実例に差し替え、[bracketed placeholders] を置き換えてから送ります。
  • 公式ドキュメントは、告知を出すだけでなく、使いこなして共有する推進役を置き、週あたりの負担を小さく保つ進め方を示しています。

公式の周知キットで何ができるか

公式ドキュメントによると、Communications kit は、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)をエンジニア組織に展開する管理者やエンジニアリングリード向けのページです。展開時の告知文、展開後に少しずつ配るヒント集、よく聞かれる質問への一行回答が載っています。

注意書きでは、載っている文面は下書きとされています。自社の言葉に書き直し、例のタスクを自社コードの実際のバグやモジュールに差し替え、[bracketed placeholders] を置き換えてから送るよう求めています。社内の誰かが書いたように読める告知が定着につながる、という説明です。

想定読者はエンジニア組織です。情シス主導で全社に広げる場合は、文面が読み手に合うか確認してください。また、Claude Code は頻繁にリリースされるため、社内に配る前にバージョン依存の内容を公式ドキュメントのホームページで確認するよう注記されています。

出典: Communications kit

送信前チェックリストと告知文の型

公式ドキュメントでは、告知の前に次の項目を済ませるよう挙げています。各項目は、そのままだと当日のサポート対応の山になる抜けを埋めるためのものです。

  • #claude-code チャンネルを作り、告知からリンクする(質問の受け皿を一つにする)
  • インストールコマンドを、自社環境の少なくとも1台で試す(プロキシやファイアウォールの問題を先に拾う)
  • セキュリティとデータの扱いのリンクを用意する(最初の質問が「コードはどこへ行くのか」になるため)
  • 自社コードの実際のバグやファイルなど、最初の具体的なタスクを1つ決める
  • 最初の48時間、チャンネルの担当者を決める
  • 役員(C-suite)に告知の送信か連名を依頼する

標準の告知文は、Claude Code が何か、2分で始められる導入手順、試す具体的なタスク、「コードはどこへ行くか」への回答という構成です。データの扱いについて公式ドキュメントは、ターミナル上で動き Anthropic の API と直接通信すること、Team または Enterprise プランでは Anthropic がコードやプロンプトをモデルの学習に使わないことを書いています。「Team または Enterprise プランでは」という条件は、社内向けの文面でも落とさないでください。自社の契約プランの確認は公式ドキュメントで行ってください。

出典: Communications kit

役員名義・パイロット・ヒント配信の使い分け

役員名義版

スポンサーとなる役員の名前とアカウントから送る版です。公式ドキュメントによると、役員名義の展開は、管理者やツールチームから同じ文面を送るより開封率が高く、最初の週の利用開始も早いとされています。依頼は「インストールして、実際のタスク1つで動かす」の一点に絞り、方法は標準の告知と #claude-code に任せる作りです。

パイロット版

段階展開向けで、パイロットのメンバーだけに送ります。今週少なくとも1つ実際のタスクで使い、#claude-code-pilot に、うまくいった点、煩わしかった点、意外だった点を書いてもらいます。このフィードバックが、他の人への展開方法を決めると説明されています。最初の複数ファイルの変更では、「plan」が表示されるまで Shift+Tab を押すと、ソースを編集せずに計画を示す、という案内も入っています。

ヒント配信

展開後は、貼り付け用の Slack や Teams 向けメッセージを、#claude-code に週に1〜2本のペースで配る使い方が示されています。順番に決まりはなく、チームの弱い部分に合うものだけを選んでもよいとされています。題材には /init と CLAUDE.md、プランモード、/rewind などがあります。

出典: Communications kit

推進役(チャンピオン)の役割と週の負担

Champion kit は、すでに Claude Code を使っていて、チームへの定着を手伝いたい個々のエンジニア向けのページです。公式ドキュメントでは、開発ツールの定着は告知よりも、誰かが上手に使い、公開の場で語り、他の人が真似しやすくすることで起きる、と説明しています。役割は次の3つの行動です。

  • 発見を共有する:自分の仕事で使ったプロンプトやスクリーンショットを、チームが普段読む場所に投稿する
  • 聞かれる人になる:質問されたら、説明より先に、実際に使ったプロンプトを返す
  • 輪を広げる:専用チャンネルや週1回のスレッドなど軽い習慣を作り、自分が不在でも勢いが続くようにする

公式ドキュメントにある投稿例(英語)の一つです。短い文と実例で足りる、という長さの見本として載っています。

Plan mode is the reason I am comfortable using this on code that matters.
Press Shift+Tab until you see "plan"; it lays out the changes it proposes
without editing your source.

負担の目安は、通常の業務週に収まる範囲とされています。投稿が週に約15分、共有チャンネルでの質問対応が約20分、週1回のスレッド運営が約5分、任意のペア作業や説明が0〜30分です。推進役を追加のサポート業務にせず、既存業務の補助にとどめるよう述べています。周知キットには、展開後に #claude-code で活発な2、3人へ声をかける DM の文例もあります。

出典: Champion kit

30日の進め方と、懸念・セキュリティ質問への対応

公式ドキュメントの30日プレイブックは、状況に合わせて調整してよいゆるい計画です。各週に「うまくいっている目安」が付いています。

  1. 1週目:チャンネルを作り、Quickstart をピン留めし、自分の例を2、3件、プロンプト付きで投稿する。目安は、数人が反応し、質問が1件以上出ること
  2. 2週目:週1回の show-and-tell スレッドを始め、質問には公開で答え、カスタムスキルか CLAUDE.md の断片を1つ共有する。目安は、他の人が自分の例を投稿すること
  3. 3週目:短いペア作業を2、3回行い、よくある質問を FAQ としてピン留めする。目安は、同じ人が繰り返し使うこと
  4. 4週目:2人目の推進役を見つけ、うまくいっている点とそうでない点を上長や管理者に伝える。目安は、質問に自分以外が答えること

懸念への対応では、一般論で議論せず、懸念を認め、短く言い換え、その人自身のコードで具体的なデモを1つ提案するのが効果的とされています。「本番コードに AI を触らせたくない」には、どの変更も読まずに取り込まないことに同意し、プランモードで提案を先に見て、diff を通常のプルリクエストと同じ基準でレビューするよう勧めます。

セキュリティとデータの扱いの質問について、公式ドキュメントは、推進役がその場で答えを作らず管理者に回すよう書いています。ここは情シス側で受け皿を用意しておく部分です。

社内展開での注意点

  • 文面は下書きです。そのまま全社に流さず、自社の言葉と実例に直してください。
  • データの扱いの説明は、Team または Enterprise プランという条件付きです。自社の契約に合わせて確認してください。
  • ヒント集の中の「ベストプラクティス」では、コミット前に diff を確認すること、重要な経路に触れる変更は検証することが挙げられ、Claude は自信を持って誤ることがあると書かれています。
  • 料金やプランの条件は、この記事の出典に書かれていません。最新の内容は公式の料金ページで確認してください。

推進役には、どれくらいの時間が必要ですか。

「コードはどこへ行くのか」と聞かれたら、どう答えますか。

周知キットの一行回答では、CLI はターミナルで動き、推論のためにコンテキストを Anthropic の API に送るとされています。Team または Enterprise プランでは、コードとプロンプトはモデルの学習に使われません。推進役向けキットは、この質問は管理者に回すよう書いているため、情シス側で回答を用意しておくと進めやすくなります。
