Claude Code の Code Review(PR 自動レビュー)の仕組み・始め方・料金

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • Code Review は、GitHub のプルリクエストを複数のエージェントが読み、検証を通った指摘をインラインコメントで返す機能です。承認やブロックはせず、マージの判断は人に残ります。
  • 対象は Team または Enterprise プランの組織で、有効化は Claude 組織の Owner が行います。Zero Data Retention や HIPAA 構成の組織では使えません。
  • 料金は1件いくらの定額ではなく、トークン使用量に応じた従量課金です。先に月次の支出上限を設定してから小さく試し、平均コストを確認して広げるのが安全です。

Code Review でできること:仕組みと出力

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)には、GitHub のプルリクエスト(変更を取り込む前のレビュー依頼)を自動でレビューする Code Review があります。公式ドキュメントによると、複数のエージェントが変更と周辺のコードを読み、ロジックの誤りや脆弱性などを探し、報告前に検証の段階で指摘をコードと照らします。

Anthropic のインフラ上で、次の4段階で動きます。

  1. 探す:複数のエージェントが差分と周辺コードを並行して調べる
  2. 検証:候補の指摘をコードと照らし、誤検知を除く
  3. 順位付け:重複を除き、重要度で並べる
  4. 投稿:結果をプルリクエストに投稿する

結果は、該当行のインラインコメント、要約、Claude Code Review という名前のチェックラン(PR に出る検査結果)として残ります。チェックランは失敗として終了せず、指摘が無いときのタイトルは Code review found no issues です。

既定では書式やテスト不足ではなく、本番を壊すバグなど正しさに重点を置きます。調整には REVIEW.md や CLAUDE.md を使い、REVIEW.md はベースブランチまたはデフォルトブランチのものが読まれます。

AI のレビューなので見逃しはあり得ます。指摘が無くても、エラーが無い、安全だという意味ではないと公式ドキュメントは注意しています。

出典: Code Review

使える条件:プラン・コードホスト・対象外の組織

公式ドキュメントによると、利用条件は次のとおりです。

  • プラン:Team または Enterprise
  • コードホスト:GitHub(GitHub Enterprise Server と、データレジデンシー付きの GitHub Enterprise Cloud を含む)
  • Zero Data Retention を有効にした組織と HIPAA 構成を適用した組織では利用できず、Anthropic の Business Associate Agreement(BAA)の対象外
  • 顧客管理の暗号鍵(CMEK)を使う組織では、まだ利用できません
  • Amazon Bedrock、Google Cloud's Agent Platform、Microsoft Foundry 経由で Claude Code を使っていても、上記プランの Claude 組織が必要

該当しなくても、/code-review は Claude Code のセッション内で、どのプランでも実行できます。ほかの方法は公式ドキュメントの比較表で確認してください。

出典: Code Review

始め方:管理画面での設定手順

公式ドキュメントによると、必要な権限は次の3つです。

  • Claude 組織の Owner ロール(管理画面の全手順)
  • GitHub 組織の Owner(Claude GitHub App のインストールと連携。Owner でなければ先に依頼)
  • 追加する各リポジトリへの書き込み権限

手順の流れは次のとおりです。

  1. Admin settings > Claude Code の Code review で Allow code review を入れる
  2. Connect GitHub が出たら Connect を押し、GitHub で認可する
  3. 対象リポジトリが出なければ Install GitHub App でインストールし、権限を承認する
  4. リポジトリを選んで Continue、次の Code review is set up で Finish を押す
  5. ドラフトでないテスト PR を開き、数分以内に Claude Code Review のチェックランが出るか確認する

注意点です。アプリの権限セットはレビューに要る範囲より広く、GitHub Actions など他の機能と共有されます。レビュー内部のリポジトリアクセスは読み取り専用で、コードのビルドや実行はしません。また Finish 以外でダイアログを閉じると、リポジトリは追加されたまま Allow code review はオフです。

費用の仕組み:何で金額が決まるか

執筆時点(2026年10月)の公式ドキュメントでは、Code Review に1件いくらの定額料金はありません。トークン使用量に応じて使用量クレジットで課金され、プランに含まれる使用量とは別です。請求は組織宛てで、PR を開いた開発者には付きません。金額は本記事の参照元に無いため、最新の金額は公式の料金ページで確認してください。

費用は「1回のレビューの費用」×「回数」で決まります。1回の費用はレビューレベル、変更の大きさ、周辺コードの複雑さ、検証が必要な候補の数で変わります。回数は、リポジトリごとの Review runs 設定で決まります。

レビューレベル

Quick は最速・最低コスト、Standard は既定のバランス型、Deep は最も徹底的で時間もコストも最大です。Owner が組織で1つ選び、リポジトリごとに変えることもできます。

回数の設定

  • Once after PR creation:PR を開いたとき、再オープン、レビュー準備完了にしたときに実行
  • After every push:プッシュのたびに実行し、費用はプッシュ数倍
  • Manual (@claude review):開いたときもプッシュ時もレビューなし

リポジトリ追加直後は After every push で、最も回数が多くなります。@claude review は1回だけ実行し、@claude review always は Once after PR creation か Manual のとき、以降のプッシュでも課金されます。ドラフトとフォークからの PR は自動レビューの対象外です。

見積もりと上限:広げる前にやること

公式ドキュメントは、広げる前の小規模パイロットを勧めています。

  1. 月次の支出上限を設定する
  2. 代表的なリポジトリ数件で、Review runs を Once after PR creation か Manual (@claude review) にして有効化する
  3. 数件のレビュー後、Repositories 表の Average cost 列で平均コストを見る
  4. 平均にひと月の PR 数を掛ける。After every push ならさらに1PRあたりのプッシュ数を掛ける

上限は usage の管理画面で、Claude Code Review サービスに設定します(組織全体に適用)。Code Review の月次上限、組織全体の月次上限、使用量クレジットの残高のどれかが尽きる、または残りが1回分の想定費用を下回ると、レビューはスキップされ、開発者は PR 上で原因を示すコメントを見ます。

使用状況は analytics の Code Review ダッシュボードで見られますが、費用の数字は請求書と異なることがあります。リポジトリ別は割引やクレジット前の定価での概算なので、正確な金額は Anthropic の請求書で確認してください。

よくある質問

Code Review はプルリクエストを承認したり、マージを止めたりしますか?

公式ドキュメントによると、レビューは承認もブロックもせず、チェックランも失敗として終了しません。マージの判断はチームに残ります。

出典: Code Review

Team・Enterprise 以外のプランでは使えませんか?

Code Review 本体は Team または Enterprise が対象で、Owner が有効にします。ただし /code-review は Claude Code のセッション内で、どのプランでも実行できます。

出典: Code Review

1回のレビューはいくらですか?

公式ドキュメントによると定額はなく、トークン使用量に応じた課金です。金額は参照元に無いため公式の料金ページで確認してください。自社の平均は管理画面の Average cost 列で見られます。
