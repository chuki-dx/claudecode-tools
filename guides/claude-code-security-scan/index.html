Claude Security プラグインでコードの脆弱性を調べてパッチにする手順

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、Claude Security プラグインは Claude Code のセッション内で、リポジトリ全体または変更差分の脆弱性を複数のエージェントがスキャンし、選んだ指摘をパッチにします。
  • 前提は、有料プラン・Anthropic API・サードパーティプロバイダーのいずれかと、python3 3.9 以降、Git(変更スキャンとパッチ作成に必要)です。
  • パッチは自動では適用されません。git apply で利用者が適用し、1件ずつ別のプルリクエストでレビューします。

Claude Security プラグインで何ができるか

以下は執筆時点(2026年10月)の公式ドキュメントに基づきます。公式ドキュメントによると、Claude Security プラグインは、Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)のセッション内で、複数のエージェントが構成の把握、脅威モデルの作成、脆弱性の探索を行い、全指摘を独立して検証してからレポートにします。

対象はリポジトリ全体のほか、ブランチや PR の差分、単一コミットも選べます。選んだ指摘をパッチにでき、レビューと適用は利用者が行います。ローカルのセッションで動き、スキャンは利用量に加算されます。金額や回数は出典に無いため、最新の金額は公式の料金ページで確認してください。

公式ドキュメントでは、既存の静的解析や依存関係スキャンの代わりではなく、併用するものとされています。リポジトリを監視するマネージド版の Claude Security は、Enterprise プランの別製品です。

動かす前に確認する前提条件

公式ドキュメントが挙げる実行の前提です。

  • 有料プラン、Anthropic API、サードパーティプロバイダーのいずれか(スキャンが使うダイナミックワークフローのため)。Pro では /config の Dynamic workflows の行でオンにします。
  • python3 として PATH にある Python 3.9 以降。追加インストールは不要です。
  • Linux、macOS、Windows のいずれか。
  • Git。変更スキャンとパッチ作成に必要で、他のバージョン管理システムは非対応です。全体スキャンはバージョン管理なしでも動きます。

プラグイン自身はモデルを呼ばないため、別の API キー設定は要りません。探索・検証・パッチ作成はセッションのモデルで動き、変更は /model で行います。サードパーティプロバイダーでは sonnet エイリアスが別バージョンになることがあり、使えない場合はモデルの固定が必要です。手順は公式ドキュメントで確認してください。

プラグインのインストール

ターミナルでは claude を実行し、プロンプトで次を入力します。VS Code 拡張機能とデスクトップアプリでは、公式の「Install a plugin」の手順に従います。

/plugin install claude-security@claude-plugins-official

プラグインの詳細が開くので、インストールスコープを選んで進めます。失敗したときは、表示されたメッセージで対処します。

  • Marketplace "claude-plugins-official" not found: /plugin marketplace add anthropics/claude-plugins-official を実行して再試行します。
  • Plugin "claude-security" not found in marketplace "claude-plugins-official": カタログが古い可能性があるため、/plugin marketplace update claude-plugins-official を実行して再試行します。

結果に Run /reload-plugins to apply. と出たら、再起動せずに有効化する手順を公式ドキュメントで確認します。削除は claude plugin uninstall claude-security です。

スキャンの流れと対象の絞り方

追加されるコマンドは /claude-security の1つで、メニューから全体スキャン、変更スキャン、パッチ提案の3つを選びます。基本の流れは次のとおりです。

  1. /claude-security を実行し、Scan codebase を選びます。
  2. リポジトリ全体か特定の領域かを選びます。「I don't know」と答えると、規模に合う既定値が選ばれます。
  3. 実行を確認します。時間とトークンを多く使うことがあり、完了まで Claude Code を開いたままにします。確認するまで何も走りません。
  4. 進行は /workflows で見られ、結果は日時つきのディレクトリに書かれます。
  5. もう一度 /claude-security を実行して Suggest patches を選び、対応する指摘を選びます。
  6. 採用するパッチを git apply で、1件ずつ別のプルリクエストで適用します。

/claude-security scan my branch のように引数で頼むこともできます。公式ドキュメントでは、各手順で許可を求められない auto mode が向くとされています。

変更だけを調べる

ベースにないコミットがあるブランチでは、その差分だけを調べられます。対象はコミット済みの変更だけなので、作業中の編集はコミットか stash するか、作業ツリーを読む全体スキャンを使います。変更スキャンには git リポジトリが必要です。プルリクエストを探す手順だけがネットワークに出るもので、セッションに GitHub CLI の実行許可があり、gh にサインイン済みのときだけ提示されます。

大きなリポジトリ

領域を1つずつ選んで調べます。レポートのカバレッジの節に、調べた範囲と調べていない範囲が書かれます。

スキャン結果の読み方

結果は、リポジトリ内の日時つきディレクトリに書かれます。

  • CLAUDE-SECURITY-RESULTS.md: レポート。指摘 ID(F1 など)、影響、悪用シナリオ、深刻度、確信度、推奨対応が載ります。
  • CLAUDE-SECURITY-RESULTS.jsonl: 同じ指摘を1行1 JSON で並べたものです。
  • CLAUDE-SECURITY-RESULTS.sarif: SARIF 2.1.0 形式のログで、GitHub code scanning などで使えます。指摘は CWE の分類つきです。
  • リビジョンスタンプの JSON: どのコミットをスキャンしたかなどを記録し、レポートを対象コードと結び付けます。

このディレクトリがスキャンで変わる唯一の箇所で、専用の .gitignore が入っているため、誤って git add してもコミットされません。監査証跡として履歴に残すなら、その .gitignore を削除してコミットします。指摘は独立した検証を通ったものだけが載ります。スキャンは非決定的で、同じコードでも結果が変わることがあるため、定期的に実行し、スタンプで対象を確認します。

指摘をパッチにして適用する

Suggest patches を選ぶか、「fix finding F3」のように頼み、対応する指摘を選びます。パッチはコミット済みのコードに対して作られ、コードが変わった指摘はメモつきでスキップされ、新しいスキャンが提案されます。下書きは作業用コピーで行うため、利用者が適用するまでソースは変わりません。

書いたのとは別のエージェントが、テストがあれば実行し、差分も確認します。パッチが書かれるのは、その指摘への対応、新しい脆弱性が入らないこと、他の挙動が変わらないことの3点を保証できるときだけです。保証できないときは、理由のメモが出ます。

パッチは patches/ フォルダに、指摘ごとに F<n>.patch として書かれ、説明メモが付きます。次のように適用します。

git apply CLAUDE-SECURITY-<timestamp>/patches/F1.patch

テストが無いコードの場合は、メモにその旨が書かれます。1件ずつ別のプルリクエストにして、個別にレビューとテストを行います。

よくある質問

未コミットの変更もスキャンできますか?

変更スキャンの対象はコミット済みの変更だけです。作業中の編集は、コミットか stash するか、作業ツリーを読む全体スキャンを使ってください。

出典: Scan your codebase for vulnerabilities

パッチが出てこない指摘はありますか?

あります。別のエージェントによるレビューが、その指摘への対応、新しい脆弱性が入らないこと、他の挙動が変わらないことの3点を保証できないときは、パッチの代わりに理由のメモが出ます。パッチが出た場合も自動では適用されません。

出典: Scan your codebase for vulnerabilities

メニューに Python の警告が出たらどうしますか?

python3 3.9 以降が PATH に必要です。見つからない場合は動かないという警告が、先頭の python3 が古い場合は見つかったバージョンを示す警告が出ます。Python 3 を入れるか新しい python3 を先頭に置き、新しいセッションを始めてください。
