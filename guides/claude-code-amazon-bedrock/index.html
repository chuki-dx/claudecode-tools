Claude Code を Amazon Bedrock で使う設定|サインイン・IAM・トラブル対応

公開: 2026年10月24日 ・ 中小DXラボ ・ 内容は執筆時点(2026年10月)の公式ドキュメントなどの出典にもとづきます(各節の末尾に出典を記載)

結論

  • 公式ドキュメントによると、前提は Amazon Bedrock を有効にした AWS アカウント、Claude モデルへのアクセス、適切な IAM 権限です。
  • 自分の認証情報で使い始めるなら、claude を起動して 3rd-party platform、Amazon Bedrock を選び、ウィザードに従う方法があります。
  • チームに配る場合は、手動セットアップとモデルバージョンの固定を先に行い、IAM・リージョン・プロキシ周りの注意点を押さえます。

最初に確認する前提条件

Claude Code(Anthropic 社が提供する、ターミナルで動く AI コーディングエージェント)は、Amazon Bedrock(AWS のサービス)経由でも使えます。公式ドキュメントによると、事前に次を用意します。

  • Amazon Bedrock へのアクセスを有効にした AWS アカウント
  • Amazon Bedrock で使いたい Claude モデル(例:Claude Sonnet 4.6)へのアクセス
  • AWS CLI のインストールと設定(任意。ほかに認証情報を得る手段がない場合だけ必要)
  • 適切な IAM(AWS の権限管理の仕組み)権限

自分の Bedrock 認証情報でサインインするなら、次節のウィザードを使います。チームに展開する場合は、公式ドキュメントの手動セットアップの手順に従い、展開前にモデルのバージョンを固定するよう案内されています。手動セットアップの詳細は本記事では扱いませんので、公式ドキュメントで確認してください。なお、執筆時点(2026年10月)の根拠は公式ドキュメントのみです。

出典: Claude Code on Amazon Bedrock

ウィザードで Bedrock にサインインする

公式ドキュメントでは、AWS の認証情報があればログインウィザードで設定できるとされています。AWS 側の準備はアカウントごとに1回で、Claude Code 側の設定はウィザードが行います。

  1. Amazon Bedrock コンソールの Model catalog で Anthropic のモデルを選び、use case form を送信します。送信後すぐにアクセスが許可されます。AWS Organizations を使う場合は、公式ドキュメントの該当箇所を確認してください。
  2. claude を実行し、ログイン画面で 3rd-party platform、Amazon Bedrock の順に選びます。すでにサインイン済みでチャット画面が出る場合は /setup-bedrock を実行します。CLAUDE_CODE_USE_BEDROCK=1 が設定されるまでこのコマンドはコマンドメニューに出ないため、全文を入力します。
  3. ウィザードで AWS への認証方法を選びます。~/.aws から検出した AWS プロファイル、Amazon Bedrock API キー、アクセスキーとシークレット、環境にすでにある認証情報のいずれかです。続けてリージョンを入力すると、アカウントで呼び出せる Claude モデルが確認され、固定もできます。

結果はユーザー設定ファイルの env ブロックに保存されるため、環境変数を自分で export する必要はありません。サインイン後も /setup-bedrock で認証情報、リージョン、モデル固定を変更できます。書き込み先は ~/.claude/settings.json で、CLAUDE_CONFIG_DIR を設定している場合は $CLAUDE_CONFIG_DIR/settings.json です。

出典: Claude Code on Amazon Bedrock

IAM ポリシーの設定

公式ドキュメントは、Claude Code 用に次の権限を持つ IAM ポリシーを作成するよう示しています。

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "AllowModelAndInferenceProfileAccess",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream",
        "bedrock:ListInferenceProfiles",
        "bedrock:GetInferenceProfile"
      ],
      "Resource": [
        "arn:aws:bedrock:*:*:inference-profile/*",
        "arn:aws:bedrock:*:*:application-inference-profile/*",
        "arn:aws:bedrock:*:*:foundation-model/*"
      ]
    },
    {
      "Sid": "AllowMarketplaceSubscription",
      "Effect": "Allow",
      "Action": [
        "aws-marketplace:ViewSubscriptions",
        "aws-marketplace:Subscribe"
      ],
      "Resource": "*",
      "Condition": {
        "StringEquals": {
          "aws:CalledViaLast": "bedrock.amazonaws.com"
        }
      }
    }
  ]
}
  • より厳しく絞りたい場合は、Resource を特定の inference profile の ARN に限定できます。
  • bedrock:GetInferenceProfile は、application inference profile の ARN から元のモデルを判別するために使われます。トークンにこの権限が無くても自動で再試行して動きますが、新しいモデルごとに往復が1回増えます。権限を付与すれば再試行を避けられ、AWS_BEARER_TOKEN_BEDROCK を使う構成で起きやすいとされています。
  • Claude Code 専用の AWS アカウントを作ると、コストの追跡とアクセス制御が簡単になると案内されています。

出典: Claude Code on Amazon Bedrock

リージョンとモデル ID の接頭辞

公式ドキュメントによると、Invoke API では、組み込みのデフォルトモデルは cross-region inference profile の ID に解決されます。解決されたリージョンごとに優先される接頭辞は次のとおりです。

  • us-gov-*(AWS GovCloud):us-gov.
  • us-*:us.
  • eu-*:eu.
  • ap-*:apac.
  • その他のリージョン:global.

最初に試す接頭辞は ANTHROPIC_BEDROCK_REGION_PREFIX で選べます。有効な値は us、eu、apac、jp、au、global で、v2.1.224 以降が必要です。たとえばアカウントで global. のプロファイルが有効なのに、リージョンから別の接頭辞が選ばれる場合に使います。

export ANTHROPIC_BEDROCK_REGION_PREFIX=global
# In a us-* region, the primary model now resolves to
# global.anthropic.claude-opus-5-5 instead of us.anthropic.claude-opus-5-5

注意点として、この接頭辞は希望であって保証ではありません。プロファイルの一覧を取得できない場合、確認なしで接頭辞が適用され、アカウントでその接頭辞のプロファイルが有効でなければ 400 エラーになります。GovCloud では常に us-gov. が使われ、有効でない値を設定するとリージョンから決まる接頭辞に戻ります。

出典: Claude Code on Amazon Bedrock

つまずきやすい点とトラブル対応

SSO のサインインタブが開き続ける

設定ファイルから awsAuthRefresh を削除します。社内 VPN や TLS 検査プロキシが SSO のブラウザ操作を中断すると、認証失敗と扱われ、認証情報が期限切れのままだと awsAuthRefresh が再実行されて別のタブが開くためです。ブラウザでの SSO を妨げる環境では、起動前に aws sso login を手動で実行します。

TLS 検査プロキシでの証明書エラー

OS の信頼ストアや NODE_EXTRA_CA_CERTS にある社内ルート証明書は、Bedrock 固有の設定なしで使われます。v2.1.261 より前は、ウィザードで Use credentials already in my environment を選んだ場合、OS ストアにだけルート証明書がある環境では、モデル確認に使う認証情報の取得が unable to get local issuer certificate で失敗したり、モデルが unreachable と表示されたりしました(推論リクエスト自体は成功していました)。v2.1.261 以降への更新が案内されています。

リージョンの問題

  • モデルの提供状況は aws bedrock list-inference-profiles --region your-region で確認します。
  • 対応リージョンへは export AWS_REGION=us-east-1 で切り替えられます。
  • 「on-demand throughput isn't supported」と出たら、モデルを inference profile の ID で指定します。
  • Claude Code は Invoke API を使い、Converse API には対応していません。

ゲートウェイ経由でストリーミングが失敗する

間にあるゲートウェイやプロキシは、Content-Type を含むレスポンスを変更せずに転送する必要があります。書き換えられると Bedrock streaming response has content-type で始まるエラーになります。ヘッダーを落としたうえでサーバー送信イベントに変換する場合は、毎ターン非ストリーミングに戻って遅くなり、CLAUDE_CODE_DISABLE_BEDROCK_CONTENT_TYPE_DEFAULT=1 の設定が案内されています。根本対応はゲートウェイ側で転送を無改変にすることです。

その他

/context の各ツールグループが 0 トークンと表示される問題は、v2.1.196 より前のバージョンで起きます。更新してください。Mantle エンドポイントの設定とエラーは、公式ドキュメントで確認してください。

出典: Claude Code on Amazon Bedrock

よくある質問

AWS CLI は必ず入れる必要がありますか。

公式ドキュメントでは任意とされています。認証情報を得るほかの手段がない場合にだけ必要です。

出典: Claude Code on Amazon Bedrock

すでにサインイン済みで、ウィザードの画面が出ません。

チャット画面が表示されている場合は /setup-bedrock を実行するとウィザードが開きます。CLAUDE_CODE_USE_BEDROCK=1 が設定されるまではコマンドメニューに表示されないため、全文を入力してください。

出典: Claude Code on Amazon Bedrock

AWS SSO でブラウザのタブが何度も開きます。どうすればよいですか。

設定ファイルから awsAuthRefresh を削除します。ネットワーク環境が自動のブラウザ SSO を妨げる場合は、Claude Code を起動する前に aws sso login を手動で実行します。

出典: Claude Code on Amazon Bedrock
